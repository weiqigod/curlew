# Implementation Plan: M12-004

## Overview

Add two more argument-bearing dynamic helpers — `{{$sha256('s')}}`
and `{{$md5('s')}}` — to the registry. Each is a thin, deterministic
wrapper over the standard library (`crypto/sha256.Sum256` and
`crypto/md5.Sum` respectively, formatted as lowercase hex). Both
plug into the M12-001 argument-parsing wiring and reuse the
`oneArg` helper introduced by M12-002. The slice is two new
registrations, table-driven golden-vector tests, two new MANUAL.md
rows plus an MD5-deprecation caveat, and one rephrasing of the
"More argument-bearing helpers land in M12-004 onward" parenthetical.

## Architectural Decisions

The exploration of `internal/variable/dynamic.go` (post-M12-003),
`internal/variable/dynamic_test.go`, `docs/MANUAL.md` §3.7, and
the M12-002 / M12-003 plan + verified docs surfaces seven design
choices worth recording up front. Each is the lowest-risk option
that satisfies the behaviors and reuses the M12-001 / M12-002
wiring without modification.

1. **Use `crypto/sha256.Sum256` and `crypto/md5.Sum` directly.**
   Both return fixed-size arrays (`[32]byte` and `[16]byte`). The
   scope text pins the implementation: `fmt.Sprintf("%x",
   sha256.Sum256([]byte(s)))` and `fmt.Sprintf("%x",
   md5.Sum([]byte(s)))`. `%x` on a `[N]byte` produces lowercase
   hex without any separator — the canonical hash representation
   used by `sha256sum(1)`, `md5(1)`, `git hash-object`, and every
   webhook-signature spec we are targeting. No `encoding/hex`
   import is needed because `fmt`'s verb does the work.

2. **Lowercase hex, exactly 64 / 32 chars.** Behaviors 1 and 2
   are explicit ("lowercase hex … 64 chars" / "32 chars"). The
   golden vectors in the observable block (`$sha256('hello')` →
   `2cf24dba5fb…`, `$md5('hello')` → `5d41402abc4…`) are the
   well-known RFC test vectors and lock the byte-for-byte
   contract. We assert these exact values in tests.

3. **Reuse `oneArg(funcName, fn)` from M12-002 unchanged.** Both
   helpers take exactly one string, ignore the RNG, and are pure
   deterministic transformations — the same shape `oneArg` was
   designed for. No new helper or refactor is needed. Both return
   `(string, nil)` — neither hash function has any runtime failure
   mode for any input bytes a user can construct from a YAML
   string literal. (Arity errors are still surfaced through
   `oneArg`'s `arityError` wrapper; that path is re-exercised here
   for the two new function names — behavior 5.)

4. **No new sentinel error code.** M12-002 introduced
   `DYNFN_BASE64_DECODE` because base64 decoding has a real,
   user-visible failure mode (corrupt input). Hashing has no such
   path: any `[]byte` input produces a hash. A placeholder code
   "just in case" would be a code smell — we add it when a real
   failure path appears.

5. **MD5 ships with a documented deprecation caveat, not a
   `[WARN]` log.** The MANUAL.md update calls out that MD5 is
   provided for parity with legacy webhook signature schemes only
   and steers new integrations toward `$sha256` (or HMAC-SHA-256
   from a later M12 task). A runtime warning would be noisy and
   does not belong in the value-rendering hot path. The static
   docs notice is enough to discourage misuse and matches the
   broader spec convention (cryptographic warnings live in the
   manual, not in stdout).

6. **Bump the `Available()` count assertion from 19 to 21 in
   the same patch.** `dynamic_test.go:298` (`if len(avail) != 19`)
   has been updated in every M12 task; M12-004 follows that
   pattern, keeping the build green between RED and GREEN cycles.
   This is the deliberate signal that the registry has grown by
   exactly the expected amount — not a smell.

7. **Per-request memoisation is honoured automatically.** The
   `Evaluate` cache (M12-001) keys by function name + NUL-joined
   args. `$sha256('x')` referenced twice in the same request hits
   the cache on the second call; referenced once per request in
   two different requests still resolves to the same byte string
   because the function is pure. Behavior 6 is therefore
   inherently true and does not need a separate test — it is
   covered by the existing `TestRegistry_Base64_caches_per_request`
   pattern, which we mirror for `$sha256` to lock the contract.

    // urlEncode applies query-component percent-encoding via net/url.QueryEscape.
    // Space becomes '+', '&' becomes '%26', '/' becomes '%2F'. This matches the
    // query-string convention; it is not suitable for path segments.
    r.funcs["urlEncode"] = oneArg("urlEncode", func(s string) (string, error) {
        return url.QueryEscape(s), nil
    })

    // jsonEncode returns the canonical RFC 8259 JSON-string literal for the
    // input string, including the surrounding double quotes. Characters such as
    // '"', '\', and control bytes are escaped per the spec. The result is valid
    // JSON and can be inlined directly into a JSON body without further quoting.
    // json.Marshal of a Go string never returns a non-nil error.
    r.funcs["jsonEncode"] = oneArg("jsonEncode", func(s string) (string, error) {
        b, _ := json.Marshal(s)
        return string(b), nil
    })
}

// internal/variable/dynamic_test.go

func TestRegistry_Sha256(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name  string
        input string
        want  string
    }{
        // Behavior 1 + observable: golden vector for "hello".
        {"hello", "hello", "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"},
        // Behavior 3: empty string.
        {"empty string", "", "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"},
        // Behavior 4: UTF-8 multibyte — hash is over the byte sequence,
        // not the rune sequence. Golden value computed once and pinned.
        {"utf-8 multibyte", "héllo", "3c48591d8d098a4538f5e013dfcf406e948eac4d3277b10bf614e295d6068179"},
        // Determinism cross-check — repeating the call returns the same hash.
        {"abc", "abc", "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := reg.Evaluate("sha256", []string{tt.input}, make(map[string]string))
            if err != nil {
                t.Fatalf("Evaluate(sha256, %q) unexpected error: %v", tt.input, err)
            }
            if got != tt.want {
                t.Errorf("sha256(%q) = %q, want %q", tt.input, got, tt.want)
            }
            // Behavior 1: 64 chars, lowercase hex only.
            if len(got) != 64 {
                t.Errorf("sha256(%q) length = %d, want 64", tt.input, len(got))
            }
            if !regexp.MustCompile(`^[0-9a-f]{64}$`).MatchString(got) {
                t.Errorf("sha256(%q) = %q, not lowercase 64-char hex", tt.input, got)
            }
        })
    }
}

func TestRegistry_Md5(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name  string
        input string
        want  string
    }{
        // Behavior 2 + observable: golden vector for "hello".
        {"hello", "hello", "5d41402abc4b2a76b9719d911017c592"},
        // Empty-string golden vector (RFC 1321).
        {"empty string", "", "d41d8cd98f00b204e9800998ecf8427e"},
        // UTF-8 multibyte — hash is over the byte sequence.
        // Golden value computed once and pinned.
        {"utf-8 multibyte", "héllo", "be50e8478cf24ff3595bc7307fb91b50"},
        // Determinism cross-check.
        {"abc", "abc", "900150983cd24fb0d6963f7d28e17f72"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := reg.Evaluate("md5", []string{tt.input}, make(map[string]string))
            if err != nil {
                t.Fatalf("Evaluate(md5, %q) unexpected error: %v", tt.input, err)
            }
            if got != tt.want {
                t.Errorf("md5(%q) = %q, want %q", tt.input, got, tt.want)
            }
            // Behavior 2: 32 chars, lowercase hex only.
            if len(got) != 32 {
                t.Errorf("md5(%q) length = %d, want 32", tt.input, len(got))
            }
            if !regexp.MustCompile(`^[0-9a-f]{32}$`).MatchString(got) {
                t.Errorf("md5(%q) = %q, not lowercase 32-char hex", tt.input, got)
            }
        })
    }
}

func TestRegistry_Sha256_NestedVar(t *testing.T) {
    seed := int64(1)
    reg := NewRegistry(&seed)
    s := NewScope(map[string]string{"payload": "hello"})
    if err := s.Resolve(); err != nil {
        t.Fatalf("Resolve: %v", err)
    }
    s = s.WithDynamic(reg)
    s.BeginRequest()
    defer s.EndRequest()

    got, err := s.Interpolate(`{{$sha256('{{payload}}')}}`)
    if err != nil {
        t.Fatalf("Interpolate: %v", err)
    }
    const want = "2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824"
    if got != want {
        t.Errorf("got %q, want %q", got, want)
    }
}

func TestRegistry_Sha256_caches_per_request(t *testing.T) {
    // Behavior 6: pure function of input — calling Evaluate twice with the
    // same arg in the same request must hit the cache. Verify by wrapping
    // the registered function with a counter.
    reg := NewRegistry(nil)
    var calls int
    reg.funcs["sha256"] = oneArg("sha256", func(s string) (string, error) {
        calls++
        return fmt.Sprintf("%x", sha256.Sum256([]byte(s))), nil
    })

    cache := make(map[string]string)
    v1, err := reg.Evaluate("sha256", []string{"x"}, cache)
    if err != nil {
        t.Fatalf("first call: %v", err)
    }
    v2, err := reg.Evaluate("sha256", []string{"x"}, cache)
    if err != nil {
        t.Fatalf("second call: %v", err)
    }
    if v1 != v2 {
        t.Errorf("memoized values differ: %q vs %q", v1, v2)
    }
    if calls != 1 {
        t.Errorf("expected 1 underlying call, got %d", calls)
    }
    // Different request (fresh cache) → same value because the function is pure.
    cache2 := make(map[string]string)
    v3, _ := reg.Evaluate("sha256", []string{"x"}, cache2)
    if v3 != v1 {
        t.Errorf("pure function should be deterministic across requests: %q vs %q", v3, v1)
    }
}

func TestRegistry_HashFns_arity_errors(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name     string
        funcName string
        args     []string
    }{
        {"sha256 zero args", "sha256", nil},
        {"sha256 two args", "sha256", []string{"a", "b"}},
        {"md5 zero args", "md5", nil},
        {"md5 two args", "md5", []string{"a", "b"}},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            _, err := reg.Evaluate(tt.funcName, tt.args, nil)
            if err == nil {
                t.Fatal("expected arity error, got nil")
            }
            var se *apierrors.Structured
            if !errors.As(err, &se) {
                t.Fatalf("expected *apierrors.Structured, got %T", err)
            }
            if se.Code != "DYNFN_ARITY" {
                t.Errorf("Code = %q, want DYNFN_ARITY", se.Code)
            }
            wantArity := fmt.Sprintf("expected 1 arguments, got %d", len(tt.args))
            if !strings.Contains(se.Message, wantArity) {
                t.Errorf("message %q should mention %q", se.Message, wantArity)
            }
            // The full err.Error() should name the function exactly once.
            if got := strings.Count(err.Error(), "$"+tt.funcName); got != 1 {
                t.Errorf("err.Error() should name $%s exactly once, got %d: %q", tt.funcName, got, err.Error())
            }
        })
    }
}

## Risks and Edge Cases

- **Risk:** A user expects `$md5` / `$sha256` to operate on raw
  bytes from a binary file (e.g. body bytes from a multipart
  upload). → **Mitigation:** The helper takes a string argument
  resolved from a YAML literal; binary content is out of scope
  for M12-004. The MANUAL.md row pins the contract ("UTF-8
  bytes"). A future helper that hashes file content (e.g.
  `$sha256File('path')`) would be a separate task.
- **Risk:** Cryptographic-style misuse — a user assumes `$md5`
  is "secure enough" for an integrity check on user-supplied
  data. → **Mitigation:** The MD5 caveat paragraph in MANUAL.md
  §3.7 explicitly directs new integrations to `$sha256` or HMAC.
  We do not emit a runtime warning (would be noisy in the
  value-rendering hot path) — the docs are the canonical
  source.
- **Risk:** Future helper needs the RNG (e.g., a salted hash). →
  **Mitigation:** Already addressed by the M12-002 plan — add a
  sibling `oneArgRNG` rather than re-shape `oneArg`. M12-004 does
  not need it.
- **Risk:** Golden UTF-8 vector drift — `héllo` could be encoded
  differently by different editors (NFC vs NFD normalisation). →
  **Mitigation:** The Go source-file string literal `"héllo"` is
  bytes `[0x68, 0xc3, 0xa9, 0x6c, 0x6c, 0x6f]` (NFC, six bytes,
  one code point for `é`). The execute phase verifies the golden
  hex via `printf 'héllo' | shasum -a 256` (or an in-test
  computation if the shell layer is uncertain). If a future
  editor reformats the test file with NFD, the test fails
  immediately with a clear diff.
- **Edge case:** Empty string `{{$sha256('')}}`. → **Handling:**
  Returns `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`
  (the SHA-256 of zero bytes) — asserted in the test table per
  behavior 3.
- **Edge case:** Empty string `{{$md5('')}}`. → **Handling:**
  Returns `d41d8cd98f00b204e9800998ecf8427e` (the MD5 of zero
  bytes) — asserted in the test table.
- **Edge case:** Repeated calls in the same request. →
  **Handling:** Behavior 6 — covered by
  `TestRegistry_Sha256_caches_per_request` and inherently true
  for any pure helper because the cache memoises identical input.
- **Edge case:** Repeated calls in different requests. →
  **Handling:** Pure function → identical output for identical
  input across requests; explicitly asserted in the per-request
  cache test (`v3 != v1` would fail).
- **Edge case:** `nil` cache. → **Handling:** Already handled by
  `Evaluate` (M12-001 line 96-100 `if cache != nil`); the new
  helpers inherit that behaviour because they go through
  `Evaluate`. No new test needed — exercised in the arity test
  (which passes `nil` cache).
