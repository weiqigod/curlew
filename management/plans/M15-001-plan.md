### Tier wiring (how tier reaches a gate)

`currentTier()` at `cmd/apitest/main.go:52` is package-level `var`. It reads
`APITEST_TIER` env override (used by tests and smoke) and otherwise returns
`TierFree`. There is no `--license <jwt>` flag in the CLI today; the M15-001
observable's `--license ./testdata/m15/license-*.jwt` invocation is aspirational
notation for "the active license tier resolves to X." We honor the *behaviors*
section, which specifies the four-tier matrix purely via `auth.CheckFeature`,
and translate the observable to the established `APITEST_TIER=<tier>` form.
Decision recorded: tests and smoke use `APITEST_TIER=` to drive the matrix —
this matches every other gate test in the repository and keeps the slice
runnable without inventing a new flag or fabricating JWT fixtures.

### Gate-error rendering paths already in place

- **Standalone subcommands** (perf.go pattern) — call `newStderrPrinterTo` +
  `Printer.FeatureGate(&ge.Result)` then `return 6`. We mirror this in
  `pluginsListCmdOut`.
- **Run command** — when a gate fires before `runner.Run`, the established
  helper is `writeGateForFormat(stdout, stderr, format, report, noColor, err)`
  (defined at `discovery_run.go:125`). It selects the renderer by output
  format (json/tap/junit/html/terminal). We mirror this for the
  `buildHookDispatcher` callsite at `main.go:1238`.

func TestDefaultRegistry_PluginLoading_TierMatrix(t *testing.T) {
	r := DefaultRegistry()
	tests := []struct {
		name     string
		tier     Tier
		wantGate bool // true means CheckFeature should return *GateError
	}{
		{"free rejects", TierFree, true},
		{"solo rejects", TierSolo, true},
		{"professional rejects", TierProfessional, true},
		{"team rejects", TierTeam, true},
		{"enterprise allows", TierEnterprise, false},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			err := CheckFeature(r, "plugin_loading", tt.tier)
			gotGate := err != nil
			if gotGate != tt.wantGate {
				t.Fatalf("CheckFeature(plugin_loading, %s) gate=%v, want %v (err=%v)",
					tt.tier, gotGate, tt.wantGate, err)
			}
			if tt.wantGate {
				var ge *GateError
				if !errors.As(err, &ge) {
					t.Fatalf("expected *GateError, got %T", err)
				}
				if ge.Result.Feature != "plugin_loading" {
					t.Errorf("Feature = %q, want plugin_loading", ge.Result.Feature)
				}
				if ge.Result.RequiredTier != TierEnterprise {
					t.Errorf("RequiredTier = %q, want %q", ge.Result.RequiredTier, TierEnterprise)
				}
				if ge.Result.Workaround == "" {
					t.Error("Workaround must propagate to GateResult")
				}
			}
		})
	}
}

func pluginsListCmdOut(args []string, stdout, stderr io.Writer) int {
	for _, a := range args {
		switch a {
		case "--help", "-h":
			printPluginsHelpTo(stdout)

			_, _ = fmt.Fprintf(stderr, "Unknown flag: %s\n", a)
			return 2
		}
	}

	// Tier gate — plugin_loading requires Enterprise. Only fires when
	// APITEST_PLUGINS is non-empty so unset-env prints an empty table at every
	// tier (mirrors the existing TestPluginsList_EmptyEnv contract).
	if env != "" {
		reg := auth.DefaultRegistry()
		if gateErr := auth.CheckFeature(reg, "plugin_loading", currentTier()); gateErr != nil {
			var ge *auth.GateError
			if errors.As(gateErr, &ge) {
				printer := newStderrPrinterTo(stderr, false)
				printer.FeatureGate(&ge.Result)
				return 6
			}
			_, _ = fmt.Fprintf(stderr, "error: %v\n", gateErr)
			return 1
		}
	}

	host := pluginsHostFactory()
	defer func() { _ = host.Close() }()

	loaded, loadErrs, err := host.Load(pluginsCtxFactory(), env)

## Risks and Edge Cases

- **Risk:** `APITEST_PLUGINS` set to whitespace-only or to empty after path
  separator (e.g. `APITEST_PLUGINS=:`) might bypass the gate by passing the
  `env != ""` check. → **Mitigation:** the gate intentionally mirrors the
  existing `if env == ""` early-return semantic so a string with content
  triggers the load attempt today and the gate tomorrow. Whitespace-only is
  unchanged from current behavior — the gate fires, then `host.Load` would
  parse-fail. We do not normalize beyond what current code does; this matches
  the established pattern and avoids divergence between the two enforcement
  points.
- **Edge case:** `apitest plugins list --help` with `APITEST_PLUGINS` set at
  Free tier → should print help and exit 0, not gate. → **Handling:** the
  argument loop runs before the gate (already in current order); help still
  prints. `TestPluginsList_Help` and `TestPluginsList_HelpArg` cover this and
  do not set `APITEST_PLUGINS` so the gate is also bypassed by the empty-env
  check — both layers protect.
- **Edge case:** `apitest plugins list --unknown-flag` with `APITEST_PLUGINS`
  set → exits 2 (existing behavior), not 6. → **Handling:** the unknown-flag
  branch returns 2 inside the argument loop, before reaching `os.Getenv` and
  the gate. Existing test `TestPluginsList_UnknownFlag` continues to assert
  exit 2 and does not set the env var.
- **Edge case:** `apitest run` with `--format json --events ...` and the gate
  triggers → events emitter must record `feature_gated` once. → **Handling:**
  the new mapping at the `buildHookDispatcher` callsite calls
  `eventsEmitter.EmitRunError(hookErr)` and sets `evExitCode = 6` before
  returning, mirroring the established `parallel_execution` and
  `distributed_execution` callsites. Renderer selection is delegated to
  `writeGateForFormat`.
- **Edge case:** Worker mode (`--workers >= 2`) reaches the run path. → It
  hits the existing `distributed_execution` gate at line 1164 first, so a Free
  tier with `APITEST_PLUGINS` and `--workers 2` exits 6 for `distributed_execution`
  before plugin loading is even attempted. We do not change that order;
  `buildHookDispatcher` is called only on the local path (line 1238 is after
  the workers-dispatch switch), so the plugin gate fires only when local
  execution proceeds. **No interaction risk.**
- **Edge case:** `--dry-run` and `--show-dependencies` paths return before
  line 1238. → They never call `buildHookDispatcher`, so the gate does not
  fire. Existing behavior preserved. (Acceptable: dry-run is not "loading
  plugins"; nothing is spawned.)
- **Risk:** New imports could trigger lint / `goimports` reordering. →
  **Mitigation:** `auth` is already imported in `cmd/apitest/main.go`;
  `cmd/apitest/plugins.go` will newly import `errors` and `auth`. Both
  conform to existing import grouping (stdlib, blank line, module path).
  `golangci-lint run` covers this.
