### How the existing `noArgs` registration pattern works

Each `$faker.*` function at `dynamic.go:430-565` is registered as
`r.funcs["faker.<name>"] = noArgs("faker.<name>", func(rng *rand.Rand) string { … })`.
The `noArgs` wrapper (line 84) rejects argument-bearing calls with a
structured `DYNFN_ARITY` error. Closures route all randomness through
`intn(rng, n)` (line 715), which is the same dispatch surface that
seeded-vs-crypto-rand routing rides on. New internet functions
follow this exact shape — nine `noArgs` registrations, one for each.

### Composition of `$faker.url` and `$faker.domain`

Per behaviors 1–2 + SPECIFICATION.md:805–806:
- `$faker.url` → full URL with scheme, host, and path (must match
  `^https?://[^/]+/[^\s]*$`). Composed as
  `https://<domain>/<path>` where `<domain>` reuses the same
  `<lowercaseToken>.<tldSuffix>` shape used by `$faker.domain`, and
  `<path>` is a single lowercase ASCII token from a small path-segment
  pool.
- `$faker.domain` → hostname with TLD only (no scheme, no path),
  matching `^[a-z0-9-]+\.[a-z]{2,}$`. Composed as
  `<lowercaseToken>.<tldSuffix>` — the lowercase token is drawn from
  a small "domain-name root" pool (e.g. `example`, `acme`, `widgets`).

The same pool of lowercase domain-name roots and TLD suffixes feeds
both. `$faker.url` is composed from those plus a small path pool;
the call order is fixed so `--seed 42` reproducibility is stable
across `$faker.url` and `$faker.domain` on independent invocations.

**Decision:** ship three small pools — `domainNameRoots`,
`tldSuffixes`, `urlPathSegments` — at `var` scope, sized 30 / 12 / 12
to land round numbers and keep entropy ≥ 4000 combinations for
`$faker.url`. Pool entries are picked to satisfy the regex contracts
on every shipped permutation.

### Composition of `$faker.ip`, `$faker.ipv6`, `$faker.mac`

- `$faker.ip` (IPv4): four octets in `[0, 255]` joined by dots:
  `fmt.Sprintf("%d.%d.%d.%d", intn(rng,256), intn(rng,256), intn(rng,256), intn(rng,256))`.
  Each octet is independently drawn — full IPv4 space allowed
  (no exclusion of reserved blocks; this is test data). Behavior 4
  asserts each octet is in `[0,255]`.
- `$faker.ipv6` (IPv6): 8 groups of 4 lowercase hex digits joined by
  `:`. Eight independent `rng.Uint32()` draws, each masked to 16 bits
  and rendered with `%04x`. Result is full-form (no `::`
  abbreviation) — net.ParseIP accepts it. Behavior 5 asserts the
  result is parseable by `net.ParseIP`.
- `$faker.mac` (MAC-48): six octets of two **uppercase** hex digits
  joined by `:`, e.g. `00:1B:63:84:45:E6`. Each octet is an
  independent `intn(rng, 256)` rendered with `%02X`. Behavior 6
  asserts the regex `^([0-9A-F]{2}:){5}[0-9A-F]{2}$`.

### `$faker.userAgent`

Per behavior 7 + SPECIFICATION.md:811: a non-empty UA string drawn
from a shipped pool covering Chrome / Firefox / Safari / Edge
variants on Windows, macOS, and Linux. Pool size is 6 (two per major
browser family). Each entry begins with `Mozilla/5.0` per current
browser convention. Behavior tests assert non-emptiness; the spec
narrative example begins with `Mozilla/5.0` so the shipped pool is
chosen to honour that prefix everywhere.

### `$faker.color` vs legacy `$randomColor` — the M13 Open Decision #3 split

Per task YAML scope and behavior 8: the existing `$randomColor`
registration at `internal/variable/dynamic.go:235-240` returns a
six-digit hex string (`#RRGGBB`). SPECIFICATION.md:812 specifies
`$faker.color` as a CSS color name (e.g. `"blue"`). M13 Open
Decision #3 ships **both contracts side-by-side**: no aliasing, no
deprecation, no behavior change to `$randomColor`. The new
`$faker.color` draws from a curated pool of CSS color keywords
(common subset: `red`, `green`, `blue`, `yellow`, `orange`, `purple`,
`pink`, `cyan`, `magenta`, `black`, `white`, `gray`, etc.).

**Decision:** ship a 24-entry `cssColorNames` pool covering the
canonical 17 named-color CSS1 keywords (per CSS Color Module Level 1)
plus 7 high-frequency named keywords from CSS3 (`crimson`,
`coral`, `gold`, `salmon`, `tan`, `khaki`, `violet`). All entries
are lowercase. The behavior validator asserts membership in this
exact pool — no regex alone (CSS color names cannot be expressed
as a meaningful regex without enumerating).

### `$faker.hexColor`

Per behavior 9 + SPECIFICATION.md:813: a `#RRGGBB` hex string with
**lowercase** hex (matches `^#[0-9a-f]{6}$`). Implementation mirrors
the existing `$randomColor` closure exactly — three `intn(rng, 256)`
draws rendered as `#%02x%02x%02x`. The two functions are independent
registrations: identical mechanics, distinct cache keys, distinct
seeded output traces. The existing `isHexColor` test helper at
`dynamic_test.go:147-152` is reusable for `$faker.hexColor`.

// isIPv4 asserts the value matches the spec regex AND each octet
// is in [0, 255] (behavior 4 + SPECIFICATION.md:808).
func isIPv4(t *testing.T, val string) {
    t.Helper()
    if !regexp.MustCompile(`^(\d{1,3}\.){3}\d{1,3}$`).MatchString(val) {
        t.Errorf("$faker.ip %q does not match dotted-quad regex", val)
        return
    }
    parts := strings.Split(val, ".")
    for i, p := range parts {
        n, err := strconv.Atoi(p)
        if err != nil || n < 0 || n > 255 {
            t.Errorf("$faker.ip %q octet %d (%q) out of range [0,255]", val, i, p)
        }
    }
}

// isIPv6 asserts net.ParseIP accepts the value as an IPv6 address
// (behavior 5 + SPECIFICATION.md:809). Uses net.ParseIP rather than
// a regex because IPv6 textual representations are not adequately
// captured by a single regex.
func isIPv6(t *testing.T, val string) {
    t.Helper()
    ip := net.ParseIP(val)

    if ip.To4() != nil {
        t.Errorf("$faker.ipv6 %q parsed as IPv4, not IPv6", val)
    }
}

// TestRegistry_FakerInternet_URLShape explicitly exercises the
// composition contract: scheme is "https://", host has exactly one
// dot, path is a single token after a leading "/".

    }
}

## Risks and Edge Cases

- **Risk: `$randomColor` accidentally aliased / overwritten.** The
  legacy hex contract MUST be preserved untouched. **Mitigation:**
  the new `$faker.color` registration uses a distinct map key
  (`"faker.color"`) so it cannot overwrite `"randomColor"`. The new
  `TestRegistry_FakerInternet_RandomColorVsFakerColor` asserts both
  names appear in `Available()` and asserts each contract holds.
  The existing `isHexColor` helper and any `randomColor` test stays
  untouched.
- **Risk: TLD pool drift breaks behavior-2 regex.** The composed
  `$faker.domain` regex is `^[a-z0-9-]+\.[a-z]{2,}$`. If a future
  TLD entry contains digits or hyphens (e.g. `xn--p1ai`), the regex
  fails. **Mitigation:** `TestFakerInternet_TLDSuffixesShape` asserts
  every shipped entry matches `^[a-z]{2,}$` exactly — drift trips
  the test. To add an internationalised TLD, the regex must be
  expanded in lockstep.
- **Risk: domain-root pool drift breaks behavior-2 regex.** Same
  shape — domain roots must match `^[a-z0-9-]+$` so the composed
  domain has only one dot. **Mitigation:**
  `TestFakerInternet_DomainRootsShape` pins this.
- **Risk: IPv6 implementation produces malformed strings.** Eight
  16-bit groups joined by `:` is the simplest representation, but
  it's easy to produce `0fff` instead of `0fff` (correct), or to
  emit one group too few. **Mitigation:** the implementation uses a
  fixed `%04x:%04x:…` format string with eight slots, and
  `TestRegistry_FakerInternet_IPv6Parseable` runs 100 trials
  asserting `net.ParseIP` accepts every result and reports it as
  IPv6 (not IPv4-mapped). A typo in the format string trips the
  test on the first trial.
- **Risk: MAC uppercase regression.** Spec requires uppercase hex
  (`^([0-9A-F]{2}:){5}[0-9A-F]{2}$`) but the implementer might
  accidentally use `%02x` (lowercase). **Mitigation:** the
  format-string call uses `%02X` (capital X) explicitly, and
  `TestRegistry_FakerInternet_MACUppercase` runs 100 trials with a
  case-sensitive regex. A `%02x` typo trips on iteration 1.
- **Risk: URL path is empty / multiple slashes.** Behavior 1's regex
  `^https?://[^/]+/[^\s]*$` requires exactly one `/` between host
  and path-start, then ≥ 0 non-whitespace chars. **Mitigation:** the
  implementation hardcodes `"/"` between host and segment, and the
  shipped path-segment pool contains only single-token entries (no
  slashes, no whitespace). `TestRegistry_FakerInternet_URLShape`
  decomposes the result and asserts the host and path shapes
  separately.
- **Risk: pool-size growth changes seeded output.** Three new pools
  (`domainNameRoots` 30, `tldSuffixes` 12, `urlPathSegments` 12)
  define seeded `$faker.url` output through the `intn` indices. Any
  resize would shift seeded byte-stable output. **Mitigation:**
  this slice doesn't modify M13-002 / M13-003 / M13-004 pools — they
  are independent slices. Each new pool addition lives in its own
  `var` block at file scope.
- **Risk: `$faker.color` pool excludes a CSS keyword someone needs.**
  The 24-entry pool covers the canonical CSS1 named-color set plus 7
  CSS3 keywords. A consumer wanting `cornflowerblue` is not served.
  **Mitigation:** the test `TestFakerInternet_CSSColorNamesLowercase`
  pins the membership invariant (lowercase ASCII), but pool size is
  intentionally small to keep `--seed` reproducibility predictable.
  Future expansions can add entries to the existing slice without a
  contract change. Documented in MANUAL.md as a "common subset".
- **Risk: user-agent strings drift over browser versions.** The
  shipped UA pool references Chrome 120, Firefox 121, Safari 17.2,
  Edge 120 — all current as of plan time. UA strings are mostly
  inert to the test fixtures; the only assertion is "starts with
  Mozilla/5.0". **Mitigation:** version drift is not a contract
  concern — the prefix invariant holds regardless. Pool refresh is a
  documentation-only change.
- **Risk: behavior 12 (`--locale`) coverage.** The flag does not
  exist in M13. **Mitigation:** the `t.Skip`-guarded
  `TestRegistry_FakerInternet_LocaleDeferred` documents the contract
  stub for the future locale-support milestone, mirroring the
  M13-002 / M13-003 / M13-004 pattern.
- **Edge case: per-request memoization.** `Registry.Evaluate` already
  caches results per (name, args) within a request via the `cache`
  parameter. Two `{{$faker.url}}` placeholders in the same request
  resolve to the same value — this is documented behavior
  (MANUAL.md:1261) and is the property we want.
- **Edge case: `TestRegistry_FakerInternet_Unseeded` collision.**
  `$faker.url` entropy is 30 × 12 × 12 = 4320 combinations.
  Single-trial collision is ~1/4320 ≈ 0.023%; the re-roll mitigates
  this to ~5×10⁻⁸ false-positive rate — acceptable for CI.
