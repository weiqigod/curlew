# Implementation Plan: M16-016

## Overview

Lands the per-org GitLab integrations management surface: backend endpoints that create (POST), list (GET — already stubbed) and soft-delete (DELETE) `gitlab_installations` rows with PAT encryption via `IGitLabKeyProvider` and project-path → numeric `project_id` lookup against `{gitlab_base_url}/api/v4/projects/<encoded-path>`; plus a tier-gated SvelteKit page at `/org/[slug]/integrations/gitlab` that exposes a Connect-GitLab form, a connection-health table, and a Disconnect action.

## Open Decisions Resolved Up Front (Auto Mode)

The task YAML defers to "Open Decision 11 — minimum-viable working page." Concrete decisions taken:

1. **Tier gate.** Re-use `VaultConfigTierGate.EnsureTeamOrAboveAsync` (the spec line 10256 cross-references it, and it is the cleanest existing "Team or above" gate for non-schedule resources; we avoid coupling integrations to ScheduleExecutor naming). Feature code in 402 ProblemDetails: `gitlab_integrations`.
2. **Project lookup mockability.** Introduce a narrow `IGitLabProjectLookup` interface inside `ApiTool.Backend/GitLab/Installations/`, with a single production implementation `GitLabProjectLookup` that uses `IHttpClientFactory` (new named client `gitlab-projects`). Tests register a fake via `WithWebHostBuilder` — mirrors the pattern used by `GitLabWebhookEndpointTests` for `IGitLabWebhookDispatcher`. The check-poster's `gitlab-statuses` client is not reused — concerns differ (Private-Token auth + per-installation rate limit vs. one-shot lookup with explicit PAT and per-request CA bundle).
3. **CA bundle on lookup.** When `gitlab_ca_bundle` is provided in the create request, the lookup uses a request-scoped `HttpClient` built from a custom handler with that CA. We do not persist a trust chain across requests for now — the same one-shot bundle is also stored on the installation row for the outbound poster (already handled in M16-014). This intentionally narrow: full CA bundle plumbing into `gitlab-statuses`/`gitlab-projects` named clients is a future task.
4. **HTTP enforcement.** Reuse the existing `GitLabOptions.Poster.AllowHttp` switch — the lookup honours the same flag so dev stubs work but prod rejects `http://` base URLs.
5. **Project-path encoding.** URL-encode the *whole* `group/project` value (per GitLab API: the slash must be encoded as `%2F`).
6. **Soft-delete semantics.** DELETE sets `deleted_at = now` and `updated_at = now`. The PAT ciphertext is intentionally *not* wiped here — the 30-day grace period for hard-delete remains a future cleanup task (spec line 9194), out of scope.
7. **Token revoked badge.** The list endpoint already surfaces `access_token_revoked_at`; the page renders a `token-revoked` badge and a "Re-paste PAT" affordance that opens the same Connect modal pre-filled with the project path. Re-pasting is implemented as a DELETE-then-POST (simplest; soft-deleted rows are tolerated by the UNIQUE-WHERE-deleted-IS-NULL index). A future task can collapse this into a PATCH.
8. **Last-status-post.** The list response carries the most-recent `pr_checks.posted_at` for each installation (LEFT JOIN, ordered by `posted_at` desc). The DB has no per-installation aggregate column — one extra grouped query per list call is fine for the scale here.
9. **Subnav link.** A new `subnav-gitlab-link` is added to the `(app)/+layout.svelte` shell next to the existing GitHub link, gated by `isTeamTier && isAdmin`. It points to `/org/[slug]/integrations/gitlab`.

The existing `web/src/routes/(app)/org/[slug]/integrations/github` and `.../schedules` pages are the closest UX templates.
- **E2E pattern.** `web/tests/e2e/github-connect.spec.ts` and `org-schedules.spec.ts` route `**/api/v1/integrations/...` requests via `context.route(...)` to mock backend payloads — no real backend required for the spec.

- **Test scaffolding.** `FakeHttpMessageHandler` + `FakeHttpClientFactory` exist for unit tests; for endpoint-level tests we override services via `WithWebHostBuilder` per the `GitLabWebhookEndpointTests` pattern.

/// <summary>
/// One-shot project-path → numeric project_id resolution against GitLab's
/// public API. Used during integration creation to validate the PAT + path
/// pair before persisting the row.
/// </summary>
public interface IGitLabProjectLookup
{
    Task<GitLabProjectLookupResult> LookupAsync(
        string gitlabBaseUrl,
        string projectPath,
        string accessToken,
        string? caBundlePem,
        CancellationToken ct);

/// <summary>Outcome of <see cref="IGitLabProjectLookup.LookupAsync"/>.</summary>
public sealed record GitLabProjectLookupResult(
    GitLabProjectLookupStatus Status,
    long? ProjectId,
    string? ResolvedPath);

public enum GitLabProjectLookupStatus
{
    Ok,
    NotFound,             // 404 — project missing or PAT lacks access
    Unauthorized,         // 401 — PAT invalid/revoked
    InsecureBaseUrl,      // http:// rejected by AllowHttp
    Unreachable,          // network/timeout
    InvalidResponse,      // 2xx but body did not contain numeric "id"
}

```csharp
// In MapGitLabIntegrationsEndpoints:
group.MapGet("",     ListInstallations)
     .RequireAuthorization()
     .WithName("ListGitLabIntegrations")
     .Produces<GitLabInstallationListResponse>()
     .ProducesProblem(StatusCodes.Status402PaymentRequired)
     .Produces(StatusCodes.Status401Unauthorized);

group.MapPost("",    CreateInstallation)
     .RequireAuthorization()
     .WithName("CreateGitLabIntegration")
     .Accepts<CreateGitLabIntegrationRequest>("application/json")
     .Produces<GitLabInstallationListItem>(StatusCodes.Status201Created)
     .Produces<ErrorResponse>(StatusCodes.Status400BadRequest)
     .Produces<ErrorResponse>(StatusCodes.Status409Conflict)
     .ProducesProblem(StatusCodes.Status402PaymentRequired);

group.MapDelete("{id:guid}", DeleteInstallation)
     .RequireAuthorization()
     .WithName("DeleteGitLabIntegration")
     .Produces(StatusCodes.Status204NoContent)
     .Produces<ErrorResponse>(StatusCodes.Status404NotFound)
     .ProducesProblem(StatusCodes.Status402PaymentRequired);
```

Handler logic (high level, all with explicit `CancellationToken`):

- **List:** resolve user → resolve unambiguous `org_id` (or accept `?org_id=` query, same as the GitHub install-url endpoint) → tier gate → SELECT installations WHERE org_id = X AND deleted_at IS NULL, LEFT JOIN pr_checks for max(posted_at) per gitlab_installation_id.
- **Create:** read body → validate `project_path` non-empty and `access_token` non-empty → default `gitlab_base_url` to `https://gitlab.com` → resolve org_id → tier gate → call `IGitLabProjectLookup.LookupAsync` → on Ok, encrypt PAT via `IGitLabKeyProvider`, INSERT row, return 201 with the projected `GitLabInstallationListItem` (PAT NOT echoed). Map lookup errors to 4xx ErrorResponse with `code` fields the web can show inline.
- **Delete:** resolve user + org → tier gate → SELECT installation WHERE id = X AND org_id = current → 404 if missing or already soft-deleted → set `deleted_at = updated_at = now` → SaveChangesAsync → 204.

import { api, type RequestOptions } from './client';
import type { GitLabInstallation, CreateGitLabIntegrationRequest } from '$lib/types/gitlab-integrations';

interface ListResponse { installations: GitLabInstallation[]; }

export const gitlabIntegrationsApi = {
  async list(opts: RequestOptions = {}): Promise<GitLabInstallation[]> {
    const r = await api.get<ListResponse>('/api/v1/integrations/gitlab', opts);
    return r.installations;
  },
  async create(body: CreateGitLabIntegrationRequest, opts: RequestOptions = {}): Promise<GitLabInstallation> {
    return await api.post<GitLabInstallation>('/api/v1/integrations/gitlab', body, opts);
  },
  async remove(id: string, opts: RequestOptions = {}): Promise<void> {
    await api.delete<void>(`/api/v1/integrations/gitlab/${encodeURIComponent(id)}`, opts);
  }
};

```typescript
import type { PageServerLoad } from './$types';
import { requireAuth, requireTeamTier } from '$lib/server/guards';
import { organizationsApi } from '$lib/api/organizations';
import { gitlabIntegrationsApi } from '$lib/api/gitlab-integrations';
import { ApiError } from '$lib/types/api-error';

export const load: PageServerLoad = async ({ locals, params, url, fetch }) => {
    const token = requireAuth(locals.accessToken, url.pathname + url.search);
    const org = await organizationsApi.findBySlug(params.slug, { token, fetch });
    const teamOrg = requireTeamTier(org, params.slug);

    let installations: GitLabInstallation[] = [];
    let loadError: string | null = null;
    try {
        installations = await gitlabIntegrationsApi.list({ token, fetch });
    } catch (e) {
        if (e instanceof ApiError && e.status === 402) {
            // requireTeamTier should already catch this — but be defensive
            throw e;
        }
        loadError = e instanceof Error ? e.message : 'failed to load integrations';
    }
    return { org: teamOrg, installations, loadError };
};
```

## Risks and Edge Cases

- **Risk:** Cross-tenant data leakage on DELETE. → **Mitigation:** `WHERE id = X AND org_id = currentOrg` in the SELECT; 404 on miss (not 403, which would leak existence).
- **Risk:** PAT echoed back in response. → **Mitigation:** `GitLabInstallationListItem` has no `access_token`/`access_token_ciphertext` fields; a dedicated unit test asserts the response JSON does not contain the submitted PAT.
- **Risk:** Re-creating after soft-delete hits the unique index. → **Mitigation:** The index is `WHERE deleted_at IS NULL` — soft-deleted rows do not collide. Re-paste flow uses DELETE-then-POST.
- **Risk:** Project-path containing `%2F` already encoded. → **Mitigation:** Validation rejects any `%` in `project_path` and asks the user to submit decoded form. Documented in the modal's helper text.
- **Risk:** Unlimited request body from a malicious PAT submission. → **Mitigation:** Existing `MaxRequestBodySize` middleware (referenced in `Program.cs:653`) already protects; no per-endpoint change needed.
- **Edge case:** `gitlab_ca_bundle` PEM with CRLF line endings. → **Handling:** Store as-is; the connection during lookup uses `X509Certificate2.CreateFromPem` which handles both line-ending forms.
- **Edge case:** GitLab returns 200 with `"id": "non-numeric"`. → **Handling:** `InvalidResponse` status → 502 to client, generic error.
- **Edge case:** `last_status_post` join when zero `pr_checks`. → **Handling:** LEFT JOIN; field is nullable `DateTimeOffset?` on the DTO and rendered as `—` in the UI.
