# Implementation Plan: M25-001

## Overview

Wire the release build into `scripts/ci-local.sh` so `.goreleaser.yaml` is
executed on every `--go` gate rather than trusted: validate the config, build a
single-target snapshot, and — the load-bearing part — run the resulting binary
and assert on its `--version`. A missing `goreleaser` must fail the gate with an
install instruction, never skip it.

## Design decisions

### D1 — How `goreleaser` is resolved: mirror `lint_cmd`, do not invent

`scripts/ci-local.sh` already has exactly one precedent for a required external
tool, at lines 126–135:

```bash
lint_cmd() {
  if [ -x "$HOME/go/bin/golangci-lint" ]; then
    "$HOME/go/bin/golangci-lint" "$@"
  elif command -v golangci-lint >/dev/null 2>&1; then
    golangci-lint "$@"
  else
    echo "golangci-lint not found (checked ~/go/bin and PATH)" >&2
    return 1
  fi
}
```

Two properties matter and both are copied: it probes the Go install location
*before* `PATH`, and its absent branch **returns 1** — it does not warn and
continue. Under `set -euo pipefail` (line 28), the bare call `lint_cmd run`
(line 175) aborts the script.

The file contains **no** "skip if absent" idiom to accidentally copy. The only
conditional execution is opt-*in* (`CURLEW_RUN_SELF_HOSTED`, line 376) and
change-scope detection for the .NET/web/E2E gates — never a tool-presence skip.

**Decision:** add `goreleaser_cmd()` next to `lint_cmd()`, same shape, with one
documented deviation: probe `$(go env GOPATH)/bin` instead of a hardcoded
`$HOME/go/bin`, because the failure message tells the operator to run
`go install`, and the probe should look where `go install` actually writes.

### D2 — Minimum goreleaser version: yes, major ≥ 2, failing closed

`.goreleaser.yaml:19` declares `version: 2`, and the config uses `archives[].ids`
and `archives[].formats` (plural) — keys that only recent goreleaser v2 accepts.
A goreleaser v1 would reject the file with a message about YAML fields, not
about the tool being too old.

**Decision:** gate on the major version, parsed by anchoring on the
`GitVersion:` line. Anchoring is not optional — the naive
`grep -Eo '[0-9]+\.[0-9]+\.[0-9]+'` also matches `GoVersion: go1.26.6`:

```
$ goreleaser --version | grep -Eo '[0-9]+\.[0-9]+\.[0-9]+'
2.17.1
1.26.6          <- the Go version, not goreleaser's
```

Verified working parse: `awk '/^GitVersion:/ { v=$2; sub(/^v/,"",v); print v; exit }'` → `2.17.1`.

**An unparseable version must fail, not pass.** That is the same rule as a
missing binary: a version string the gate could not read must never become a
green light.

Rejected: a full semver comparison against a minimum like `2.6.0`. It costs
fragile shell for a case `goreleaser check` already fails on, loudly.

### D3 — No escape hatch

No `CURLEW_SKIP_RELEASE_CHECK` or equivalent. `internal/backlog/backlog.go`'s
package comment states the rule this project learned in M22-001:

> A checker that answers "clear" when it has in fact read nothing is worse than
> no checker, because it converts an unread file into a green light.

An opt-out env var is that failure mode with a flag on it. The step costs ~2.1s;
there is no runtime argument for one.

### D4 — Placement: after `smoke`, before the dogfood gate

The Go gate (lines 142–286) runs in every mode, so anywhere inside it satisfies
"inside the `--go` scope". Within that:

- **After** `go build` / tests / `golangci-lint` / the instant grep guards /
  `smoke`, so the fast feedback ordinary edits break still comes first.
- **Before** the dogfood gate (lines 204–286), which starts mudflat and runs
  four harnesses over several minutes. A broken release config should fail in
  ~2s rather than after that.

Insertion point: between `./smoke/run.sh` (line 202) and the
`# --- Dogfood gate` comment (line 204).

### D5 — The `--version` assertion

Must fail on `curlew 0.1.0-dev` (the `cmd/curlew/main.go:52` default), and must
still hold after M25-002 cuts `v0.1.0` — at which point the snapshot version
becomes `0.1.1-snapshot`, not `0.0.1-snapshot`. So the exact current string is
**not** hardcoded.

`snapshot.version_template` is `"{{ incpatch .Version }}-snapshot"`, which always
yields `X.Y.Z-snapshot`. Output format is `fmt.Fprintf(stdout, "curlew %s\n", version)`
(`cmd/curlew/main.go:75`).

**Decision:** two checks, specific first for a better message:

1. equality against `curlew 0.1.0-dev` → names the exact regression;
2. regex `^curlew [0-9]+\.[0-9]+\.[0-9]+-snapshot$` → proves the injected value
   came from the snapshot template.

Check 2 alone would reject `0.1.0-dev`, but check 1 is what makes the failure
legible to whoever hits it.

### D6 — Artifact path resolved by count, not by glob

`--clean` plus `--single-target` yields exactly one build directory, so
`./dist/curlew_*/curlew` works today. It is still resolved by counting matches
and failing on anything other than exactly one: a glob that silently expands to
nothing would turn the assertion into a no-op, which is precisely the outcome
this step exists to prevent. Portable `find`/`wc` is used rather than `mapfile`,
which macOS's system bash 3.2 lacks.

### D7 — No new Go test

The behaviour under test is the gate script's own control flow. A Go test
asserting that `ci-local.sh` *contains* a goreleaser step would restate the
script rather than exercise it — a document about the gate that nothing holds
the gate to, which is the shape of defect this milestone exists to close. The
verification is executing the gate (see Verification below).

The `-X main.version` mechanism is already pinned at the Go level by
`cmd/curlew/version_test.go:34 TestVersion_is_injectable_at_link_time`. What was
missing is proof that the *release configuration* uses it — which only running
the built artifact can give, and which Step 4 below adds.

### D8 — Considered and rejected: extracting the step into its own script

The alternative is to put the release logic in `scripts/check-release-build.sh`
with a `scripts/check-release-build_test.sh` beside it, and have `ci-local.sh`
call both. The repo has the precedent: `ci-local.sh:80` delegates
`--check-signing-keys` to its own script with the stated reason *"Delegated to
check-signing-keys.sh for unit-testability"*.

The real argument for it: behaviour 3 ("a missing goreleaser fails the gate")
cannot be tested automatically inline, because `goreleaser_cmd` is a function
inside a script whose only entry point runs the whole gate. Extracted, it can be
driven with a stubbed `PATH` in a subprocess.

**Rejected for this task**, on three grounds:

1. The task scope says "Add a release step to `scripts/ci-local.sh`". Extraction
   plus a new test file is a larger design than was asked for.
2. The model being copied is **an orphan**. `scripts/check-signing-keys_test.sh`
   is referenced by nothing — not `ci-local.sh`, not any workflow (verified by
   `grep -rn check-signing-keys_test`). Adding a second never-executed test file
   in a task about checkers that never run would be the wrong lesson to draw.
3. The DoD frames behaviour 3's verification as a manual procedure anyway
   ("break the config, confirm the gate fails, restore"). The exact commands are
   specified under *Missing-tool verification* below and must be pasted into the
   verification report.

If `/review` disagrees, the extraction is pre-specified here and the release
logic in Step 4 moves wholesale into the new script with no change to its body.

### Step 3: Add the `goreleaser_cmd` resolver

**Rationale:** A self-contained function that changes no existing control flow;
adding it alone cannot alter the gate's outcome, so it is the smallest possible
first edit.

#### Files to Modify

| File | Action | Description |
|------|--------|-------------|
| `scripts/ci-local.sh` | modify | New `goreleaser_cmd()` after `lint_cmd()` (line 135) |

#### Current Code (`scripts/ci-local.sh:125–140`)

```bash
# Resolve golangci-lint (CLAUDE.md notes it lives at ~/go/bin and may not be in PATH).
lint_cmd() {
  if [ -x "$HOME/go/bin/golangci-lint" ]; then
    "$HOME/go/bin/golangci-lint" "$@"
  elif command -v golangci-lint >/dev/null 2>&1; then
    golangci-lint "$@"
  else
    echo "golangci-lint not found (checked ~/go/bin and PATH)" >&2
    return 1
  fi
}
```

#### New Code (inserted directly after `lint_cmd`)

```bash
# Resolve goreleaser, the same way and for the same reason as lint_cmd above:
# probe the Go install location before PATH, and *fail* when it is absent.
#
# The absent branch returns 1 rather than skipping the release step. A gate that
# reports PASS while quietly omitting a step is the false clear M22-001 exists
# to prevent (see internal/backlog/backlog.go), and the release path is the
# worst place to reintroduce it: a parser bug is caught by the next test run, a
# release bug by the first user, after the tag is public and immutable.
#
# Unlike lint_cmd this asks `go env GOPATH` rather than hardcoding ~/go/bin,
# because the failure message below tells the operator to run `go install`, and
# the probe should look where `go install` actually writes.
goreleaser_cmd() {
  if [ -x "$(go env GOPATH)/bin/goreleaser" ]; then
    "$(go env GOPATH)/bin/goreleaser" "$@"
  elif command -v goreleaser >/dev/null 2>&1; then
    goreleaser "$@"
  else
    echo "goreleaser not found (checked \$(go env GOPATH)/bin and PATH)." >&2
    echo "Install it with:" >&2
    echo "    go install github.com/goreleaser/goreleaser/v2@latest" >&2
    return 1
  fi
}
```

#### Impact on existing tests
None. The function is defined but not yet called; the gate's behaviour is
unchanged.

### Step 4: Add the release section to the Go gate

**Rationale:** The behavioural change. It comes after the resolver exists so
that the only new failure mode introduced here is the intended one.

#### Files to Modify

| File | Action | Description |
|------|--------|-------------|
| `scripts/ci-local.sh` | modify | Four new `step`s between `smoke` (line 202) and the dogfood gate (line 204) |

#### Current Code (`scripts/ci-local.sh:201–205`)

```bash
step "smoke"
./smoke/run.sh

# --- Dogfood gate: curlew against mudflat ---
#
```

#### New Code

```bash
step "smoke"
./smoke/run.sh

# --- Release gate: .goreleaser.yaml, executed rather than trusted ---
#
# Added by M25-001. .goreleaser.yaml shipped in #14 and was never once run: no
# tag exists, goreleaser was not installed, and this script did not mention it.
# Every property the config claims — static CGO_ENABLED=0 builds, -X
# main.version injection, LICENSE and NOTICE carried per Apache-2.0 4(a)/4(d) —
# was a claim about a build nobody had performed.
#
# This runs on every --go gate. Measured cost is ~2.1s: `check` is 0.07s and the
# single-target snapshot is 2s, which is why it can afford to be unconditional.
# It sits before the dogfood gate so a broken release config fails in seconds
# rather than after several minutes of mudflat harnesses.
#
# Nothing here publishes: no tag, no `goreleaser release`, no network push.
step "release: goreleaser is installed and new enough"
# Anchored on the GitVersion: line on purpose — `goreleaser --version` also
# prints `GoVersion: go1.26.6`, and an unanchored semver grep picks up the Go
# version instead. An unparseable version fails rather than being assumed
# compatible, for the same reason a missing binary does.
goreleaser_version="$(goreleaser_cmd --version | awk '/^GitVersion:/ { v=$2; sub(/^v/,"",v); print v; exit }')"
goreleaser_major="${goreleaser_version%%.*}"
case "$goreleaser_major" in
  ''|*[!0-9]*)
    echo "could not read a version out of \`goreleaser --version\` (parsed: '${goreleaser_version}')." >&2
    echo "Refusing to continue rather than assume it is compatible." >&2
    echo "Install a known-good build with:" >&2
    echo "    go install github.com/goreleaser/goreleaser/v2@latest" >&2
    exit 1
    ;;
esac
if [ "$goreleaser_major" -lt 2 ]; then
  echo "goreleaser $goreleaser_version is too old: .goreleaser.yaml declares 'version: 2'." >&2
  echo "    go install github.com/goreleaser/goreleaser/v2@latest" >&2
  exit 1
fi
echo "goreleaser $goreleaser_version"

step "release: goreleaser check"
goreleaser_cmd check

step "release: snapshot build for this host"
# --single-target builds only the host platform, which is what keeps this
# affordable on every gate; the full six-target matrix is M25-002's job, at tag
# time. --clean wipes dist/ (gitignored, .gitignore:42) and does not touch the
# tracked internal/uiserver/assets/dist/index.html, which lives under a
# different directory entirely.
goreleaser_cmd build --snapshot --clean --single-target

step "release: the built artifact reports its injected version"
# The step that actually matters. `check` proves the YAML parses and the build
# proves it compiles; only running the artifact proves -X main.version reached
# it. A binary still reporting the cmd/curlew/main.go default is exactly the
# failure that would otherwise be discovered by a user, after the tag is public.
#
# Resolved by count rather than by bare glob: a glob that expanded to nothing
# would turn this assertion into a no-op, which is the one outcome this step
# exists to prevent.
release_bin_count="$(find dist -type f -name curlew | wc -l | tr -d ' ')"
if [ "$release_bin_count" != "1" ]; then
  echo "expected exactly one built curlew under dist/, found ${release_bin_count}" >&2
  exit 1
fi
release_bin="$(find dist -type f -name curlew)"
release_version="$("$release_bin" --version)"
echo "${release_bin}: ${release_version}"

if [ "$release_version" = "curlew 0.1.0-dev" ]; then
  echo "FAIL: the release artifact reports the cmd/curlew/main.go default." >&2
  echo "      -X main.version never reached the binary; every published archive" >&2
  echo "      would be mislabelled with no build step failing to warn." >&2
  exit 1
fi
# X.Y.Z-snapshot, from snapshot.version_template "{{ incpatch .Version }}-snapshot".
# Deliberately not an equality check: this reads 0.0.1-snapshot while no tag
# exists and 0.1.1-snapshot once M25-002 cuts v0.1.0, and both are correct.
if ! printf '%s\n' "$release_version" | grep -qE '^curlew [0-9]+\.[0-9]+\.[0-9]+-snapshot$'; then
  echo "FAIL: release artifact reported '${release_version}'," >&2
  echo "      want 'curlew <X.Y.Z>-snapshot' from snapshot.version_template." >&2
  exit 1
fi

# --- Dogfood gate: curlew against mudflat ---
#
```

## Risks and Edge Cases

- **Risk:** `goreleaser check` gives a false sense of coverage — it exits 0 on a
  config whose build cannot run (measured above). → **Mitigation:** the plan
  never relies on `check` alone; the mutation verification explicitly expects
  the *build* step to be the one that fails, and the artifact is executed.
- **Risk:** hardcoding `0.0.1-snapshot` would break the moment M25-002 cuts
  `v0.1.0` (the value becomes `0.1.1-snapshot`). → **Mitigation:** D5's regex
  matches any `X.Y.Z-snapshot`, with a separate equality check naming
  `0.1.0-dev`.
- **Risk:** an assertion loose enough to pass on the wrong binary (e.g. "output
  is non-empty"). → **Mitigation:** the regex requires the `-snapshot` suffix,
  which the hardcoded default cannot produce; the explicit `0.1.0-dev`
  comparison is checked first for a legible message.
- **Risk:** `--clean` destroying tracked files — `internal/uiserver/assets/dist/index.html`
  is a **tracked** file living under a `dist/` path. → **Mitigation:** measured.
  `.goreleaser.yaml` sets no `dist:` key, so goreleaser cleans the project-root
  `dist/` only; after a build `git status --porcelain` was empty and
  `git diff --exit-code -- internal/uiserver/assets/dist/index.html` reported
  unchanged. `/verify` should re-confirm both.
- **Risk:** parsing `goreleaser --version` is coupled to the `GitVersion:` label.
  → **Mitigation:** if the label ever moves, the parse yields empty and the step
  **fails closed** with a message naming the parsed value. Loud and one line to
  fix; never a silent pass.
- **Risk:** a developer mid-edit runs the gate with a dirty tree. → **Mitigation:**
  measured — `--snapshot` logs "ignoring errors because this is a snapshot" and
  exits 0 with a modified tracked file present.
- **Risk:** `go install …/v2@latest` pulls a newer Go toolchain (it fetched
  go1.26.6 on this host, which runs go1.25.5). → **Mitigation:** it is automatic
  and exited 0. The CI step in Step 5 pins `@v2.17.1` so the toolchain fetch is
  at least deterministic.
- **Edge case:** `find dist -type f -name curlew` matching zero or several files.
  → **Handling:** counted, and any count other than 1 exits 1 (D6). `dist/` also
  holds `artifacts.json`, `config.yaml` and `metadata.json`; none is named
  `curlew`.
- **Edge case:** `goreleaser_cmd --version` inside a pipeline when the binary is
  absent. → **Handling:** `set -o pipefail` (line 28) propagates the failure to
  the assignment, so `set -e` aborts. stderr is deliberately **not** redirected
  to `/dev/null`, or the install instruction would be swallowed.
- **Edge case:** goreleaser v1 present on PATH. → **Handling:** D2's major check
  fails with a message naming `version: 2`, rather than v1's confusing YAML-field
  error.
