## Scope boundary — read this before executing anything

This task's YAML has two halves. They are **not** both in scope for this
pipeline.

### In scope

Everything local. Write the test that drives `goreleaser release --snapshot
--clean` and asserts on the produced artifacts. Snapshot mode publishes nothing
and needs no tag — goreleaser's own log says so:

```
• skipping announce, publish, and validate...
```

and `goreleaser release --help` documents `--snapshot` as *"…without publishing
any artifacts (implies --skip=announce,publish,validate)"*.

### Out of scope — must NOT be executed by `/execute` or `/verify`

- creating the git tag `v0.1.0` (even locally)
- pushing any tag
- running `goreleaser release` in **non**-snapshot mode
- creating or publishing a GitHub release
- dispatching `.github/workflows/release.yml`

A pushed tag is public and effectively immutable, and this task's own definition
of done requires *a human* to review the release notes. `.goreleaser.yaml:94`
sets `draft: true` for exactly that reason. The full procedure is specified at
the end of this plan as a ready-to-run runbook awaiting the project owner's
go-ahead.

### Definition-of-done item that will remain OPEN

> `v0.1.0 tagged, artifacts published, release notes reviewed by a human`

This will **not** be satisfied when this pipeline finishes, and the DoD is not
being rewritten to pretend otherwise. It is deliberately deferred because:

1. A pushed tag cannot be meaningfully retracted. Anyone who fetches it keeps
   the ref; re-tagging the same name gives two people different commits under
   one version.
2. The DoD itself requires human review of the release notes. An automated
   phase cannot satisfy a criterion whose subject is a person.
3. The changelog filter (`.goreleaser.yaml:82-89`) has never been executed
   against real tag history. With **no previous tag**, `v0.1.0`'s notes span the
   entire repository history — they will be long and will need editing by hand.
   That editing is the review the DoD is asking for.
4. Publishing requires a `GITHUB_TOKEN` with `contents: write`, or Actions
   billing to be restored so `release.yml` can be dispatched. Neither is a
   decision for a pipeline phase to make.

`/verify` must record this item as **deferred, with reason**, not as passed.

## Design decisions

### D1 — Placement: a build tag *plus* an explicit gate step

`scripts/ci-local.sh` runs `go test` **three times** — line 190 `go test
$(go_pkgs)`, line 193 `go test -race $(go_pkgs)`, line 196 `go test
-coverprofile=coverage.out $(go_pkgs)`. An untagged test in `cmd/curlew` that
drives a 28s release therefore costs **3 × 28s ≈ 84s minimum** (more under
`-race`) on a 353s gate: **+24%**, two-thirds of it pure repetition. Instrumenting
a `goreleaser` subprocess for data races detects nothing.

**Decision:** the test file carries `//go:build release_artifacts`, and
`scripts/ci-local.sh` gains **one** named step inside the existing M25-001
release block that runs it exactly once:

```bash
go test -tags release_artifacts -run '^TestRelease' ./cmd/curlew/ -count=1 -v
```

Measured cost: 1.4s compile+link (m16) + 28s release (m1) + 0.6s inspection
(m9) + native exec ≈ **~30s**, i.e. **+8%** on a 353s gate.

Alternatives considered and rejected:

| Option | Verdict |
|---|---|
| (a) untagged, unconditional | **Rejected on cost** — 3×28s, +24%, two runs of which are redundant |
| (b) `testing.Short()` | **Rejected** — the gate never passes `-short`, so it would still run 3× |
| (c) env-var opt-in, like `CURLEW_RUN_SELF_HOSTED` (`ci-local.sh:494`) | **Rejected** — that precedent is an opt-in the gate never sets, i.e. a step that never runs. M25-001 D3 already ruled out escape hatches on the release path |
| (d) changed-file scoping | **Rejected** — `CHANGELOG.md` is edited by **every** task's DoD *and* ships inside the archives, so the predicate fires on nearly every branch. It buys almost no time and adds a way to be silently skipped |
| (e) a separate shell script | **Rejected** — M25-001 D8 rejected this shape, and the DoD asks for a *test* |

**The tag is not an escape hatch, because ci-local.sh names the step
unconditionally.** That is the difference between this and
`scripts/check-signing-keys_test.sh`, the orphan M25-001 D8 warned about: an
orphan is a test nothing runs, and this one is run by the gate on every `--go`
invocation. If `/review` disagrees, the tag can be dropped and the file made
unconditional with **no change to the test body** — only the gate cost changes.

**The linting blind spot must be closed in the same step.** `.golangci.yml` has
no `run:` section, so golangci-lint builds with default tags and would **skip
the new file entirely** — an unlinted file in a repo whose gate claims to lint
everything. `.golangci.yml` gains:

```yaml
run:
  build-tags:
    - release_artifacts
```

Verified as a valid golangci-lint v2 key (m17: `config verify` exit 0; m18: a
bogus sibling key exits 3, so the check is real). `/execute` must **prove the
tag took effect** rather than assume it: temporarily introduce a deliberate
`ineffassign` or `errcheck` violation into the tagged file, run `golangci-lint
run`, confirm it is **reported**, then remove it. A config key that parses but
does not change which files are analysed is precisely the false clear this
project keeps closing.

### D2 — The test drives goreleaser itself; it never inspects a `dist/` it did not create

The DoD says *"A test **drives** a snapshot release and asserts on the produced
archives."* Reading a pre-existing `dist/` would let the test pass on artifacts
built from a different commit, a different config, or a previous, mutated run —
and Mutation A proves a stale `dist/` can contain six readable, empty archives.

The test therefore runs `goreleaser release --snapshot --clean` as a subprocess
and **asserts its exit code is 0 before looking at anything**.

goreleaser is resolved the same way `goreleaser_cmd` resolves it in
`scripts/ci-local.sh:149-160`: `$(go env GOPATH)/bin/goreleaser` first, then
`exec.LookPath`. **Absent → `t.Fatal`, never `t.Skip`.** Both CI workflows
already supply it — `.github/workflows/go.yml:55` via `go install …@v2.17.1`
(lands in GOPATH/bin) and `.github/workflows/release.yml` via
`goreleaser-action` `install-only: true` (lands on PATH) — so both resolution
branches are exercised in practice.

There is no `--dist` flag (m13), so the test necessarily uses the repo-root
`dist/`. That is safe; see D8.

### D3 — The version assertion: one derivation, three independent cross-checks

The version is **derived from exactly one place** — the archive filename, which
`.goreleaser.yaml:54-55` generates from `{{ .ProjectName }}_{{ .Version }}_{{
.Os }}_{{ .Arch }}` — and then cross-checked against three sources that would
have to fail in the same direction to agree wrongly:

1. **All six archive filenames agree** on one version string. (Catches a mixed
   `dist/` from a partial or stale run.)
2. **`checksums.txt` filenames** carry the same version.
3. **Each binary's buildinfo `-ldflags`** contains `-X main.version=<V>` with
   the same `<V>` — read via `debug/buildinfo`, which works on all six
   cross-compiled artifacts (m8).
4. **The one natively-executable binary prints** `curlew <V>` (m10).

Then two rejections that hold in every mode:

- `<V>` must match `^[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`.
- `<V>` must **not** equal the compiled-in default, and the executed binary's
  output must not report it either.

**The default is referenced by symbol, not by literal.** The test file is
`package main` in `cmd/curlew/`, and the test binary is built *without*
`-ldflags`, so the package-level `version` var (`cmd/curlew/main.go:52`) holds
`"0.1.0-dev"` at test runtime. Comparing against `version` rather than against
the string `"0.1.0-dev"` means the assertion cannot drift if the default is ever
changed — the same source-derived discipline `doc_exit_codes_test.go` and
`internal/schema/parity_test.go` already apply.

**Why this is two-legged, and why both legs are needed.** The failure modes are
distinct and each is caught by exactly one leg:

| Regression | buildinfo leg | executed-binary leg |
|---|---|---|
| `-X main.version=` dropped from `.goreleaser.yaml` (M25-001's M3 mutation) | **catches** — no `-X main.version=` in `-ldflags` | catches |
| `version` regresses from `var` to `const` | **blind** — the flag is still passed, so buildinfo still records it | **catches** — the linker silently ignored it and the binary prints `0.1.0-dev` |
| A cross-compiled target built with different flags from the host target | **catches** — per-target, all six checked | blind — only one target is executable |

The `const` regression is the one `.goreleaser.yaml:43-46` warns about in prose;
only executing a binary can detect it, and only for the host target. The
buildinfo leg is what extends *per-target* coverage to the five that cannot run
here. Neither leg subsumes the other.

**On the `-snapshot` suffix.** The test always invokes `--snapshot`, so the
produced version always ends in `-snapshot` by construction of
`snapshot.version_template` (`.goreleaser.yaml:80`). Asserting that suffix is
therefore legitimate *and* honest — but it is stated as a **mode-specific**
check, kept in its own assertion with its own comment, separate from the
mode-independent chain above. Everything in items 1–4 and both rejections holds
identically for a real tagged build (`curlew_0.1.0_darwin_arm64.tar.gz` →
`0.1.0`); only the suffix check is tied to how this test invokes goreleaser.

Note the shape of the space: `0.1.0-dev` *does* match the semver regex. The
explicit symbol comparison is what rejects it, which is why the regex alone is
not the assertion.

### D4 — Non-executable targets: buildinfo + format parse, and no Rosetta opportunism

Measured (m10): on this darwin/arm64 host **four of six binaries cannot be
executed at all** (`exec format error`, exit 126). On any host, exactly one
target is *guaranteed* runnable — the `runtime.GOOS`/`runtime.GOARCH` match.

**Decision — three tiers, all mandatory, none conditional:**

1. **All six**, from the archive bytes with no temp file:
   - `debug/buildinfo` → `GOOS` and `GOARCH` equal the values in the archive
     filename; `CGO_ENABLED=0`; `-ldflags` contains `-X main.version=<V>`.
   - format parse with the package selected by expected GOOS —
     `debug/elf` for linux, `debug/macho` for darwin, `debug/pe` for windows —
     and the machine field must equal the expected GOARCH (values in the table
     above). Choosing the parser by *expected* GOOS means a windows archive
     containing an ELF binary fails on the parse, not on a magic-byte mismatch.
   - the binary's entry name is `curlew.exe` for windows and `curlew` otherwise;
     the archive extension is `.zip` for windows and `.tar.gz` otherwise.
2. **The native target only:** written to `t.TempDir()` with mode 0755, executed
   with `--version`, stdout compared to `curlew <V>`.
3. **A vacuity guard on tier 2:** the test asserts that **exactly one** archive
   matched `runtime.GOOS`/`runtime.GOARCH` and that it *was* executed. If the
   host is a platform the matrix does not cover, that is a `t.Fatal` naming the
   host — not a quiet skip that would leave the executed-binary leg silently
   uncovered.

**Rosetta opportunism is rejected.** darwin_amd64 runs on this host only because
Rosetta happens to be installed (m10). A check that passes when a translation
layer is present and is skipped when it is not is a conditional pass — the exact
false-clear shape `internal/backlog/backlog.go`'s package comment names:

> A checker that answers "clear" when it has in fact read nothing is worse than
> no checker, because it converts an unread file into a green light.

**Asserting that cross-target binaries *cannot* run is also rejected.** It would
encode a property of the host, not of the artifact, and would break the day
someone runs the gate under `binfmt_misc`/qemu or on a Windows host with WSL
interop. The test asserts what the artifact *is*, never what the host refuses
to do with it.

So: this host executes 1 of 6 (2 with Rosetta, unclaimed); a Linux CI runner
executes a different 1 of 6. The other five are held by buildinfo and format
parse. That is the honest coverage statement and it belongs in the CHANGELOG
entry, not only here.

### D5 — Expectations come from the config **and** from a hardcoded floor

Two sources, because each catches what the other cannot:

**Config-derived** — parse `.goreleaser.yaml` with `gopkg.in/yaml.v3` (already a
direct dependency, m19):

- `builds[0].goos × builds[0].goarch` → the expected target matrix. Catches a
  target that is *declared but not archived*.
- `archives[0].files` → the expected file list. Catches a file that is
  *declared but not archived*.

**Hardcoded floor** — the six targets and the six documents the task names:

- `{linux,darwin,windows} × {amd64,arm64}` must all be present.
- `LICENSE`, `NOTICE`, `README.md`, `CHANGELOG.md`, `docs/MANUAL.md`,
  `docs/CLI_SPECIFICATION.md` must all be present.

**Mutation B is why the floor exists.** Dropping `- NOTICE` from the config
shrinks the config-derived expectation in lockstep with the archives, so the
config-derived check agrees with itself and passes (measured: exit 0). Only the
hardcoded floor fails. The same holds for deleting `windows` from `goos`. A
check derived *solely* from the artifact under test is a tautology; the floor is
what makes it an assertion.

The two failure messages must be different and must say which kind of drift
occurred — "declared in .goreleaser.yaml but missing from the archive" versus
"required by Apache-2.0 §4(a)/§4(d) but no longer declared in .goreleaser.yaml".

The config parse also needs its own vacuity guards: an empty `goos` list, an
empty `goarch` list, or an empty `files` list must **fail**, and the presence of
a `builds[].ignore:` key (absent today) must fail loudly, because the cartesian
product would no longer be the right expectation.

Rejected: deriving expectations from `dist/artifacts.json` or
`dist/metadata.json`. Those are goreleaser's own report of what it did; holding
the artifacts to them proves only that goreleaser agrees with itself.

### D6 — `checksums.txt`: re-hashed, and asserted bidirectionally

Format measured (m11):

```
fe8d9be2c6c57d59abf3a75a4513cba9e884ac8c5500368cc6d63d7497c8c337  curlew_0.0.1-snapshot_darwin_amd64.tar.gz
```

— `<64 lowercase hex><two spaces><basename>`.

The test computes `sha256.Sum256` over each archive's raw bytes and compares.
**Both directions are asserted**, because either alone is vacuous:

- every archive found on disk has a line in `checksums.txt` — without this, a
  seventh unlisted archive would ship unverified;
- every line in `checksums.txt` names an archive that exists on disk — without
  this, a `checksums.txt` containing zero lines, or lines for files that were
  never produced, would pass;
- and the two sets must have the **same cardinality**, equal to the expected
  target count. A file that is missing from both sides is otherwise invisible.

`checksums.txt` itself must not appear in its own listing (it does not).

### D7 — Test decomposition: one release, two named tests

The task YAML names two tests and both need the same 28s release. Running
goreleaser twice would double the gate cost for nothing.

**Decision:** a package-level `sync.Once` guarded helper,
`releaseSnapshot(t *testing.T) *snapshotRelease`, that performs the release on
first call and returns the cached, already-parsed result afterwards. Both named
tests call it. The `-run '^TestRelease'` in the gate step selects both, in one
`go test` process, so the `Once` fires once.

Rejected: `TestMain`. It cannot call `t.Fatal`, so a release failure would have
to be smuggled into the tests as stored state anyway; the `Once` is the same
mechanism without the indirection. Rejected: `t.Run` subtests under a single
parent — the task YAML names two top-level tests and the observable invokes them
separately.

A cached *failure* must stay a failure: if the release fails, the cached value
records the error and every caller fails with it. It must not be retried, and
must never degrade to a skip.

**The `sync.Once` + `t.Fatal` hazard, stated explicitly because it produces a
silent pass.** `t.Fatal` calls `runtime.Goexit`. `sync.Once.Do` marks itself
done via `defer`, so a `t.Fatal` *inside* the once-function still marks the
`Once` complete — while the result was never stored. The **second** caller then
receives a zero-valued `snapshotRelease`: no archives, no error, and every
range-over-archives assertion passes vacuously. This is the exact failure shape
the whole task exists to prevent, reintroduced by a helper.

**Therefore the once-function must never call `t.Fatal`, `t.Fatalf`, `t.Skip`
or anything that Goexits.** It returns every failure into `snapshotRelease.Err`;
`releaseSnapshot` inspects `rel.Err` *after* `Once.Do` returns and fails from
the caller's own context. As a belt-and-braces guard, `releaseSnapshot` also
fails when `rel.Err == nil && len(rel.Archives) == 0`, so a zero value can never
be mistaken for a successful release. `/review` should check this specifically.

### D8 — `dist/` collisions: ordering, and why nothing else is at risk

Three hazards, all checked:

**(a) M25-001's `release_bin_count` guard (`scripts/ci-local.sh:294-302`)
requires exactly one file named `curlew` under `dist/`.** After a six-target
release there are **four** (`linux×2`, `darwin×2`) plus two named `curlew.exe`.

Resolved by **ordering**: the new step goes *after* the existing version
assertion ends at line 320, immediately before the `# --- Dogfood gate` comment
at line 322. The existing single-target step at line 275 runs `--clean` itself,
so it is unaffected by anything the new step leaves behind, and nothing after
line 320 reads `dist/` at all (m20, verified with
`awk 'NR>320 && /dist/' scripts/ci-local.sh` → no output).

**(b) `go test ./...` runs packages in parallel.** Only `cmd/curlew` would drive
goreleaser, and the tag keeps the file out of all three routine `go test` passes
entirely, so no routine pass touches `dist/`. Within the tagged run, tests in a
package run sequentially unless `t.Parallel()` is called; these must not call
it, and the `sync.Once` makes concurrent entry safe regardless.

**(c) `TestCiLocalDownIdempotent` (`cmd/curlew/ci_local_test.go`)** executes
`ci-local.sh --down`, which is handled in the `case "$MODE"` block and `exit 0`s
at line 76 — before `goreleaser_cmd` is even defined and far before the release
block. Unaffected. `/verify` should still run it explicitly.

**(d) the repo-root `curlew` binary** built by `ci-local.sh:169` is gitignored
(`.gitignore:2:/curlew`, m15) and lives outside `dist/`. No collision.

### D9 — Deviation from the task YAML's `observable`

The task YAML writes:

```bash
go test ./cmd/curlew/ -run TestRelease_every_archive_is_complete -v
```

Under D1 this must become:

```bash
go test -tags release_artifacts ./cmd/curlew/ -run TestRelease_every_archive_is_complete -v

package main

// Sentinel errors for the well-known failure modes, per CLAUDE.md's error
// conventions.
var (
    ErrGoreleaserNotFound = errors.New("goreleaser not found")
    ErrNoArchives         = errors.New("no release archives produced")
    ErrEmptyArchive       = errors.New("archive contains no entries")
)

// archive is one produced release archive, fully read into memory.
// Measured at 573ms for all six, so holding them is cheaper than the
// bookkeeping of streaming them (M25-002 measurement 9).
type archive struct {
    Path    string            // dist/curlew_0.0.1-snapshot_linux_amd64.tar.gz
    Name    string            // basename
    Version string            // parsed from Name
    OS      string            // parsed from Name
    Arch    string            // parsed from Name
    Zip     bool              // .zip rather than .tar.gz
    Raw     []byte            // the archive file itself, for checksum re-hashing
    Entries map[string][]byte // entry name -> contents
}

// snapshotRelease is the cached result of one `goreleaser release --snapshot
// --clean`. Cached because both named tests need it and it costs 28s.
type snapshotRelease struct {
    Archives  []archive
    Checksums map[string]string // basename -> lowercase hex sha256, as listed
    Err       error
}

// releaseSnapshot drives goreleaser once per test binary and returns the
// parsed result. It never skips: a missing goreleaser is a failure, because a
// gate that reports clear while omitting a step is worse than no gate
// (internal/backlog/backlog.go).
func releaseSnapshot(t *testing.T) *snapshotRelease

// findGoreleaser mirrors goreleaser_cmd in scripts/ci-local.sh:342-353 —
// $(go env GOPATH)/bin first, then PATH — so the test and the gate cannot
// resolve different binaries.
func findGoreleaser() (string, error)

// readArchive reads one .tar.gz or .zip entirely into memory.
func readArchive(path string) (archive, error)

// parseArchiveName splits curlew_<version>_<goos>_<goarch>.(tar.gz|zip).
func parseArchiveName(base string) (version, goos, goarch string, isZip bool, err error)

// releaseConfig is the subset of .goreleaser.yaml this test holds the
// artifacts to. Parsed with gopkg.in/yaml.v3 (already a direct dependency).
type releaseConfig struct {
    Builds []struct {
        GOOS   []string `yaml:"goos"`
        GOARCH []string `yaml:"goarch"`
        Ignore []any    `yaml:"ignore"`
    } `yaml:"builds"`
    Archives []struct {
        Files []string `yaml:"files"`
    } `yaml:"archives"`
}

func loadReleaseConfig(path string) (releaseConfig, error)

// targets is the cartesian product goos × goarch, guarded against an empty
// product and against an `ignore:` key that would make the product wrong.
func (c releaseConfig) targets() ([]string, error)   // "linux/amd64", ...

// injectedVersion pulls <V> out of a buildinfo -ldflags value containing
// `-X main.version=<V>`. Returns ok=false when the flag is absent, which is
// exactly the regression .goreleaser.yaml:43-46 warns about.
func injectedVersion(ldflags string) (string, bool)

// buildSettings reads GOOS, GOARCH, CGO_ENABLED and -ldflags out of a
// cross-compiled binary held in memory. debug/buildinfo works on all six
// targets (M25-002 measurement 8).
func buildSettings(bin []byte) (map[string]string, error)

// assertMachine parses bin with the debug package matching wantOS and checks
// the machine field against wantArch. Choosing the parser by *expected* OS
// means a windows archive holding an ELF binary fails on the parse.
func assertMachine(t *testing.T, name string, bin []byte, wantOS, wantArch string)
```

## Risks and Edge Cases

- **Risk:** the test passes on a `dist/` it did not create — stale, or from a
  mutated config. → **Mitigation:** D2. The test drives `--clean` itself and
  asserts goreleaser's exit code before reading anything.
- **Risk:** the glob finds zero archives and the loop body never executes, so
  the test passes having asserted nothing. → **Mitigation:** the archive count
  is compared against the expected target count *before* any per-archive
  assertion, following M25-001 D6's precedent at `ci-local.sh:294-302`
  (resolve by count, never by bare glob).
- **Risk:** an archive opens cleanly but is empty. **Measured**: a failed
  release leaves 32-byte `.tar.gz` and 22-byte `.zip` stubs that `archive/tar`
  and `archive/zip` read as **zero entries with no error**. → **Mitigation:**
  entry count asserted per archive, and the required-file set is checked
  positively rather than by absence-of-error.
- **Risk:** the expected file list is derived from the config under test, so
  deleting `- NOTICE` shrinks both sides and the check agrees with itself.
  **Measured** (Mutation B): exit 0, six archives, no NOTICE. → **Mitigation:**
  D5's hardcoded floor, with a distinct failure message naming Apache-2.0
  §4(d).
- **Risk:** the version assertion is blind to `version` regressing to a
  `const`, because buildinfo still records the flag the linker ignored. →
  **Mitigation:** D3's second leg executes the one natively-runnable binary.
  Residual, stated honestly: that leg covers **one** target per host.
- **Risk:** hardcoding `0.0.1-snapshot` would break the day `v0.1.0` is cut
  (the snapshot becomes `0.1.1-snapshot`). → **Mitigation:** D3 derives the
  version from the archive filename; nothing is hardcoded but the *rejection*
  of the default, and that is referenced by symbol (`version`), not literal.
- **Risk:** `0.1.0-dev` satisfies the semver regex, so the shape check alone
  would not reject it. → **Mitigation:** explicit comparison against the
  package-level `version` symbol, checked separately with its own message.
- **Risk:** the build tag makes the test an orphan nothing runs — the failure
  mode M25-001 D8 explicitly warned about with
  `scripts/check-signing-keys_test.sh`. → **Mitigation:** `ci-local.sh` names
  the step unconditionally on every `--go` gate. `/review` should verify the
  step is present and reached; if unconvinced, D1 pre-specifies dropping the
  tag with no change to the test body.
- **Risk:** the tagged file is silently unlinted. → **Mitigation:** Step 2, and
  it must be **proved** by planting a real lint violation and observing it
  reported — parsing the config is not evidence.
- **Risk:** M25-001's `release_bin_count` guard breaks because a six-target
  release leaves four `curlew` files under `dist/`. → **Mitigation:** D8's
  ordering. The new step runs after line 320; nothing below reads `dist/`
  (verified).
- **Edge case:** a host whose `runtime.GOOS`/`runtime.GOARCH` is outside the
  matrix, so no binary is executable. → **Handling:** `t.Fatal` naming the
  host. Not a skip — a silently-uncovered execution leg is the false clear this
  whole design is built against.
- **Edge case:** Rosetta makes darwin_amd64 runnable on darwin_arm64
  (measured). → **Handling:** deliberately **not** used. A check that runs only
  when a translation layer happens to be installed is a conditional pass.
- **Edge case:** `builds[].ignore:` added to `.goreleaser.yaml` later, making
  the cartesian product the wrong expectation. → **Handling:** the config
  parser fails loudly if the key is present. It is absent today.
- **Edge case:** `checksums.txt` missing entirely (measured: a failed release
  produces no `checksums.txt`). → **Handling:** its absence is a `t.Fatal`, and
  the bidirectional cardinality check would fail regardless.
- **Edge case:** goreleaser absent from the host. → **Handling:** `t.Fatal`
  with the `go install` instruction, mirroring `goreleaser_cmd`'s message. The
  gate's own earlier step would have failed first, but the test must not depend
  on that to stay honest when run standalone.
- **Risk:** a dirty working tree during a snapshot release. → **Mitigation:**
  measured by M25-001 and again here — `--snapshot` logs *"ignoring errors
  because this is a snapshot"* and exits 0. Build metadata records
  `vcs.modified`, which the test does not assert on, since a developer running
  the gate mid-edit is normal.
- **Risk:** 28s is measured on a warm build cache; a cold cache on a CI runner
  will be slower. → **Mitigation:** accepted. `go.yml` and `release.yml` both
  enable `cache: true` on `actions/setup-go`. The number in the CHANGELOG is
  labelled as measured on this host, not promised as a CI figure.
- **Risk:** `sync.Once` + `t.Fatal` yields a zero-valued cached release that
  passes vacuously (see D7). → **Mitigation:** the once-function never Goexits;
  `releaseSnapshot` additionally fails on `Err == nil && len(Archives) == 0`.
- **Risk:** `.goreleaser.yaml:23-27`'s `before` hook runs `go mod download`, so
  the release needs a warm module cache or network. → **Mitigation:** it
  exited 0 in the measured run (m1) and the cache is warm in both CI workflows
  (`actions/setup-go` `cache: true`). If it ever fails, it fails *loudly* at
  goreleaser's exit code, which D2 asserts before reading anything — it cannot
  become an empty `dist/` that the test then mis-reads.

### Deviations (found during `/execute`, 2026-08-16)

An independent review pass ran concurrently with `/plan` and returned after
`/execute` had already reconciled the plan against current code and started
Step 1. Its findings are applied here rather than silently, per this project's
own convention (see `M25-001-plan.md`'s Deviations section). Each item below
is marked against what the plan already said, because most of it was already
covered by design — the review's value was in the four items that were not.

1. **The task YAML's own `observable` is vacuous — already covered by D9/Step
   7, and now independently confirmed by execution.** `go test ./cmd/curlew/
   -run TestRelease_every_archive_is_complete -v` (no `-tags`) was run
   directly during `/execute`, before any implementation existed:

   ```
   testing: warning: no tests to run
   PASS
   ok  	github.com/weiqigod/curlew/cmd/curlew	0.395s [no tests to run]
   ```

   Exit 0. This is the same defect class the task exists to close — a command
   that reports success having verified nothing — reproduced inside the task
   file that closes it. D9 already mandates `-tags release_artifacts` on both
   `go test` lines and Step 7 already rewrites `management/tasks/M25-002.yaml`
   to match. No plan change; this is confirmation the existing Step 7 must not
   be skipped, recorded because a reviewer independently flagged it as the
   most important item and it is now execution-verified rather than predicted.

2. **New: a count guard on the gate step, for the identical reason.** `go test
   -run '^TestReleaseTYPO'` or a misspelled `-tags` value also exits 0 printing
   `ok ... [no tests to run]` — the same vacuity as item 1, one level down, and
   nothing in Step 4's gate step as originally written would catch a typo in
   its own `-run` pattern or tag name. Step 4's new code gains a `-list` guard
   immediately before the run line:

   ```bash
   release_tests="$(go test -tags release_artifacts -list '^TestRelease' ./cmd/curlew/ | grep -c '^TestRelease' || true)"
   if [ "$release_tests" != "3" ]; then
     echo "expected 3 TestRelease_* tests under -tags release_artifacts, found ${release_tests}." >&2
     exit 1
   fi
   ```

   (3, not 2 — `TestRelease_checksums_match_the_archives` from Step 3 is a
   third top-level test under the same prefix.) The `|| true` is required:
   under `set -euo pipefail` (line 28), `grep -c` on zero matches exits 1, and
   without `|| true` the pipeline would abort *before* the `if` line could
   print the intended message — the same class of trap M25-001 hit with `find`
   on a missing `dist/` (`ci-local.sh:287-293`'s comment explains that
   precedent). The existing `go test -tags release_artifacts -run
   '^TestRelease' ./cmd/curlew/ -count=1 -v` line is kept streaming directly
   (not captured to a variable), matching every other test invocation already
   in this script — a 28-second step going silent until the end and losing
   output on failure would be a regression from the existing style, not an
   improvement.

3. **`.golangci.yml` has no `run:` block at all today — confirmed by re-read,
   matches what Step 2 already does.** The file goes `version: "2"` directly to
   `linters:`; Step 2 creates the block, it does not amend one. No plan change.
   Verification is escalated to three steps, because the second and third are
   what actually distinguish "parses" from "changes behaviour":

   - `golangci-lint config verify` — exit code recorded.
   - `golangci-lint run -v 2>&1 | grep 'Using build tags'` — must show
     `Using build tags: [release_artifacts]`.
   - **The mutation, and it must be `errcheck`, not the `ineffassign` D1
     originally suggested as one of two options, and specifically not a
     `govet`/printf violation.** `go test` itself runs a vet subset that
     includes `printf` — a printf violation would fail the `go test` step too,
     so a report at that stage could not be attributed to golangci-lint's build
     tag picking up the file rather than to `go vet`. A fully-discarded
     error-returning call (e.g. `os.Remove(path)` with no assignment and no
     `_ =`) is `errcheck`'s job alone and not part of the vet subset `go test`
     runs, so a report cleanly isolates the claim to lint scope.
   - Noted, not acted on further: without this block, `gofumpt` also never
     formats the new file — the blind spot Step 2 closes is wider than lint
     findings alone. The file is written gofumpt-clean from the start so this
     never becomes visible as a diff.

4. **New: identifier discipline for the new file.** `cmd/curlew/main.go:52`
   declares `var version = "0.1.0-dev"` at package level, and D3 requires
   comparing against it *by symbol* — so a local `version := ...` anywhere in
   the new file would shadow it in a file whose entire subject is versions,
   silently comparing against the shadow instead of the real default. The
   struct field and every local holding a version string in the new file is
   named `release`/`archiveVersion`/etc., never `version`. New identifiers are
   prefixed `release`, `archive`, or `checksum` to stay clear of
   `testVersion`, `buildBinary`, `buildBinaryWithVersion`, and every
   `runBinary*` helper already declared in untagged files compiled alongside
   this one (confirmed present at `main_test.go:55,67,72,3635,5167` and
   `version_test.go:21,52` during reconciliation). Additionally: the goreleaser
   subprocess itself is run with a dedicated helper, not `runBinary`/
   `runBinaryWithEnv` — those two `t.Fatalf` on any non-`*exec.ExitError` and
   were written to report a test binary's own failures, not to produce
   goreleaser's own `go install` remediation message on a not-found error the
   way `findGoreleaser` needs to (D2). `runBinary` is still reused, exactly as
   the plan's Test Impact Summary says, for the one native-target binary in D4
   tier 2.

5. **New: `injectedVersion` must match the literal, case-sensitive token `-X
   main.version=`, never a substring or case-insensitive test.** Not a
   plan change so much as an implementation constraint the plan's signature
   list didn't spell out: a loose match such as
   `strings.Contains(ldflags, "main.version")` (case-insensitive, or matching
   on `main.Version` too) would pass on a mutated
   `-X main.Version=` (capital V) — the linker silently drops `-X` for a
   symbol that does not exist, buildinfo still faithfully records the flag
   text it was given, and every binary would report the `0.1.0-dev` default
   while the buildinfo leg reported green. Implemented as an exact,
   case-sensitive `strings.Index` on the literal `-X main.version=`, value
   taken to the next whitespace, compared with `==`. Covered by a fast
   table-driven unit test against fabricated ldflags strings (happy path,
   flag absent, `main.Version` wrong case, extra whitespace) rather than by
   another 28-second mutation run — the same "verify the helper directly
   rather than mutate `dist/`" precedent the plan already uses for N5.

6. **Sharpened, not changed: cardinality asserted before set-difference in the
   checksums test.** D6 already requires "the two sets must have the same
   cardinality, equal to the expected target count" — this makes explicit that
   the cardinality check runs *first* and independently, because the two
   subset checks ("every archive has a line", "every line has an archive") are
   jointly vacuous when both sets are empty: a release that produced zero
   archives and an absent `checksums.txt` would pass both with nothing to
   range over. `len(onDisk) == want` and `len(inSums) == want` are asserted
   before either subset comparison. Every `checksums.txt` line must match
   `<64 lowercase hex><two spaces><name>`; an unparsed line is a `t.Fatal`,
   never a skipped `continue`. Re-hashing stays in Go (`crypto/sha256`, D6 as
   written) rather than shelling out — worth stating explicitly because
   `sha256sum` does not exist on macOS and `shasum -a 256 -c` against an empty
   or missing manifest exits 0, which would have reintroduced exactly the
   vacuity this test exists to prevent.

7. **CHANGELOG — confirmed, not changed: Step 6 already targets `###
   Added` under `## [Unreleased]`, never a `## [0.1.0]` heading.** Worth
   recording explicitly because the DoD line reads "CHANGELOG.md updated with
   *the release entry*" and that phrase could be misread as the actual
   `[0.1.0]` section. It is not: `CHANGELOG.md` ships inside every archive
   (`.goreleaser.yaml:72`), and a `[0.1.0]` heading written before the tag
   exists would ship inside snapshot archives whose binaries report
   `0.0.1-snapshot`, announcing a release that has not happened from inside
   artifacts that are not it. The renumbering to `## [0.1.0] — YYYY-MM-DD` is
   listed as precondition 2 of the deferred runbook, to happen immediately
   before tagging, which this pipeline does not run. `/verify` should read the
   DoD's "release entry" as satisfied by the `### Added` entry Step 6 writes,
   not by a section this phase deliberately does not create — recorded here as
   a deviation in *interpretation*, not in file content.

8. **New, all confirmed during Step 3/4 implementation rather than assumed:**
   - Linux binaries are additionally asserted to have no `.interp` ELF
     section, rather than asserting `Type == ET_EXEC`. `.interp`'s absence is
     what "requires no dynamic linker" actually means; `ET_EXEC` vs `ET_DYN`
     can change with a harmless future PIE default without the binary becoming
     any less static, and would then fail a check that never should have
     encoded a linker implementation detail. This is additive — the plan's
     `assertMachine` (machine-field check) is unchanged and still required for
     all six.
   - Every archive's binary entry mode is asserted to be `0o755`. Not in the
     plan's per-case list; a `0644` binary would extract unrunnable and no
     other assertion would notice.
   - The archive **file's** own filesystem mtime (`os.Stat`, not any entry
     inside it) is asserted not to predate the moment this test invoked
     goreleaser. Entry mtimes are deliberately not used for this — they are
     pinned to `{{ .CommitTimestamp }}` by `.goreleaser.yaml:48` for
     reproducibility and do not reflect when this run produced them. This
     guards against a stale `dist/` surviving `--clean` and being misread as
     this run's output; D2's own exit-code-first check remains the primary
     guard.
   - No design change: entries were already read fully into memory
     (`archive.Entries map[string][]byte`) per the Proposed Go signatures, and
     the only on-disk write is the native binary to `t.TempDir()` that D4 tier
     2 already specifies. Confirmed during implementation that nothing writes
     into the repository working tree, where a root-level `curlew` would
     collide with the dogfood gate's own binary (`ci-local.sh:169`).

None of the above changes Steps 1–7's ordering or the scope boundary. No item
weakens or removes an assertion the plan already specified; every change is
additive rigor or a naming/implementation constraint. The scope boundary
(no tag, no push, no publish, `git tag -l` stays empty) is unaffected and
restated as non-negotiable in `/execute`'s own instructions.

### Backing out

**Before publishing (still a draft):**

```bash
gh release delete v0.1.0 --yes
git push --delete origin v0.1.0
git tag -d v0.1.0
```

Recoverable in practice, with one caveat: anyone who fetched in the interval
keeps a stale local ref. Prefer cutting `v0.1.1` over re-using `v0.1.0` for a
different commit.

**After publishing:** do **not** delete or retag. Publish a corrected `v0.1.1`.
A published release URL may already be in someone's install script, and a
release that changes contents under a fixed version is worse than a wrong one
that stays put.

### Why a pipeline phase must not do this

A tag push is the one action in this task that cannot be undone by
`git checkout --`. Everything else in this plan was verified by running it and
restoring; this cannot be. `draft: true` exists precisely so the last step is a
person's decision, and automating up to and including that decision would
remove the safeguard the configuration was written to provide.
