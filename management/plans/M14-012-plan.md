# Implementation Plan: M14-012

## Overview
Replace `NoopStripeWebhookDispatcher` with a real router and four type-specific handlers — `customer.subscription.{created,updated,deleted}` and `customer.updated` — that re-fetch the underlying object from Stripe (defensive against out-of-order delivery), upsert the local `subscriptions` row, mirror customer email/metadata changes, enqueue `billing_subscription_canceled` on cancellation, and quarantine rows whose Stripe object has 404'd.

## Task Details
- **ID:** M14-012
- **Title:** Backend: Stripe subscription + customer event handlers
- **Phase:** M14: Revenue plumbing
- **Priority:** 2
- **Complexity:** high

## Dependencies

| Task | Title | Status |
|------|-------|--------|

| M14-014 | SendGridSmtpSender + EmailQueueProcessor + MJML compile pipeline | done |

## Architectural Decisions

The task YAML is partly aspirational — these are the resolutions baked into the plan:

1. **`/api/v1/me` does not exist.** The observable references it; no such endpoint is implemented in the backend. Replace the `/api/v1/me` curl call in `scripts/replay-stripe-event.sh` with a call to the existing `GET /api/v1/subscriptions` endpoint (the one wired in `SubscriptionsEndpoints.cs`), which returns `{ "tier": "..." }`. The behavior under test — that webhook handlers move the org's tier from `team` back to `free` after a deletion — is the same.

2. **`orgs.stripe_customer_email` does not exist.** The `Organization` entity has no such column and the spec's `subscriptions` table does not have it either. Behavior #4 is interpreted as: mirror the email/metadata change into the existing `subscriptions.stripe_customer_id`-keyed row. We add `Subscription.StripeCustomerEmail` (nullable string column, max 320) via a new EF migration `20260506120000_AddSubscriptionStripeCustomerEmail` so the deleted-from-Stripe and email-mirroring paths have a place to land. The behavior text loses no semantic content — Stripe customer email lives next to the customer-id on the same row.

3. **`SubscriptionStatus.Quarantined` is added.** The enum currently lacks it. Behavior #5 ("row is marked status='quarantined'") needs a value. Add `Quarantined = 5` to the `SubscriptionStatus` enum and document it as the "Stripe object disappeared (404), retry budget exhausted, manual intervention required" state. The `[Conversion<string>]` mapping persists it as the lowercase string `"quarantined"`. No new migration needed (the column is `VARCHAR(20)` with no CHECK constraint on SQLite/Postgres-test paths).

4. **Re-fetch contract additions to `IStripeGateway`.** Add two methods:
   - `Task<Stripe.Subscription?> GetSubscriptionAsync(string subscriptionId, CancellationToken ct)` — returns null on 404, throws on other 5xx.
   - `Task<Stripe.Customer?> GetCustomerAsync(string customerId, CancellationToken ct)` — same null-on-404 contract.

   `FakeStripeGateway` returns from a scriptable in-memory dictionary; `StripeGateway` calls `new SubscriptionService(_client).GetAsync(id, …)` / `new CustomerService(_client).GetAsync(id, …)` and translates `StripeException.HttpStatusCode == 404` to null. This is the only sensible boundary — handlers cannot safely use the raw `StripeClient` (cannot be mocked at the boundary used by other tests).

5. **Email-queue soft-coupling.** Behavior #6 is satisfied by-construction: `IEmailQueue` is registered as a singleton in `Program.cs` (real `ChannelEmailQueue`) and replaced by `RecordingEmailQueue` in `BackendFactory`. Handlers depend on `IEmailQueue` only; the channel is bound either way.

6. **Tier resolution.** Behavior #3 says "the org tier falls back per the existing license-tier-resolution logic." The existing logic in `SubscriptionsService.GetForOrgAsync` is: if no subscription row → `"free"`; else `sub.Tier.ToString().ToLowerInvariant()`. Setting `Status=Canceled` does NOT affect the tier value returned by `GetForOrgAsync` today. To honour the behavior we update `GetForOrgAsync` to treat a canceled subscription as `"free"` — a one-line change. The task explicitly references this so we treat it as in-scope.

7. **Duplicate-event behavior #7 is exercised by existing M14-011 tests.** No new test needed; the dispatcher is wired only after the idempotency check passes. We verify this with one assertion in the new tests (count of dispatcher invocations equals 1 when the same event is delivered twice).

8. **Step ordering, smallest blast radius first.** The dispatcher seam is added last; before it, every change is internal to new files (handler code) or single-line additions to existing types (enum value, gateway methods, Subscription column, GetForOrgAsync return). This keeps every commit independently buildable and testable.

#### `HandleCreatedOrUpdatedAsync` body sketch

```csharp
var stripeSub = await gateway.GetSubscriptionAsync(subscriptionId, ct);
if (stripeSub is null)
{
    // Subscription gone from Stripe (404). Quarantine the local row if any.
    var existing = await db.Subscriptions
        .FirstOrDefaultAsync(s => s.StripeSubscriptionId == subscriptionId, ct);
    if (existing is not null)
    {
        existing.Status = SubscriptionStatus.Quarantined;
        existing.UpdatedAt = clock.GetUtcNow().UtcDateTime;
        await db.SaveChangesAsync(ct);
        log.LogWarning(
            "stripe_subscription_quarantined sub_id={SubscriptionId} reason=stripe_404",
            subscriptionId);
    }
    return;
}

// Map Stripe state → local entity. The customer-id on the Stripe sub is the
// canonical link back to our row.
var customerId = stripeSub.CustomerId;
var row = await db.Subscriptions
    .FirstOrDefaultAsync(
        s => s.StripeSubscriptionId == subscriptionId
          || (s.StripeCustomerId == customerId && s.StripeSubscriptionId == null),
        ct);

if (row is null)
{
    // No local row for this subscription. Find the org via the customer-id link
    // (created by checkout). If we can't, log and drop — Stripe is the source of
    // truth and we have no org to associate.
    row = await db.Subscriptions.FirstOrDefaultAsync(s => s.StripeCustomerId == customerId, ct);
    if (row is null)
    {
        log.LogWarning(
            "stripe_subscription_no_local_row sub_id={SubscriptionId} customer_id={CustomerId}",
            subscriptionId, customerId);
        return;
    }
}

// Apply Stripe's current state.
var (tier, _, interval) = StripePriceParser.Parse(stripeSub.Items?.Data?.FirstOrDefault()?.Price?.Id ?? string.Empty);
row.StripeSubscriptionId = stripeSub.Id;
row.Status = MapStatus(stripeSub.Status);
row.Tier = tier;
row.Interval = interval;
row.SeatCount = (int?)(stripeSub.Items?.Data?.FirstOrDefault()?.Quantity) ?? row.SeatCount;
row.SeatLimit = row.SeatCount;
row.CurrentPeriodStart = stripeSub.CurrentPeriodStart;
row.CurrentPeriodEnd = stripeSub.CurrentPeriodEnd;
row.CancelAtPeriodEnd = stripeSub.CancelAtPeriodEnd;
row.UpdatedAt = clock.GetUtcNow().UtcDateTime;
await db.SaveChangesAsync(ct);
```

#### `HandleDeletedAsync` body sketch

```csharp
// Even on delete we re-fetch — Stripe still returns the (canceled) subscription
// for a window after deletion. If 404, we still proceed: cancellation is the
// right local outcome regardless.
var stripeSub = await gateway.GetSubscriptionAsync(subscriptionId, ct);

var row = await db.Subscriptions
    .FirstOrDefaultAsync(s => s.StripeSubscriptionId == subscriptionId, ct);
if (row is null)
{
    log.LogInformation(
        "stripe_subscription_deleted_no_local_row sub_id={SubscriptionId}", subscriptionId);
    return;
}

var now = clock.GetUtcNow();
row.Status = SubscriptionStatus.Canceled;
row.CanceledAt = stripeSub?.CanceledAt ?? now.UtcDateTime;
row.StripeSubscriptionId = null; // clear per behaviour #3
row.UpdatedAt = now.UtcDateTime;

// Compose the cancellation email.
var owner = await db.Users
    .Where(u => u.Id == db.OrganizationMembers
        .Where(m => m.OrgId == row.OrgId && m.Role == OrgRole.Owner)
        .Select(m => m.UserId)
        .FirstOrDefault())
    .Select(u => new { u.Email })
    .FirstOrDefaultAsync(ct);

if (owner is not null)
{
    var firstName = owner.Email.Contains('@')
        ? owner.Email[..owner.Email.IndexOf('@', StringComparison.Ordinal)]
        : owner.Email;
    await emailQueue.EnqueueAsync(new EmailMessage(
        To: owner.Email,
        TemplateSlug: "billing_subscription_canceled",
        Variables: new Dictionary<string, string>
        {
            ["first_name"]     = firstName,
            ["tier"]           = row.Tier.ToString(),
            ["effective_date"] = (stripeSub?.CanceledAt ?? now.UtcDateTime).ToString("yyyy-MM-dd"),
        },
        EnqueuedAt: now), ct);
}

await db.SaveChangesAsync(ct);
```

#### Dispatcher sketch

```csharp
public sealed class StripeWebhookDispatcher(
    StripeSubscriptionHandler subs,
    StripeCustomerUpdatedHandler customers,
    ILogger<StripeWebhookDispatcher> log) : IStripeWebhookDispatcher
{
    public async Task DispatchAsync(Event @event, CancellationToken ct)
    {
        switch (@event.Type)
        {
            case Events.CustomerSubscriptionCreated:
            case Events.CustomerSubscriptionUpdated:
            {
                var sub = (Subscription)@event.Data.Object;
                await subs.HandleCreatedOrUpdatedAsync(sub.Id, ct);
                break;
            }
            case Events.CustomerSubscriptionDeleted:
            {
                var sub = (Subscription)@event.Data.Object;
                await subs.HandleDeletedAsync(sub.Id, ct);
                break;
            }
            case Events.CustomerUpdated:
            {
                var customer = (Customer)@event.Data.Object;
                await customers.HandleAsync(customer.Id, ct);
                break;
            }
            default:
                // M14-013 will add invoice.* and payment_method.* handlers; until then,
                // unknown types are logged and dropped — the upstream store still marks
                // them processed so Stripe stops retrying.
                log.LogInformation(
                    "stripe_webhook_unhandled_type event_type={EventType} event_id={EventId}",
                    @event.Type, @event.Id);
                break;
        }
    }
}
```

#### Script sketch

```bash
#!/usr/bin/env bash
# Refs docs/SPECIFICATION.md:6796–6848 (webhook event handlers, re-fetch pattern).
set -euo pipefail
event_type="${1:?usage: $0 <event-type> <subscription-id>}"
sub_id="${2:?usage: $0 <event-type> <subscription-id>}"
secret="${STRIPE_WEBHOOK_SECRET:-whsec_test}"
backend="${BACKEND_URL:-http://localhost:5000}"

evt_id="evt_replay_$(date +%s)_${RANDOM}"
body=$(jq -nc \
  --arg id "$evt_id" \
  --arg type "$event_type" \
  --arg sub "$sub_id" \
  '{ id: $id, object:"event", api_version:"2024-06-20", created: now|floor,
     livemode:false, pending_webhooks:0, request:null, type:$type,
     data:{ object:{ id: $sub, object:"subscription", customer:"cus_test_owner" } } }')

sig=$(./scripts/sign-stripe-webhook.sh "$secret" "$body")
curl -sS -X POST "${backend}/webhooks/stripe" \
  -H "Content-Type: application/json" \
  -H "Stripe-Signature: ${sig}" \
```

## Risks and Edge Cases

- **Risk: Stripe.Net 43.x type signatures drift between mock-test and production.** **Mitigation:** unit tests cast `event.Data.Object` to the correct type (Stripe.Net handles the deserialization); integration tests run against real `stripe-mock` so the wire-protocol is checked.
- **Risk: `Subscription.Items.Data` is null on a deleted subscription.** **Mitigation:** the deleted-handler ignores `stripeSub?.Items` entirely (it does not need price info to mark `Canceled`).
- **Risk: A `customer.subscription.updated` arriving before `customer.subscription.created` finds no local row.** **Mitigation:** `HandleCreatedOrUpdatedAsync` falls back to a `StripeCustomerId`-keyed lookup (the row is created by checkout with the customer id pre-populated). If even that fails, log and drop — there is genuinely no org for this subscription.
- **Risk: Concurrent webhooks for the same subscription mutate the row.** **Mitigation:** EF tracks the entity per scope; the `[Scoped]` registration plus per-request dispatch keeps writes serialized through SaveChangesAsync. The `stripe_webhook_events` row is the actual idempotency key — the upstream store ensures we don't double-process.
- **Risk: `MapStatus` for an unknown Stripe status defaults to `Incomplete`.** **Mitigation:** add a log-warning in the default branch so unknown statuses surface in operations.
- **Risk: `SeatCount` cast from `long?` to `int`.** **Mitigation:** explicit cast and `?? row.SeatCount` fallback; Stripe quantities are always small ints in practice.
- **Edge case: Customer email NULL on Stripe.** **Mitigation:** assigning `row.StripeCustomerEmail = null` is correct.
- **Edge case: Owner email contains no `@`.** **Mitigation:** `firstName` falls back to the full email (already handled in `RefreshTokenService`).
