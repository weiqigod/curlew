# Implementation Plan: M14-021

## Overview

Convergence slice that wires the four M14 cluster heads (login → license refresh → CLI `--report-upload` → backend → check-run posting → Stripe receipt → email queue) end-to-end on the local docker-compose stack and proves the full happy path with a Playwright Plus-Five spec. Adds no new HTTP endpoints, CLI commands, or DB tables in the production surface — only adds (a) test-only `/internal/test/*` audit hooks, (b) two narrow web routes that consume **existing** backend endpoints, and (c) the test plumbing (`testdata/m14/e2e-collection.yaml`, the spec, `--down` flag on `ci-local.sh`, and a CI workflow gating PRs that touch backend/CLI/web).

## Architectural Decisions (Resolved Up-Front)

The convergence slice scope says "NO new endpoints, NO new CLI commands, NO new database tables". Two assertions in the observable require visibility surfaces that don't exist today (`/integrations/github` posted_at view, email-queue audit). I resolved each as follows; each decision is recorded here so reviewers do not have to re-derive it.

1. **Email-queue audit visibility — test-only hook, not a production endpoint.** Today's `IEmailQueue` is an in-process `Channel<EmailMessage>` with no DB persistence; only dead-lettered messages persist (via `IEmailDeadLetterStore`). To assert that a `billing_receipt` email was *successfully* enqueued and consumed, register a Testing-environment-only `IRecentlySentEmailLog` singleton that the `EmailQueueProcessor` records into on success, exposed via `GET /internal/test/email-audit` (Development+Testing only, gated identically to the existing `/internal/test/seed-refresh` precedent at `src/ApiTool.Backend/Auth/Refresh/InternalRefreshSeedEndpoint.cs`). This is **test infrastructure** in the same category as `seed-refresh`, not a new public REST surface — does not violate the "no new endpoints" intent of the scope (which means: no new public API surface for the production CLI to depend on).
2. **`/org/<slug>/runs` route — alias of existing `/results`.** The observable refers to `/org/acme/runs`. The existing route is `/results`. Add a thin SvelteKit redirect (`+page.server.ts` returning `redirect(307, /results)`) so the published URL `/runs` works without renaming the well-known existing route. No new backend surface; the redirect is web-only.
3. **`/org/<slug>/integrations/github` route — new web view, existing backend.** The current `/integrations` page sits at the top level (no org slug) and shows install state but not posted_at on the most-recent pr-check. Add a new SvelteKit route `web/src/routes/(app)/org/[slug]/integrations/github/+page.{server.ts,svelte}` that loads the same `GET /api/v1/integrations/github` install state plus `GET /api/v1/organizations/{orgId}/pr-checks?limit=1&include=posted_at`. This requires extending `PrCheckDto` with two **additive** fields: `posted_at: string|null` and `check_run_id: long|null` (already present on the row from M14-018). Additive DTO extension is not a new endpoint and is backwards-compatible.
4. **CLI stdout format — extend, do not replace.** The observable expects `Uploaded result res_...; check-run posted; status=success`. The current CLI prints `Uploaded result <id>; state posted: <state>` only when `--pr` is set. Update `handleReportUpload` to format `Uploaded result <id>; check-run posted; status=<state>` when both `--pr > 0` and `--repo != ""`. Existing test `TestRunWithReportUpload` will need its expected substring updated; this is one assertion change in `cmd/apitest/report_upload_test.go`.
5. **`--down` on `ci-local.sh`.** Add a top-level `--down` flag mode that calls `./scripts/test-stack.sh down` then `docker compose -f docker-compose.test.yml down -v` and returns 0. Idempotent; smoke-tested by a Go test that runs the script with `--down` against an already-down stack and asserts exit 0.
6. **Seed extension for the convergence slice.** `seed-test-data.sh` already creates the `acme` org, owner user, and notification rule. Add a guarded block (skip-if-exists) that seeds (a) a `team` tier subscription on `acme` (currently `free`), (b) a `cus_test_owner` Stripe customer mirror row (so `replay-stripe-event.sh invoice.payment_succeeded` matches), and (c) one `github_installations` row pointing at the github-mock sidecar (`installation_id=12345`, `app_id=111`, `repo_set=['acme/api']`, `claimed_at=now()`). Done via the existing `/internal/test/*` style — no migrations, no new tables.
7. **Replay flow.** The Playwright spec does not call `replay-stripe-event.sh` directly; instead the CLI test in the global Playwright setup calls it once after the apitest CLI run finishes. This separates the CLI assertion (exit-code-0, check-run-posted) from the email-queue assertion (audit page lists `billing_receipt`).
8. **CI workflow scope.** New workflow `.github/workflows/m14-e2e.yml` runs on PR file-path filter `src/ApiTool.Backend/**`, `cmd/apitest/**`, `web/**`, `scripts/ci-local.sh`, `scripts/replay-stripe-event.sh`, `testdata/m14/**`, and `docker-compose.test.yml`. Job runs `./scripts/ci-local.sh --full` then `cd web && npx playwright test tests/e2e/m14-revenue-loop.spec.ts`.
9. **Login under Playwright.** The Playwright spec runs `apitest login --no-browser` against the docker stack (port 5000). Until M14-005's fake browser-confirmation hook lands, the spec uses the existing `seed-refresh` test endpoint to provision a refresh token + license JWT directly into the CLI's config dir, then asserts the CLI binary recognises the seeded state (i.e. `apitest license --debug` prints the correct kid/tier). The "login" assertion in the observable is satisfied by the CLI surface accepting the seeded tokens and producing a working `--report-upload` flow.

// TestCiLocalDownIdempotent asserts that ./scripts/ci-local.sh --down succeeds
// even when no stack is running, and again on a second invocation.
func TestCiLocalDownIdempotent(t *testing.T) {
    if testing.Short() {
        t.Skip("integration script test; skipped under -short")
    }
    repoRoot, err := filepath.Abs("../..")
    if err != nil { t.Fatalf("abs: %v", err) }
    script := filepath.Join(repoRoot, "scripts", "ci-local.sh")

    for i := 0; i < 2; i++ {
        cmd := exec.Command("bash", script, "--down")
        cmd.Dir = repoRoot
        out, err := cmd.CombinedOutput()
        if err != nil {
            t.Fatalf("iteration %d: --down failed: %v\noutput: %s", i, err, out)
        }
    }
}

```markdown
### 6.1a Logging in to the backend `[Team]`

For team-tier features (--report-upload, PR checks, license refresh), apitest needs to know which backend you're talking to and which user you are.

```bash
export APITEST_BACKEND_URL=https://api.apitool.dev
apitest login --no-browser
# First, copy your one-time code: ABCD-1234
# Then visit: https://app.apitool.dev/device
```

Visit the URL in your browser, paste the code, and confirm. The CLI persists three artefacts:

- `~/.config/apitesttool/license.json` — License JWT (offline-verified daily; valid 30 days + 14-day grace)
- OS keychain (or `refresh_token.enc` fallback) — refresh token, never logged
- `~/.config/apitesttool/device.json` — device id (rotated when you log out)

Subsequent commands are silent; the License JWT is verified offline against the embedded JWKS.

```bash
apitest license --debug      # decode + show kid, tier, exp
apitest license --refresh    # rotate the refresh family (~ every 7 days; auto-skipped when fresh)
```

## Risks and Edge Cases

- **Risk:** github-mock startup race — backend may try to fetch an installation token before the mock is ready. **Mitigation:** the existing `docker-compose.test.yml` healthcheck on github-mock uses a 5-retry probe with `start_period: 5s`; the mock is healthy before backend's `service_healthy` dep on backend takes effect. No new wait in the spec needed.
- **Risk:** stripe-mock invoice IDs don't deterministically match the org's `stripe_customer_id`. **Mitigation:** `replay-stripe-event.sh` already hardcodes `customer: "cus_test_owner"`. The new seed step inserts `acme.stripe_customer_id = "cus_test_owner"`, completing the join.
- **Risk:** `EmailQueueProcessor` records to the audit log via `IServiceProvider.GetService` — DI overhead per send. **Mitigation:** acceptable; the processor already resolves `ISmtpSender` via `GetRequiredService` per attempt. The audit log is only registered in Dev/Testing.
- **Risk:** Playwright `beforeAll` running the apitest binary may run before `apitest` is built. **Mitigation:** `ci-local.sh --full` builds Go before running web; the workflow `m14-e2e.yml` mirrors that ordering.
- **Risk:** `posted_at` may be null at the moment the spec polls (the M14-018 worker is synchronous in M14-018's current implementation but races on Linux). **Mitigation:** the spec polls `/api/v1/integrations/github` with a 5s timeout (matches the observable's "within 5s of upload" SLA). The github-mock returns 201 in ~1ms; even with worker scheduling jitter, 5s is generous.
- **Risk:** `apitest login --no-browser` blocks on user confirmation; in CI there is no user. **Mitigation:** Open Decision #9 above — the spec uses `seed-refresh` to provision tokens directly. The "login" assertion is satisfied by the CLI accepting the seeded state, not by completing a real device-code round trip. (This is already how `cmd/apitest/login_test.go` simulates the flow.)
- **Edge case:** Re-running the spec inserts a duplicate `pr_checks` row but the github-mock returns a fresh `check_run_id` each time. **Handling:** the spec asserts on `posted_at != null` and `check_run_id > 0`, not on a specific id.
- **Edge case:** `replay-stripe-event.sh` is idempotent at the webhook layer (M14-011's `INSERT … ON CONFLICT (event_id) DO NOTHING`) but **not** at the `EmailMessage` enqueue layer; a second replay would queue a second email. **Handling:** the spec uses a fresh `evt_id` per run (current script generates `evt_replay_$(date +%s)_${RANDOM}`); idempotency is preserved by Stripe's idempotency middleware.
- **Edge case:** stale docker volumes from a prior failed run leak fixture state into the new run. **Handling:** `--down` runs `docker compose down -v` (removes named volumes); the smoke test exercises this path.
