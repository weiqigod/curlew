# Implementation Plan: M16-008

## Overview

Ship `TrialExpiryNotifier` — a daily `IHostedService` that queues `trial_expiring`
SendGrid emails at 3-day and 1-day expiry marks for active full-initial / on-demand
trial rows, using the `notified_3day_at` / `notified_1day_at` columns added in M16-005
to prevent duplicate emails across reruns.

## Architectural Decisions

Resolved up front so the implementation steps below are uncontroversial.

1. **Module layout.** New `src/ApiTool.Backend/Notifications/Trials/` namespace
   colocates the notifier with the broader `Notifications/` tree (sibling to
   `Notifications/Email/`). The notifier is a *producer* of email messages and
   never touches `ISmtpSender` directly — only `IEmailQueue.EnqueueAsync`.
2. **Options shape.** `TrialExpiryNotifierOptions` carries three fields:
   - `RunAtUtc` (string, default `"09:00"`) — `"HH:mm"` / `"HH:mm:ss"` daily-fire
     time OR the literal sentinel `"now"` which forces immediate firing on every
     tick (test/dev mode).
   - `BatchSize` (int, default `500`) — max rows queried per pass per tick.
     With ~8 trialable features × N users, even a small SaaS deploy with 10k
     users yields ≤ 80k trial rows total and the partial index narrows each pass
     to "rows expiring within the next N days and not yet notified" — typically
     a handful.
   - `TickInterval` (TimeSpan, default `null` → daily) — when `null`, the host
     computes the delay until the next `RunAtUtc` instant and sleeps. When set
     (tests), the host fires every `TickInterval` regardless of wall-clock time.
3. **Forced-tick contract.** The observable in the YAML asks for
   `TrialExpiryNotifierOptions:RunAtUtc=now`. We treat the literal string
   `"now"` (case-insensitive) as a sentinel meaning "fire on every tick, no
   wall-clock alignment." Unit tests pass `TickInterval = TimeSpan.FromMilliseconds(1)`
   alongside `RunAtUtc = "now"` so the loop runs many times within the test budget.
4. **Two passes per tick.** Each tick runs the 3-day pass *first*, then the
   1-day pass. The two are independent: a row notified at 3-day still has
   `notified_1day_at IS NULL` and will be picked up two days later in the 1-day
   pass. We do **not** suppress the 1-day mail for rows that received the 3-day
   mail — spec :5855 makes the two marks independent and the column scheme
   explicitly tracks them separately.
5. **Per-row write-after-enqueue.** For each matching row: build the
   `EmailMessage`, `await EnqueueAsync`, then set the corresponding
   `notified_*_at` column and `SaveChangesAsync`. If `EnqueueAsync` throws
   (channel disposed, OOM, etc.), the timestamp is *not* set and the next
   tick will retry — honoring behaviour #7. The actual SendGrid call happens
   downstream in `EmailQueueProcessor` and has its own retry / dead-letter
   path; the notifier's job ends at the queue boundary.
6. **Concurrency.** One DI scope per tick (mirrors `SchedulerHost` and
   `AuthTokenCleanupService`); fresh `AppDbContext` per tick. The notifier
   itself is a singleton via `AddHostedService<>`. No shared mutable state.
7. **Index usage.** Queries are shaped to land on the M16-005 partial indexes:
   - 3-day pass: `WHERE notified_3day_at IS NULL AND consumed_at IS NULL` + 
     `expires_at` range + `kind IN ('full_initial','ondemand')` → uses
     `idx_trials_notify_3day` (partial index sorted by `expires_at`).
   - 1-day pass: `WHERE notified_1day_at IS NULL AND consumed_at IS NULL` + 
     `expires_at` range + `kind` filter → uses `idx_trials_notify_1day`.
8. **Kind filter at the SQL level.** Although the partial indexes filter only
   on `notified_*_at IS NULL` and `consumed_at IS NULL`, the spec requires
   skipping `preempted_by_subscription` rows even if those columns are null
   (defensive — preemption flips `expires_at` to `now()` so they fall out of
   the date range anyway, but the explicit kind guard makes intent clear
   without relying on that side-effect, mirroring `DatabaseTrialStateResolver`).
9. **Email upgrade URL.** Compose as `${AppOptions.WebAppUrl}/billing` per
   the pattern already established in `SubscriptionsEndpoints.cs:327` and
   spec :8587 ("upgrade_url"). The base is required+validated at startup so
   we can read it unconditionally.
10. **expires_at_local formatting.** Use ISO-ish UTC string
    `expires_at.ToString("yyyy-MM-dd HH:mm 'UTC'")` to match
    `PasswordResetService.cs:79` and the test_data sample in
    `templates/email/trial_expiring.json:13`. The variable name says "local"
    but the spec :8587 declares it as a free-form display string and the
    test data confirms UTC formatting is acceptable for v1.
11. **Test pattern.** Unit tests mirror `AuthTokenCleanupServiceTests`:
    SQLite in-memory via `TestDb.CreateOpen()` + `FakeClock` + a hand-rolled
    `RecordingEmailQueue` + a small `TickInterval`. We do not need an
    integration test through `BackendFactory` because:
    - `BackendFactory` never registers the production `EmailQueueProcessor`
      (`sendGridMode == "live"` is false in Testing), so end-to-end SendGrid
      flow is not exercised by any backend integration test today.
    - The notifier's contract is entirely captured by "row → email message
      → timestamp write" which is exactly what the unit test asserts.
12. **Program.cs registration.** Add `AddHostedService<TrialExpiryNotifier>()`
    inside the existing `if (!builder.Environment.IsEnvironment("Testing"))`
    guard so the hosted service does not start under the test factory's web
    host. Tests instantiate the notifier directly.

namespace ApiTool.Backend.Notifications.Trials;

/// <summary>
/// Configuration options for <see cref="TrialExpiryNotifier"/>.
/// Bound from the <c>Curlew:TrialExpiryNotifier</c> configuration section.
/// Refs docs/SPECIFICATION.md:5855 (daily 09:00 UTC cron).
/// </summary>
public sealed class TrialExpiryNotifierOptions
{
    /// <summary>Configuration section key.</summary>
    public const string Section = "Curlew:TrialExpiryNotifier";

    /// <summary>
    /// Daily UTC fire time as <c>HH:mm</c> or <c>HH:mm:ss</c>. Defaults to <c>"09:00"</c>.
    /// The literal sentinel <c>"now"</c> (case-insensitive) forces immediate firing on
    /// every tick — used by tests and the observable command in <c>M16-008.yaml</c>.
    /// </summary>
    public string RunAtUtc { get; set; } = "09:00";

    /// <summary>
    /// Maximum number of trial rows queried per pass per tick. Defaults to <c>500</c>.
    /// </summary>
    public int BatchSize { get; set; } = 500;

    /// <summary>
    /// True when <see cref="RunAtUtc"/> equals the sentinel <c>"now"</c>.
    /// </summary>
    public bool IsForcedFire =>
        string.Equals(RunAtUtc, "now", StringComparison.OrdinalIgnoreCase);

    /// <summary>
    /// Parses <see cref="RunAtUtc"/> as a UTC time-of-day. Throws when the
    /// string is neither <c>"now"</c> nor a valid <c>HH:mm</c>/<c>HH:mm:ss</c>.
    /// </summary>
    public TimeOnly ParseRunAtUtc()
    {
        if (IsForcedFire)
            return new TimeOnly(0, 0); // sentinel — never consulted
        if (TimeOnly.TryParseExact(RunAtUtc, "HH:mm", out var hm))
            return hm;
        if (TimeOnly.TryParseExact(RunAtUtc, "HH:mm:ss", out var hms))
            return hms;
        throw new FormatException(
            $"Curlew:TrialExpiryNotifier:RunAtUtc must be \"now\" or \"HH:mm\"/\"HH:mm:ss\"; got \"{RunAtUtc}\".");
    }
}

// src/ApiTool.Backend/Notifications/Trials/TrialExpiryNotifier.cs
using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using ApiTool.Backend.Notifications.Email;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Options;

namespace ApiTool.Backend.Notifications.Trials;

/// <summary>
/// Daily background service that queues <c>trial_expiring</c> SendGrid emails for
/// active trial rows approaching the 3-day and 1-day expiry marks. Fires at
/// <see cref="TrialExpiryNotifierOptions.RunAtUtc"/> (default 09:00 UTC).
/// Refs docs/SPECIFICATION.md:5855 (cron schedule) and :8587 (template + variables).
/// </summary>
/// <remarks>
/// Per-row contract: build the <see cref="EmailMessage"/>, await
/// <see cref="IEmailQueue.EnqueueAsync"/>, then set the corresponding
/// <c>notified_*_at</c> column and <c>SaveChangesAsync</c>. If <c>EnqueueAsync</c>
/// throws, the timestamp is *not* set and the next tick retries.
/// </remarks>
public sealed class TrialExpiryNotifier(
    IServiceScopeFactory scopeFactory,
    IOptions<TrialExpiryNotifierOptions> options,
    IOptions<AppOptions> appOptions,
    TimeProvider clock,
    ILogger<TrialExpiryNotifier> logger,
    TimeSpan? tickInterval = null) : BackgroundService
{
    private const string TemplateSlug = "trial_expiring";
    private static readonly TimeSpan ThreeDays = TimeSpan.FromDays(3);
    private static readonly TimeSpan OneDay = TimeSpan.FromDays(1);

    // Test-only override; when null the loop sleeps until the next configured fire time.
    private readonly TimeSpan? _tickInterval = tickInterval;

    /// <inheritdoc/>
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        var opts = options.Value;
        logger.LogInformation(
            "TrialExpiryNotifier started; RunAtUtc={RunAtUtc} BatchSize={BatchSize}",
            opts.RunAtUtc, opts.BatchSize);

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await DelayUntilNextFireAsync(opts, stoppingToken);
                if (stoppingToken.IsCancellationRequested) break;

                await TickOnceAsync(opts, stoppingToken);
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                break;
            }
            catch (Exception ex)
            {
                logger.LogError(ex, "TrialExpiryNotifier tick failed");
                // On failure, still wait to avoid a tight loop.
                try { await Task.Delay(TimeSpan.FromMinutes(1), stoppingToken); }
                catch (OperationCanceledException) { break; }
            }
        }

        logger.LogInformation("TrialExpiryNotifier stopped");
    }

    /// <summary>
    /// Sleeps until the next configured fire time. If <see cref="_tickInterval"/>
    /// is set (test mode), sleeps that interval instead. If <c>RunAtUtc == "now"</c>,
    /// returns immediately on the first call and sleeps <see cref="_tickInterval"/>
    /// (or 1 minute) on subsequent calls.
    /// </summary>
    private async Task DelayUntilNextFireAsync(
        TrialExpiryNotifierOptions opts, CancellationToken ct)
    {
        if (_tickInterval is { } interval)
        {
            await Task.Delay(interval, ct);
            return;
        }

        if (opts.IsForcedFire)
        {
            // Forced fire without a test-injected tick interval — sleep 1 minute
            // between ticks so a misconfig in prod does not spin.
            await Task.Delay(TimeSpan.FromMinutes(1), ct);
            return;
        }

        var fireAt = opts.ParseRunAtUtc();
        var now = clock.GetUtcNow();
        var todayFire = new DateTimeOffset(
            now.Year, now.Month, now.Day,
            fireAt.Hour, fireAt.Minute, fireAt.Second,
            TimeSpan.Zero);
        var next = now < todayFire ? todayFire : todayFire.AddDays(1);
        var delay = next - now;
        if (delay > TimeSpan.Zero)
            await Task.Delay(delay, ct);
    }

    /// <summary>Runs the 3-day pass followed by the 1-day pass within one DI scope.</summary>
    internal async Task TickOnceAsync(TrialExpiryNotifierOptions opts, CancellationToken ct)
    {
        await using var scope = scopeFactory.CreateAsyncScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var queue = scope.ServiceProvider.GetRequiredService<IEmailQueue>();
        var now = clock.GetUtcNow().UtcDateTime;

        var sent3 = await ProcessPassAsync(
            db, queue, opts, now, ThreeDays, kind3day: true, ct);
        var sent1 = await ProcessPassAsync(
            db, queue, opts, now, OneDay, kind3day: false, ct);

        if (sent3 + sent1 > 0)
            logger.LogInformation(
                "trial_expiry_notifier_tick sent_3day={Sent3} sent_1day={Sent1}",
                sent3, sent1);
    }

    private async Task<int> ProcessPassAsync(
        AppDbContext db,
        IEmailQueue queue,
        TrialExpiryNotifierOptions opts,
        DateTime now,
        TimeSpan window,
        bool kind3day,
        CancellationToken ct)
    {
        var cutoff = now + window;

        // Query the matching trials. Filter on kind explicitly (defensive — see
        // architectural decision #8). The partial index on (expires_at) WHERE
        // notified_*_at IS NULL AND consumed_at IS NULL is used by the index
        // selector when the WHERE clause includes both nullness predicates.
        var query = db.Trials.AsQueryable()
            .Where(t => t.ExpiresAt > now && t.ExpiresAt <= cutoff)
            .Where(t => t.ConsumedAt == null)
            .Where(t => t.Kind == TrialKind.FullInitial || t.Kind == TrialKind.OnDemand);

        query = kind3day
            ? query.Where(t => t.Notified3DayAt == null)
            : query.Where(t => t.Notified1DayAt == null);

        // Fetch user emails alongside trials for the EmailMessage 'To' field.
        var rows = await query
            .OrderBy(t => t.ExpiresAt)
            .Take(opts.BatchSize)
            .Join(
                db.Users,
                t => t.UserId,
                u => u.Id,
                (t, u) => new { Trial = t, UserEmail = u.Email })
            .ToListAsync(ct);

        var upgradeUrl = appOptions.Value.WebAppUrl.TrimEnd('/') + "/billing";
        var sent = 0;

        foreach (var row in rows)
        {
            var msg = new EmailMessage(
                To: row.UserEmail,
                TemplateSlug: TemplateSlug,
                Variables: new Dictionary<string, string>
                {
                    ["user_email"]       = row.UserEmail,
                    ["feature"]          = row.Trial.Feature,
                    ["expires_at_local"] = row.Trial.ExpiresAt
                        .ToString("yyyy-MM-dd HH:mm 'UTC'"),
                    ["upgrade_url"]      = upgradeUrl,
                },
                EnqueuedAt: clock.GetUtcNow());

            try
            {
                await queue.EnqueueAsync(msg, ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                throw;
            }
            catch (Exception ex)
            {
                logger.LogWarning(ex,
                    "trial_expiry_notify_enqueue_failed trial_id={TrialId} user_id={UserId} feature={Feature}",
                    row.Trial.Id, row.Trial.UserId, row.Trial.Feature);
                continue; // do NOT set the notified_*_at column — next tick retries
            }

            if (kind3day)
                row.Trial.Notified3DayAt = now;
            else
                row.Trial.Notified1DayAt = now;
            row.Trial.UpdatedAt = now;

            try
            {
                await db.SaveChangesAsync(ct);
                sent++;
            }
            catch (DbUpdateException ex)
            {
                // Concurrent update on the same row (vanishingly rare — only the
                // notifier writes these columns). Log and continue; next tick
                // will pick the row back up if the timestamp is still null.
                logger.LogWarning(ex,
                    "trial_expiry_notify_save_failed trial_id={TrialId} user_id={UserId}",
                    row.Trial.Id, row.Trial.UserId);
                db.ChangeTracker.Clear();
            }
        }

        return sent;
    }
}

            Options.Create(new AppOptions { WebAppUrl = "https://app.apitool.dev" }),
            _clock,

    }

    private async Task EnsureSchemaAsync() => await _scope.Db.Database.MigrateAsync();

    private async Task<Guid> SeedUserAsync(string? email = null)
    {
        var id = Guid.NewGuid();
        _scope.Db.Users.Add(new User
        {
            Id = id,
            Email = email ?? $"user-{id:N}@example.com",
            CreatedAt = _clock.GetUtcNow().UtcDateTime,
        });
        await _scope.Db.SaveChangesAsync();
        return id;
    }

    private async Task<Trial> SeedTrialAsync(
        Guid userId, string feature, TrialKind kind, DateTime expiresAt,
        DateTime? notified3day = null, DateTime? notified1day = null,
        DateTime? consumedAt = null)
    {
        var now = _clock.GetUtcNow().UtcDateTime;
        var t = new Trial
        {
            Id = Guid.NewGuid(),
            UserId = userId,
            Feature = feature,
            Kind = kind,
            GrantedAt = now.AddDays(-1),
            ExpiresAt = expiresAt,
            ConsumedAt = consumedAt,
            Notified3DayAt = notified3day,
            Notified1DayAt = notified1day,
            CreatedAt = now,
            UpdatedAt = now,
        };
        _scope.Db.Trials.Add(t);
        await _scope.Db.SaveChangesAsync();
        return t;
    }

## Risks and Edge Cases

- **Risk: Race between notifier and Stripe-webhook tier-upgrade preemption.**
  M16-006's Stripe handler flips `kind` to `preempted_by_subscription` and
  `expires_at` to `now()`. A row could legally race the notifier mid-tick.
  **Mitigation:** The Kind filter (architectural decision #8) plus
  `expires_at > now` together exclude any preempted row. The notifier
  reads-and-writes inside a single `SaveChangesAsync`; if Stripe wins, the
  row's kind/expiry change causes the next tick to skip it. If the notifier
  wins, the email is enqueued but the user has actually upgraded — they
  receive one stale "your trial expires" email, which is acceptable for v1
  (spec :5855 prescribes no compensating mechanism).

- **Risk: Wall-clock drift / partial-tick failures.**
  If the host crashes mid-tick after enqueuing but before
  `SaveChangesAsync`, the next tick re-enqueues a duplicate email. The
  `EmailQueueProcessor` does not deduplicate, so the user might see two
  emails. **Mitigation:** Acceptable for v1 because the failure window is
  narrow (single-row save) and the user-visible cost is one extra email.
  Spec :5855 does not call for stricter exactly-once delivery. Documented
  in code as a known trade-off (in remarks on the method).

- **Risk: Time-zone interpretation.**
  `RunAtUtc` is unambiguously UTC; `expires_at_local` is intentionally
  rendered as UTC for v1 (the variable name is documentation-only; the
  display value is set by us). **Mitigation:** Use the
  `"yyyy-MM-dd HH:mm 'UTC'"` format consistently and document the choice
  in the notifier's XML doc.

- **Edge case: Trial expires within `< 24 hours` AND no `notified_3day_at`
  yet (e.g., backfilled row).** The notifier sends BOTH the 3-day and 1-day
  email on the same tick, setting both columns to the same timestamp. This
  matches spec :5855 — "for every active trial expiring within the next 3
  days (and not yet notified at 3-day mark)" — and is what test case
  `Tick_queues_1day_email_and_sets_notified_1day_at` verifies.

- **Edge case: Empty WebAppUrl.** Already guarded by `ValidateOnStart` on
  `AppOptions` (Program.cs:199-202). Notifier can assume non-empty.

- **Edge case: Forced-fire mode in production by misconfig.** If a deployer
  sets `RunAtUtc=now` in prod by accident, the notifier fires every minute
  rather than spinning. Eventually the backlog empties and steady-state
  cost is the partial-index scan (cheap). Logged at INFO on startup so an
  operator can spot the misconfig.

- **Edge case: User row missing for a trial (FK cascade race).** The
  `Join` is an inner join on `userId`; rows whose user has been deleted
  during a cascade race are silently skipped. The DB-level
  `ON DELETE CASCADE` should normally delete the trial row too, so this is
  belt-and-suspenders.

- **Edge case: SQLite in-memory partial-index limitation.** SQLite supports
  partial indexes but EF Core's InMemory provider used by integration
  tests does not enforce them; this is fine because the unit tests use a
  real SQLite via `TestDb.CreateOpen()` and integration tests don't
  exercise the cron at all.
