## Findings that change the task as written

Three things were established by exploration and verified by running commands.
They are recorded here because they alter what "done" means.

### 1. Four flags are missing from the synopsis, not three

The task names `--allow-sensitive`, `--events`, `--locale`. **`--quiet` is also
missing.** Verified two ways.

The observed synopsis, from the real binary:

```
$ go build -o /tmp/curlew ./cmd/curlew && /tmp/curlew run foo.yaml --bogus
Usage: curlew run <collection-file> [--env <name>] [--env-var VAR ...] [--var key=value ...] [--seed <number>] [--format <type>] [--report <file>] [--only "<name>"] [--show-dependencies] [--dry-run] [--parallel] [--confirm-large-dataset] [--color <when>] [--no-color] [-v] [-vv] [-q]
[ERROR] unknown flag: --bogus
EXIT=1
```

The flag literals `parseRunArgs` actually matches, extracted mechanically:

```
--allow-sensitive  --color  --confirm-large-dataset  --dry-run  --env
--env-var  --events  --format  --locale  --no-color  --only  --parallel
--quiet  --report  --seed  --show-dependencies  --var  -q  -v  -vv
```

`case "-q", "--quiet":` sits at `cmd/curlew/main.go:182`. The synopsis lists
`-q` only. `--quiet` appears in `curlew --help`, which is why
`TestHelp_documents_every_accepted_flag` passes on it — and precisely why the
synopsis needs its own guard rather than relying on the help guard.

**Resolution:** add all four. The guard derives its expectations from the
parser, so shipping "three" leaves the observable red. Record the discrepancy
in the CHANGELOG so the backlog entry is corrected rather than silently
contradicted.

### 2. The "recognise-but-warn-and-ignore policy" the stubs describe was never built

The personal-family stub's comment anticipates a future in which an unsupported
`--locale` warns and falls back to en-US. The shipped policy is
**recognise-or-reject**: `resolveLocaleData` (`internal/variable/locale.go:155`)
returns a structured `ERR_LOCALE_UNKNOWN` (sentinel `ErrLocaleUnknown`,
`locale.go:68`) for any code outside the 15-entry `supportedLocales` table, and
`ValidateLocale` runs before registry construction, so the run aborts.
`docs/MANUAL.md:1355` documents the abort. A warn-and-fall-back path exists
(`WithLocaleWarning`, `dynamic.go:66`, firing at `dynamic.go:108` only when
`fellBack`) but is unreachable in production while all 15 supported locales
ship pools.

**Resolution:** no new product behaviour will be written under this task. That
stub is deleted with a note recording that its premise was superseded.

### 3. What the six remaining stubs actually gesture at is real, documented, and untested

`docs/MANUAL.md` promises locale-*neutrality* family by family, and nothing
tests it:

| Line | Promise |
|------|---------|
| 1149 | location — "street, state, zip, and country pools remain en-US format" |
| 1163 | company — "locale-neutral en-US data by design; `--locale` does not localize this family" |
| 1182 | internet — "TLD pools and user-agent strings are locale-neutral by design" |
| 1212 | content — "The lorem-ipsum pool is locale-neutral Latin" |
| 1254 | financial — "Currency and financial pools are locale-neutral by design" |
| 1289 | file — "File name, extension, MIME type, and image URL pools are locale-neutral" |

Writing that test is not implementing new behaviour — it is testing shipped,

```go
// walkFlagLiterals visits every string literal in this package's non-test
// sources that a parser compares an argument against — a `case "--flag":`
// value or an `==` operand — and calls record with the unquoted value. When
// funcName is non-empty the walk is confined to that function's body, and the
// walk fails if no function of that name exists: a renamed parser must fail
// loudly rather than enumerate nothing.
func walkFlagLiterals(t *testing.T, funcName string, record func(val string))

// acceptedFlags returns every long flag any parser in this package accepts.
// Signature preserved: doc_prose_test.go depends on it.
func acceptedFlags(t *testing.T) []string

// acceptedArgTokensIn returns every flag-shaped token, long or short, that the
// named parser function accepts, sorted.
func acceptedArgTokensIn(t *testing.T, funcName string) []string

// flagSurface is one place the CLI tells a user which flags exist. A third
// surface joins the check by adding a value here — the watch synopsis
// (main.go:1504) is the known next candidate.
type flagSurface struct {
	name    string                      // for failure messages
	text    func(t *testing.T) string   // the surface as a user sees it
	flags   func(t *testing.T) []string // the flags this surface must list
	exempt  map[string]string           // deliberately absent, with a reason
	fixHint string                      // what to edit when it fails
}

// assertSurfaceDocumentsFlags checks that every flag the surface is
// responsible for appears in its text as its own token.
func assertSurfaceDocumentsFlags(t *testing.T, s flagSurface)

// runParseErrorStderr returns the first line curlew writes to stderr when the
// run parser rejects an argument — the synopsis a user sees at the typo.
func runParseErrorStderr(t *testing.T) string

// runSynopsisExceptions lists flags deliberately absent from the run synopsis.
// Keep this empty unless there is a stated reason.
var runSynopsisExceptions = map[string]string{}

var (
	helpSurface        flagSurface
	runSynopsisSurface flagSurface
)
```

The synopsis text is obtained by driving the real dispatcher, not by reading
the const — the test must assert what a user actually sees:

```go
func runParseErrorStderr(t *testing.T) string {
	t.Helper()
	var stdout, stderr bytes.Buffer
	runWithWriters([]string{"run", "--definitely-not-a-flag"}, &stdout, &stderr)
	line, _, _ := strings.Cut(stderr.String(), "\n")
	if !strings.HasPrefix(line, "Usage: curlew run") {
		t.Fatalf("first stderr line is not the run synopsis; got %q", line)
	}
	return line
}
```

`runWithWriters` is production code (`cmd/curlew/main.go:56`), so this
exercises the real path. The parse-error branch returns before any file I/O,
events emitter, or telemetry defer, so the call has no side effects.

Both entry points become thin callers of the shared checker:

```go
func TestHelp_documents_every_accepted_flag(t *testing.T) {
	assertSurfaceDocumentsFlags(t, helpSurface)
}

func TestUsage_documents_every_accepted_flag(t *testing.T) { // placeholder name; see below
	assertSurfaceDocumentsFlags(t, runSynopsisSurface)
}
```

with the new function named exactly `TestUsage_synopsis_lists_every_accepted_flag`
as the observable requires.

#### Design decisions

- **Widen the scoped walk to short flags** (`len(val) > 1 && strings.HasPrefix(val, "-")`,
  matching `acceptedArgTokens` in `doc_flag_tables_test.go`) rather than
  M23-001's `--`-only filter. All three short flags are already listed, so it
  costs nothing today and is strictly stronger tomorrow. The bare `-` sentinel
  at `main.go:262` is excluded by `len > 1`; `"--color="` is a `CallExpr`
  argument, recorded by neither node type.
- **`runSynopsisExceptions` starts empty.** The one plausible candidate,
  `--quiet`, is an alias whose partner `-q` is listed — but `--no-color` is
  likewise an alias of `--color=never` and the synopsis already spells it out.
  The codebase's own precedent is to list aliases. An empty map is a stronger
  contract and matches M23-001's empty `helpFlagExceptions`.
- **Two entry points, one mechanism.** The DoD says extend rather than
  duplicate; the observable requires a test named
  `TestUsage_synopsis_lists_every_accepted_flag`. Both are satisfied by putting
  the new function in `help_parity_test.go` and making both entry points thin
  callers of one shared walk, one matcher, one exception convention, and one
  surface table. Two entry points exist because the surfaces have genuinely
  different scopes — help must document every parser's flags, the synopsis only
  `parseRunArgs`'s — and because `-run` must address them independently.

  scope and behaviour unchanged, must stay green.
- `TestProse_everyNamedFlagIsAccepted` (`doc_prose_test.go:167`) — unaffected;
  `acceptedFlags(t) []string` keeps its exact signature and semantics.

**Test 1 — `TestFaker_localeNeutralFunctionsIgnoreLocale`:** for every name in

{"faker.fileName"}, {"faker.mimeType"}, {"faker.address"}, {"faker.state"},
{"faker.zipCode"}, {"faker.country"}, ...

**Test 2 — `TestFaker_localeAwareFunctionsVaryByLocale`:** the converse. For
each of the eight names in `localeAwareFuncs`, assert output differs between
`en-US` and at least one of `de-DE` / `ja-JP` / `ru-RU` across a handful of

draws during construction (`dynamic.go:88-114` — it seeds the PCG, resolves the

`faker.*` function defaults on `len(args) == 0`, so `Evaluate(name, nil, cache)`
is uniformly valid.

**RED check:** temporarily point one neutral function (e.g. `faker.company`) at
`r.locale.cities`, confirm test 1 fails, revert.

**Derivation is deliberately explicit for the aware set:** a newly added
`faker.*` function is auto-classified as neutral by test 1 and fails loudly the
moment it consults `r.locale`, forcing an explicit decision.

## Risks and Edge Cases

- **Risk: the task says three missing flags; there are four.** →
  **Mitigation:** verified mechanically and against the real binary; add
  `--quiet` as `[-q|--quiet]` and call the discrepancy out in the CHANGELOG and
  the verification report, so the backlog is corrected rather than silently
  contradicted.
- **Risk: the synopsis is user-facing output another test might pin.** →
  **Mitigation:** grepped `cmd/`, `internal/`, `smoke/`, `testapi/`,
  `scripts/`; zero verbatim assertions. All assertions are on the `"Usage:"` /
  `"Usage: curlew"` prefix, which is preserved.
- **Risk: the scoped AST walk passes vacuously if `parseRunArgs` is renamed.**
  → **Mitigation:** `t.Fatal` when the named `FuncDecl` is absent from every
  file, plus a `len(flags) < 10` floor — the pattern the repo already uses.
- **Risk: source-parsing is fragile.** → **Mitigation:** it is, and it is the
  right trade. M23-001 established it and two other tests reuse it; the
  alternative — a hand-maintained flag list — drifts in exactly the way this
  task is repairing. The fragility is bounded: the walk fails loudly rather
  than silently, and `parseRunArgs` is a plain `switch` with no dynamic
  dispatch.
- **Edge case: `mentionsFlag` false positives in the new text.** →
  **Handling:** each addition checked — `--locale <code>`, `--events <file>`,
  `--allow-sensitive]`, `--quiet]` all terminate on a non-`[A-Za-z0-9_-]` char;
  `--no-color` does not contain the substring `--color`; `-v` matches `[-v]`
  before `[-vv]`, both boundary-valid.
- **Risk: the byte-identical-across-locales assertion is wrong.** →
  **Mitigation:** verified `NewRegistry` draws no RNG during construction and
  `faker.address` uses the package-level `cities`. Step 5's RED check proves
  the assertion has teeth before any stub is deleted.
- **Edge case: a `faker.*` function errors on `nil` args.** → **Handling:**
  every arg-taking function defaults on `len(args) == 0`. The test `t.Fatalf`s
  rather than skipping if one ever does.
- **Risk: deleting tests trips a hygiene or count gate.** → **Mitigation:**
  `ci-local.sh` count-guards are per-named-test (`-list '^TestReadme_...'`) and
  none names a `*_LocaleDeferred`. Coverage is printed, not thresholded.
- **Risk: lint failure after deletion.** → **Mitigation:** only `unused` could
  bite; the stubs reference no package symbols and orphan no imports. Run
  `gofumpt` (extra-rules is enabled in `.golangci.yml`) on both touched files.
- **Risk: scope creep into the watch synopsis.** → **Mitigation:** explicitly
  out of scope per the task; noted in this plan and in the CHANGELOG, left as a
  one-table-row follow-up.
- **Note (out of scope):** `curlew run --help` is rejected by `parseRunArgs`
  and prints the synopsis plus `[ERROR] unknown flag: --help`. A real UX
  oddity, found while capturing output. Noted only.
