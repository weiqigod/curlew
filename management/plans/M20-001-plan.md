## Key Findings from Exploration

These facts shaped the plan and several decisions below:

1. **`variable.NewRegistry(seed *int64)` has ~50+ test call sites** (`internal/variable/dynamic_test.go`) plus **one** production call site (`internal/runner/runner.go:1156`). Changing its arity would break every test. **Decision:** keep the existing positional signature and add a **variadic functional-options** parameter (`...Option`). All existing call sites compile unchanged; locale is supplied via `WithLocale(code)`.

2. **The `exec` subcommand does NOT wire the dynamic registry into its scope at all.** `execCmdOut` (`cmd/apitest/main.go:3223`) only builds a `variable.NewScope` when `--var`/`--env-var` are present (line 3282), and never calls `WithDynamic`. Verified empirically: `{{$faker.fullName}}` passes through an exec request **unresolved**. The task observable's exec examples (#1, #2, #3, #5) therefore require *new* exec wiring: `--seed`, `--locale`, and an always-on dynamic registry on the exec scope. This is in scope per the task's `scope` block ("thread an equivalent flag through the exec subcommand").

3. **`exec` does not currently parse `--seed`.** It is silently treated as a positional arg today. The observable passes `--seed 42` to exec, so `--seed` parsing must be added to `parseExecArgs` alongside `--locale`.

4. **The environment loader flattens to a vars-only map.** `config.LoadEnvironment` / `ParseEnvironmentFile` (`internal/config/environment.go`) return `map[string]string` of *variables only* — there is no parsed `config:` block from environment files. **Decision:** implement the full 5-source `resolveLocale` precedence function with an `Environment` slot, but wire the Environment source as empty-string for this slice (the resolver honours it the moment a value is supplied). A `// TODO(M20): wire environment config.locale` seam is documented. Observable #6 only exercises Project + CLI precedence, which is fully wired. This keeps the precedence contract correct and total without a speculative environment-config parser.

5. **`testdata/locale/` does not exist** — fixtures `simple.yaml` and `de-project.yaml` (referenced by observable #4 and #6) must be created.

6. **REVIEW.md baseline correction:** `docs/REVIEW.md:75` says the flag "is recognised-but-warns-and-ignores" and `:156` says "locale deferred". Both overstate the baseline — no `--locale` parsing existed at all. Correct both per DoD.

7. **Existing faker closures** (`dynamic.go:451-566`) index en-US file-scope pools (`firstNames`, `lastNames`, `cities`, …) directly via `intn(rng, len(pool))`. To preserve **seed/locale index-invariance** (SPEC:1023-1026) the closures must select the *active locale's* pool by the SAME `intn` index. **Decision:** introduce a per-Registry `locale *localeData` holding name/phone/city slices; closures read `r.locale.firstNames` etc. The en-US `localeData` reuses the existing file-scope vars verbatim, so en-US output is byte-identical (backward-compat DoD).

#### New Code

```go
// Option configures a Registry at construction. Variadic so existing
// NewRegistry(seed) call sites are unaffected.
type Option func(*registryConfig)

type registryConfig struct {
	locale  string          // normalized "" means en-US default
	onWarn  func(string)    // verbose fallback-warning sink; nil = silent
}

// WithLocale selects the faker locale pool. Empty/"en-US" is the default.
// An unsupported code makes NewRegistry... see WithLocale validation note:
// validation surfaces through the returned registry's locale resolution,
// reported by the caller before first use.
func WithLocale(code string) Option { return func(c *registryConfig) { c.locale = code } }

// WithLocaleWarning installs a sink for the verbose fallback warning
// ("locale en-GB not available; falling back to en-US").
func WithLocaleWarning(fn func(string)) Option { return func(c *registryConfig) { c.onWarn = fn } }

func NewRegistry(seed *int64, opts ...Option) *Registry {
	cfg := registryConfig{}
	for _, o := range opts {
		o(&cfg)
	}
	r := &Registry{
		funcs:           make(map[string]DynFunc),
		sensitiveArgIdx: make(map[string]int),
		sensitiveReturn: make(map[string]bool),
		now:             time.Now,
	}
	if seed != nil {
		r.rng = rand.New(rand.NewPCG(uint64(*seed), uint64(*seed>>32^0xdeadbeef)))
	}
	// Resolve locale; unknown codes are validated by the caller via
	// ValidateLocale before constructing the registry, so here we resolve
	// through the fallback chain (which never errors for a supported code)
	// and default to en-US for "".
	data, used, fellBack, _ := resolveLocaleData(cfg.locale)
	r.locale = data
	if fellBack && cfg.onWarn != nil {
		cfg.onWarn(fmt.Sprintf("locale %s not available; falling back to %s", normalizeLocale(cfg.locale), used))
	}
	r.register()
	return r
}

// ValidateLocale reports ERR_LOCALE_UNKNOWN for an unsupported code, or nil.
// Exposed so the CLI layer can reject xx-YY before building the registry.
func ValidateLocale(code string) error {
	if code == "" { return nil }
	if _, _, _, err := resolveLocaleData(code); err != nil { return err }
	return nil
}
```

`resolveLocale` (precedence Default < Project < Environment < Collection < CLI,
SPEC:1006):

```go
// resolveLocale applies the locale precedence chain and validates the winner.
// Sources, lowest to highest: project config, environment config, collection
// config, CLI flag. Empty string means "unset" at each level. Returns "" when
// nothing is set (registry defaults to en-US). Returns ERR_LOCALE_UNKNOWN for
// an unsupported winning value.
func resolveLocale(vars VarSources) (string, error) {
	chosen := ""
	for _, src := range []string{
		vars.ProjectLocale,     // precedence 2
		vars.EnvironmentLocale, // precedence 3 (seam: empty until env config parsed)
		vars.CollectionLocale,  // precedence 4
		vars.Locale,            // precedence 5 — CLI flag, highest
	} {
		if strings.TrimSpace(src) != "" {
			chosen = src
		}
	}
	if chosen == "" {
		return "", nil
	}
	if err := variable.ValidateLocale(chosen); err != nil {
		return "", err
	}
	return chosen, nil
}
```

## Risks and Edge Cases
- **Risk:** changing `NewRegistry` arity breaks ~50 call sites → **Mitigation:** variadic `...Option`; positional `seed` unchanged.
- **Risk:** exec now interpolates unconditionally, altering pass-through behaviour for literal-brace URLs → **Mitigation:** audit exec tests for `{{` in URLs during execute; none expected (exec uses concrete URLs).
- **Risk:** en-US output drift breaks the byte-identical backward-compat DoD → **Mitigation:** en-US `localeData` aliases the existing `firstNames`/`lastNames`/`cities` vars verbatim; add `TestRegistry_Locale_EnUS_ByteIdenticalToBaseline` regression test.
- **Edge case:** seed/locale index-invariance (SPEC:1023-1026) → **Handling:** all closures use the same single `intn(rng, len(pool))` index against the active pool; `TestRegistry_Locale_SeedPositionInvariant` pins it. (Requires de-DE pools to be **non-empty** so `len(pool) > 0`.)
- **Edge case:** `--locale en-GB` (supported, unshipped) must warn + fall back, not error → **Handling:** `supportedLocales` membership gates `ERR_LOCALE_UNKNOWN`; `fallbackChain` resolves en-GB→en→en-US; warning only in verbose.
- **Edge case:** unknown `xx-YY` → **Handling:** `ERR_LOCALE_UNKNOWN` structured error lists supported locales; non-zero exit (run: via `runner.Run` error path; exec: via `ValidateLocale` pre-check).
- **Edge case:** Environment-level `config.locale` (precedence slot 3) → **Handling:** resolver honours an `EnvironmentLocale` value but the env loader is vars-only today; wired empty with a documented seam. Observable #6 only tests Project+CLI, which is fully wired.
- **Edge case:** empty/whitespace locale at any source → **Handling:** `strings.TrimSpace` skip; resolver returns `""` → registry defaults to en-US.
- **Risk:** locale normalization mishandles `de_DE`/`EN`/casing → **Mitigation:** `TestNormalizeLocale` table covers separators, casing, whitespace, language-only.
