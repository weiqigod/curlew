# Implementation Plan: M19-002

## Overview

Introduce the new `internal/cel/` package that wraps `github.com/google/cel-go` with a project-specific `Evaluator` interface, a `StandardActivation` (`response`/`previous`/`vars`/`env`), a Go-side `Response` type whose `body` is bound as the CEL `dyn` type, deterministic-only function set (cel-go standard library minus the time-of-day functions `now()` and zero-arg `timestamp()`), structured `ErrCelParse`/`ErrCelType` sentinels with 200-char source truncation, and a sensitive-value observer hook. ## Key Architectural Decisions

1. **Time-of-day rejection via AST walk, not stdlib surgery.** cel-go's standard library is exposed as one opaque `cel.StdLib()` option; surgically subtracting `now`/`timestamp(0-arg)` from it requires replicating the entire stdlib `cel.Lib` internals (fragile across cel-go versions). Instead, the package keeps `cel.StdLib()` and runs an AST walk over the checked expression. Any `Call` node whose function name is `now` (any arity) or `timestamp` with zero arguments is rejected with `ErrCelParse`. The walk runs as part of `Compile` *before* `Program` is constructed. This is robust against cel-go releases and is the same pattern used by Kubernetes admission policies for forbidding non-deterministic builtins.

2. **`Response` registered as a Go-side native type.** cel-go can adapt arbitrary Go structs via `cel.Types` + a `ref.TypeAdapter`. The package defines a public `Response` struct (`Status int`, `Headers map[string]string`, `Body any`) and a small adapter that maps `.status`/`.headers`/`.body` field accesses to the CEL type system, with `body` typed as `dyn` so JSON-decoded payloads (`map[string]any`, `[]any`, scalars) flow through cel-go's `types.DefaultTypeAdapter` for chained access like `response.body.items[0].price`.

3. **`StandardActivation` is a thin adapter, not the binding.** `StandardActivation` is a typed struct used by callers. Internally, `Program.Eval` translates it to a `map[string]any{"response": …, "previous": …, "vars": vars, "env": env}` and hands that to cel-go's `Activation` constructor. Keeping the public type a struct (not a `map[string]any`) gives us compile-time call sites in M19-004/M19-005 and clearer documentation.

4. **`SensitiveObserver` fires on `vars.<name>` references whose name is in a caller-supplied sensitive set.** Detection is at AST analysis time (a second AST pass during `Compile` collects every `vars.<X>` `Select` chain and the toplevel identifier name `X`). At `Eval` time, after the program returns, the resolved value of each detected name is looked up in the activation's `vars` map; if `X` is in the sensitive set, the observer is invoked once with `(X, stringified-value)`. The observer fires exactly once per *referenced* sensitive name per `Eval` call, regardless of how many times the expression references it. The observer fires *before* `Eval` returns the result to the caller (so the caller can mark the surrounding context as sensitive synchronously).

5. **200-char source truncation with ellipsis marker.** The package centralises this in `truncateSource(src string) string`. For inputs longer than 200 characters the function returns the first 200 runes (not bytes — handles multi-byte input correctly) followed by the marker `…` (the U+2026 ellipsis). The 200-char count *excludes* the ellipsis so the visible width is `200 + 1 rune` for truncated input, exactly matching the wording in the behaviour spec ("truncated to exactly 200 chars with a trailing ellipsis marker").

6. **`ErrCelParse` and `ErrCelType` are sentinel error values; `CelError` is the carrier struct.** Pattern matches `internal/errors/Structured`: callers use `errors.Is(err, cel.ErrCelParse)` while still being able to `errors.As(err, &*cel.CelError{})` to read the truncated source, the underlying cel-go message, and the actual/expected type strings. The carrier struct includes a `FieldPath` field that M19-004/M19-005 will fill in (e.g. `requests[3].assertions[1].cel`) — this slice leaves it empty.

7. **Package registers in `internal/errors` via `hints_init.go`.** Required by `coverage_test.go` — every exported `Err*` sentinel must be registered or the coverage test fails. This task adds `internal/cel/hints_init.go` and appends `_ "github.com/peterlindqvist/apitest/internal/cel"` to the blank-import block in `internal/errors/coverage_test.go`.

8. **cel-go pin: `v0.28.1`.** Latest stable tag at the time of planning; the package is widely deployed (Kubernetes uses recent v0.x). Tagged release satisfies the DoD pin requirement. `go mod tidy` will pull `cel.dev/expr`, `google.golang.org/protobuf`, `google.golang.org/genproto/googleapis/api/expr/v1alpha1`, `github.com/stoewer/go-strcase`, `github.com/antlr4-go/antlr/v4` — all standard transitive deps for cel-go.

package cel

import (
	"errors"

	celgo "github.com/google/cel-go/cel"
)

// ErrCelParse marks errors produced during expression parsing or by the
// deterministic-function check (rejection of now/zero-arg timestamp).
var ErrCelParse = errors.New("CEL parse error")

// ErrCelType marks errors produced when the expression's result type does
// not match the type requested by the caller via Evaluator.Compile.
var ErrCelType = errors.New("CEL type error")

// CelError is the structured carrier for ErrCelParse and ErrCelType.
// Callers may match the sentinel with errors.Is and read the structured
// fields with errors.As.
type CelError struct {
	Sentinel  error  // ErrCelParse or ErrCelType
	FieldPath string // e.g. "requests[3].assertions[1].cel"; filled in by callers
	Source    string // truncated to 200 runes + ellipsis marker
	Actual    string // for ErrCelType: actual result type (e.g. "int")
	Expected  string // for ErrCelType: expected result type (e.g. "bool")
	Inner     string // original cel-go message
}

func (e *CelError) Error() string { /* formats one-line message */ }
func (e *CelError) Unwrap() error { return e.Sentinel }
func (e *CelError) Is(target error) bool { return errors.Is(e.Sentinel, target) }

// Response is the Go-side type registered with the CEL environment under the
// CEL type name `apitest.Response`. Body is bound as CEL dyn.
type Response struct {
	Status  int
	Headers map[string]string
	Body    any
}

// StandardActivation is the binding shape exposed to every expression.
type StandardActivation struct {
	Response *Response
	Previous *Response
	Vars     map[string]any
	Env      map[string]string
}

// SensitiveObserver is invoked once per referenced sensitive variable name
// per Eval call, before Eval returns. The value argument is the stringified
// resolved value from the activation's Vars map.
type SensitiveObserver func(name, value string)

// EvalOptions carry per-evaluation hooks.
type EvalOptions struct {
	SensitiveNames    map[string]struct{} // names considered sensitive
	SensitiveObserver SensitiveObserver   // invoked for each referenced sensitive name
}

// Program is a compiled CEL expression bound to a specific result type.
type Program interface {
	Eval(activation StandardActivation, opts EvalOptions) (any, error)
}

// Evaluator compiles CEL expressions.
type Evaluator interface {
	Compile(src string, expectType *celgo.Type) (Program, error)
}

// NewEvaluator returns an Evaluator backed by cel-go with the deterministic
// function set described in the package doc.
func NewEvaluator() (Evaluator, error)
```

type evaluator struct {
	env *celgo.Env
}

func NewEvaluator() (Evaluator, error) {
	env, err := celgo.NewEnv(
		celgo.StdLib(),
		celgo.Types(&Response{}),
		celgo.Variable("response", celgo.ObjectType("apitest.Response")),
		celgo.Variable("previous", celgo.ObjectType("apitest.Response")),
		celgo.Variable("vars", celgo.MapType(celgo.StringType, celgo.DynType)),
		celgo.Variable("env",  celgo.MapType(celgo.StringType, celgo.StringType)),
	)
	if err != nil { return nil, err }
	return &evaluator{env: env}, nil
}

func (e *evaluator) Compile(src string, expectType *celgo.Type) (Program, error) {
	ast, issues := e.env.Parse(src)
	if issues != nil && issues.Err() != nil {
		return nil, newParseError(src, issues.Err())
	}
	// Step 4 adds the deterministic-function AST walk here.
	checked, issues := e.env.Check(ast)
	if issues != nil && issues.Err() != nil {
		return nil, newParseError(src, issues.Err())
	}
	if expectType != nil && !checked.OutputType().IsAssignableType(expectType) {
		return nil, newTypeError(src, checked.OutputType().String(), expectType.String(), "")
	}
	prog, err := e.env.Program(checked)
	if err != nil { return nil, newParseError(src, err) }
	// Step 5 collects sensitive-name references via AST walk.
	return &program{src: src, prog: prog}, nil
}
```

For the `Response`-to-cel-go adapter the simplest implementation is to register it via `cel.Types(&Response{})` and let cel-go's reflection adapter discover the exported fields. The field name remapping (`Status` → `status`) is handled by tagging the struct with `cel:"status"` tags or by implementing a small `ref.TypeAdapter`. Given that cel-go's native-types extension requires lowercase field names by default, the implementation uses `cel-go`'s ext/native package (`ext.NativeTypes(reflect.TypeOf(Response{}))`) which auto-lowercases. If that proves brittle, a hand-rolled adapter that satisfies the `ref.Val` / `traits.Indexer` interfaces is the fallback.

// forbid.go
package cel

import (
	"fmt"

	celast "github.com/google/cel-go/common/ast"
	"github.com/google/cel-go/cel"
)

// rejectTimeOfDay walks the parsed AST and returns a non-nil error if it
// references the disallowed time-of-day functions: now() (any arity) and
// timestamp() with zero arguments. timestamp(string) (single-argument form)
// is allowed.
func rejectTimeOfDay(ast *cel.Ast) error {
	var firstErr error
	celast.PostOrderVisit(ast.NativeRep().Expr(), celast.NewExprVisitor(func(e celast.Expr) {
		if firstErr != nil { return }
		if e.Kind() != celast.CallKind { return }
		call := e.AsCall()
		switch call.FunctionName() {
		case "now":
			firstErr = fmt.Errorf("now() is not allowed (time-of-day functions are disabled)")
		case "timestamp":
			if len(call.Args()) == 0 {
				firstErr = fmt.Errorf("zero-argument timestamp() is not allowed; use timestamp(string)")
			}
		}
	}))
	return firstErr
}
```

(Concrete cel-go API names may vary slightly across `v0.28.x`; the walker is small enough that adapting at implementation time is cheap.)

const ellipsisMarker = "…" // U+2026 HORIZONTAL ELLIPSIS

// truncateSource returns src verbatim when it is at most 200 runes long, or
// the first 200 runes followed by ellipsisMarker otherwise. Operates on
// runes (not bytes) so multi-byte input is handled correctly.
func truncateSource(src string) string {
	runes := []rune(src)
	if len(runes) <= 200 { return src }
	return string(runes[:200]) + ellipsisMarker
}
```

// observe.go
package cel

import (
	"github.com/google/cel-go/cel"
	celast "github.com/google/cel-go/common/ast"
)

// collectVarsRefs returns the sorted-unique set of names X such that the
// expression references vars.X (as a Select whose Operand is the identifier
// "vars").
func collectVarsRefs(ast *cel.Ast) []string {
	seen := map[string]struct{}{}
	celast.PostOrderVisit(ast.NativeRep().Expr(), celast.NewExprVisitor(func(e celast.Expr) {
		if e.Kind() != celast.SelectKind { return }
		sel := e.AsSelect()
		op := sel.Operand()
		if op.Kind() != celast.IdentKind || op.AsIdent() != "vars" { return }
		seen[sel.FieldName()] = struct{}{}
	}))
	out := make([]string, 0, len(seen))
	for k := range seen { out = append(out, k) }
	sort.Strings(out)
	return out
}

// program.Eval invokes opts.SensitiveObserver(name, value) for each name in
// p.varsRefs that is present in opts.SensitiveNames, looking up the value in
// activation.Vars and stringifying it (fmt.Sprintf("%v", val)).
```

		Vars: map[string]any{"api_key": "secret"},
	}, opts)

		t.Fatalf("want one call (api_key, secret), got %+v", calls)
	}
}
```

## Risks and Edge Cases

- **Risk: cel-go API surface differs in v0.28.x from earlier versions.** The AST walker uses `celast.PostOrderVisit` and `Expr.Kind`/`AsCall`/`AsSelect`/`AsIdent`; these names match v0.28.x but minor renames are possible. **Mitigation:** if the API names differ, the walker is contained in two small files (`forbid.go`, `observe.go`) — adapt at implementation time. The contract (reject `now`/`timestamp()`, collect `vars.<X>` references) is independent of the API names.

- **Risk: cel-go's native-type adapter requires lowercase field tags.** `ext.NativeTypes(reflect.TypeOf(Response{}))` auto-lowercases struct field names so `Status`/`Headers`/`Body` map to `status`/`headers`/`body` automatically; however, if Body's `any` type is not bound to `dyn` by the default adapter, manual registration via a custom `ref.TypeAdapter` is required. **Mitigation:** the `Body any` field is typed as `any` in Go so cel-go's `DefaultTypeAdapter` will map it through `types.NewDynamicMap`/`NewDynamicList`/scalars — confirmed by the `TestEvaluator_ResponseBodyIsDyn` test which exercises a JSON-shaped body.

- **Edge case: expression references both `now()` and `timestamp()` with zero args.** The walker reports the first one it encounters. The test asserts only that one of them is named — acceptable.

- **Edge case: `vars.X` where X is an unusual identifier.** cel-go's grammar restricts identifiers to `[A-Za-z_][A-Za-z0-9_]*`. The `collectVarsRefs` walker reports the name verbatim. **Handling:** the SensitiveSet matches by exact name, so weird-but-legal names round-trip correctly.

- **Edge case: 200-char boundary on multibyte input.** Handled by rune-based truncation (Step 6). Verified by a dedicated test.

- **Edge case: nil `SensitiveNames` map with non-nil observer.** Treated as empty set; observer never fires. Test added in Step 7.

- **Edge case: response body is `nil` while expression accesses `response.body.x`.** cel-go returns a runtime error; surfaced to the caller as the raw cel-go error wrapped in a `CelError{Sentinel: ErrCelParse}`. This is consistent with the "parse-class" semantics — the broader system treats runtime CEL failures as expression failures, not as assertion failures. M19-004 will refine the wrapping for assertion contexts.

- **Edge case: `body` bound as `dyn` and expression performs arithmetic on it.** cel-go's type checker accepts `dyn` for any operation but the evaluator returns a runtime type error if the actual value disagrees. Surfaces as `ErrCelParse` (runtime category). Acceptable for this slice; M19-004 will distinguish runtime vs static type errors when it adds the assertion wrapper.

## Deviations

### Medium Correction: Response bound as map(string, dyn) instead of native type

**What changed:** The plan described using `ext.NativeTypes(reflect.TypeOf(Response{}))` with `ParseStructTag("json")` to register the `Response` struct as a cel-go native type. During implementation, `cel-go`'s `convertToCelType` function was found to return `nil, false` for `reflect.Interface` kinds (the `any` type used for `Body`), making the `body` field inaccessible via native types.

**Solution used:** `response` and `previous` are declared in the CEL environment as `map(string, dyn)`. A `responseToMap` helper converts `*Response` to `map[string]any{"status": int64(r.Status), "headers": r.Headers, "body": r.Body}` at activation time. This is functionally equivalent — `body` accesses remain fully dynamic — and simpler.

**Impact:** The `Response` struct retains its json tags (unused for native-type registration now, but useful for future serialization). The `cel.Response` type name is no longer registered in the CEL type system, but callers access fields identically via `response.status`, `response.body.x`, etc. All behavior tests pass.
