# Implementation Plan: M19-001

## Overview

Wire the `if:` field on request items as a CEL-evaluated boolean gate that runs BEFORE per-request templating, short-circuits the request as `skipped` with a reason when falsy, propagates skip status to dependents declared via a new `depends_on:` list, funnels referenced-sensitive values through `variable.SensitiveSet`, and surfaces CEL parse/type failures with `ERR_CEL_PARSE` / `ERR_CEL_TYPE` from `curlew validate`. Updates all six output formatters to render the skipped status with reason, excludes skipped items from assertion totals, and adds a smoke fixture exercising the true / false / skip-on-skipped-parent branches.

## Key Architectural Decisions

1. **`if:` is parsed as a verbatim YAML string at load time; CEL parse is deferred.** The parser stores `If string` on `parser.RequestItem` and performs no CEL work. CEL Compile happens in two places: (a) inside `curlew validate` for every site, surfacing `ERR_CEL_PARSE`/`ERR_CEL_TYPE` with field path `requests[N].if` (or `setup[N].if`/`teardown[N].if`) and a 200-char truncated source, and (b) inside the runner's gate, lazily, on first use per item. Lazy compile keeps `parser.ParseFile` free of cel-go imports and matches the M19-002 pattern (the cel package is wired by callers, not by the parser).

2. **`depends_on:` is introduced as a new `[]string` field on `parser.RequestItem`.** MANUAL.md already documents the field (§ 5.6 parallel section + § F glossary "Wave") but the parser does not yet bind it. M19-001 makes it a real field because the task's skip-propagation behaviour requires an explicit declaration to be reliable in sequential mode. The parallel-execution wave inference (which uses extract→consume edges in `internal/parallel/analyze.go`) is **not** changed by this task — `depends_on:` is consumed only by the new skip-propagation walker. M19-001 explicitly does not promise parallel scheduling from `depends_on:` (that remains future work). Names referenced in `depends_on:` are resolved against main-phase items by name; unknown names produce a parser error `ErrUnknownDependsOn`.

3. **`previous` is "the immediately preceding non-skipped result in the same phase".** This is the smallest, deterministic semantics that works for sequential execution. The runner threads a `*apicel.Response` pointer through `executePhase` updated after each successful (or failed-but-executed) request. Skipped items leave `previous` unchanged. For the M19-001 happy-path fixture this matches the user mental model ("the request right before me"). Parallel execution does not invoke the `if:` gate in this slice; if a parallel collection has any item with `if:` set, the runner falls back to sequential execution for the main phase and emits a Diagnostics line ("if: gate active; falling back to sequential main phase"). This avoids the much harder problem of resolving `previous` under wave scheduling, while keeping `if:` universally available. (Parallel + `if:` is recorded as future work; M19-001's behaviour tests cover sequential only.)

4. **Skip-on-skipped-parent walks `depends_on:` strictly.** Inside `executePhase`, before the per-item gate runs, the runner consults a `skippedSet map[string]struct{}` of item names already marked skipped in this phase. If any name in `item.DependsOn` is in `skippedSet`, the item is marked skipped with reason `"parent skipped: <parent-name>"` and added to `skippedSet`. The walker is per-phase (setup→main→teardown); cross-phase skip propagation is out of scope (teardown always runs regardless). This implements the "(a) skip-on-skipped-parent" semantics from milestone-mapping.md Open Decision #4.

5. **`if:` gate runs BEFORE templating.** In `executePhase`, the new gate fires after the parent-skip check but BEFORE `requtil.InterpolateRequest`. Because templating is what triggers `{{from_command:}}` sub-shells, vault provider fetches, and faker seeding (via `variable.NewRegistry(seed)`), short-circuiting before templating delivers the behaviour spec's "no sub-shell, vault fetch, or faker seed call is observed" property. The test for this uses a recording fake that wraps `variable.CommandExecutor` (sub-shell), `vault.CommandExecutor` (vault), and a counter on `variable.Registry` dispatch.

6. **Sensitive observer threads into `summary.RuntimeSensitive`.** `apicel.EvalOptions.SensitiveObserver` is wired to a closure that calls `scope.RuntimeSensitive().AddValue(value)` (the same set populated by `$hmacSha256` etc.). The set is exposed on `summary.RuntimeSensitive` so the redaction layer in `cmd/curlew` sees `if:`-referenced sensitive values without touching `SensitiveSet` machinery. The sensitive *name* set fed into `EvalOptions.SensitiveNames` is the union of `col.Variables.Sensitive.Names()` and every per-item `item.Variables.Sensitive.Names()` whose scope reaches this item — same conservative union the parser builds today for redaction.

7. **CEL evaluator is constructed once per run and threaded through `VarSources`.** A new `CelEvaluator apicel.Evaluator` field on `VarSources` (defaulting to `apicel.NewEvaluator()` when nil, with `sync.Once` lazy init) holds the evaluator. Lazy construction means runs with no `if:` (the overwhelming common case) pay zero cel-go init cost. The validator's `Validate()` path constructs its own evaluator (separate process from `curlew run`).

8. **`If`-compile cache lives on the runner's per-run state, not on the parsed item.** The parser stores raw source; the runner maintains a `map[string]apicel.Program` keyed by source string and reused across items. Per-run, not global, so two test invocations get clean state. This avoids cross-item compile work and keeps parser-side concurrency-safe (parser items are read-only after load).

9. **Validate command surfaces `ERR_CEL_PARSE` and `ERR_CEL_TYPE` as `validator.Issue` entries with `SeverityError`.** The validator already has the issue-collection pattern; this slice adds a CEL-validation pass that iterates every section/item, calls `evaluator.Compile(item.If, celgo.BoolType)`, and for any returned `*apicel.CelError` produces an `Issue` whose `Message` includes the field path (`setup[2].if`, `requests[0].if`, `teardown[1].if`) and whose `Hint` is the canonical hint already registered in `internal/cel/hints_init.go`. The truncated source comes from `(*apicel.CelError).Source`. Exit code follows the existing validator rules (`exit 3` on error).

10. **Formatter changes are minimal: render `skipped` with reason; never count toward assertion totals.** Existing formatters all already know `Skipped`. The only required changes are: (a) terminal printer renders `SKIPPED  <name>  (<reason>)` (status-first, matching the observable) — current format is `<name>  SKIPPED`; (b) all formatters carry `SkipReason` through to output; (c) assertion-total counters (in terminal, JSON, TAP, JUnit, HTML, Markdown) verified to exclude skipped items. Most counters already do because they iterate `rr.AssertionResults.Items` which is nil for skipped items.

11. **`assertion_total` semantics: skipped items count toward `Total` and `Skipped` but not toward `Passed`/`Failed`/`AssertionFailures`.** This matches `runner.computeSummary` today — no changes needed there. The behavioural test asserts that when six items execute (3 pass, 1 skip via `if: false`, 1 skip-on-skipped-parent, 1 pass), `summary.AssertionFailures == 0` and `summary.Skipped == 2`.

12. **`If` is allowed in setup and teardown items, not only main.** The spec says "request item"; treating setup and teardown uniformly is the smallest-surprise rule. Skip-propagation operates within a phase. A skipped setup item is still considered "passed" for the `requiredSetupFailed` check (a skipped item is not a failure).

```go
func validateDependsOn(col *Collection, rootPath string) error {
    names := make(map[string]struct{}, len(col.Setup.Items)+len(col.Requests.Items)+len(col.Teardown.Items))
    for _, section := range [][]RequestItem{col.Setup.Items, col.Requests.Items, col.Teardown.Items} {
        for _, item := range section {
            if item.Name != "" {
                names[item.Name] = struct{}{}
            }
        }
    }
    for _, section := range [][]RequestItem{col.Setup.Items, col.Requests.Items, col.Teardown.Items} {
        for _, item := range section {
            for _, dep := range item.DependsOn {
                if _, ok := names[dep]; !ok {
                    return &apierrors.Structured{
                        Category: apierrors.CategoryParse,
                        FilePath: item.SourceFile,
                        Line:     item.SourceLine,
                        Message:  fmt.Sprintf("request %q: depends_on %q does not match any request name", item.Name, dep),
                        Hint:     "depends_on must reference an item by its name (case-sensitive). Names are unique within main; setup/teardown names are not addressable from main.",
                        Inner:    ErrUnknownDependsOn,
                    }
                }
            }
        }
    }
    return nil
}
```

```go
// internal/runner/runner.go — additions on VarSources
type VarSources struct {
    ...
    // CelEvaluator compiles `if:` (and future cel: assertion) expressions.
    // When nil, an evaluator is lazily constructed on first use.
    CelEvaluator apicel.Evaluator

    // celOnce + celEval back the lazy initialiser; callers should leave
    // these zero. Set by ensureCelEvaluator.
    celOnce sync.Once
    celEval apicel.Evaluator
    celErr  error
}

func (v *VarSources) ensureCelEvaluator() (apicel.Evaluator, error) {
    if v.CelEvaluator != nil { return v.CelEvaluator, nil }
    v.celOnce.Do(func() {
        v.celEval, v.celErr = apicel.NewEvaluator()
    })
    return v.celEval, v.celErr
}
```

```go
func compileIfProgram(cache map[string]apicel.Program, ev apicel.Evaluator, src string) (apicel.Program, error) {
    if p, ok := cache[src]; ok { return p, nil }

    cache[src] = p
    return p, nil
```

```go
// internal/validator/validator.go (additions)
import (
    celgo "github.com/google/cel-go/cel"
    apicel "github.com/weiqigod/curlew/internal/cel"
)

func validateIfExpressions(col *parser.Collection) []Issue {
    ev, err := apicel.NewEvaluator()
    if err != nil {
        return []Issue{{Severity: SeverityError, Message: "internal: build CEL evaluator: " + err.Error()}}
    }
    var issues []Issue
    sections := []struct {
        prefix string
        items  []parser.RequestItem
    }{
        {"setup", col.Setup.Items},
        {"requests", col.Requests.Items},
        {"teardown", col.Teardown.Items},
    }
    for _, sec := range sections {
        for i, item := range sec.items {
            if item.If == "" { continue }
            if _, compileErr := ev.Compile(item.If, celgo.BoolType); compileErr != nil {
                var cerr *apicel.CelError
                if errors.As(compileErr, &cerr) {
                    cerr.FieldPath = fmt.Sprintf("%s[%d].if", sec.prefix, i)
                    issues = append(issues, Issue{
                        Severity: SeverityError,
                        FilePath: item.SourceFile,
                        Line:     item.SourceLine,
                        Message:  fmt.Sprintf("%s: %s (source: %s)", cerr.FieldPath, sentinelLabel(cerr.Sentinel), cerr.Source),
                        Hint:     hintForCelSentinel(cerr.Sentinel),
                    })
                }
            }
        }
    }
    return issues
}

func sentinelLabel(s error) string {
    if errors.Is(s, apicel.ErrCelType) { return "ERR_CEL_TYPE" }
    return "ERR_CEL_PARSE"
}
```

`Validate()` is amended to:

```go
    result.Issues = append(result.Issues, iss)
    if iss.Severity == SeverityError { result.Valid = false }
}
return result
```

## Risks and Edge Cases

- **Risk: Parallel execution + `if:`.** Decision: fall back to sequential main when any item has `if:`, with a Diagnostics line. **Mitigation:** test asserts the fallback. Documented as future work in the task `improved.md` follow-up.
- **Risk: `previous` semantics surprise users in setup→main boundary.** `previous` is per-phase: the first main item sees `previous = nil`. **Mitigation:** documented in the new help text and (in M19-005) the manual.
- **Risk: `depends_on:` allows cycles.** A cycle would loop the walker indefinitely. **Mitigation:** the per-phase skip walker only consults `skippedSet`, which is monotonic; a cycle without a prior skip would simply leave both items un-skipped (the walker exits when no name matches `skippedSet`). Parser-level cycle detection is not added in this slice (the parallel package already detects extract-based cycles and `depends_on:` does not yet feed wave scheduling). Edge-case test: `A depends_on:[B], B depends_on:[A]`, both execute normally when neither is skipped.
- **Risk: Sensitive value not redacted if observer fires after templating already used the value.** Templating fires AFTER the gate, so the order is: gate (observer captures sensitive value into `RuntimeSensitive`) → templating uses scope → exec → output redaction (consults `RuntimeSensitive`). Order is correct. **Mitigation:** test `TestIfConditional_SensitiveValueRoutedToRuntimeSet`.
- **Risk: `if:` source with `{{var}}` Go-template syntax.** Per spec, `if:` is pure CEL — no `{{}}` interpolation. We do NOT pre-process the `if:` string with `scope.Interpolate`. Variable access happens through CEL's `vars.<name>` surface. **Mitigation:** documented in the help text and validator hint; behaviour test exercises `vars.foo`.
- **Edge case: `if: ""` (empty string).** Treated as "no gate" (fast path). YAML `if:` with no value → empty string → unset. Test: `TestParseFile_if_empty_is_noop`.
- **Edge case: `if:` source longer than 200 runes.** Validator's reported `Source` field uses `truncateSource` from M19-002 — already capped at 200 runes + ellipsis. Behaviour spec asserts ≤ 200; M19-002's existing test covers truncation.
- **Edge case: `depends_on:` on a setup item references a main item.** Skip propagation operates within a phase only. The parser's `validateDependsOn` accepts cross-phase names (they exist) but the runtime walker never finds them in `skippedSet`. Edge documented; test asserts cross-phase deps do not propagate.
- **Edge case: a data-driven item carries `if:`.** Gate fires once per item (before data-driven expansion). Falsy → entire item skipped; no rows executed. Test: `TestIfConditional_DataDriven_SkipsAllRows`.
- **Edge case: stop_on_failure interaction.** A failed request followed by an `if: false` skip should not flip `requiredFailed`. `if:`-skipped items do not affect the `stop_on_failure` ledger (matches the existing "skipped is not a failure" semantics in `runner.computeSummary`).
