# Implementation Plan: M14-018

## Overview

Wires the outbound GitHub Checks API path: a new `CheckRunPoster` worker that exchanges
the App JWT (M14-016) for an installation token, posts to
`POST /repos/{owner}/{repo}/check-runs`, and persists the resulting `check_run_id`. Adds
a `POST /api/v1/pr-checks` endpoint, expands the `pr_checks` table additively (migration
0017_pr_checks_v421), and ships a `github-mock` test sidecar plus the real
`GitHubInstallationsApi` HTTP client (replacing the M14-017 stub).

## Key Architectural Decisions

The task references several "Open Decisions"; this plan resolves them per the YAML scope:

1. **Endpoint shape** — observable shows `POST /api/v1/pr-checks` (top-level, not nested under `/organizations/{orgId}`). The org is resolved from the user's bearer token via `OrganizationMember.UserId`. This is a NEW endpoint; the existing M4-007 nested POST is preserved unchanged for backward compatibility (returns "storage-only" semantics — `state ∈ {success, failure}`, no GitHub side effects). The new endpoint is the v4.2.1 shape: it creates the `pr_checks` row AND triggers the outbound poster synchronously.
2. **Synchronous posting in the request** — the YAML observable expects the POST response to already include `state: "posted"` and `github_check_run_id`. We therefore call `CheckRunPoster.PostAsync` inline within the request handler with the request's `CancellationToken`. The token-bucket rate-limiter and single-flight refresh still serialise concurrent posts; if the budget is exhausted for the installation, we mark the row `queued` and return 202 with `state: "queued"` (transparent retry). On 5xx-from-GitHub we record the failure but defer the retry to a future drain pass (not in scope for M14-018; row is left with `state: "queued"`, `last_error` set, and a TODO for the drain worker).
3. **Migration shape** — `0017_pr_checks_v421` is purely additive `ALTER TABLE` per Open Decision #6 default. The legacy `state` column is preserved (the M4-007 endpoint still writes to it). New columns: `installation_id`, `check_run_id`, `external_id` (UUID, NOT NULL, backfilled `gen_random_uuid()` on Postgres / `randomblob` on SQLite, UNIQUE indexed), `conclusion`, `details_url`, `output_summary`, `output_text`, `annotations` JSONB, `posting_started_at`, `posted_at`, `attempt_count` INT NOT NULL DEFAULT 0, `last_error`, `status` (backfilled via CASE on existing `state`).
4. **GitHubInstallationsApi promotion** — M14-017 left an `IGitHubInstallationsApi` interface + `StubGitHubInstallationsApi` for non-Testing environments. M14-018 ships the real `GitHubInstallationsApi` (HTTP client) and registers it in production; the stub is deleted (the file's docstring already announces this).
5. **TimeProvider injection for token cache** — the in-process token cache uses `TimeProvider.GetUtcNow()` so unit tests can drive expiry deterministically via `FakeTimeProvider`.
6. **Testing strategy** — unit tests use a `FakeHttpMessageHandler` (a minimal recorded response queue) to assert exact requests/responses; the docker-compose `github-mock` sidecar (a tiny Go HTTP stub mirroring the existing `testdata/m14/stub_server.go` pattern) is wired only for the smoke/E2E observable. The test count target (≥14) is met by unit tests alone — the docker stack is just the observable proof.
7. **Token leak detector** — a single regex `^|\W(ghs_[A-Za-z0-9]{36,})\W|$` scans the entire raw JSON request body before deserialisation. We do NOT additionally check against an "active install token" cache — the cache is keyed by installation_id and a request body is not normally inspected against every cached token. Documented choice: the regex catches the format-level leak; runtime token cross-reference is omitted as low-value (would require iterating the cache on every request).

```csharp
namespace ApiTool.Backend.PrChecks;

/// <summary>
/// Maps the CLI's <c>state</c> field to GitHub's <c>conclusion</c> enum
/// per docs/SPECIFICATION.md:8501-8511.
/// </summary>
public static class PrCheckConclusionMapper
{
    public static readonly IReadOnlyList<string> ValidStates =
        ["success", "failure", "cancelled", "timed_out", "neutral", "skipped"];

    public static bool TryMap(string? state, out string conclusion)
    {
        conclusion = string.Empty;
        if (string.IsNullOrWhiteSpace(state)) return false;
        var s = state.Trim().ToLowerInvariant();
        // action_required is reserved per :8512 — never emitted in M14
        if (s == "action_required") return false;
        if (!ValidStates.Contains(s)) return false;
        conclusion = s;
        return true;
    }
}
```

```csharp
// TokenLeakDetector.cs
public static class TokenLeakDetector
{
    private static readonly Regex GhsToken = new(
        @"ghs_[A-Za-z0-9]{36,}",
        RegexOptions.Compiled | RegexOptions.CultureInvariant);

    public static bool ContainsTokenLeak(string rawBody) =>
        !string.IsNullOrEmpty(rawBody) && GhsToken.IsMatch(rawBody);
}

// MarkdownSafety.cs
public static class MarkdownSafety
{
    public const int MaxField = 60_000;
    public static string Truncate(string? input)
    {
        if (string.IsNullOrEmpty(input)) return input ?? string.Empty;
        if (input.Length <= MaxField) return input;
        return string.Concat(input.AsSpan(0, MaxField - "(truncated)".Length), "(truncated)");
    }

    /// <summary>Escapes markdown specials in user-controlled interpolated strings (test names, headers, URLs).</summary>
    public static string EscapeUserContent(string input)
    {
        if (string.IsNullOrEmpty(input)) return input;
        var sb = new StringBuilder(input.Length + 16);
        foreach (var c in input)
        {
            if (c is '*' or '_' or '`' or '[' or ']' or '\\') sb.Append('\\');
            sb.Append(c);
        }
        return sb.ToString();
    }
}
```

#### Algorithm — `CheckRunPoster.PostAsync`

```
1. Load PrCheck row by id; if null → throw (caller's bug).
2. Load alive github_installations row for OrgId; if null → return Failed(NoInstallation).
3. If install.SuspendedAt != null → InstallationSuspended.
4. If install.DeletedAt    != null → InstallationDeleted.
5. Parse install.RepoSetJson; if PrCheck.Repo not in {owner/name} of repo_set → RepoNotCovered.
6. If PostingStartedAt set AND PostedAt null:
       GET /repos/{owner}/{repo}/check-runs?head_sha=<sha>&app_id=<our_app>&filter=latest
       If a run with our external_id is found → record CheckRunId, mark Posted, return AlreadyPosted.
7. If RateLimitTracker.IsBlocked(installationId) → mark queued, return Queued.
8. token = await InstallationTokenCache.GetOrRefreshAsync(installationId, ct).
9. row.PostingStartedAt = now; row.AttemptCount++; SaveChanges.
10. POST /repos/{owner}/{repo}/check-runs with body:
       { name="Curlew", head_sha=<row.HeadSha or pr_checks-derived>, external_id=row.ExternalId,
         status="completed", conclusion=Mapper.Map(row.State),
         started_at=row.CreatedAt, completed_at=now,
         details_url=row.DetailsUrl,
         output={ title=truncate(60), summary=Truncate(row.OutputSummary), text=Truncate(row.OutputText), annotations=parsed_first_50 } }
11. Observe X-RateLimit-Remaining/Reset → RateLimitTracker.Update.
12. On 2xx: parse check_run.id; row.CheckRunId, row.PostedAt, row.Status="posted"; return Posted.
13. On 5xx / network error: row.LastError = paraphrase, row.Status = "queued" (or "failed" after 5 attempts); return GithubUnavailable.
14. On 403 Retry-After: rateLimit.BlockUntil(...); row.Status="queued"; return GithubRateLimited.
15. On 404 (repo missing) or 422: row.Status="failed", row.LastError, return NoInstallation/RepoNotCovered.
```

Important: `head_sha` is not currently a column on `pr_checks`. The YAML observable's `pr-check-payload.json` is expected to include `head_sha`. The CLI shape is the source of truth — Step 5 below adds `HeadSha` to the new request DTO and to the entity (under Step 1's column additions, we add `head_sha` TEXT NOT NULL with backfill `''`).

#### Endpoint flow

```
POST /api/v1/pr-checks  (Bearer auth)
{
  "repo": "owner/name",
  "pr": 42,
  "state": "success" | "failure" | "cancelled" | "timed_out" | "neutral" | "skipped",

Flow:
1. Read raw body bytes once.
2. TokenLeakDetector.ContainsTokenLeak(rawBody) → 400 PRCHECK_TOKEN_LEAK_DETECTED + structured-log security_incident.
3. Deserialize to PrCheckUploadRequest.
4. Resolve user → unique org membership (or 401/403 on miss).
5. Validate state via PrCheckConclusionMapper.TryMap.
6. Insert PrCheck row { ExternalId=Guid.NewGuid(), Status="pending", Repo, Pr, State, HeadSha, ... }.
7. Synchronously: result = await CheckRunPoster.PostAsync(row.Id, ct).
8. Map result.Code → HTTP status per :8537-8549; on success return 200 { state: "posted", github_check_run_id, pr_check_id }.
```

```csharp
public sealed class GitHubInstallationsApi(
    IHttpClientFactory httpFactory,
    IInstallationTokenCache tokens,
    ILogger<GitHubInstallationsApi> log) : IGitHubInstallationsApi
{
    public async Task<IReadOnlyList<RepoRef>> ListInstallationRepositoriesAsync(
        long installationId, CancellationToken ct)
    {
        var token = await tokens.GetOrRefreshAsync(installationId, ct);
        var http = httpFactory.CreateClient("github-checks");
        using var req = new HttpRequestMessage(HttpMethod.Get, "/installation/repositories");
        req.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);
        req.Headers.Accept.ParseAdd("application/vnd.github+json");
        using var rsp = await http.SendAsync(req, ct);
        rsp.EnsureSuccessStatusCode();
        var doc = await JsonDocument.ParseAsync(await rsp.Content.ReadAsStreamAsync(ct), cancellationToken: ct);
        var arr = doc.RootElement.GetProperty("repositories");
        var list = new List<RepoRef>(arr.GetArrayLength());
        foreach (var r in arr.EnumerateArray())
        {
            var fullName = r.GetProperty("full_name").GetString()!;
            var slash = fullName.IndexOf('/');
            list.Add(new RepoRef(r.GetProperty("id").GetInt64(), fullName[..slash], fullName[(slash+1)..]));
        }
        return list;
    }
}
```

## Risks and Edge Cases

- **Risk:** EF Core InMemory provider used by `BackendFactory` does not enforce unique indexes — `PrChecksMigrationTests` would silently pass on InMemory but fail on real SQLite. **Mitigation:** Migration tests use `TestDb.CreateSqlite()` (real SQLite in-memory with migrations applied), per the existing pattern referenced in `BackendFactory.cs` line 26-29.
- **Risk:** `pr_checks.external_id` UUID default differs across providers (`gen_random_uuid()` is Postgres-only; SQLite has no UUID type so we generate via `lower(hex(randomblob(16)))` and parse back). **Mitigation:** EF Core's default-value-sql is provider-specific — guard with `migrationBuilder.IsNpgsql()`. Application code always sets `ExternalId = Guid.NewGuid()` explicitly on insert; the DB default exists only for backfill on existing rows.
- **Risk:** The synchronous-post design means a slow GitHub round-trip blocks the inbound HTTP request. **Mitigation:** Per-call timeout of 10s on the named `HttpClient` (`github-checks`); if exceeded, the row is left `status=queued` and we return `502 PRCHECK_GITHUB_UNAVAILABLE`. CLI-side retry then re-uploads (the GET-by-(head_sha,app_id) idempotency check prevents double-post).
- **Risk:** `IInstallationTokenCache` registered as singleton means tokens persist across requests. **Mitigation:** This is the design — but tests must reset the cache between runs. Add `IInstallationTokenCache.Clear()` (test-only via internal `InternalsVisibleTo`) and call from `BackendFactory.InitializeAsync`.
- **Risk:** Single-flight refresh under heavy concurrency could deadlock if the lock is held while the HTTP call is in-flight. **Mitigation:** `SemaphoreSlim(1,1)` with `WaitAsync(ct)` — caller-cancellation propagates; the lock is released on every code path via `try/finally`.
- **Edge case:** Concurrent requests for the same `pr_checks.external_id` (e.g., CLI retried because the previous response hung). **Handling:** The unique index on `external_id` rejects duplicate INSERTs at the DB level; our endpoint catches `DbUpdateException` with `IsUniqueIndexViolation` (reuse the helper from `GithubInstallationsService`) and returns the existing row.
- **Edge case:** `output.summary == null` and `output.text == null`. **Handling:** Both are nullable; we send only what is provided. GitHub accepts a missing `output` field.
- **Edge case:** Annotation array > 50 entries. **Handling:** Per :8525, we send the first 50 in POST and emit a warning log noting that PATCH-based extension lands in a later milestone. M14-018 does NOT do PATCH.
- **Edge case:** `head_sha` not provided by CLI. **Handling:** New endpoint requires `head_sha` — reject 400 `invalid_request` if missing or not 40-char hex. The legacy endpoint does not use `head_sha`, so its tests are unaffected.
- **Edge case:** GitHub returns `repository_selection: "all"` for an installation. **Handling:** When `repo_selection == "all"`, the repo-set check is bypassed (any repo passes). Stored as is in `github_installations.repo_selection`.
- **Risk:** `BearerTokenRedactor` (the structured-logging filter) must scrub `ghs_…` tokens. The redactor is registered already (Program.cs:284-289). **Mitigation:** Add a unit test under `Logging/` that asserts `BearerTokenRedactor` removes `ghs_<36+ chars>` substrings from log lines (third negative test for token handling).
