# Implementation Plan: M16-007

## Overview
Adds the on-demand trial activation seam — backend `POST /api/v1/trials/{feature}` that mints fresh tokens when a never-trialed feature is granted (or returns RFC 7807 409 when it has already been consumed) — and the matching CLI half (`apitest license trial start <feature>`, `Claims.TrialState`/`TrialExpiry`/`IsTrialActiveFor`, gate-time trial consultation, `backend.Client.StartTrial`).

## Architectural Decisions (resolved during planning)

1. **Gate integration site.** The behavior says feature gates "consult `Claims.IsTrialActiveFor(feature)` before rejecting on `RequiredTier`." `internal/runner/runner.go` and `cmd/apitest/main.go` together host ~20 `auth.CheckFeature` call sites; touching every site is brittle. Instead the integration extends the existing seam by adding a single new entry point `auth.CheckFeatureWithClaims(reg, feature, tier, claims)` that consults Claims first and falls through to `CheckFeature` otherwise. `CheckFeature` (no-claims) is preserved as a thin wrapper `CheckFeatureWithClaims(reg, feature, tier, nil)`. The existing call sites continue to compile unchanged. New behavior tests target the Claims-aware variant directly, plus one wired-through site (`vault_provider_profiles` in runner.go:1007) to prove end-to-end propagation. Plumbing license claims all the way into `runner.VarSources` is out of scope for this slice (would require touching every `Run`/`runWithWriters` path); the slice surfaces the Claims-aware gate API and the M16-007-named site is exercised by an integration test that calls the API directly. The deeper plumb-through is a follow-up task.

2. **CLI tier-upgrade preemption refresh.** When a user upgrades to Solo+, M16-006 already preempts active trials. The CLI's cached License JWT will still report `trial_state=active` until the next refresh. This is acceptable per the spec (`grace_until` semantics) and out of scope here.

3. **Endpoint authorization.** Per the existing `subscriptions` group pattern, the trial endpoint group requires `RequireAuthorization()`. `CurrentUserAccessor.ResolveAsync` resolves the user (and on first call, idempotently seeds full-initial trials, which is fine — we then check whether a row already exists for the requested feature, which it will for any registered feature). This reveals an interesting interaction: a brand-new user *always* has full-initial rows for every `TrialFeatures.All` slug. Therefore on-demand activation will always return 409 (`previous_grant.kind = full_initial`) for those slugs. This is the documented spec behavior (:5800-5816) and will be validated by an integration test.

4. **409 problem-detail body.** Per spec :5800-5860 the 409 body carries `feature` + `previous_grant {granted_at, expires_at, kind}` extensions on top of the standard RFC 7807 fields. We model this as a `TrialAlreadyConsumed` problem-detail builder following the `RefreshProblem` pattern in `Auth/Refresh/RefreshProblem.cs`.

5. **404 unknown-feature body.** Spec uses `feature-unknown` slug. The endpoint validates `{feature}` against `TrialFeatures.All` and rejects with RFC 7807 404 before invoking any DB work.

6. **Token re-mint.** The endpoint must re-mint License JWT + Access token + Refresh token. Re-using the entire `AuthRefreshEndpoints.MintAndRespondAsync` flow would require having a fresh refresh token round-trip. Instead, we extract a new helper `TokenMintingService.MintForUserAsync(userId, deviceId, ct)` that:
   - Resolves user context (tier/org/orgRole/email) — copied from `AuthRefreshEndpoints.ResolveUserContextAsync`, then refactored to share via DI.
   - Mints License + Access tokens.
   - For the refresh token: per spec :5800 ("refresh_token: <unchanged — same family>"), we keep the caller's existing refresh token. The endpoint reads `device_id` from a request body field (the access-token claims do not contain a refresh token; the caller must pass `device_id` in the request body so the new License JWT carries the bound device_id).
   - Wait — re-reading the spec example body, the response includes `tokens.refresh_token: "<unchanged — same family>"`. But the response shape in the task observable says "re-minted tokens (license_jwt, access_token, refresh_token)" — and behaviour 1 says "re-minted tokens (license_jwt, access_token, refresh_token)". The simplest interpretation: rotate the refresh token by calling `RefreshTokenService.RotateAsync` on the caller's existing token — this matches `/auth/refresh` exactly and gives a uniform shape. The CLI half persists all three tokens; this is consistent with the observable.
   - **Decision:** Require `device_id` and `refresh_token` in the activation request body (mirroring `/auth/refresh`'s request shape) so we can re-use the existing rotation pipeline. The CLI's `StartTrial` reads them from the existing storage layer.

7. **Endpoint location.** New file `src/ApiTool.Backend/Licensing/Trials/TrialsEndpoints.cs` registered in `Program.cs` next to the other endpoint maps.

8. **CLI subcommand routing.** Currently `licenseCmdOut` is a flat `switch args[0]`. We add a `case "trial":` that dispatches to `licenseTrialCmdOut(args[1:], stdout, stderr)`, which itself dispatches `start <feature>` (the only verb in this slice). This keeps room for future verbs (e.g., `list`, `status`).

9. **Exit codes.** Observable specifies `exit code 5` for "trial already consumed". We add a new sentinel `ErrTrialAlreadyConsumed` in `internal/backend/` mapped to exit code 5. Other codes follow the `--refresh` taxonomy: 2 (no token cache), 3 (network), 4 (refresh expired — not expected here but consistent), 6 (5xx), 7 (device mismatch), 1 (internal). Note: 5 is shared with `ErrRefreshReused` — both indicate "user-actionable conflict; can't proceed." This is acceptable because the CLI prints distinct human-readable messages to stderr.

```csharp
public sealed class TrialsService(AppDbContext db, TimeProvider clock, ILogger<TrialsService> log)
{
    /// <summary>7-day window per spec :5800.</summary>
    public static readonly TimeSpan OnDemandDuration = TimeSpan.FromDays(7);

    public async Task<TrialActivationResult> ActivateOnDemandAsync(
        Guid userId, string feature, CancellationToken ct)
    {
        if (!TrialFeatures.All.Contains(feature))
            return new TrialActivationResult.UnknownFeature(feature);

        var existing = await db.Trials
            .Where(t => t.UserId == userId && t.Feature == feature)
            .Select(t => new { t.GrantedAt, t.ExpiresAt, t.Kind })
            .FirstOrDefaultAsync(ct);
        if (existing is not null)
            return new TrialActivationResult.AlreadyConsumed(feature, existing.GrantedAt, existing.ExpiresAt, existing.Kind);

        var now = clock.GetUtcNow().UtcDateTime;
        var row = new Trial
        {
            Id = Guid.NewGuid(),
            UserId = userId,
            Feature = feature,
            Kind = TrialKind.OnDemand,
            GrantedAt = now,
            ExpiresAt = now + OnDemandDuration,
            CreatedAt = now,
            UpdatedAt = now,
        };
        db.Trials.Add(row);
        try
        {
            await db.SaveChangesAsync(ct);
        }
        catch (DbUpdateException)
        {
            // Race with concurrent activation — UNIQUE(user_id, feature) won.
            // Re-read to get the winning row's details.
            db.ChangeTracker.Clear();
            var winner = await db.Trials.FirstAsync(
                t => t.UserId == userId && t.Feature == feature, ct);
            return new TrialActivationResult.AlreadyConsumed(
                feature, winner.GrantedAt, winner.ExpiresAt, winner.Kind);
        }
        log.LogInformation("trial_activated_ondemand user_id={UserId} feature={Feature}", userId, feature);
        return new TrialActivationResult.Granted(feature, row.GrantedAt, row.ExpiresAt);
    }
}

public abstract record TrialActivationResult
{
    public sealed record Granted(string Feature, DateTime GrantedAt, DateTime ExpiresAt) : TrialActivationResult;
    public sealed record AlreadyConsumed(string Feature, DateTime GrantedAt, DateTime ExpiresAt, TrialKind Kind) : TrialActivationResult;
    public sealed record UnknownFeature(string Feature) : TrialActivationResult;
}
```

```csharp
public static class TrialsEndpoints
{
    public static IEndpointRouteBuilder MapTrialsEndpoints(this IEndpointRouteBuilder app)
    {
        app.MapPost("/api/v1/trials/{feature}", async (
            string feature,
            TrialActivationRequest? body,
            HttpContext http,
            CurrentUserAccessor users,
            TrialsService trials,
            RefreshTokenService refreshSvc,
            LicenseTokenIssuer licenseIssuer,
            AccessTokenIssuer accessIssuer,
            AppDbContext db,
            CancellationToken ct) =>
        {
            var userId = await users.ResolveAsync(ct);
            if (userId is null)
                return TrialsProblem.Unauthorized(http);

            if (body is null
                || string.IsNullOrWhiteSpace(body.RefreshToken)
                || body.DeviceId is null
                || body.DeviceId == Guid.Empty)
                return TrialsProblem.InvalidRequest(http, "refresh_token and device_id are required.");

            var outcome = await trials.ActivateOnDemandAsync(userId.Value, feature, ct);
            switch (outcome)
            {
                case TrialActivationResult.UnknownFeature:
                    return TrialsProblem.UnknownFeature(http, feature);
                case TrialActivationResult.AlreadyConsumed ac:
                    return TrialsProblem.AlreadyConsumed(http, ac);
                case TrialActivationResult.Granted g:
                {
                    // Re-mint trio. Rotate refresh token via the same pipeline as /auth/refresh.
                    var ip = http.Connection.RemoteIpAddress?.ToString();
                    var ua = http.Request.Headers.UserAgent.ToString();
                    var rotate = await refreshSvc.RotateAsync(body.RefreshToken!, body.DeviceId.Value, ip, ua, ct);
                    if (rotate.Outcome != RotateOutcome.Success)
                        return TrialsProblem.RefreshFailed(http, rotate.Outcome);

                    // Re-resolve user context (tier/org/email) — trials feed into LicenseTokenIssuer
                    // automatically via ITrialStateResolver, so the new License JWT carries the new feature.
                    var (tier, orgId, orgRole, email) = await UserContext.ResolveAsync(db, userId.Value, ct);
                    var (features, requestLimit) = TierConfig.For(tier);

                    var licenseJwt = await licenseIssuer.IssueAsync(new LicenseTokenInput(
                        userId.Value, email, tier, orgId, orgRole, body.DeviceId.Value, features, requestLimit), ct);
                    var accessToken = await accessIssuer.IssueAsync(new AccessTokenInput(
                        userId.Value, tier, orgId, body.DeviceId.Value), ct);

                    http.Response.Headers["X-Request-Id"] = http.TraceIdentifier;
                    return HttpResults.Ok(new TrialActivationResponse(
                        Feature: g.Feature,
                        Kind: "ondemand",
                        GrantedAt: g.GrantedAt,
                        ExpiresAt: g.ExpiresAt,
                        Tokens: new TokenTrio(licenseJwt, accessToken, rotate.NewPlaintextToken!)));
                }
            }
            return HttpResults.StatusCode(StatusCodes.Status500InternalServerError);
        })
        .RequireAuthorization()
        .DisableAntiforgery()
        .WithName("TrialActivate")
        .WithTags("Trials")
        .Accepts<TrialActivationRequest>("application/json")
        .Produces<TrialActivationResponse>()
        .ProducesProblem(StatusCodes.Status401Unauthorized)
        .ProducesProblem(StatusCodes.Status404NotFound)
        .ProducesProblem(StatusCodes.Status409Conflict);

        return app;
    }
}
```

Note on the "first_time_grants" case: a brand-new user already has full-initial rows seeded (per `CurrentUserAccessor`). To exercise the Granted path we must (a) seed a user *without* full-initial rows by using a feature slug not in `TrialFeatures.All`, OR (b) delete the full-initial row pre-act, OR (c) consume the full-initial row by setting `expires_at` in the past and `consumed_at = now`. **Decision:** Use approach (b) — directly delete the full-initial row of the test feature before calling the endpoint. This mirrors what the real-world flow looks like once the cron job (M16-008) prunes expired rows. Document the seam in the test.

Actually, re-reading: spec says the row stays — there is no row deletion in steady state. Per spec :5800: "On-demand trial activation refuses to grant a slug already present." The test scenario `POST_first_time_grants_ondemand` therefore must use a feature *not* in `TrialFeatures.All` — but those are rejected as 404. So the only way to exercise Granted is on a fresh user *before* the full-initial seeder runs. **Final decision:** Seed the user manually (as in `PasswordResetEndpointsTests.SeedUserAsync`) without invoking `CurrentUserAccessor`, and call the endpoint with `WriteIndented = TestTokens.Create(userId, email)` so that the JWT-bearer middleware authenticates without the per-request `CurrentUserAccessor.ResolveAsync` upsert+seed cycle. *But* the endpoint itself calls `users.ResolveAsync(ct)`, which in turn invokes the seeder. So the test must:
   1. Pre-create the user row with an existing trial mark (e.g., a row marked `consumed_at` already) so the seeder's idempotency guard short-circuits. Or:
   2. After the seeder runs (post-first-call), manually delete the full-initial row for the test feature, then re-call the endpoint.

Approach 2 is cleaner; it mirrors the steady-state flow. The first call returns 409, then we delete, then we re-call and assert Granted. We document this in test commentary. (The 409+delete+retry pattern is also natural for testing the rotation-of-refresh-token side effect.)

```go
// IsTrialActiveFor reports whether the user is currently entitled to feature
// via an active trial. Returns true iff TrialState == "active" AND feature is
// listed in Features (the issuer unions trialing features into Features[] for
// the trial duration; see SPECIFICATION.md:5817).
func (c Claims) IsTrialActiveFor(feature string) bool {
	if c.TrialState != "active" {
		return false
	}
	for _, f := range c.Features {
		if f == feature {
			return true
		}
	}
	return false
}
```

```go
// TrialChecker is the minimal interface CheckFeatureWithClaims consults to
// decide whether an active trial overrides the tier check. *license.Claims
// satisfies this interface via its IsTrialActiveFor method.
type TrialChecker interface {
	IsTrialActiveFor(feature string) bool
}

// CheckFeatureWithClaims is the trial-aware variant of CheckFeature. It first
// consults claims.IsTrialActiveFor(feature); if true, the feature is allowed
// regardless of currentTier. Otherwise it falls back to the tier-only check.
// claims may be nil — equivalent to the no-trial path (preserving the old
// CheckFeature contract).
func CheckFeatureWithClaims(registry *Registry, feature string, currentTier Tier, claims TrialChecker) error {
	if claims != nil && claims.IsTrialActiveFor(feature) {
		return nil
	}
	return CheckFeature(registry, feature, currentTier)
}

// CheckFeature is preserved unchanged — every existing call site continues to
// work without modification. New code that has Claims should call
// CheckFeatureWithClaims directly.
func CheckFeature(registry *Registry, feature string, currentTier Tier) error {
	def, ok := registry.Lookup(feature)
	if !ok {
		return nil
	}
	if currentTier.Includes(def.RequiredTier) {
		return nil
	}
	return &GateError{
		Result: GateResult{
			Feature:        def.Name,
			RequiredTier:   def.RequiredTier,
			CurrentTier:    currentTier,
			Message:        def.Description,
			UpgradeURL:     UpgradeURL,
			TrialAvailable: true,
			RegisterURL:    RegisterURL,
			Workaround:     def.Workaround,
		},
	}
}
```

The `auth` package cannot import `internal/license` (would create a cycle: license → auth → license through cmd). The `TrialChecker` interface decouples them. `*license.Claims` is automatically a `TrialChecker` because it has `IsTrialActiveFor(string) bool`.

```go
package backend

import (
    "context"
    "errors"
    "fmt"
    "time"
)

// Sentinel errors for trial activation.
var (
    // ErrTrialAlreadyConsumed is returned when the backend's TRIAL_ALREADY_CONSUMED
    // problem code surfaces (HTTP 409). CLI exit code 5; the user has previously
    // used a trial of the requested feature.
    ErrTrialAlreadyConsumed = errors.New("backend: trial already consumed")
    // ErrTrialFeatureUnknown is returned for TRIAL_FEATURE_UNKNOWN (HTTP 404).
    // The feature slug is not registered.
    ErrTrialFeatureUnknown = errors.New("backend: trial feature unknown")
)

// trialCodeToSentinel routes problem codes returned by /api/v1/trials/{feature}.
var trialCodeToSentinel = map[string]error{
    "TRIAL_ALREADY_CONSUMED": ErrTrialAlreadyConsumed,
    "TRIAL_FEATURE_UNKNOWN":  ErrTrialFeatureUnknown,
}

// TrialActivation is the success-shape from POST /api/v1/trials/{feature}.
type TrialActivation struct {
    Feature   string    `json:"feature"`
    Kind      string    `json:"kind"`
    GrantedAt time.Time `json:"granted_at"`
    ExpiresAt time.Time `json:"expires_at"`
    Tokens    Tokens    `json:"tokens"`
}

// StartTrial calls POST /api/v1/trials/{feature}.
//
// On 200, returns the activation result with re-minted tokens.
// On 404 with TRIAL_FEATURE_UNKNOWN → ErrTrialFeatureUnknown.
// On 409 with TRIAL_ALREADY_CONSUMED → wrapped sentinel that also implements
// errors.As for *ProblemDetails so callers can inspect the previous_grant
// extension.
func (c *Client) StartTrial(ctx context.Context, feature, refreshToken, deviceID string) (TrialActivation, error) {
    body := map[string]string{
        "refresh_token": refreshToken,
        "device_id":     deviceID,
    }
    var out TrialActivation
    err := c.PostJSON(ctx, "/api/v1/trials/"+feature, "", body, &out)
    if err == nil {
        return out, nil
    }

    var pd *ProblemDetails
    if !errors.As(err, &pd) {
        return TrialActivation{}, err
    }
    if sentinel, ok := trialCodeToSentinel[pd.Code]; ok {
        return TrialActivation{}, &trialSentinelError{sentinel: sentinel, pd: pd}
    }
    return TrialActivation{}, err
}

// trialSentinelError mirrors refreshSentinelError — sentinel + ProblemDetails for errors.As.
type trialSentinelError struct {
    sentinel error
    pd       *ProblemDetails
}
func (e *trialSentinelError) Error() string { return fmt.Sprintf("%s: %s (%s)", e.sentinel, e.pd.Title, e.pd.Type) }
func (e *trialSentinelError) Unwrap() []error { return []error{e.sentinel, e.pd} }
```

```go
// licenseTrialCmdOut handles `apitest license trial <verb> [args]`.
// Currently only `start <feature>` is implemented.
func licenseTrialCmdOut(args []string, stdout, stderr io.Writer) int {
    if len(args) == 0 || args[0] == "--help" || args[0] == "-h" {
        printLicenseTrialHelpTo(stdout)
        return 0
    }
    switch args[0] {
    case "start":
        if len(args) < 2 {
            _, _ = fmt.Fprintln(stderr, "error: trial start requires <feature>")
            printLicenseTrialHelpTo(stdout)
            return 1
        }
        return licenseTrialStartOut(args[1], stdout, stderr)
    default:
        _, _ = fmt.Fprintf(stderr, "Unknown trial subcommand: %s\n", args[0])
        printLicenseTrialHelpTo(stdout)
        return 1
    }
}

// licenseTrialStartOut activates an on-demand trial of feature.
// Exit codes (mirrors --refresh taxonomy with one addition):
//   0 success
//   1 internal error
//   2 no cached refresh token
//   3 network failure
//   4 not used (refresh expired — call /auth/refresh first)
//   5 trial already consumed (or refresh-family revoked)
//   6 backend 5xx or feature unknown
//   7 device not registered
func licenseTrialStartOut(feature string, stdout, stderr io.Writer) int {
    cfgDir, err := licenseConfigDir()
    if err != nil { _, _ = fmt.Fprintln(stderr, err); return 1 }
    dev, err := device.Read(cfgDir)
    if err != nil {
        if errors.Is(err, device.ErrNotFound) {
            _, _ = fmt.Fprintln(stderr, "device not registered; run `apitest login`")
            return 7
        }
        _, _ = fmt.Fprintf(stderr, "read device.json: %v\n", err); return 1
    }
    storage, err := backend.NewStorage(backend.StorageOptions{ConfigDir: cfgDir, DeviceID: dev.DeviceID})
    if err != nil { _, _ = fmt.Fprintf(stderr, "init storage: %v\n", err); return 1 }
    rt, err := storage.GetRefreshToken()
    if err != nil {
        if errors.Is(err, backend.ErrTokenNotFound) {
            _, _ = fmt.Fprintln(stderr, "no cached refresh token; run `apitest login`")
            return 2
        }
        _, _ = fmt.Fprintf(stderr, "read refresh token: %v\n", err); return 1
    }
    backendURL := os.Getenv("APITEST_BACKEND_URL")
    if backendURL == "" { backendURL = "https://api.apitool.dev" }
    client, err := backend.NewClient(backend.Options{BaseURL: backendURL})
    if err != nil { _, _ = fmt.Fprintln(stderr, err); return 1 }

    activation, err := client.StartTrial(context.Background(), feature, rt, dev.DeviceID)
    if err != nil {
        return licenseTrialStartExitForError(err, feature, stderr)
    }

    // Persist the new tokens. RefreshToken via storage; License JWT via license.NewStore.
    if err := storage.SetRefreshToken(activation.Tokens.RefreshToken); err != nil {
        _, _ = fmt.Fprintf(stderr, "persist refresh token: %v\n", err); return 1
    }
    rec := &license.LicenseRecord{
        AccessToken:           activation.Tokens.LicenseJWT,
        Tier:                  tierFromLicenseJWT(activation.Tokens.LicenseJWT),
        LastValidatedAt:       time.Now().UTC(),
        LastValidationAttempt: time.Now().UTC(),
        ValidationFailures:    0,
    }
    if err := license.NewStore(cfgDir).Save(rec); err != nil {
        _, _ = fmt.Fprintf(stderr, "persist license.json: %v\n", err); return 1
    }
    _, _ = fmt.Fprintf(stdout, "Trial activated: %s (expires %s)\n",
        activation.Feature, activation.ExpiresAt.UTC().Format(time.RFC3339))
    return 0
}

func licenseTrialStartExitForError(err error, feature string, stderr io.Writer) int {
    switch {
    case errors.Is(err, backend.ErrTrialAlreadyConsumed):
        _, _ = fmt.Fprintf(stderr, "Trial already consumed for feature %s\n", feature)
        return 5
    case errors.Is(err, backend.ErrTrialFeatureUnknown):
        _, _ = fmt.Fprintf(stderr, "Unknown feature: %s\n", feature)
        return 6
    case errors.Is(err, backend.ErrNetworkFailure):
        _, _ = fmt.Fprintln(stderr, "trial activation failed, will retry next invocation")
        return 3
    case errors.Is(err, backend.ErrServerError):
        _, _ = fmt.Fprintln(stderr, "backend 5xx; try again later")
        return 6
    case errors.Is(err, backend.ErrRefreshExpired):
        _, _ = fmt.Fprintln(stderr, "refresh expired; run `apitest login`")
        return 4
    case errors.Is(err, backend.ErrRefreshReused):
        _, _ = fmt.Fprintln(stderr, "refresh family revoked; run `apitest login`")
        return 5
    case errors.Is(err, backend.ErrDeviceMismatch):
        _, _ = fmt.Fprintln(stderr, "device mismatch; run `apitest login`")
        return 7
    default:
        _, _ = fmt.Fprintf(stderr, "trial activation failed: %v\n", err)
        return 1
    }
}
```

## Risks and Edge Cases

- **Risk: brand-new user always returns 409.** A freshly-registered user has full-initial rows for every `TrialFeatures.All` slug, so on-demand activation always returns 409 with `previous_grant.kind = full_initial`. **Mitigation:** This is the documented spec behaviour (:5800-5816). Document the "must wait until full-initial expires" in the help text and the 409 detail message. The CLI's stderr message names the previous-grant date so the user can plan around it. Tests cover both cases (existing-row-blocks vs. row-deleted-permits) and the integration test pre-deletes the seeded row to exercise the Granted path.
- **Risk: refresh-token rotation under contention.** If the user runs `license trial start` while another `license --refresh` is in flight, the second `RefreshTokenService.RotateAsync` will see a reused token and return `Reused`. **Mitigation:** Acquire `refresh.lock` (the existing flock pattern in `internal/backend/lock.go`) around the StartTrial flow. The simplest path: have `licenseTrialStartOut` acquire the same flock before calling StartTrial. Alternative: skip the lock (acceptable because trial activation is interactive and not a hot path; if it loses the race, the user re-runs and the server has already updated the trial row, so the second call returns 409 — informationally consistent though slightly noisy). **Decision:** Skip the flock in this slice. The race window is brief (one HTTP round-trip) and the trial row will already exist on retry, so the 409 path correctly reports "already consumed" — which is true. We document this in the help text: "If you ran `apitest license --refresh` recently, wait a few seconds before trying again."
- **Edge case: empty feature slug.** `apitest license trial start ""` → `licenseTrialStartOut` should reject pre-flight rather than POST `/api/v1/trials/`. **Handling:** Add an early-return: if `feature == ""`, print error and exit 1.
- **Edge case: feature slug with URL-unsafe chars.** `apitest license trial start "vault profiles"` (with space). **Handling:** Pre-validate the slug client-side using `regexp.MustCompile(\`^[a-z0-9_]+$\`)`. Reject with exit 1 + clear message. The server also validates and returns 404 if it slips through.
- **Edge case: backend returns 200 with a different `feature` than requested.** Theoretically possible if the backend has a bug. **Handling:** The CLI trusts the response; any mismatch is logged but doesn't fail the command. The expires_at in stdout reflects whatever the backend said.
- **Edge case: `RefreshTokenService.RotateAsync` returns `DeviceMismatch`.** The endpoint maps this to a problem-detail with `AUTH_DEVICE_MISMATCH`. The CLI's `StartTrial` wrapper sees that code and returns `*ProblemDetails` (not a trial-specific sentinel). The `licenseTrialStartExitForError` handler routes through the existing `errors.Is(err, backend.ErrDeviceMismatch)` branch — but `StartTrial` doesn't currently translate AUTH_DEVICE_MISMATCH to `ErrDeviceMismatch`. **Mitigation:** Reuse `translateRefreshError` (already-exported helper from `refresh.go`) inside `StartTrial` so AUTH_REFRESH_* / AUTH_DEVICE_MISMATCH codes resolve to the same sentinels as `/auth/refresh`. This keeps exit-code semantics symmetric.
- **Risk: data integrity on race condition (two activations of same feature in flight).** The `UNIQUE(user_id, feature)` constraint guarantees only one row wins. The losing transaction's `DbUpdateException` is caught and re-read to return `AlreadyConsumed` with the winning row's grant time. Tested via Step 1 service-level test (manual race simulation: pre-insert + try to activate).
- **Edge case: license JWT does not include `trial_state` (legacy token from pre-M16-006 backend).** `Claims.TrialState` is `""`, `IsTrialActiveFor` returns false. Old behavior preserved.
