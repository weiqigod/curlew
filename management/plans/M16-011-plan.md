# Implementation Plan: M16-011

## Overview

Adds `curlew worker --schedule-pull` mode to the Go CLI, implementing the
self-hosted runner side of the M16 schedule-execution model: poll
`GET /api/v1/schedules/next-run`, resolve the `file:` collection ref locally,
execute it through the existing `runner.Run` engine, heartbeat every 30s, and
post the result to `POST /api/v1/schedules/runs/{run_id}/result`. On
unrecoverable post failure the result payload is queued under
`~/.config/curlew/pending-uploads/<run_id>.json` and drained on the next
successful poll cycle.

## Open Decisions Resolved

The task references several open decisions that were either already resolved
upstream or that this plan resolves explicitly to avoid blocking on tasks that
have not landed yet:

1. **Open Decision 4 — `git:` refs deferred.** The CLI rejects `git:` refs with
   a clear stderr message and posts a result with `fail_count = 1` and a
   single `error` item describing the rejection. The reject path lives on a
   small `ResolveCollection` function in `internal/worker/schedule/` so the
   future M-anything task that adds git resolution only edits one helper.

2. **`--all-modes` / `--perf-pull` cross-flag.** Spec section 6013-6015 lists
   `--perf-pull` and `--all-modes` as forward-looking. They do **not** exist in
   today's CLI — the current `curlew worker` flow is the M5/M11 distributed
   coordinator (`--job/--org`). Implementing both queues concurrently would
   force a breaking redesign of `cmd/curlew/worker.go`'s flag set and the
   existing `--job/--org` validation. **Out of scope for this slice.**
   `--schedule-pull` is mutually exclusive with the existing `--job` flag for
   M16; running both queues from one process is a separate task. The behaviour
   in the task YAML referencing `--all-modes` is documented as a future
   extension in the help text and recorded in the package doc comment.

3. **M16-018 (vault-config endpoint) not yet shipped.** The worker treats a
   `404` from `GET /api/v1/organizations/{orgId}/vault-config` as "vault
   enrichment unavailable" and proceeds with an empty `TeamTemplate`. The
   `ScheduleClient.FetchVaultConfig` call is wired so the M16-018 implementer
   only needs to flip behaviour for non-404 responses.

4. **Org id discovery for the vault-config endpoint.** The worker does not yet
   know its `org_id`. The Access token is org-bound (per spec line 6017), so
   on first claim the worker reads `schedule_id`/`run_id` from the response;
   the endpoint URL is built lazily once an org id surfaces. For this slice
   the vault-config call is **deferred entirely** (treated as an unimplemented
   M16-018 dependency) and the runner is invoked without `TeamTemplate`. A
   `// TODO(M16-018):` comment marks the integration point.

5. **Smoke script path.** The task observable says `scripts/smoke.sh`; the
   actual file is `smoke/run.sh`. The plan uses the real path.

6. **Stdout vs. stderr discipline.** The observable specifies `claimed run …`
   and `posted result for …` on **stdout**. We honour that contract: those two
   lines are routed to stdout; warnings, retry chatter, and pending-upload
   messages go to stderr.

The steps are ordered smallest-blast-radius first: pure types and helpers

```go
    "context"
    "errors"
    "net/http"

    "github.com/weiqigod/curlew/internal/backend"
)

// HTTPClient is the subset of backend.Client used by Client. Exposed as an
// interface for test stubbing without a live HTTP server.
type HTTPClient interface {
    GetJSON(ctx context.Context, path, accessToken string, out any) error
    PostJSON(ctx context.Context, path, accessToken string, body, out any) error
}

// Client is the schedule-executor endpoint wrapper.
type Client struct {
    HTTP        HTTPClient
    AccessToken string
}

// PollNextRun calls GET /api/v1/schedules/next-run. Returns ErrNoRunAvailable
// on HTTP 204.
func (c *Client) PollNextRun(ctx context.Context) (*NextRunResponse, error)

// Heartbeat calls POST /api/v1/schedules/runs/{runID}/heartbeat. Maps 409
// (problem+json type=claim-reaped|stale-claim) to ErrClaimReaped.
func (c *Client) Heartbeat(ctx context.Context, runID, claimToken string) error

// PostResult calls POST /api/v1/schedules/runs/{runID}/result. Maps 409
// (already-completed) to ErrAlreadyCompleted; maps transport errors to
// backend.ErrNetworkFailure (so the caller can decide to retry / queue).
func (c *Client) PostResult(ctx context.Context, runID string, body *ResultRequest) error
```

#### Detail: 204 handling

`backend.Client.GetJSON` does not currently distinguish 204 from "decoding a
2xx body" — it tries to decode. For 204 the decode of an empty body into a
struct will fail. We add a thin wrapper that issues a raw `http.Request` via
the existing `*backend.Client` is **not** trivial because `backend.Client`'s
internals are unexported. **Resolution:** add a single new exported method
`backend.Client.GetJSONOptional(ctx, path, accessToken, out any) (found bool, err error)`
that returns `(false, nil)` on HTTP 204 and behaves identically to `GetJSON`
otherwise. This is a minimal, additive change to the existing client and is
covered by a dedicated test.

```go
package schedule

import (
    "context"
    "io"
    "time"

    "github.com/weiqigod/curlew/internal/runner"
)

// CollectionExecutor produces the schedule-result payload for a resolved
// collection path. The default implementation parses the YAML and invokes
// runner.Run; tests inject a stub.
type CollectionExecutor interface {
    Execute(ctx context.Context, collectionPath string, envVars map[string]string) (*ExecutionOutcome, error)
}

// ExecutionOutcome is what we map onto ResultRequest. Captured in our own
// type so the schedule package does not leak runner.Summary upward.
type ExecutionOutcome struct {
    CollectionName string
    StartedAt      time.Time
    DurationMs     int64
    PassCount      int
    FailCount      int
    SkippedCount   int
    Items          []ResultItem
}

// Runner is the schedule-pull orchestration loop.
type Runner struct {
    Client            *Client
    Queue             *Queue
    Executor          CollectionExecutor
    PollInterval      time.Duration // default 30s
    HeartbeatInterval time.Duration // default 30s
    PostMaxElapsed    time.Duration // default 1h (exp backoff cap)
    WorkingDir        string        // default os.Getwd()
    Stdout            io.Writer     // observable status lines: "claimed run …", "posted result for …"
    Stderr            io.Writer     // warnings + retry chatter
    Now               func() time.Time // injectable clock (default time.Now)
    Sleep             func(context.Context, time.Duration) error // injectable (default time.After + ctx)
}

// Run polls forever (until ctx cancellation). On each cycle it drains queued
// pending uploads first, then attempts a fresh claim.
func (r *Runner) Run(ctx context.Context) error

// RunOnce performs one drain + one claim cycle. Returns nil when no run was
// available and the queue was empty; returns the post error (if any) after a
// successful claim.
func (r *Runner) RunOnce(ctx context.Context) error
```

#### Loop Pseudocode

```
for {
    // 1. Drain pending-uploads queue first.
    for each Pending in q.List():
        err := client.PostResult(ctx, p.RunID, p.Payload)
        if err == nil { q.Remove(p.RunID); log "drained queued result for <run_id>" }
        else if errors.Is(err, backend.ErrNetworkFailure) { break } // still down — give up draining this cycle
        else if errors.Is(err, ErrAlreadyCompleted) { q.Remove(p.RunID) } // server already accepted somehow
        else { warn and leave on disk }

    // 2. Poll for a new run.
    next, err := client.PollNextRun(ctx)
    if errors.Is(err, ErrNoRunAvailable) { sleep(pollInterval); continue }
    if errors.Is(err, backend.ErrNetworkFailure) { warn; sleep(pollInterval); continue }
    if err != nil { return err } // unauthorized / 5xx after retry → fatal

    // 3. Resolve collection ref.
    fmt.Fprintf(stdout, "claimed run %s; executing collection %s\n", next.RunID, next.CollectionRef)
    started := now()
    var outcome *ExecutionOutcome
    path, resolveErr := ResolveCollection(next.CollectionRef, workingDir)
    if errors.Is(resolveErr, ErrUnsupportedCollectionRef) {
        fmt.Fprintf(stderr, "git: collection refs are not yet supported in M16; …\n")
        outcome = &ExecutionOutcome{StartedAt: started, FailCount: 1, Items: []ResultItem{{Name: "collection_ref", Status: "error", Message: resolveErr.Error()}}}
    } else if resolveErr != nil {
        outcome = &ExecutionOutcome{StartedAt: started, FailCount: 1, Items: []ResultItem{{Name: "resolve", Status: "error", Message: resolveErr.Error()}}}
    } else {
        // 4. Start heartbeater bounded to executor lifetime.
        hctx, hcancel := context.WithCancel(ctx)
        go heartbeatLoop(hctx, client, next.RunID, next.ClaimToken, hbInterval, stderr, abandonCh)

        outcome, runErr := executor.Execute(ctx, path, next.EnvVars)
        hcancel()
        if abandonCh signalled { /* skip post entirely — claim was reaped */ continue }
        if runErr != nil { /* still POST a fail result with runErr message — runs that crash count as a failed schedule run */ }
    }

    // 5. Build ResultRequest and POST with retry.
    payload := buildResultRequest(next.ClaimToken, outcome)
    postErr := postWithRetry(ctx, client, next.RunID, payload, postMaxElapsed)
    if errors.Is(postErr, ErrAlreadyCompleted) { /* nothing to do, server has it */ }
    if postErr != nil && errors.Is(postErr, backend.ErrNetworkFailure) {
        path, qErr := q.Enqueue(next.RunID, payload)
        fmt.Fprintln(stderr, "backend unreachable; queued result locally")
        // do not return; loop continues
    } else if postErr != nil {
        warn and continue
    } else {
        fmt.Fprintf(stdout, "posted result for %s (pass=%d, fail=%d)\n", next.RunID, payload.PassCount, payload.FailCount)
    }
}
```

#### Heartbeat ↔ abandon channel

`heartbeatLoop` sends on `abandonCh` exactly once when `Heartbeat` returns
`ErrClaimReaped`, then returns. The orchestrator selects on it after
`Execute` returns; if signalled, it skips the result POST per the
behavior: "on 409 (claim reaped) it abandons the run cleanly without
posting."

```go
package schedule

import (
    "context"
    "time"

    "github.com/weiqigod/curlew/internal/auth"
    "github.com/weiqigod/curlew/internal/httpexec"
    "github.com/weiqigod/curlew/internal/parser"
    "github.com/weiqigod/curlew/internal/runner"
)

// NewRunnerExecutor returns a CollectionExecutor that parses the YAML at
// collectionPath and executes it via runner.Run.
func NewRunnerExecutor(tier auth.Tier) CollectionExecutor

type runnerExecutor struct {
    tier auth.Tier
}

func (e *runnerExecutor) Execute(ctx context.Context, collectionPath string, envVars map[string]string) (*ExecutionOutcome, error) {
    started := time.Now().UTC()
    col, err := parser.ParseFileWithOptions(collectionPath, parser.ParseOptions{
        IncludeGate: includeGateFor(e.tier),
        SchemaGate:  schemaGateFor(e.tier),
    })
    if err != nil { return nil, fmt.Errorf("parse %s: %w", collectionPath, err) }

    results, summary, runErr := runner.Run(ctx, col, httpexec.Execute, runner.VarSources{
        EnvVar:        envVars,
        Tier:          e.tier,
        ProjectRoot:   filepath.Dir(collectionPath),
        CollectionDir: filepath.Dir(collectionPath),
        // TODO(M16-018): plumb TeamTemplate from /vault-config endpoint.
    })
    if runErr != nil { return nil, runErr }

    return mapOutcome(col.Name, started, results, summary), nil
}
```

#### Mapping `runner` → `ExecutionOutcome`

```go
func mapOutcome(collectionName string, started time.Time, results []runner.RequestResult, sum *runner.Summary) *ExecutionOutcome {
    items := make([]ResultItem, 0, len(results))
    for _, r := range results {
        status := "pass"
        msg := ""
        if r.Skipped { status = "error"; msg = r.SkipReason }
        else if r.Err != nil { status = "error"; msg = r.Err.Error() }
        else if r.AssertionResults != nil && r.AssertionResults.Failed > 0 { status = "fail"; msg = r.AssertionResults.FirstFailureMessage() }
        items = append(items, ResultItem{
            Name:       r.Name,
            Status:     status,
            DurationMs: r.Result.DurationMs(), // or computed similarly
            Message:    msg,
        })
    }
    return &ExecutionOutcome{
        CollectionName: collectionName,
```

```go
type workerSchedulePullCfg struct {
    enabled      bool
    backendURL   string        // --backend (or CURLEW_BACKEND_URL); defaults to https://api.apitool.dev
    accessToken  string        // resolved from license.NewStore(cfgDir).Load().AccessToken
    pollInterval time.Duration // --poll-interval, default 30s
    once         bool          // --once: run RunOnce and exit (used by smoke + tests)
    workingDir   string
}

func workerCmdOut(args []string, stdout, stderr io.Writer) int {
    cfg, schedCfg, showHelp, err := parseWorkerArgs(args)
    if showHelp { printWorkerHelpTo(stdout); return 0 }
    if err != nil { /* same as today */ }

    if schedCfg.enabled {
        return runSchedulePull(args, schedCfg, stdout, stderr)
    }
    // ... existing M11 path unchanged ...
}

func runSchedulePull(args []string, sc workerSchedulePullCfg, stdout, stderr io.Writer) int {
    if sc.accessToken == "" {
        fmt.Fprintln(stderr, "error: not logged in (run `curlew login` first)")
        return 10
    }
    ctx, cancel := signal.NotifyContext(context.Background(), os.Interrupt)
    defer cancel()
    bc, err := backend.NewClient(backend.Options{BaseURL: sc.backendURL})
    if err != nil { fmt.Fprintf(stderr, "error: %v\n", err); return 1 }
    runner := &schedule.Runner{
        Client:       &schedule.Client{HTTP: bc, AccessToken: sc.accessToken},
        Queue:        &schedule.Queue{}, // default dir
        Executor:     schedule.NewRunnerExecutor(currentTier()),
        PollInterval: sc.pollInterval,
        WorkingDir:   sc.workingDir,
        Stdout:       stdout,
        Stderr:       stderr,
    }
    if sc.once {
        if err := runner.RunOnce(ctx); err != nil { fmt.Fprintf(stderr, "error: %v\n", err); return 1 }
        return 0
    }
    if err := runner.Run(ctx); err != nil && !errors.Is(err, context.Canceled) {
        // map ErrUnauthorized / ErrNetworkExhausted as the M11 path does
        return 1
    }
    return 0
}
```

## Risks and Edge Cases

- **Risk:** Worker token discovery diverges from CLI conventions. **Mitigation:**
  Reuse `license.NewStore(cfgDir).Load().AccessToken` exactly as `curlew license`
  does today. The token is the same License JWT; if a deployment uses
  `CURLEW_BACKEND_TOKEN` for the M11 worker, we honour it as a fallback when
  `license.json` is absent.

- **Risk:** Backend is unreachable for the entire poll cycle (no claim, no
  drain). **Mitigation:** Each call is wrapped with `backend.ErrNetworkFailure`
  detection; the cycle warns once on stderr and sleeps the poll interval.
  Drain failure does not block claim (different endpoints can be reachable in
  partial-outage scenarios).

- **Risk:** Result POST partial success — the server writes the result row
  but the network drops on the way back. **Mitigation:** the M16-010
  atomicity guard treats a re-POST of the same `run_id` as `ErrAlreadyCompleted`.
  Our worker treats that as success (removes from queue); no double-counting
  of pass/fail.

- **Risk:** Heartbeat goroutine leak on early ctx cancellation. **Mitigation:**
  `hcancel()` is called before each `continue`/`return` of the loop body
  (matching the M11 `worker.Run` pattern).

- **Risk:** Pending-uploads queue grows unbounded if backend is down for
  weeks. **Mitigation:** Out of scope for this slice; the queue is one
  payload per `run_id` and `scheduled_runs` reaping limits how many fresh
  runs accumulate. Add a `// TODO(M17):` comment for size capping if it
  becomes an operational concern.

- **Edge case:** `collection_ref = "file:./testdata/api.yaml"` resolved against
  the working directory. **Handling:** strip `file:` prefix, then
  `filepath.Join(workingDir, ref)` if not absolute; reject paths that escape
  via `..` only when an explicit allowlist surfaces (out of scope for M16 —
  the worker host is trusted infrastructure).

- **Edge case:** Heartbeat fires while POST is in-flight after `Execute`
  returned. **Handling:** `hcancel()` is invoked before `PostResult` so no
  heartbeat races with the final POST; the server already accepts a result
  with no preceding heartbeat in the 30-second window.

- **Edge case:** Empty `EnvVars` on the next-run response. **Handling:**
  `runner.VarSources.EnvVar` accepts nil maps; pass through unchanged.

- **Edge case:** Worker started in a directory that does not contain the
  YAML referenced by a queued schedule. **Handling:** parser returns a
  descriptive error → mapped to a single `error` item in the result; the
  schedule run is recorded as failed, the operator sees it on the dashboard
  and updates the worker's working directory.
