# Implementation Plan: M12-003

## Overview

Add two more argument-bearing dynamic helpers to the registry:
`{{$urlEncode(s)}}` (a thin wrapper over `net/url.QueryEscape`) and
`{{$jsonEncode(s)}}` (a thin wrapper over `encoding/json.Marshal` of
the input string, including the surrounding double quotes). Both
plug into the M12-001 argument-parsing wiring and reuse the
`oneArg` helper introduced by M12-002 — the slice is two new
registrations, table-driven tests, and one manual-edit row.

## Architectural Decisions

The exploration of `internal/variable/dynamic.go` (post-M12-002),
`internal/variable/dynamic_test.go`, `docs/MANUAL.md` §3.7, and
the M12-002 plan/verified docs surfaces six design choices worth
recording up front. Each is the lowest-risk option that satisfies
the behaviors and reuses the M12-001/M12-002 wiring without
modification.

1. **Use `net/url.QueryEscape` — not `PathEscape`.** The first
   behavior pins the contract verbatim: spaces → `+`, `&` → `%26`,
   `/` → `%2F`. That is exactly `QueryEscape`'s output.
   `PathEscape` instead emits `%20` for space and leaves `/` alone —
   wrong for query strings, which is the entire motivating use
   case (`?q={{$urlEncode('hello world & co')}}`). The scope block
   in `M12-003.yaml` is explicit ("Not in scope: $pathEncode") so
   we register only the query-component encoder. If a real test
   later needs path-segment encoding, it lands as a sibling helper.

2. **Use `encoding/json.Marshal(s)` — not a hand-rolled escape
   loop.** `json.Marshal` of a Go `string` returns the canonical
   RFC 8259 JSON-string serialisation, including the surrounding
   `"…"`. Hand-rolling the escapes (replace `\`, `"`, control
   chars) would re-implement what the standard library already
   gets right, drift from it on edge cases (Unicode `U+2028`,
   `U+2029`, surrogate halves, control bytes), and require its
   own test surface. `json.Marshal` of a string never errors in
   practice — it returns `(nil, error)` only for non-encodable
   types, never for a `string` — so we deliberately discard the
   error in the helper (commented in the code). The cost is one
   `[]byte → string` conversion per call, which is unmeasurable
   at request-rendering rates.

3. **`$jsonEncode` returns the value WITH the surrounding double
   quotes.** Behavior 2 is unambiguous: `$jsonEncode('he said
   "hi"')` → the literal 14-char string `"he said \"hi\""`. The
   scope text says it explicitly: "The output includes the
   surrounding double quotes so the result is a valid JSON string
   literal that can be inlined into a JSON body without further
   escaping." A user template like `body: '{"name": {{$jsonEncode(
   '{{name}}')}}}'` therefore Just Works without manual quote
   wrangling. This is the whole point of the helper.

4. **Reuse `oneArg(funcName, fn)` from M12-002 unchanged.** Both
   new helpers take exactly one string, ignore the RNG, and are
   pure deterministic transformations — the same shape `oneArg`
   was designed for. No new helper or refactor is needed.
   `$urlEncode` returns `(string, nil)` and `$jsonEncode` returns
   `(string, nil)` — neither has a runtime failure mode that needs
   a structured `apierrors.Structured`. (Arity errors are still
   surfaced through `oneArg`'s `arityError` wrapper; that path is
   already covered by M12-002 tests but is re-exercised here for
   the two new function names.)

5. **No new sentinel error code.** M12-002 introduced
   `DYNFN_BASE64_DECODE` because base64 decoding has a real,
   user-visible failure mode (corrupt input). `url.QueryEscape`
   and `json.Marshal(string)` cannot fail at runtime with any
   input a user can construct from a YAML string literal.
   Introducing a placeholder code "just in case" would be a code
   smell — we add it when a real failure path appears.

6. **Bump the `Available()` count assertion from 17 to 19 in the
   same patch.** `dynamic_test.go:296` (`if len(avail) != 17`)
   has been updated in every M12 task; M12-003 follows that
   pattern, keeping the build green between RED and GREEN cycles.
   This is the deliberate signal that the registry has grown by
   exactly the expected amount — not a smell.

```go
// internal/variable/dynamic_test.go

func TestRegistry_UrlEncode(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name  string
        input string
        want  string
    }{
        // Behaviors 1 + observable: spaces → '+', '&' → '%26',
        // '/' → '%2F', UTF-8 percent-encoded.
        {"hello world", "hello world", "hello+world"},
        {"hello world & co", "hello world & co", "hello+world+%26+co"},
        {"slashes encoded", "a/b", "a%2Fb"},
        {"ampersand encoded", "a&b", "a%26b"},
        {"empty string", "", ""},
        {"unicode multibyte", "héllo", "h%C3%A9llo"},
        {"plus stays encoded", "a+b", "a%2Bb"},
        {"already-encoded value re-encoded", "a%20b", "a%2520b"},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := reg.Evaluate("urlEncode", []string{tt.input}, make(map[string]string))
            if err != nil {
                t.Fatalf("Evaluate(urlEncode, %q) unexpected error: %v", tt.input, err)
            }
            if got != tt.want {
                t.Errorf("urlEncode(%q) = %q, want %q", tt.input, got, tt.want)
            }
        })
    }
}

func TestRegistry_UrlEncode_NestedVar(t *testing.T) {
    seed := int64(1)
    reg := NewRegistry(&seed)
    s := NewScope(map[string]string{"query": "a b"})
    if err := s.Resolve(); err != nil {
        t.Fatalf("Resolve: %v", err)
    }
    s = s.WithDynamic(reg)
    s.BeginRequest()
    defer s.EndRequest()

    got, err := s.Interpolate(`{{$urlEncode('{{query}}')}}`)
    if err != nil {
        t.Fatalf("Interpolate: %v", err)
    }
    const want = "a+b"
    if got != want {
        t.Errorf("got %q, want %q", got, want)
    }
}

func TestRegistry_JsonEncode(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name  string
        input string
        want  string
    }{
        // Behavior 2: surrounding double quotes included.
        {"plain ascii", "hello", `"hello"`},
        // Behavior 7: empty input → literal three chars `""`.
        {"empty string", "", `""`},
        // Behavior 3: quote and backslash escaped per RFC 8259.
        {"contains quote", `he said "hi"`, `"he said \"hi\""`},
        {"contains backslash", `a\b`, `"a\\b"`},
        // Behavior 4: literal newline byte → \n in output, valid JSON.
        {"contains newline", "line1\nline2", `"line1\nline2"`},
        {"contains tab", "a\tb", `"a\tb"`},
        {"contains carriage return", "a\rb", `"a\rb"`},
        // Unicode round-trip.
        {"unicode multibyte", "héllo", `"héllo"`},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := reg.Evaluate("jsonEncode", []string{tt.input}, make(map[string]string))
            if err != nil {
                t.Fatalf("Evaluate(jsonEncode, %q) unexpected error: %v", tt.input, err)
            }
            if got != tt.want {
                t.Errorf("jsonEncode(%q) = %q, want %q", tt.input, got, tt.want)
            }
            // Sanity check: the result must itself be valid JSON
            // that round-trips back to the original input.
            var rt string
            if err := json.Unmarshal([]byte(got), &rt); err != nil {
                t.Errorf("jsonEncode(%q) result %q is not valid JSON: %v", tt.input, got, err)
            }
            if rt != tt.input {
                t.Errorf("jsonEncode(%q) round-trip = %q, want %q", tt.input, rt, tt.input)
            }
        })
    }
}

func TestRegistry_UrlJsonEncode_arity_errors(t *testing.T) {
    reg := NewRegistry(nil)

    tests := []struct {
        name     string
        funcName string
        args     []string
    }{
        {"urlEncode zero args", "urlEncode", nil},
        {"urlEncode two args", "urlEncode", []string{"a", "b"}},
        {"jsonEncode zero args", "jsonEncode", nil},
        {"jsonEncode two args", "jsonEncode", []string{"a", "b"}},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            _, err := reg.Evaluate(tt.funcName, tt.args, nil)
            if err == nil {
                t.Fatal("expected arity error, got nil")
            }
            var se *apierrors.Structured
            if !errors.As(err, &se) {
                t.Fatalf("expected *apierrors.Structured, got %T", err)
            }
            if se.Code != "DYNFN_ARITY" {
                t.Errorf("Code = %q, want DYNFN_ARITY", se.Code)
            }
            wantArity := fmt.Sprintf("expected 1 arguments, got %d", len(tt.args))
            if !strings.Contains(se.Message, wantArity) {
                t.Errorf("message %q should mention %q", se.Message, wantArity)
            }
            // The full err.Error() should name the function exactly once.
            if got := strings.Count(err.Error(), "$"+tt.funcName); got != 1 {
                t.Errorf("err.Error() should name $%s exactly once, got %d: %q", tt.funcName, got, err.Error())
            }
        })
    }
}
```

## Risks and Edge Cases

- **Risk:** A user expects `$urlEncode` to encode for path segments
  (i.e. `%20` for space, leave `/` alone). → **Mitigation:** The
  manual entry calls out "query-component" explicitly and
  documents the `+`-for-space convention. The function name (and
  the `net/url.QueryEscape` mapping) are intentional. A future
  `$pathEncode` is out of scope but tracked in the M12-003 YAML
  scope ("Not in scope: $pathEncode … revisit if a real test
  exposes the need.").
- **Risk:** A user inlines `$jsonEncode` inside an already-quoted
  JSON string and gets doubled quotes (e.g.,
  `"{"name":"{{$jsonEncode('a')}}"}"` → `"{"name":""a""}"`). →
  **Mitigation:** The manual entry shows the correct usage (no
  outer quotes around the helper). The doubled-quote failure is
  surfaceable to the user as soon as they `--dry-run --format
  json`, so the feedback loop is short. We do not try to detect
  this server-side.
- **Risk:** `json.Marshal` on a Go string with invalid UTF-8 bytes
  silently replaces them with `U+FFFD` — a behaviour that differs
  from a strict round-trip. → **Mitigation:** Out of scope for
  M12 (variables are already resolved to UTF-8 strings before
  reaching the helper); the `TestRegistry_JsonEncode` round-trip
  asserts on valid UTF-8 inputs only. If a user passes invalid
  UTF-8 via a YAML literal, the file would not parse in the first
  place.
- **Risk:** Future helper needs the RNG (e.g., a salted hash). →
  **Mitigation:** Already addressed by the M12-002 plan — add a
  sibling `oneArgRNG` rather than re-shape `oneArg`. M12-003 does
  not need it.
- **Edge case:** Empty string `{{$urlEncode('')}}`. →
  **Handling:** `url.QueryEscape("")` returns `""` — asserted in
  the test table.
- **Edge case:** Empty string `{{$jsonEncode('')}}`. →
  **Handling:** `json.Marshal("")` returns `[]byte{'"', '"'}` —
  the literal three-char string `""` per behavior 7 — asserted
  in the test table.
- **Edge case:** A literal `+` in the input to `$urlEncode`. →
  **Handling:** `url.QueryEscape` encodes `+` → `%2B` (so it
  cannot be confused with the space-as-`+` convention on the
  decode side) — asserted in the test table.
- **Edge case:** A literal newline byte to `$jsonEncode`. →
  **Handling:** `json.Marshal` escapes to `\n` and the result is
  valid JSON — asserted in the test table and verified via
  `json.Unmarshal` round-trip.
- **Edge case:** Nested template `{{$urlEncode('{{query}}')}}` with
  `query='a b'`. → **Handling:** Behavior 6 — covered by
  `TestRegistry_UrlEncode_NestedVar`, mirroring the M12-002
  `TestRegistry_Base64_NestedVar` pattern.
- **Edge case:** `nil` cache. → **Handling:** Already handled by
  `Evaluate` (M12-001 line 96-100 `if cache != nil`); the new
  helpers inherit that behaviour because they go through
  `Evaluate`. No new test needed — exercised in the arity test
  (which passes `nil` cache).
