# Implementation Plan: M16-006

## Overview

Wires the `trials` table (M16-005) into the License JWT pipeline. Introduces `ITrialStateResolver` + `DatabaseTrialStateResolver` (computes `(trial_state, trial_expiry, trialing_features)` from `trials` rows + active subscription), injects it into `LicenseTokenIssuer` so the JWT replaces the M14 hardcoded `"none"`/`null` defaults, seeds one `kind = full_initial` row per gated feature whenever a brand-new user appears, and adds preemption logic to the `customer.subscription.created` webhook handler so checkout success transitions live trial rows to `kind = preempted_by_subscription`.

## Architectural Decisions

1. **Registration concept = User row creation.** The backend has no public `/auth/register` endpoint (closed/observed). Brand-new users appear via three paths today: (a) `CurrentUserAccessor.ResolveAsync` (first authenticated request upserts the row), (b) `Bootstrap/AdminBootstrap.RunAsync` (first-boot admin), (c) `InternalRefreshSeedEndpoint` (Dev/Testing only). All three paths must seed the per-feature `full_initial` rows to satisfy behavior #7. Resolution: introduce a `TrialSeederService` with one method `SeedFullInitialAsync(Guid userId, DateTime grantedAt, CancellationToken ct)` and call it from each of the three paths. SeederService is idempotent — `SELECT 1 FROM trials WHERE user_id = ?` short-circuits if any row exists, so re-invocations on existing users are a noop. (Decision rationale: a hosted background scanner would race the first License JWT issuance and is harder to test deterministically.)
2. **Gated-feature catalogue.** The spec narrative names individual feature slugs (`vault_provider_profiles`, `shared_vault_templates`, `schedules`, etc.) but the codebase has no central catalogue. The closest existing list is `Licensing/Tokens/TierConfig.cs`, but that is a **tier-features** map (capability-per-tier), not a **trial-features** list. They are different concepts: `unlimited_requests` is a billing capability, not a trialable feature. Resolution: add a new constant `TrialFeatures` in `Licensing/Trials/TrialFeatures.cs` with the spec-named per-feature slugs. Initial set (per spec narrative `:5777`, `:5787`, `:5827`, `:5860`, plus the v3-11 closure `:5691`): `["vault_provider_profiles", "shared_vault_templates", "schedules", "dashboards", "custom_roles", "audit_log", "sso", "ai_agents"]`. This list is the **catalogue of trialable features** — the universe of (`user_id`, `feature`) full-initial rows seeded at registration. (Open Decision A — see end of document — addresses adding/removing slugs later.)
3. **`ITrialStateResolver` returns a record, not a tuple.** The result is consumed at exactly one call site today (`LicenseTokenIssuer.IssueAsync`) but the M16-007 trials endpoint will also re-mint via the same input shape, so a named return is more durable than a tuple. Define `TrialStateResult(string TrialState, long? TrialExpiryUnixSeconds, IReadOnlyList<string> TrialingFeatures)`. The third field is the union of feature slugs whose rows are active+unconsumed, used by `LicenseTokenIssuer` to widen the `features[]` claim per spec `:5817` ("the issuer adds trialing features to features[] for the trial duration").
4. **Resolver inputs.** `ResolveAsync(Guid userId, string tier, CancellationToken ct)`. The `tier` argument is required because the spec table row "Active subscription (Solo+) → trial_state = none" overrides any active trial state. Passing `tier` keeps the resolver pure (no DB call to `subscriptions`); the caller (`AuthRefreshEndpoints.MintAndRespondAsync`) already resolves tier via `ResolveUserContextAsync` so reusing it avoids a redundant query. Tier values that mean "subscribed" per the spec are anything other than `"free"` (i.e., `professional|team|enterprise`; v4.3 introduces `solo` but that ship hasn't sailed in this codebase yet, and the comparison `tier != "free"` is forward-compatible).
5. **Resolver query shape.** Single `db.Trials.Where(t => t.UserId == userId && t.ConsumedAt == null && t.ExpiresAt > now)` materialises into a small list (`<= |TrialFeatures|` rows). Compute the four cases in-memory:
   - **No rows at all** (no `full_initial` ever seeded — should be unreachable post-seeder, but defensive): `(none, null, [])`. This matches spec row 1 (anonymous) and is the only safe default.
   - **All rows kind = `full_initial` and within the 14-day window**: `(active, min(expires_at), distinct features)`. Matches spec row 2.
   - **No active rows** but `db.Trials.AnyAsync(t => t.UserId == userId)` is true: `(expired, null, [])`. Matches spec row 3 + 5 + 6 (all three "registered, no live trial" cases collapse to one outcome).
   - **At least one active `OnDemand` row** (with or without expired full-initial rows): `(active, min(expires_at across all active), distinct features)`. Matches spec row 4.
   - **Tier-upgrade override**: if `tier != "free"`, return `(none, null, [])` regardless of trial rows. Matches spec rows 5 + 7. The preemption webhook ensures live rows transition to `preempted_by_subscription` (which fails the `ConsumedAt == null` filter via the `expires_at = now()` write — see Decision 8), so this override is belt-and-suspenders.
6. **Why `min(expires_at)` and not aggregate by kind.** Behavior #2 asks for "soonest expires_at" when within the 14-day window; behavior #4 asks for "earliest expires_at across active on-demand rows" when full-initial has expired but on-demand is active. Both reduce to "minimum expires_at across all active rows" because the rows in the active set are exactly the rows that satisfy the filter. The single-min computation is correct for both cases.
7. **`LicenseTokenIssuer` constructor adds `ITrialStateResolver` (no `LicenseTokenInput` shape change).** The cleanest place to consult the resolver is the issuer itself, not the call site. Adding `resolver` to the issuer constructor means the call sites (`AuthRefreshEndpoints` and the M16-007 trials endpoint) don't change — they pass the same `LicenseTokenInput` and the issuer transparently calls the resolver. This decouples mint sites from trial logic. The resolver result mutates two payload fields (`trial_state`, `trial_expiry`) and unions `TrialingFeatures` into `Features` before serialisation.
8. **Preemption SQL uses `kind = preempted_by_subscription` AND `expires_at = now()`.** Per spec narrative `:5851` and DDL appendix `:11030`. The handler updates rows where `user_id = $1 AND consumed_at IS NULL AND expires_at > NOW() AND kind != 'preempted_by_subscription'` to `kind = 'preempted_by_subscription', expires_at = NOW(), updated_at = NOW()`. Note the DDL appendix mentions `consumed_at IS NULL` but does NOT set `consumed_at` on the preemption write — that column is reserved for explicit consumption in M16-007. The post-write `expires_at <= now` check causes the resolver's filter `t.ExpiresAt > now` to skip these rows. (Setting `consumed_at` would also work but conflicts with the M16-007 design where `consumed_at` marks user-initiated consumption — keep separate for auditability.)
9. **Preemption is keyed by `customer_id → user_id`, not by `subscription_id`.** The `customer.subscription.created` event delivers a `subscription_id`. The handler re-fetches the subscription from Stripe (already done — line `:31`), reads `stripeSub.CustomerId`, looks up the local `Subscription` row by `StripeCustomerId`, then walks the org membership table to find the **owner** user(s). The trials table is keyed per **user** so we must update only the rows for the user whose Stripe checkout this represents. In the v4 model only the org owner can upgrade (per the AdminBootstrap pattern + Stripe checkout flow), so "preempt the owner of the org" is the correct scope. (Multi-user orgs with shared subscriptions: each member retains their own trial table; only the owner upgrades. Other members' trials are unaffected — this is by design, not a bug. Documented in Open Decision B.)
10. **Extend `StripeSubscriptionHandler.HandleCreatedOrUpdatedAsync`, do not add a new handler.** Adding a `TrialPreemptionHandler` would duplicate the re-fetch path and the dispatcher routing. Inlining the preemption write at the bottom of the existing handler keeps the spec-mandated single-fetch invariant (`:6845-6848`). One new helper `PreemptOwnerTrialsAsync(Guid orgId, DateTime now, CancellationToken ct)` is called only when the event type is `customer.subscription.created` AND the post-update tier is non-free. (`customer.subscription.updated` should NOT preempt — only the initial transition does, otherwise every webhook delivery would be a redundant write.)
11. **Dispatching: pass `event.Type` through.** The current handler signature is `HandleCreatedOrUpdatedAsync(string subscriptionId, ...)` and the dispatcher routes both `created` and `updated` to the same method. To preempt only on `created`, change the signature to `HandleCreatedOrUpdatedAsync(string subscriptionId, bool isCreated, CancellationToken ct)`. The dispatcher passes `true` for `Events.CustomerSubscriptionCreated` and `false` for `Events.CustomerSubscriptionUpdated`. Single new boolean parameter; no return-type change. (Alternative: split into two methods. Single method + flag is simpler given the >95% shared body.)
12. **Trial seeder runs as a side-effect of user creation, in the same transaction where possible.** For `AdminBootstrap.RunAsync` (already in a transaction): add seeder call before `tx.CommitAsync`. For `CurrentUserAccessor.ResolveAsync` (no transaction): seeder call after the user `SaveChangesAsync` succeeds, swallowing race-condition `DbUpdateException` the same way the user upsert does. For `InternalRefreshSeedEndpoint` (no transaction): seeder call after the user `SaveChangesAsync`. Idempotent guard (Decision 1) makes the non-transactional paths safe even if two concurrent requests both think they created the user.
13. **`granted_at` vs registration_at.** The observable says "`granted_at = registration_at`". Since "registration_at" maps to `User.CreatedAt`, the seeder must read or accept the user's `CreatedAt` and apply it to all rows. Resolution: `SeedFullInitialAsync` takes `(Guid userId, DateTime grantedAt, CancellationToken ct)`. Each path passes `user.CreatedAt`. `expires_at = grantedAt + 14 days`. `created_at` and `updated_at` columns track the row insertion time (`clock.GetUtcNow()`) — these are the entity-row audit columns from M16-005, distinct from `granted_at` (the trial domain timestamp).
14. **DI registration shape.** Add `builder.Services.AddScoped<ITrialStateResolver, DatabaseTrialStateResolver>();` and `builder.Services.AddScoped<TrialSeederService>();` next to the License-token issuer registrations (`Program.cs:387-389`). Both are scoped because they consume `AppDbContext`. The `LicenseTokenIssuer` registration (`AddScoped<LicenseTokenIssuer>()`) automatically picks up the new constructor dependency via DI — no change needed to the registration line.
15. **Test isolation.** Unit tests for `DatabaseTrialStateResolver` use `TestDb.CreateOpen()` (in-memory SQLite, real migrations) so the `UNIQUE (user_id, feature)` and `CHECK ck_trials_kind` constraints participate. Integration tests (`AuthRefreshEndpointsTests`, `StripeSubscriptionHandlerIntegrationTests`) use `BackendFactory` (EF InMemory) which does NOT enforce unique constraints; this is fine because the resolver tests already cover the constraint paths and the integration tests focus on wiring.
16. **Existing `Trial_fields_default_to_none_and_null` test (AuthRefreshEndpointsTests.cs:215) is now incorrect.** Behavior #1 says the default IS still `(none, null)` for a brand-new user only when no trial rows exist. With the seeder in place, the seed rows give the user a 14-day active trial — `trial_state = "active"`. Resolution: rewrite that test to verify the new contract (active+expiry on a freshly-seeded user). The seeded user is created by `SeedRefreshTokenAsync` helper which already calls `db.Users.Add` — extend the helper to also call `TrialSeederService.SeedFullInitialAsync`, OR (preferred) wire the seeder into the InternalRefreshSeedEndpoint and `CurrentUserAccessor` so the integration helper picks up seeding implicitly. The latter is cleaner because it tests the actual production code path.
17. **`LicenseTokenIssuerTests.cs` unit tests are now incorrect for the trial fields.** Two tests assert `trial_state = "none"` (line :71) and `trial_expiry = null` (line :74-76). With the resolver injected, they'd need a resolver fixture. Resolution: introduce a fake `FakeTrialStateResolver` in test infrastructure (returns whatever the test wants) and use it for these tests. The "default" test renames to `IssueAsync_emits_license_jwt_with_17_claim_shape_using_resolver` and the resolver returns `("none", null, [])` to keep the assertion stable.
18. **Idempotency of seeder.** Use `db.Trials.AnyAsync(t => t.UserId == userId, ct)` as the guard. If true → noop. If false → bulk-insert one row per `TrialFeatures` slug. This is O(1) read + O(|features|) write. The `UNIQUE (user_id, feature)` index makes a concurrent second-call fail safely (caught and ignored, mirroring CurrentUserAccessor's existing pattern).
19. **Preemption + per-user trial table interaction with multi-org.** A user could be a member of multiple orgs. The trials table is per-user, not per-org. If org A upgrades to Team, the owner-user's trials all preempt — but the owner could also be a member of org B (still free), where having an active trial would have been useful. Spec is silent. Resolution: preempt regardless of which org the upgrade is for — the spec table row "Active subscription (Solo+) → trial_state = none" is keyed on the user's tier in the issued JWT, and the JWT's tier is per-org-membership-pick (oldest membership wins, per `AuthRefreshEndpoints.ResolveUserContextAsync`). If the user re-mints a JWT scoped to org B (free), their trial_state will reflect... `expired` because the rows are now preempted, even though their effective tier in that org is free. This is a degenerate edge case (multi-org user upgrades one org). Documented in Open Decision C; not blocking M16-006 because the spec explicitly treats trials as a user-level resource.
20. **CHANGELOG entry.** Add `## [Unreleased]` entry for M16-006 documenting: trial state now populated in License JWT; trial seeder runs at user creation; Stripe `customer.subscription.created` preempts active trials.
21. **OpenAPI doc update.** `docs/api-errors.md` does not include `/auth/refresh` response shape. The closest existing surface is `Subscriptions/SwaggerSurfaceTests.cs`. The DoD asks for "OpenAPI/HTTP API doc updated where /auth/refresh response shape now reflects populated trial_state/trial_expiry" — the actual response (`AuthRefreshResponse`) is unchanged (still `LicenseJwt, AccessToken, RefreshToken`); only the JWT payload shape changes. The JWT payload is documented at spec `:8132-8136` which already states the M16 expectation. Resolution: no API doc edit needed; the JWT is opaque from the HTTP API's perspective. Adding a doc note is sufficient if any docs file currently states "trial_state always defaults to none" — grep confirms none do (only the M14 issuer code says so). The CHANGELOG entry covers the public-facing change.

## Open Decisions (resolved in plan, documented for traceability)

- **A. Adding/removing trialable feature slugs.** When a new gated feature ships, add its slug to `TrialFeatures.All`. New users registered after the change get the slug in their full-initial seed. Existing users do **not** retroactively get the new slug — the spec's `UNIQUE (user_id, feature)` model implies "no row = never trialed", so they can request an on-demand trial later (M16-007). This is correct: existing users were already past their 14-day window for the features they had at registration; they shouldn't get a fresh 14-day window for a newly-shipped feature. Documented in `TrialFeatures.cs` XML doc.
- **B. Multi-user org preemption scope.** Preempt only the org owner. Other org members keep their trials. Acceptable because (a) only the owner can checkout, (b) members have their own user-level subscription tier (today: always free unless they're owner of another paid org), and (c) the spec treats trials as user-keyed. Documented in `StripeSubscriptionHandler.PreemptOwnerTrialsAsync` XML doc.
- **C. Multi-org user with mixed tiers.** Once a user upgrades any org, all their trials preempt. They cannot re-use trials in their free orgs. This is a known degenerate case — not blocking. Documented in the resolver's XML doc.

/// <summary>
/// Computes the JWT-facing trial state for a user, given their effective tier.
/// Refs docs/SPECIFICATION.md:5806-5816 (transition table).
/// </summary>
/// <remarks>
/// Multi-org users see preemption for all trials when ANY of their orgs upgrades.
/// This is per spec — trials are a user-level concept; tier resolution is per-JWT.
/// </remarks>
public interface ITrialStateResolver
{
    /// <summary>
    /// Resolves the trial state for the given user.
    /// </summary>
    /// <param name="userId">User whose trials are being queried.</param>
    /// <param name="tier">
    /// User's effective tier for the current JWT (from <c>AuthRefreshEndpoints.ResolveUserContextAsync</c>).
    /// Any tier other than <c>free</c> short-circuits to <c>none</c> per spec row "Active subscription (Solo+)".
    /// </param>
    /// <param name="ct">Cancellation token.</param>
    Task<TrialStateResult> ResolveAsync(Guid userId, string tier, CancellationToken ct = default);
}

#### New Code — `DatabaseTrialStateResolver.cs`

```csharp
using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using Microsoft.EntityFrameworkCore;

namespace ApiTool.Backend.Licensing.Trials;

/// <summary>EF-backed implementation reading the <c>trials</c> table.</summary>
public sealed class DatabaseTrialStateResolver(AppDbContext db, TimeProvider clock) : ITrialStateResolver
{
    private static readonly TrialStateResult None =
        new("none", null, Array.Empty<string>());

    private static readonly TrialStateResult Expired =
        new("expired", null, Array.Empty<string>());

    /// <inheritdoc/>
    public async Task<TrialStateResult> ResolveAsync(Guid userId, string tier, CancellationToken ct = default)
    {
        // Spec row "Active subscription (Solo+)": tier overrides trial state.
        if (!string.Equals(tier, "free", StringComparison.OrdinalIgnoreCase))
            return None;

        var now = clock.GetUtcNow().UtcDateTime;

        // Pull active+unconsumed rows. Bound by |TrialFeatures|, never large.
        var active = await db.Trials
            .Where(t => t.UserId == userId
                     && t.ConsumedAt == null
                     && t.ExpiresAt > now
                     && t.Kind != TrialKind.PreemptedBySubscription)
            .Select(t => new { t.Feature, t.ExpiresAt })
            .ToListAsync(ct);

        if (active.Count > 0)
        {
            var earliest = active.Min(r => r.ExpiresAt);
            var features = active.Select(r => r.Feature).Distinct().ToArray();
            return new TrialStateResult(
                TrialState: "active",
                TrialExpiryUnixSeconds: new DateTimeOffset(earliest, TimeSpan.Zero).ToUnixTimeSeconds(),
                TrialingFeatures: features);
        }

        // No active rows. If any rows exist at all, the user has consumed/expired
        // their entitlements — spec rows "full trial expired" and "subscription
        // cancelled, period ended". Otherwise the user has never had trials seeded
        // (defensive — should be unreachable post-seeder).
        var anyRow = await db.Trials.AnyAsync(t => t.UserId == userId, ct);
        return anyRow ? Expired : None;
    }
}
```

using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Logging;

namespace ApiTool.Backend.Licensing.Trials;

/// <summary>
/// Seeds one <see cref="TrialKind.FullInitial"/> row per <see cref="TrialFeatures.All"/>
/// slug for a brand-new user. Idempotent — re-invocation on a user with any trial row is
/// a noop. Refs docs/SPECIFICATION.md:5800-5866 (Trial Persistence).
/// </summary>
public sealed class TrialSeederService(
    AppDbContext db,
    TimeProvider clock,
    ILogger<TrialSeederService> log)
{
    /// <summary>14-day window for the registration trial per spec :5811.</summary>
    public static readonly TimeSpan FullInitialDuration = TimeSpan.FromDays(14);

    /// <summary>
    /// Inserts one full-initial row per <see cref="TrialFeatures.All"/> slug.
    /// Idempotent: returns 0 if any trial row already exists for the user.
    /// Returns the count of rows inserted (0 or |TrialFeatures.All|).
    /// </summary>
    public async Task<int> SeedFullInitialAsync(
        Guid userId, DateTime grantedAt, CancellationToken ct = default)
    {
        if (await db.Trials.AnyAsync(t => t.UserId == userId, ct))
            return 0;

        var now = clock.GetUtcNow().UtcDateTime;
        var expires = grantedAt + FullInitialDuration;

        foreach (var feature in TrialFeatures.All)
        {
            db.Trials.Add(new Trial
            {
                Id = Guid.NewGuid(),
                UserId = userId,
                Feature = feature,
                Kind = TrialKind.FullInitial,
                GrantedAt = grantedAt,
                ExpiresAt = expires,
                CreatedAt = now,
                UpdatedAt = now,
            });
        }

        try
        {
            await db.SaveChangesAsync(ct);
            log.LogInformation(
                "trial_seeded_full_initial user_id={UserId} count={Count}",
                userId, TrialFeatures.All.Count);
            return TrialFeatures.All.Count;
        }
        catch (DbUpdateException)
        {
            // Race: another request already seeded this user. UNIQUE(user_id, feature)
            // rejects the conflict. Clear the change tracker and return 0.
            db.ChangeTracker.Clear();
            return 0;
        }
    }
}

public async Task HandleCreatedOrUpdatedAsync(
    string subscriptionId, bool isCreated, CancellationToken ct)
{
    // ... existing body unchanged through the upsert SaveChangesAsync ...

    // M16-006 preemption: only on the initial create event AND only when the
    // resulting subscription is non-free. Refs spec :5851.
    if (isCreated && row.Tier != SubscriptionTier.Free && row.Status == SubscriptionStatus.Active)
        await PreemptOwnerTrialsAsync(row.OrgId, ct);
}

/// <summary>
/// Transitions all active trial rows of the given org's <see cref="OrgRole.Owner"/> to
/// <see cref="TrialKind.PreemptedBySubscription"/> with <c>expires_at = now()</c>.
/// Refs spec :5851 (transition rule), :11030 (UPDATE pattern).
/// Multi-org scope: only the owner's trials preempt — other org members keep theirs.
/// </summary>
private async Task PreemptOwnerTrialsAsync(Guid orgId, CancellationToken ct)
{
    var ownerId = await db.OrganizationMembers
        .Where(m => m.OrgId == orgId && m.Role == OrgRole.Owner)
        .Select(m => (Guid?)m.UserId)
        .FirstOrDefaultAsync(ct);
    if (ownerId is null) return;

    var now = clock.GetUtcNow().UtcDateTime;

    // Load + update active trial rows. Bounded by |TrialFeatures| so the
    // load+update is O(few) — no need for ExecuteUpdateAsync (which adds an
    // EF Core 7+ dependency that the project may or may not have wired).
    var rows = await db.Trials
        .Where(t => t.UserId == ownerId
                 && t.ConsumedAt == null
                 && t.ExpiresAt > now
                 && t.Kind != TrialKind.PreemptedBySubscription)
        .ToListAsync(ct);

    if (rows.Count == 0) return;

    foreach (var r in rows)
    {
        r.Kind = TrialKind.PreemptedBySubscription;
        r.ExpiresAt = now;
        r.UpdatedAt = now;
    }
    await db.SaveChangesAsync(ct);

    log.LogInformation(
        "trial_preempted_by_subscription user_id={UserId} org_id={OrgId} count={Count}",
        ownerId, orgId, rows.Count);
}

## Risks and Edge Cases

- **Risk: Existing `LicenseTokenIssuerTests` and `AuthRefreshEndpointsTests` break loudly with the constructor change.** This is the desired RED state — the failures pin down all call sites to update. **Mitigation:** Step 9 enumerates every break.
- **Risk: `BackendFactory` does not register `ITrialStateResolver` explicitly, so DI defaults will pick up `DatabaseTrialStateResolver` from `Program.cs`.** This is correct for integration tests — the resolver runs against the test in-memory DB and reads whatever rows the test seeded. **Mitigation:** no change to `BackendFactory`; verify by running the integration test suite in CI.
- **Risk: The `TrialSeederService` injected into `CurrentUserAccessor` runs on every authenticated request.** `AnyAsync` short-circuits, so the cost is one indexed `SELECT 1` per request. With `idx_trials_user`, this is fast. **Mitigation:** no change; document the trade-off in the seeder XML doc.
- **Risk: EF Core's `db.Trials.Add` inside `CurrentUserAccessor` could race with the user upsert.** The user-insert happens first; if it succeeds, the seeder runs. If the user-insert raises `DbUpdateException` (race-loser), the catch-clear pattern returns without seeding. The first request to win the race seeds; the loser sees the existing user and skips. **Mitigation:** seeder's own race-loser path (catches `DbUpdateException` on the unique index) handles concurrent first-request-per-user.
- **Risk: `CHECK ck_trials_kind` rejects `preempted_by_subscription` writes if the converter map drifts.** The M16-005 converter handles all three values. **Mitigation:** existing `Kind_round_trips_via_string_converter` theory covers `PreemptedBySubscription`.
- **Edge case: User with active subscription has `kind = full_initial` rows still present (pre-preemption).** Resolver short-circuits on `tier != free`, so the JWT still says `trial_state = none`. The preemption webhook fires asynchronously; if the user re-mints between Stripe success and webhook delivery, they see `none` from the tier override. **Handling:** correct per spec table row "Active subscription".
- **Edge case: User downgrades from paid → free, with preempted trial rows.** The resolver returns `expired` (rows exist, none active). Spec row "Subscription cancelled, period ended" matches. **Handling:** no change needed.
- **Edge case: `granted_at` stored as a `DateTime` with `Kind = Unspecified`.** The seeder reads `user.CreatedAt` (set as `clock.GetUtcNow().UtcDateTime`), which is `Kind = Utc`. SQLite stores as ISO-8601 and round-trips. **Handling:** consistent with all other entities.
- **Edge case: `customer.subscription.created` arrives for a downgrade-then-resubscribe scenario.** The user already has preempted trial rows. The handler skips them (`Kind != PreemptedBySubscription` filter). **Handling:** correct — no double-write.
- **Edge case: Owner of org A and member of org B; org A upgrades.** Owner's trials preempt globally. If the user re-mints a JWT scoped to org B (free tier), they see `expired`. **Handling:** documented in Open Decision C; not blocking.
- **Edge case: Webhook arrives before the local subscription row exists.** The handler's existing logic upserts the row (re-fetch + `FirstOrDefault` by sub_id or customer_id+null sub_id). After the upsert, `row.Tier` reflects the post-upsert state. The preemption check uses `row.Tier` and runs. **Handling:** correct flow per existing handler design.
- **Risk: In-memory provider (BackendFactory) does not enforce `UNIQUE(user_id, feature)`.** The seeder's idempotency guard (`AnyAsync`) is the actual protection in production-tested SQLite. The InMemory provider may allow concurrent double-seed in theory; in practice xunit serialises tests within a class. **Mitigation:** the unit test (Step 4) uses real SQLite via `TestDb.CreateOpen()` to verify the unique-index path.
- **Risk: SubscriptionTier comparison when post-upsert subscription is `Status != Active`.** Handler only preempts when `Status == Active && Tier != Free`. A `past_due` or `incomplete` create event does not preempt. **Handling:** correct — preemption requires an actually-paid subscription.
