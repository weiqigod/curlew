# Implementation Plan: M14-019

## Overview

Adds the `POST /webhooks/github` endpoint plus its supporting infrastructure: a new `github_webhook_events` table (EF migration 0018), a `GithubWebhookOptions` config block (`APITOOL__GITHUB__WEBHOOK__SECRETS` multi-secret list), a raw-body-preserving HMAC-SHA256 verifier using `CryptographicOperations.FixedTimeEquals`, an `INSERT … ON CONFLICT (delivery_id) DO NOTHING` idempotency pattern, the same 5-failure quarantine budget as the Stripe handler, and a daily 90-day cleanup hosted service. Wires the existing M14-017 webhook handlers (`installation.created`, `installation_repositories.{added,removed}`) plus four new handlers (`installation.{deleted,suspend,unsuspend}`, `check_run.rerequested`) into a `GithubWebhookDispatcher`. Adds soft-delete/suspend lifecycle methods on `GithubInstallationsService` that evict the M14-018 `IInstallationTokenCache` and mark in-flight `pr_checks` with the `INSTALLATION_DELETED` state code. The `check_run.rerequested` handler logs a structured re-run-requested event but does not enqueue work yet — the re-run pipeline is out of M14 (the handler is the wiring point future milestones extend).

## Architectural Decisions (resolved up-front)

The task YAML carries several open shapes; resolved here so the implementation steps are mechanical.

1. **Endpoint path: `POST /webhooks/github` (top-level, no `/api/v1` prefix).** The task observable uses `http://localhost:5000/webhooks/github`. Mirrors the Stripe path convention (`/webhooks/stripe`) registered by `MapStripeWebhookEndpoint`. The endpoint is `AllowAnonymous` (signature verification is the gate) and is **not** rate-limited (GitHub is a trusted source).

2. **Raw body preservation strategy.** Per spec `:8570`, the verifier reads the *exact* bytes GitHub signed — re-serialising a parsed JSON body breaks HMAC. We accept `HttpContext` directly in the endpoint delegate and read the raw body via `await new StreamReader(context.Request.Body, Encoding.UTF8, leaveOpen: true).ReadToEndAsync(ct)` *before* any JSON parse. Identical pattern to `StripeWebhookEndpoint.HandleAsync`.

3. **Multi-secret rotation: comma-separated env var, fail-on-any-pass.** Per spec `:8577–8584`, despite GitHub itself supporting only one secret at a time, the operator-side overlap window requires our verifier to accept either old or new during cutover. Mirrors `StripeWebhookOptions.SecretList()`. New options class `GithubWebhookOptions` binds from `ApiTool:GitHub:Webhook:*`; canonical env var is `APITOOL__GITHUB__WEBHOOK__SECRETS` per ASP.NET Core's `__` → `:` convention. The task observable uses `GITHUB__WEBHOOK_SECRETS=whsec_test` — that single-underscore tail spelling (with the `APITOOL` prefix dropped per the M14-017 install-state convention) is **not** going to bind via standard configuration. We resolve this exactly as M14-011 did for Stripe: support both spellings by also reading `GITHUB__WEBHOOK_SECRETS` directly in `Program.cs` and feeding it via `AddInMemoryCollection`. The clean form (`APITOOL__GITHUB__WEBHOOK__SECRETS`) remains the documented operator interface.

4. **Constant-time signature compare.** Use `System.Security.Cryptography.CryptographicOperations.FixedTimeEquals(byte[], byte[])` exactly as the task spec mandates. Both operands must be the same length; we compare HMAC-SHA256 raw bytes (32 bytes) after parsing the `sha256=<hex>` header and decoding the hex to bytes. Length-mismatched headers (anything other than 64 hex chars after the prefix) short-circuit to a 401 without a comparison so timing attacks cannot probe parsing.

5. **Legacy SHA-1 header rejection.** Per spec `:8575`, when only `X-Hub-Signature` (SHA-1) is present and `X-Hub-Signature-256` is absent, return **401**. We do not log the SHA-1 value. Negative test asserts the 401 response and that no row was inserted.

6. **`github_webhook_events` entity name: `GithubWebhookEvent`.** Mirrors `StripeWebhookEvent`. Note camel-case `Github` (not `GitHub`) for consistency with the existing `GithubInstallation` entity (M14-017). DbSet is `GithubWebhookEvents`; table is `github_webhook_events`.

7. **`delivery_id` column type: `string` (TEXT) on the C# side, mapped to `uuid` on Postgres via `HasColumnType("uuid")` when `Database.IsNpgsql()`.** The spec at `:10035` declares `delivery_id UUID PRIMARY KEY`. `X-GitHub-Delivery` is always a UUID string; storing it as `string` on the entity (length 36) keeps the migration trivial under SQLite while still hitting `uuid` on Postgres. Identical pattern to `payload` jsonb conditioning. We validate the header parses as `Guid` before insertion (reject 400 on malformed delivery IDs).

8. **`payload` jsonb conditional, `attempt_count` / `last_error` / `last_error_at` mirror Stripe.** All three columns share the exact semantics of `StripeWebhookEvent`. The 5-failure quarantine logic also mirrors. The new entity adds an `Action` (TEXT, nullable) column matching spec `:10037` — GitHub events have a top-level `action` field; storing it lets ops query "all installation.deleted events in the last week" without re-parsing payload JSON.

9. **`status` column: TEXT with three legal values (`pending|processed|quarantined`).** Same pattern as `StripeWebhookEvent.Status`.

10. **The dispatcher is real (not a stub).** Unlike M14-011 which shipped a no-op `NoopStripeWebhookDispatcher`, M14-017 already shipped real handlers for `installation.created` and `installation_repositories.{added,removed}`. M14-019 must wire those through plus add four new handlers. The new `IGithubWebhookDispatcher` interface has one method `Task DispatchAsync(GithubWebhookEnvelope env, CancellationToken ct)` where `GithubWebhookEnvelope` carries the parsed event-type, action, and payload `JsonDocument`. Concrete `GithubWebhookDispatcher` switches on `(event_type, action)` and calls into the appropriate handler. Unknown `(event_type, action)` pairs are logged and dropped (response 200, idempotency row marked processed) — per the same "stop the retry storm" pattern as Stripe.

11. **Lifecycle handlers added to `GithubInstallationsService`.** Three new methods needed:
    - `MarkSuspendedAsync(long installationId, CancellationToken ct)` — sets `suspended_at = now`; evicts token cache.
    - `MarkUnsuspendedAsync(long installationId, CancellationToken ct)` — clears `suspended_at`.
    - `MarkDeletedAsync(long installationId, CancellationToken ct)` — sets `deleted_at = now`; evicts token cache; sets `state = 'INSTALLATION_DELETED'` on all open `pr_checks` for the org (same set-difference pattern `ApplyRepoRemovedAsync` uses for `REPO_NOT_COVERED`).

    The token-cache eviction requires injecting `IInstallationTokenCache` into `GithubInstallationsService`. This is a constructor-signature change. Existing call sites are limited (the M14-017 reconciler host, M14-018 callsites already created the service via DI) — DI catches the change automatically. Tests that construct the service directly (`GithubInstallationsServiceTests`, `GithubInstallationCreatedHandlerTests`, `GithubInstallationRepositoriesHandlerTests`) must be updated to pass a fake or null token cache. We add a `FakeInstallationTokenCache` helper to `TestInfrastructure` and use it across all such tests.

12. **`pr_checks.state` MaxLength constraint.** The column is `MaxLength(20)` (M14-017). `INSTALLATION_DELETED` is exactly 20 chars — fits. Verified by the existing `REPO_NOT_COVERED` (16 chars) precedent. The tests assert `state == "INSTALLATION_DELETED"` not `PRCHECK_INSTALLATION_DELETED` (which is 27 chars and would not fit).

13. **`check_run.rerequested` handler is a logging-only stub for this slice.** Spec `:8565` says "Re-run the originating ApiTool collection on the same `head_sha`; emit a new check run." But the re-run job-queue pipeline does not exist yet (no `M14-XXX` task for it; out of milestone scope). The handler:
    - Looks up the originating `pr_checks` row via `external_id` (the `check_run.external_id` field carries the ApiTool-issued `Guid` — set in M14-018's `CheckRunPoster`).
    - Emits a structured log: `LogInformation("github_check_run_rerequested external_id={ExternalId} head_sha={HeadSha} repo={Repo}", ...)`.
    - Returns success — the idempotency row marks `processed`, GitHub stops retrying.

    The "enqueue a re-run job" sentence in the behavior is satisfied at the *interface* level: the handler exists, is wired, and is the documented extension point. Future milestones will swap the log line for an actual enqueue without changing the surface. We document this clearly in the handler's doc comment with a `// TODO(re-run-pipeline)` reference and add the structured-log assertion to the behavior test (instead of an unimplementable end-to-end re-run assertion).

14. **`installation.suspend` (singular) vs `installation.suspended` (past tense).** The GitHub Webhooks API uses the action `suspend` (and `unsuspend`) on the `installation` event — not the past-tense form. The task YAML mirrors this precisely (`installation.suspend`). Our switch matches `action == "suspend"` and `action == "unsuspend"`.

15. **Quarantine alert: structured warning log with `delivery_id={DeliveryId} event_type={EventType} attempt_count=5 last_error={LastError}`.** Identical pattern to `StripeWebhookEndpoint`. The search anchor is `event=github_webhook_quarantined`.

16. **Daily cleanup hosted service: `GithubWebhookCleanupHost`.** Mirrors `StripeWebhookCleanupHost`. 24-hour tick; deletes `processed` rows older than 90 days; quarantined rows retained indefinitely. Skipped under `IsEnvironment("Testing")`.

17. **`github_webhook_events` migration name: `0018_github_webhook_events`** per the task definition_of_done. The EF Core migration filename will be `20260507131000_AddGithubWebhookEvents.cs` (timestamp comes after the most recent `20260507130000_PrChecksV421` in the existing folder; we add 1000 seconds to maintain ordering). The migration `Up` creates the table + two indexes; `Down` drops them.

18. **Spec citation header in `GithubWebhookEndpoint.cs`.** Per definition_of_done item: `// Spec refs: docs/SPECIFICATION.md:8551-8597 (signature verification + idempotency + quarantine + multi-secret rotation + retention); :10031-10051 (github_webhook_events schema).`

19. **Test-host divergence.** Same as M14-011: `BackendFactory` uses EF Core InMemory which lacks raw-SQL `ON CONFLICT … RETURNING` support. Endpoint tests use `BackendFactory` and exercise the LINQ branch in the new `GithubWebhookStore`; unit-level idempotency tests use `TestDb.CreateOpen()` (SQLite) to exercise the Postgres-style raw SQL branch.

20. **No coupling to `Stripe.Net`.** GitHub webhooks have no third-party SDK requirement — we hand-roll the HMAC verifier with `System.Security.Cryptography.HMACSHA256` and `CryptographicOperations.FixedTimeEquals`. The new `Webhooks/` GitHub-side code lives in `src/ApiTool.Backend/GitHub/Webhooks/` (existing folder) for handlers and `src/ApiTool.Backend/Webhooks/` (existing folder, alongside Stripe) is **not** used — the Stripe folder is for Stripe-specific code. The endpoint, options, store, dispatcher, and cleanup-host all live in `src/ApiTool.Backend/GitHub/Webhooks/`.

21. **`GithubWebhookEnvelope` shape.** A small record that carries the parsed JSON document, the event type (X-GitHub-Event header), the action (extracted from the JSON), and the delivery ID:
    ```csharp
    public sealed record GithubWebhookEnvelope(
        Guid DeliveryId, string EventType, string Action, JsonDocument Payload);
    ```
    The dispatcher inspects the envelope to route. Each handler accepts `JsonDocument` and parses the fields it needs — matching how `GithubInstallationCreatedPayload` is currently shaped.

22. **`check_run.external_id` lookup.** Spec `:8565` says re-run "the originating ApiTool collection." `M14-018` set `external_id` (a `Guid`) on the `pr_checks` row when posting to GitHub. GitHub echoes this value back on `check_run` events as `check_run.external_id` (a string). The handler parses the JSON path `check_run.external_id` as a `Guid`, then queries `pr_checks` for that ID. If no row found, the handler logs a warning and returns success (the original collection has been deleted; nothing to re-run).

```csharp
namespace ApiTool.Backend.Data.Entities;

/// <summary>
/// One row per GitHub webhook event delivery — idempotency store and audit trail.
/// Refs docs/SPECIFICATION.md:10031-10049 (schema), :8586-8595 (idempotency contract).
/// </summary>
public sealed class GithubWebhookEvent
{
    /// <summary>Value of the X-GitHub-Delivery header (a UUID GitHub assigns per delivery). Primary key.</summary>
    public Guid DeliveryId { get; set; }

    /// <summary>Event type, e.g. <c>installation</c>, <c>check_run</c>, <c>installation_repositories</c>.</summary>
    public string EventType { get; set; } = string.Empty;

    /// <summary>Action, e.g. <c>created</c>, <c>deleted</c>, <c>rerequested</c>. Nullable; some events have none.</summary>
    public string? Action { get; set; }

    /// <summary>UTC moment we received the delivery.</summary>
    public DateTime ReceivedAt { get; set; }

    /// <summary>UTC moment processing succeeded; null while pending or after a failure.</summary>
    public DateTime? ProcessedAt { get; set; }

    /// <summary>One of <c>pending</c>, <c>processed</c>, <c>quarantined</c>.</summary>
    public string Status { get; set; } = "pending";

    /// <summary>Raw JSON event payload — TEXT on SQLite, jsonb on Postgres.</summary>
    public string PayloadJson { get; set; } = "{}";

    /// <summary>Number of failed handler attempts. Increments to 5 then quarantines.</summary>
    public int AttemptCount { get; set; }

    /// <summary>Last error message; null if never failed.</summary>
    public string? LastError { get; set; }

    /// <summary>UTC moment the most recent failure was recorded.</summary>
    public DateTime? LastErrorAt { get; set; }
}
```

```csharp
/// <summary>
/// Configuration for the GitHub webhook ingest pipeline. Bound from
/// <c>ApiTool:GitHub:Webhook:*</c> with environment-variable equivalents
/// <c>APITOOL__GITHUB__WEBHOOK__SECRETS</c> (canonical) and <c>GITHUB__WEBHOOK_SECRETS</c>

/// </summary>
public sealed class GithubWebhookOptions
{
    /// <summary>Configuration section name.</summary>
    public const string Section = "ApiTool:GitHub:Webhook";

    /// <summary>
    /// Comma-separated list of webhook signing secrets. Multiple values support
    /// the rotation grace window — verification iterates the list and succeeds
    /// on any match. Empty entries are skipped.
    /// </summary>
    public string Secrets { get; set; } = string.Empty;

    /// <summary>Splits <see cref="Secrets"/> on comma, trims whitespace, drops empties.</summary>
    public IReadOnlyList<string> SecretList()
    {
        if (string.IsNullOrWhiteSpace(Secrets)) return Array.Empty<string>();
        return Secrets.Split(',', StringSplitOptions.TrimEntries | StringSplitOptions.RemoveEmptyEntries);
    }
}
```

#### New Code (`GithubWebhookStore.cs`)

```csharp
// Refs docs/SPECIFICATION.md:8586-8595 (INSERT … ON CONFLICT DO NOTHING),
// :8597 (5-failure quarantine), :8595 (90-day retention).
using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using Microsoft.EntityFrameworkCore;

namespace ApiTool.Backend.GitHub.Webhooks;

/// <summary>Encapsulates all DB writes against <c>github_webhook_events</c>.</summary>
public sealed class GithubWebhookStore(AppDbContext db, TimeProvider clock)
{
    /// <summary>Quarantine threshold — same as Stripe (spec :8597).</summary>
    public const int QuarantineThreshold = 5;

    /// <summary>
    /// Atomically inserts a new pending row keyed by <paramref name="deliveryId"/>.
    /// Returns Inserted=true on first delivery, false on duplicate.
    /// </summary>
    public async Task<IdempotentInsertResult> TryInsertPendingAsync(
        Guid deliveryId, string eventType, string? action, string payloadJson, CancellationToken ct)
    {
        var now = clock.GetUtcNow().UtcDateTime;

        if (db.Database.IsNpgsql())
        {
            var inserted = await db.GithubWebhookEvents
                .FromSqlInterpolated($@"
                    INSERT INTO github_webhook_events
                        (delivery_id, event_type, action, received_at, status, payload, attempt_count)
                    VALUES
                        ({deliveryId}, {eventType}, {action}, {now}, 'pending', {payloadJson}::jsonb, 0)
                    ON CONFLICT (delivery_id) DO NOTHING
                    RETURNING *")
                .AsNoTracking()
                .ToListAsync(ct);

            if (inserted.Count > 0)
                return new IdempotentInsertResult(true, null, null);
            var (existingAt, existingStatus) = await ExistingRowMetaAsync(deliveryId, ct);
            return new IdempotentInsertResult(false, existingAt, existingStatus);
        }

        // SQLite / InMemory path
        var existingRow = await db.GithubWebhookEvents
            .Where(x => x.DeliveryId == deliveryId)
            .FirstOrDefaultAsync(ct);
        if (existingRow is not null)
            return new IdempotentInsertResult(false, existingRow.ReceivedAt, existingRow.Status);

        db.GithubWebhookEvents.Add(new GithubWebhookEvent
        {
            DeliveryId = deliveryId, EventType = eventType, Action = action,
            ReceivedAt = now, Status = "pending", PayloadJson = payloadJson, AttemptCount = 0,
        });
        try
        {
            await db.SaveChangesAsync(ct);
            return new IdempotentInsertResult(true, null, null);
        }
        catch (DbUpdateException)
        {
            db.ChangeTracker.Clear();
            var racedRow = await db.GithubWebhookEvents.FirstOrDefaultAsync(x => x.DeliveryId == deliveryId, ct);
            return new IdempotentInsertResult(false, racedRow?.ReceivedAt, racedRow?.Status ?? "pending");
        }
```

```csharp
/// Unknown (event_type, action) pairs are logged and dropped — GitHub still receives
/// 200 so it stops retrying.
/// </summary>
public sealed class GithubWebhookDispatcher(
    GithubInstallationCreatedHandler created,
    GithubInstallationRepositoriesHandler repos,
    GithubInstallationLifecycleHandler lifecycle,
    GithubCheckRunHandler checkRun,
    ILogger<GithubWebhookDispatcher> log) : IGithubWebhookDispatcher

    /// <inheritdoc/>
    public async Task DispatchAsync(GithubWebhookEnvelope envelope, CancellationToken ct)
    {
        switch (envelope.EventType, envelope.Action)
        {
            case ("installation", "created"):
                await created.HandleAsync(GithubWebhookPayloadParser.ParseInstallationCreated(envelope.Payload), ct);
                break;
            case ("installation", "deleted"):

                break;
            case ("installation", "suspend"):
                await lifecycle.HandleSuspendedAsync(GithubWebhookPayloadParser.ParseLifecycle(envelope.Payload), ct);

                break;

                break;
```

```csharp
// Refs docs/SPECIFICATION.md:8568-8575 (signature verification, SHA-1 rejection, multi-secret).
using System.Security.Cryptography;
using System.Text;

namespace ApiTool.Backend.GitHub.Webhooks;

/// <summary>HMAC-SHA256 verifier for GitHub webhook deliveries.</summary>
public static class GithubWebhookSignatureVerifier
{
    private const string Sha256Prefix = "sha256=";

    /// <summary>
    /// Verifies <paramref name="signatureHeader"/> against <paramref name="rawBody"/> using
    /// constant-time comparison against each secret in <paramref name="secrets"/>. Succeeds
    /// on any match. Returns false when the header is malformed (wrong prefix, non-hex,
    /// wrong length) or no secret matches. Constant-time per spec :8572.
    /// </summary>
    public static bool TryVerify(byte[] rawBody, string? signatureHeader, IReadOnlyList<string> secrets)
    {
        if (string.IsNullOrEmpty(signatureHeader)) return false;
        if (!signatureHeader.StartsWith(Sha256Prefix, StringComparison.Ordinal)) return false;
        var hex = signatureHeader.AsSpan(Sha256Prefix.Length);
        if (hex.Length != 64) return false; // 32-byte HMAC-SHA256 = 64 hex chars
        Span<byte> received = stackalloc byte[32];
        if (!TryHexDecode(hex, received)) return false;

        Span<byte> computed = stackalloc byte[32];
        foreach (var secret in secrets)
        {
            if (string.IsNullOrEmpty(secret)) continue;
            using var hmac = new HMACSHA256(Encoding.UTF8.GetBytes(secret));
            if (!hmac.TryComputeHash(rawBody, computed, out _)) continue;
            if (CryptographicOperations.FixedTimeEquals(received, computed)) return true;
        }
        return false;
    }

    private static bool TryHexDecode(ReadOnlySpan<char> hex, Span<byte> output) { /* return false on non-hex */ }
}
```

#### New Code (`GithubWebhookEndpoint.cs`)

```csharp
// Spec refs: docs/SPECIFICATION.md:8551-8597 (signature verification + idempotency
// + 5-failure quarantine + multi-secret rotation + 90-day retention);
// :10031-10049 (github_webhook_events schema).
using System.Text;
using System.Text.Json;
using Microsoft.Extensions.Options;
using HttpResults = Microsoft.AspNetCore.Http.Results;

namespace ApiTool.Backend.GitHub.Webhooks;

/// <summary>Maps the <c>POST /webhooks/github</c> endpoint.</summary>
public static class GithubWebhookEndpoint
{
    public static IEndpointRouteBuilder MapGithubWebhookEndpoint(this IEndpointRouteBuilder app)
    {
        app.MapPost("/webhooks/github", HandleAsync)
            .AllowAnonymous().WithName("GithubWebhook").WithTags("Webhooks");
        return app;
    }

    private static async Task<IResult> HandleAsync(
        HttpContext context,
        IOptions<GithubWebhookOptions> webhookOptions,
        GithubWebhookStore store,
        IGithubWebhookDispatcher dispatcher,
        ILoggerFactory loggerFactory,
        CancellationToken ct)
    {
        var logger = loggerFactory.CreateLogger(typeof(GithubWebhookEndpoint).FullName!);

        // 1) Read raw body BEFORE JSON parse — spec :8570.
        byte[] rawBody;
        using (var ms = new MemoryStream())
        {
            await context.Request.Body.CopyToAsync(ms, ct);
            rawBody = ms.ToArray();
        }

        // 2) Reject SHA-1-only deliveries — spec :8575.
        if (!context.Request.Headers.TryGetValue("X-Hub-Signature-256", out var sigHeaderValues))
        {
            if (context.Request.Headers.ContainsKey("X-Hub-Signature"))
                logger.LogWarning("github_webhook_legacy_sha1_rejected delivery_id={DeliveryId}",
                    context.Request.Headers["X-GitHub-Delivery"].FirstOrDefault());
            return HttpResults.Unauthorized();
        }
        var signatureHeader = sigHeaderValues.FirstOrDefault();

        // 3) Parse delivery ID & event type headers.
        var deliveryHeader = context.Request.Headers["X-GitHub-Delivery"].FirstOrDefault();
        if (!Guid.TryParse(deliveryHeader, out var deliveryId))
            return HttpResults.BadRequest();
        var eventType = context.Request.Headers["X-GitHub-Event"].FirstOrDefault();
        if (string.IsNullOrEmpty(eventType))
            return HttpResults.BadRequest();

        // 4) Verify signature against every configured secret — spec :8577-8584.
        var opts = webhookOptions.Value;
        var secrets = opts.SecretList();
        if (secrets.Count == 0)
        {
            logger.LogWarning("github_webhook_no_secrets_configured");
            return HttpResults.Unauthorized();
        }
        if (!GithubWebhookSignatureVerifier.TryVerify(rawBody, signatureHeader, secrets))
        {
            logger.LogWarning(
                "github_webhook_signature_invalid delivery_id={DeliveryId} secrets_tried={Count}",
                deliveryId, secrets.Count);
            return HttpResults.Unauthorized();
        }

        // 5) Parse JSON only after signature is verified.
        JsonDocument payload;
        try { payload = JsonDocument.Parse(rawBody); }
        catch (JsonException) { return HttpResults.BadRequest(); }

        var action = payload.RootElement.TryGetProperty("action", out var actionEl)
            ? actionEl.GetString() : null;
        var rawPayloadJson = Encoding.UTF8.GetString(rawBody);

        // 6) Idempotency insert — spec :8586-8595.
        var insert = await store.TryInsertPendingAsync(deliveryId, eventType, action, rawPayloadJson, ct);
        if (!insert.Inserted)
        {
            if (insert.ExistingStatus is "processed" or "quarantined")
            {
                logger.LogInformation(
                    "github_webhook_duplicate delivery_id={DeliveryId} status={Status}",
                    deliveryId, insert.ExistingStatus);
                return HttpResults.Ok();
            }
            // pending row → fall through to re-dispatch (retry semantics).
        }

        // 7) Dispatch.
        try
        {
            var envelope = new GithubWebhookEnvelope(deliveryId, eventType, action, payload);
            await dispatcher.DispatchAsync(envelope, ct);
            await store.MarkProcessedAsync(deliveryId, ct);
            return HttpResults.Ok();
        }
        catch (Exception ex)
        {
            var attempts = await store.RecordFailureAsync(deliveryId, ex.Message, ct);
            if (attempts >= GithubWebhookStore.QuarantineThreshold)
            {
                logger.LogError(ex,
                    "github_webhook_quarantined delivery_id={DeliveryId} event_type={EventType} attempt_count={AttemptCount}",
                    deliveryId, eventType, attempts);
                return HttpResults.Ok(); // break the retry storm
            }
            logger.LogWarning(ex,
                "github_webhook_handler_failed delivery_id={DeliveryId} event_type={EventType} attempt_count={AttemptCount}",
                deliveryId, eventType, attempts);
            return HttpResults.StatusCode(StatusCodes.Status500InternalServerError);
        }
        finally { payload.Dispose(); }
    }
}
```

## Risks and Edge Cases

- **Risk: `IInstallationTokenCache` constructor injection ripples through reconciler tests.** → **Mitigation:** introduce `FakeInstallationTokenCache` in TestInfrastructure once and reuse across the four affected test files; verified by running `dotnet test` after Step 5.
- **Risk: Postgres `delivery_id uuid` vs SQLite `TEXT` divergence breaks raw-SQL idempotency on Postgres.** → **Mitigation:** explicit `HasColumnType("uuid")` on Npgsql; `FromSqlInterpolated` uses parameterised `{deliveryId}` of type `Guid`; tested against Postgres by `dotnet ef database update` in the staging step of definition_of_done.
- **Risk: `pr_checks.state` MaxLength(20) drops `INSTALLATION_DELETED`.** → **Mitigation:** the constant is exactly 20 chars (verified); add a unit test that round-trips this value through the entity to catch any future MaxLength regression. The behavior test also asserts the value lands in the column.
- **Risk: `JsonDocument.Parse` on attacker-controlled payload.** → **Mitigation:** parse runs only *after* HMAC verification succeeds, so the attacker cannot reach the parser without a valid secret. We catch `JsonException` and return 400 to be safe.
- **Risk: `MemoryStream` for raw body grows unbounded under a malicious giant payload.** → **Mitigation:** ASP.NET Core `MaxRequestBodySize` defaults to ~30 MB which already caps this; signature verification additionally requires the attacker to know the secret to make a giant payload "valid", and we set no explicit per-route limit (matches the Stripe endpoint shape).
- **Edge case: header `X-Hub-Signature-256` present but with `sha1=` prefix (mis-set).** → **Handling:** `TryVerify` rejects (prefix mismatch). Returns 401.
- **Edge case: signature header present but body is empty.** → **Handling:** `HMAC` of empty body is well-defined; if the operator's secret matches, the empty body is accepted; downstream `JsonDocument.Parse` fails on empty input → 400.
- **Edge case: same delivery retried while still `pending` (i.e. previous handler crashed mid-flight).** → **Handling:** `TryInsertPendingAsync` returns `(Inserted=false, ExistingStatus="pending")` and the handler falls through to re-dispatch — same retry semantics as the Stripe endpoint.
- **Edge case: `installation.deleted` arrives for an installation row that was never claimed (org_id=NULL).** → **Handling:** `MarkDeletedAsync` skips the `pr_checks` mark (no `OrgId.HasValue` branch) and only sets `deleted_at`; covered by `MarkDeleted_when_orgid_null_skips_pr_checks` test.
- **Edge case: `check_run.rerequested` for a `pr_checks` row whose collection has been deleted.** → **Handling:** `external_id` lookup returns null; handler logs `github_check_run_rerequested_unknown_pr_check` warning and returns success (idempotency row marks processed; no further retry).
- **Edge case: `marketplace_purchase.*` events.** → **Handling:** the dispatcher's `default` branch logs them as unhandled and marks the row processed. No code path explicitly references marketplace events — they're treated as "unknown." Behavior test confirms a `marketplace_purchase.purchased` event returns 200 and lands `processed`.
