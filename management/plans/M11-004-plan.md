## Architectural Decisions

1. **New shared package `internal/output/ids`** for the run-id generator.
   - Both `internal/output/events` (private `newRunID`) and `internal/runner` (exported `NewRunID`) currently mint near-identical 32-char lowercase hex IDs via `crypto/rand`. They diverge only in the never-hit fallback string (`fallback-%016x` vs `fallback%016x`).
   - A new sub-package `internal/output/ids` is the cleanest seam: no current package under `internal/output` imports `internal/runner` or `internal/output/events`, so the new package has no inbound import-cycle risk. It is reachable from both call sites and from `cmd/apitest` (which already imports both `runner` and `output`).
   - `runner.NewRunID` and `events.newRunID` become thin wrappers that call `ids.NewRunID`. This preserves both public and private package surfaces (no breakage for callers of `runner.NewRunID`).
   - Fallback string is unified to `fallback%016x` (no dash) — matches the runner's current shape and stays inside `^[0-9a-zA-Z]+$` for tooling that grep/regex-filters IDs.

2. **`exec` mints one `run_id` at the top of `execCmdOut`** and threads it through every `JSONLEntry` write site (dry-run, exec error, exec success). The invariant from the task body — *every invocation has a run_id, even when no HTTP happens* — requires the ID to be minted before the dry-run branch.

3. **`request_id` is the literal `"req-1"`** for the exec command (single-request invocation). The task explicitly mandates this; we do not import the runner's counter.

4. **Field names and JSON tags:** `RunID string \`json:"run_id,omitempty"\`` and `RequestID string \`json:"request_id,omitempty"\``. `omitempty` keeps the change additive — old consumers parsing existing log files see no schema break (no field appears when the value is empty), and new consumers see the IDs populated for every exec write.

5. **No JSONL emit from `apitest run`:** the only `output.AppendJSONL` call sites are the three inside `execCmdOut`. `apitest run`'s `--log` already routes through the events stream and other formatters; verified by `grep -rn "AppendJSONL" cmd/apitest/`. Therefore this change touches the exec path only.

6. **Test naming:** the task's observable section names two test functions verbatim (`TestExecCmd_LogContainsRunIDAndRequestID`, `TestExecCmd_LogDryRun_RunIDPresent`). Use those exact names so the observable command in the YAML file is byte-true.

#### New Code (`internal/output/ids/ids.go`)

```go
// Package ids mints 32-char lowercase hex identifiers used as run IDs across
// apitest's output surfaces (events stream, exec --log, markdown sentinels).
//
// The events emitter, runner, and exec command all delegate to NewRunID so a
// single invocation produces correlatable identifiers in every artifact.
package ids

import (
	"crypto/rand"
	"encoding/hex"
	"fmt"
	"time"
)

// NewRunID returns a 32-char lowercase hex identifier (128 bits of crypto/rand
// entropy). On the never-hit failure path where crypto/rand cannot be read,
// it falls back to a time-based hex string of the form "fallback%016x" so the
// returned value is still safely matchable as identifier-shaped text.
func NewRunID() string {
	var b [16]byte
	if _, err := rand.Read(b[:]); err != nil {
		return fmt.Sprintf("fallback%016x", time.Now().UnixNano())
	}
	return hex.EncodeToString(b[:])
}
```

// TestExecCmd_LogContainsRunIDAndRequestID asserts that a live exec invocation
// writes a JSONL log entry carrying the additive M11-004 correlation fields:
// run_id (32-char lowercase hex) and request_id ("req-1").
func TestExecCmd_LogContainsRunIDAndRequestID(t *testing.T) {
	srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, _ *http.Request) {
		w.WriteHeader(http.StatusOK)
	}))
	defer srv.Close()

	logFile := filepath.Join(t.TempDir(), "exec.jsonl")
	stdin := fmt.Sprintf(`{"url":"%s/get","method":"GET"}`, srv.URL)
	_, _, exitCode := captureExecCmd(t, stdin, "--stdin", "--log", logFile)
	if exitCode != 0 {
		t.Fatalf("exit code = %d, want 0", exitCode)
	}

	data, err := os.ReadFile(logFile)
	if err != nil {
		t.Fatalf("read log file: %v", err)
	}
	if len(data) == 0 {
		t.Fatal("log file is empty")
	}
	var entry output.JSONLEntry
	if err := json.Unmarshal(data[:len(data)-1], &entry); err != nil {
		t.Fatalf("invalid JSONL: %v\ndata: %s", err, data)
	}
	runIDPattern := regexp.MustCompile(`^[0-9a-f]{32}$`)
	if !runIDPattern.MatchString(entry.RunID) {
		t.Errorf("run_id %q does not match %s", entry.RunID, runIDPattern)
	}
	if entry.RequestID != "req-1" {
		t.Errorf("request_id = %q, want %q", entry.RequestID, "req-1")
	}
}

## Risks and Edge Cases

- **Risk:** Removing `crypto/rand`/`encoding/hex` imports from `runner.go` or `emitter.go` if they remain used elsewhere → **Mitigation:** Run `grep -n "rand\.\|hex\." <file>` before deleting either import; only remove imports that have zero remaining call sites. `golangci-lint` will flag stragglers either way.
- **Risk:** `events.newRunID` fallback string changes from `fallback-%016x` to `fallback%016x`, which is technically observable → **Mitigation:** The fallback path requires `crypto/rand` to fail — never observed in practice. No test in the repo asserts on the dash variant (verified via grep). If a future test ever pinned the dash form, it would be a brittle test against a never-fired path.
- **Risk:** Doc grep observability checks fail because `grep -E '^[[:space:]]*RunID[[:space:]]+string' internal/output/jsonl.go` is sensitive to the exact whitespace shape → **Mitigation:** Use the exact `\t` indentation Go's gofmt produces for struct fields. The pattern `^[[:space:]]*RunID[[:space:]]+string` matches both tabs and spaces, so this is robust.
- **Risk:** `apitest exec` is invoked in a tight loop → 32 bits of `crypto/rand` per call is negligible; existing run_id mint in `cmd/apitest/main.go::runCmdInner` already does this for every `apitest run` → no perf concern.
- **Edge case:** Variable interpolation fails or stdin parse fails → control returns to the caller before any `JSONLEntry` is written. The `runID` minted at the top is silently discarded, which is fine; we never persist it absent a log write. → **Handling:** No special handling needed; this is the existing flow.
- **Edge case:** `opts.LogFile == ""` (no `--log`) → all three write blocks are skipped; the minted `runID` is never persisted. → **Handling:** Existing flow; unchanged.
- **Edge case:** Log file write error (`AppendJSONL` returns an error) → existing path prints `log error: ...` to stderr; the runID was successfully minted but only written if the write succeeded. The test stays single-write so this path isn't exercised by the new tests; existing `TestAppendJSONL_errorOnInvalidPath` already covers the error surface.
