# Implementation Plan: M26-001

## Overview

Strip the deleted five-tier licensing system from the agent skill that
`curlew init --skill agent` installs into other people's repositories, then hold
the skill's exit-code table and its `curlew <subcommand>` invocations to the
binary by tests that read source rather than prose — so the next removed feature
fails the build instead of reaching an agent that will obey it literally.

## Task Details

- **ID:** M26-001
- **Title:** The shipped agent skill stops describing a licensing system that was deleted
- **Phase:** M26: The agent skill tells the truth
- **Priority:** 1
- **Complexity:** medium
- **Branch:** `feature/M26-001-agent-skill-truth`

### G2. "The binary returns 0 through 5" is false

Both the task YAML (line 40) and `docs/PRODUCT_ROADMAP.md:87` assert the binary
returns 0–5. It returns **`{0, 1, 2, 3, 4, 5, 130}`**.

`cmd/curlew/perf.go:142` is `return 130 // SIGINT`. Running the real binary:

```
$ curlew perf --help | grep -i "exit codes"
Exit codes: 0=ok, 1=failures, 2=usage, 3=request-file error, 130=SIGINT
```

130 is not a paper claim — `cmd/curlew/perf_test.go:226`
`TestPerfCmd_ContextCancelExitCode130` covers it behaviourally.

**And the rest of the repository already knows this.** `docs/MANUAL.md:2220`,
`docs/MANUAL.md:3888` and `docs/CLI_SPECIFICATION.md:1667` each publish a table
containing `130`, and `cmd/curlew/doc_exit_codes_test.go` already forces those
three tables into agreement with each other and with the binary. Its lines
163-166 carry an explicit carve-out:

```go
// 130 is 128+SIGINT: it is produced by a signal, not by an invocation, and
// TestPerfCmd_ContextCancelExitCode130 is what covers it. Requiring it here
// would mean racing a signal against process startup for no added coverage.
const signalCode = 130
```

So the documented set on three surfaces is `{0,1,2,3,4,5,130}`, the binary's set
is `{0,1,2,3,4,5,130}`, and **the skill is the sole outlier** at
`{0,1,2,3,4,5,6,9}` — inventing two codes and omitting one.

### G3. The extraction strategy, validated three ways

Three independent AST strategies were written and run against `cmd/curlew`. All
three returned the same set, `{0,1,2,3,4,5,130}`:

| Strategy | Rule | Result |
|---|---|---|
| A | int literals in `return` of every func whose sole result is `int` | `{0,1,2,3,4,5,130}` |
| B | call graph from `run`, return-position calls only | `{0,1,2,3,4,5,130}` |
| **C (adopted)** | as B, **plus local ident resolution** | `{0,1,2,3,4,5,130}` |

Strategy C is adopted because it is the only one that is both complete and not
over-broad, verified on four discriminating cases:

- **Excludes** `htmlResultStatusCode` (`main.go:2307`) — returns an HTTP status
  code, sole result is `int`, so Strategy A would have swept it in.
- **Excludes** `countWaveResults` (`main.go:1894`) — returns a count.
- **Includes** `runErrorExitCode` (2, 3, 5) — reached only via
  `code := runErrorExitCode(varErr)`, which Strategy B missed for want of ident
  resolution.
- **Includes** `perfCmdOut` (130).

**The property that makes this design correct rather than merely convenient:**
the dead `exitCodeSeverity` map in `cmd/curlew/discovery_run.go:18-26` contains
`6: 6, // feature gate`. A return-statement-scoped walk never sees it, because
`6` appears there only as a composite-literal key and value. The out-of-scope
dead mapping (M26-002's job) is excluded structurally, with no special case and
no exception list.

### G4. Subcommand extraction must be scoped to code, not prose

The binary's subcommands are the `case` clauses of the `switch args[0]` in
`runWithWriters` (`cmd/curlew/main.go:69-111`): `run, exec, validate, init,
info, schema, watch, ui, vault, pr-check, import, telemetry, perf, plugins`.

A naive `curlew\s+([a-z][a-z-]*)` regex over the skill yields four false
positives — `curlew with`, `curlew to`, `curlew skill`, `curlew can` — all
prose. This is not hypothetical: `cmd/curlew/doc_prose_test.go:114-132` carries
a **60-entry hand-maintained `nonCommandWords` blocklist** (`"is"`, `"was"`,
`"reads"`, `"with"`, `"to"`, …) for exactly this reason. That blocklist is the
anti-pattern this task exists to avoid.

Measured fix: scope extraction to **markdown inline code spans and fenced code
blocks**. Result over the skill: `{exec, init, license, run, validate, watch}`
— six entries, zero false positives, and `license` is the only non-command. All
three `curlew license` occurrences are inside backticks (`SKILL.md:119`,
`exit-codes.md:44`, `failure-playbook.md:87`), so the scoping still fires on the
defect it must catch.

## Decisions Made (pipeline mode — resolved, not asked)

### D1. Exit 130 is added to the skill. The skill gains a row, it does not only lose two.

The DoD requires set equality in both directions, and behaviour #2 says
explicitly that a code the binary can return but the skill omits must fail. 130
qualifies. Final skill set = binary set = `{0,1,2,3,4,5,130}`.

**Why not scope the skill's table to `curlew run` instead?** Because M26-002 —
the task that immediately follows and that M25-002 waits on — requires *"all
four surfaces agree"* on one set. Three surfaces already publish
`{0,1,2,3,4,5,130}`. Scoping the skill would make it the one surface with a
different set and would render M26-002 unimplementable as written. Shipping this
task by breaking the next one is not a trade worth making.

Secondary: the skill is the only one of the four surfaces read by a machine that
acts on it unsupervised. An agent that meets exit 130 with no row does the worst
available thing — reports an unexplained crash to a user who merely pressed
Ctrl+C.

**The honest argument against, recorded.** The playbook table sits under
`## Failure playbook`, straight after a section opening *"After every `curlew
run`, three artifact streams exist"*, and every existing row's third column names
a `curlew run` artifact. The 130 row's artifact column can only be an em dash.
That is a genuine aesthetic cost — a row that does not share the table's frame.
It is aesthetic and not functional: the row still tells the agent something true,
and the alternative is a table that is silently incomplete.

**Adding 130 is not "rewriting guidance for codes that are correct"** (the
out-of-scope clause). That clause protects rows 0–5, which this plan does not
touch. Adding a missing row is mandated by behaviour #2.

### D2. The extractor lives in `internal/exitcodes`, not in a `_test.go`

`cmd/curlew/help_parity_test.go`'s `acceptedFlags` is the house precedent for an
AST-derived set living in a test file, and it works there because its failure
mode is *total*: collect zero literals and `len(seen) == 0` fires.

A call-graph walk with ident resolution fails **partially**. Break one edge and
the result is a smaller, non-empty, entirely plausible set that no emptiness
guard catches. That difference means the extractor needs its own unit tests
against fixtures whose right answer is known — which needs a `testdata/`
directory of synthetic Go packages and a `dir` parameter. A test file in package
`main` cannot have those without putting fake Go packages under
`cmd/curlew/testdata/` or hardcoding the answer for the real source, which is
circular.

Two further reasons: M26-002 needs the same set for the manual and the CLI
spec, and a `dir` parameter structurally excludes
`.claude/worktrees/sleepy-hawking-c63960/` — a second full checkout of this
repository, on branch `claude/sleepy-hawking-c63960`, carrying its own
`cmd/curlew/main.go` and `perf.go` (confirmed via `git worktree list`). Any
repo-root walk ingests it; `doc_prose_test.go`'s `goSourceText` already does,
harmlessly. For a set-equality walk it would be fatal — a stale worktree could
inject or hide an exit code.

### D3. All four contract statements are parsed and required to agree

The skill states its exit-code contract in **four** places, not three:

| # | Statement | Location | Shape | Column |
|---|---|---|---|---|
| 1 | SKILL.md failure playbook | `SKILL.md:110-119` | table | `Exit` |
| 2 | exit-codes.md master table | `exit-codes.md:8-17` | table | `Code` |
| 3 | exit-codes.md "How to read" | `exit-codes.md:32-44` | ordered list | — |
| 4 | failure-playbook.md sections | `failure-playbook.md:8-88` | `### Exit N —` headings | — |

Parsing one and calling it done reproduces the very defect being fixed, one
level down: SKILL.md would be held to the binary while `failure-playbook.md`
regrew a `### Exit 6` unnoticed. `cmd/curlew/doc_exit_codes_test.go:19` already
wrote the argument for the docs: *"Three copies of a contract drift pairwise:
any two can agree while the third goes its own way, and the binary is free to
disagree with all of them."*

All four agree today on `{0,1,2,3,4,5,6,9}`, so the agreement test is green from
the start. It is a regression guard, not a TDD driver — which is exactly why
mutation M2a exists to prove it works.

**Column names differ per statement** (`Exit` vs `Code`) — verified at
`SKILL.md:110` and `exit-codes.md:8`. A shared parser keyed on `"Code"` would
find no column in SKILL.md, return an empty set, and pass vacuously. Column name
is therefore per-statement, with a fatal when the named column is absent.

### D4. The observable's literal grep is kept; a word-anchored Go test is the real gate

The task's literal `! grep -ril "license\|feature gate\|tier"` is **correct as
written and as scoped** — `-r` over `.claude/skills/` never reaches the
repo-root `LICENSE`/`NOTICE`, and it currently matches exactly the four
offending files and will match zero after the fix. It is kept verbatim as the
observable.

Its weaknesses are latent rather than present, and the Go test must not inherit
them: `-i` plus bare `tier` matches `prettier`, `frontier`, `craftier`;
`license` matches an SPDX header a shipped artifact could plausibly acquire.
Neither occurs today.

**`internal/schema/parity_test.go:496`'s `tierWords` must NOT be reused.** It is
`[]string{"tier", "free", "solo", "professional", "enterprise", "upgrade",
"license", "licence"}` matched with `strings.Contains`, and its `"free"` entry
fires on `SKILL.md:161` — *"Edit it freely for your team's conventions"* —
today. Verified. A word-anchored regex is used instead, with `\btiers?\b` to
kill `prettier` and the colour words bound to `tier` so `freely` is safe.

#### New Code

```go
// Package exitcodes reads the exit codes cmd/curlew can return out of the
// source, so that every document publishing an exit-code table is held to the
// binary rather than to a list someone maintains.
//
// The walk is scoped to return statements reachable from a named root. That
// scoping is the point, not an implementation detail: cmd/curlew's
// exitCodeSeverity map contains a dead `6: 6, // feature gate` entry left by
// the removed licensing system, and a walk that collected "integers appearing
// near the word exit" would resurrect it as a code the binary can return.
package exitcodes

// Code is one exit code and where the walk found it. Provenance is not
// decoration: "the binary can return 7" is unactionable; "perf.go:141, in
// perfCmdOut" is a place to go.
type Code struct {
	Value int
	File  string // path as opened, e.g. "perf.go" when dir is "."
	Line  int
	Fn    string // function whose return statement carries it
	Depth int    // 0 = the root function itself
}

// Reachable parses every non-test .go file in dir, roots a call graph at the
// function named root, follows calls appearing in return position only,
// resolving local identifiers through their assignments, and collects the
// integer literals appearing in return statements.
//
// dir is a parameter rather than a repo-root walk so that a second checkout
// under .claude/worktrees/ cannot inject or hide a code.
func Reachable(dir, root string) ([]Code, error)

// Set reduces codes to sorted, deduplicated integers.
func Set(codes []Code) []int

// Find returns the first Code with the given value, for failure messages.
func Find(codes []Code, value int) (Code, bool)

// MaxDepth reports the deepest Depth in codes. A walk that collected nothing
// below its root resolved no calls at all, whatever its result looks like.
func MaxDepth(codes []Code) int

var (
	ErrRootNotFound = errors.New("root function not found")
	ErrNoSources    = errors.New("no non-test Go sources")
)
```

Errors wrap with `fmt.Errorf("context: %w", err)`; `ErrRootNotFound` and
`ErrNoSources` are sentinels per the project's error conventions.

#### Vacuity Guards

Each is stated in the house phrasing — *"… the \<extractor\> is broken, not the
\<subject\>"* — copied from `help_parity_test.go:130`.

| Guard | Condition | Message |
|---|---|---|
| Source, root | `ErrRootNotFound` | `no exit codes read from cmd/curlew: %v — the AST walk is broken, not the CLI` |
| Source, size | `len(got) < 2` | `the walk found %d exit code(s) in cmd/curlew (%v) — a CLI returns at least success and failure, so the AST walk is broken, not the CLI` |
| **Source, depth** | `MaxDepth(codes) == 0` | `every exit code came from %s itself (%v); nothing was collected through a return-position call — the call-graph walk is broken, not the CLI` |
| Skill, per statement | `len(codes) == 0` | `%s (%s): no exit codes read — the parser is broken, not the skill` |
| Skill, column | header lacks column | `%s: no %q column in header %v — the table was renamed, or the parser is reading the wrong table` |
| Skill, cell | `cellBad` | `%s: Code cell %q in row %d is neither an exit code nor an explicit non-code — the row is malformed, or the parser is` |

**The depth guard is the highest-value one in this design.** If return-position
call resolution breaks entirely, the walk still finds the literals in
`runWithWriters` itself — three `return 0` and the `default: return 1`. That is
`{0,1}`: non-empty, plausible, and it passes every emptiness and size guard.
`MaxDepth > 0` is what catches it.

#### New Code

```go
// licensingSurface matches the vocabulary of the removed five-tier system.
//
// Word-anchored on purpose. internal/schema/parity_test.go's tierWords uses
// strings.Contains over a bare "free", which fires on SKILL.md's "Edit it
// freely for your team's conventions"; \btiers?\b likewise keeps "prettier"
// and "frontier" out. The colour words appear only bound to "tier".
var licensingSurface = regexp.MustCompile(
	`(?i)\b(?:` +
		`licen[cs](?:e|es|ed|ing)` + `|` +
```

## Risks and Edge Cases

- **Risk: the plausible wrong answer `{0,1}`.** If return-position call
  resolution breaks, the walk still collects `runWithWriters`'s own three
  `return 0` and `default: return 1` — non-empty, size ≥ 2, passes naive
  guards. → **Mitigation:** the `MaxDepth(codes) > 0` guard (Step 2), plus
  `internal/exitcodes` fixture tests where the right answer is known
  independently.

- **Risk: the extractor silently reads the second checkout.**
  `.claude/worktrees/sleepy-hawking-c63960/` is a full worktree with its own
  `cmd/curlew/perf.go` (confirmed via `git worktree list`). A repo-root walk
  would ingest it and could inject or hide a code. → **Mitigation:** `Reachable`
  takes `dir`; callers pass `"."`. Never walk the repo root. If anything later
  must, skip `.claude`.

- **Risk: a shared table parser reads the wrong table.** `exit-codes.md` has two
  tables whose Code column differs in kind (integers vs `ERR_CEL_PARSE`), and
  `failure-playbook.md:96` likewise. → **Mitigation:** two defences, both used —
  scope by heading (`## Exit code table` vs `## CEL-specific codes …`), and
  classify every cell so `ERR_CEL_PARSE` lands in `cellBad` and fails loudly
  rather than yielding a silent empty set.

- **Risk: vacuous pass from a column rename.** SKILL.md's header is `Exit`;
  exit-codes.md's is `Code`. A parser keyed on one finds no column in the other
  and returns nothing. → **Mitigation:** per-statement column name plus the
  "no %q column in header" fatal.

- **Edge case: em dash encoding.** `exit-codes.md` uses U+2014 in Code cells and
  in prose. → **Handling:** the classifier compares the literal `—`, not an
  ASCII `-`; both are accepted as `cellNone`.

- **Edge case: `-run` regex collision.** `-run TestSkill_exit_codes_are_reachable`
  does not match `TestSkillAgent_*` — the underscore is literal. The observable's
  form is safe as written. `-run TestSkill` would match both; do not use it.

- **Edge case: `docs.Claims` pollution.** `internal/docs/inventory_test.go:37`
  calls `docs.Claims("../..")`, collecting any `"*.md"` string literal followed
  by further string literals in a `CallExpr` or `CompositeLit`. A statement table
  written as `{"exit-codes.md", []string{"Code", "Meaning"}}` registers a claim
  resolving against no table in `docs/`. It does not fail that test, but it
  corrupts its diagnostic. → **Handling:** declare the file name and header cells
  as package-level consts and reference them by identifier, keeping them out of
  one literal.

- **Edge case: 130 cannot be triggered by an in-process scenario test.** It needs
  a real signal. → **Handling:** this task derives it from source, which is the
  point; `TestPerfCmd_ContextCancelExitCode130` already covers it behaviourally,
  and `doc_exit_codes_test.go:166` documents the same carve-out.

- **Noted, out of scope:** `internal/schema/parity_test.go`'s
  `TestSchema_descriptions_are_tier_free` iterates `descriptionsIn`'s map with no
  vacuity guard — if that walk ever returned empty, it would report clean having
  read nothing. That is the failure mode `internal/backlog/backlog.go`'s package
  comment names. It belongs to M26-002 or its own task, not here.
