# Implementation Plan: M18-003

## Overview
Stand up the GDPR data inventory as a code-and-docs pair. Two `[GdprIncluded]` / `[GdprAnonymise]` property-level attributes get applied to the user-attributable columns on the 13 enumerated EF entities; a new `GdprAttributeScanner` reflects across the entity assembly and emits a `GdprBundleManifest` that downstream slices (M18-004 export, M18-006 anonymiser) consume directly. `docs/security/data-inventory.md` lands as the human-reviewable decision matrix; a `GdprInventoryCoverageTests` CI guard fails when a future user-attributable entity is added without GDPR attributes (closes the lint-on-new-table gap); a doc-vs-code consistency test asserts every row in the inventory matches the scanner's disposition.

## Architecture Decisions

Pipeline-mode decisions (no user prompt available):

1. **Disposition enum — exactly four values.** The YAML enumerates the four dispositions explicitly:
   - `InExportInDeletionHard` — row included in `/me/export` JSON bundle; row is hard-deleted when the user is deleted (typical for user-owned auth tokens and the user's own membership rows).
   - `InExportInDeletionAnonymise` — row included in the export; on deletion, user-attribution columns are anonymised (`ActorId → NULL`, `ActorEmail → deleted-user-{first8(sha256(user_id+org_id))}`). Used by `OrganizationAuditLogEntry`.
   - `ExcludedFromExportAnonymisedInDeletion` — row not exported (org-scoped business record someone else may still need); on deletion the *creator's* UserId is anonymised but the row survives. Used by `Schedule.CreatedBy`, `NotificationRule.CreatedBy`, `CustomRole.CreatedBy`, `CoordinatorJob.CreatedBy`, `TeamVault.CreatedBy` + `UpdatedBy`, `OrganizationMember.InvitedBy` (nullable already).
   - `ExcludedFromBoth` — row neither exported nor anonymisable here (no user-attribution column to act on; row is org-scoped). Used to record the explicit decision for `GithubInstallation` and `GitLabInstallation`, which the YAML enumerates among the 13 tables but which carry no `UserId`/`ActorId`/`CreatedBy` column. The two tables still appear in the manifest and the inventory doc with `ExcludedFromBoth` as the disposition — making the decision visible rather than silently dropping them.

2. **Per-property attributes drive the manifest, not per-entity.** `[GdprIncluded(Disposition.X)]` and `[GdprAnonymise(AnonymiseAs.NullOrToken)]` are attached to *properties* (the `UserId`/`ActorId`/`CreatedBy` columns), not classes. This is the shape the YAML behaviors describe ("discovers every property tagged [GdprIncluded]"). The scanner emits one manifest entry per `(Entity, Property, Disposition)` triple. For the two `ExcludedFromBoth` tables (GitHub/GitLab installations) there is no user-attribution property to tag; the scanner is taught to synthesise a placeholder triple from a class-level `[GdprTable(ExcludedFromBoth)]` attribute so the manifest's "13 tables" cardinality is preserved.

3. **Two attributes, separate concerns.**
   - `[GdprIncluded]` (carries `Disposition` enum) declares export/deletion intent.
   - `[GdprAnonymise]` (carries `AnonymiseAs` enum: `NullOrToken` for `Guid?` properties, `DeletedUserToken` for `string?` properties) declares how the column is anonymised when the row is `InExportInDeletionAnonymise` or `ExcludedFromExportAnonymisedInDeletion`. It's optional; absence means the column is hard-deleted along with the row (i.e. `InExportInDeletionHard`).
   - This split lets M18-006 consume `[GdprAnonymise]` directly to know "NULL the Guid column" vs "substitute the deterministic token on the string column" without re-parsing `[GdprIncluded]`'s disposition.

4. **Scanner reflects from `typeof(AppDbContext).Assembly`.** Walks every public `DbSet<T>` property on the context, then every `T` property carrying a Gdpr attribute. Yields a deterministic ordering (alphabetical by entity name, then property name) so the manifest is reproducible and the doc-vs-code consistency test can diff without flakiness. Output is a `record GdprBundleManifest(IReadOnlyList<GdprManifestEntry> Entries)`; one entry per table (aggregating its properties).

5. **`GdprInventoryCoverageTests` enumerates the entity assembly, not a hardcoded list.** The CI-guard test reflects over every `DbSet<T>` on `AppDbContext` and applies a *user-attribution heuristic*: a class is "user-attributable" if it carries any property named `UserId`, `ActorId`, `CreatedBy`, `UpdatedBy`, `InvitedBy`, `UploadedBy`, `OwnerId`, or `RequesterIp` (last one carved out because `PasswordResetToken.RequesterIp` is forensic-only and not a user-attribution column for GDPR purposes — heuristic explicitly excludes it). For each user-attributable class found, the test asserts at least one property carries `[GdprIncluded]` OR the class carries `[GdprTable(ExcludedFromBoth)]`. Failure mode: test name in the failure message names the offending entity, suggesting which attribute to add. This is exactly the "future-drift gap" the YAML calls out.

6. **`Organization.OwnerId` is intentionally excluded from the 13.** The YAML enumerates 13 specific entities. `Organization` (with `OwnerId`) is NOT among them — and rightly so: a user's org-owner status is structural data the org-deletion path handles, not the user-deletion path. The coverage test must therefore *exclude* `Organization` from its "user-attributable" set; we add an opt-out via `[GdprTable(NotUserAttributable)]` on `Organization` to make the decision explicit.

   Other entities surfaced by the heuristic but NOT in the 13: `Result.UploadedBy`, `OrganizationInvitation.InvitedBy`, `Trial.UserId`. The YAML scope is explicit ("the 13 enumerated entities"); these three are tagged `[GdprTable(NotUserAttributable)]` with a clarifying remark in the attribute usage (e.g. `Result.UploadedBy` is org-scoped run metadata, scope-restricted to the v4-4 follow-up; `Trial.UserId` is short-lived per-feature; `OrganizationInvitation.InvitedBy` is org-internal). Coverage test skips them. Doc-vs-code consistency test only asserts the 13 enumerated tables match — additional excluded tables don't pollute the inventory.

7. **`User` entity gets `[GdprIncluded(InExportInDeletionHard)]` on its `Id` property.** The user is the data subject; its row is exported (profile fields), and the row itself is hard-deleted on finalisation. Disposition is recorded against `User.Id` so the manifest emits a `User` entry. (Alternative — recording disposition class-level on `User` — was considered but rejected for consistency: every other entity records via property attributes.)

8. **`docs/security/data-inventory.md` is structured Markdown.** Columns per YAML: `Table | Owner | InExport | InDeletion | Retention | Notes`. One row per table (13 data rows + a header + a separator). Owner column: short identifier (`auth`, `org`, `audit`, `notify`, `vault`, etc.) — not a person; this is the team/subsystem owner for the GDPR decision matrix. Retention column: free-text duration ("until rotated", "session-bound", "until user deleted", "per-org retention policy" for audit log) — not a number; the audit-log retention is governed separately by M18-002. The Notes column carries the disposition phrase verbatim from the enum so the consistency test can substring-match it.

9. **Doc-vs-code consistency test.** New `GdprInventoryDocConsistencyTests` parses the Markdown table at `docs/security/data-inventory.md` (simple `|`-split parser; no external library), maps each row to a (TableName, Disposition) tuple via the Notes column, and asserts the set equals the scanner manifest's 13 entries. Failure mode: prints the symmetric difference of the two sets. Test marked `[Trait("Category", "DocConsistency")]` so it can be filtered out of fast inner-loop test runs if needed (not in scope for this slice, but the trait makes the option available).

10. **No EF Core migration needed.** Attributes are reflection-only metadata; no column changes. The migration burden lands in M18-005 (`User.PendingDeletionAt`/`AnonymisedAt`) and M18-004 (export-request table). This slice is pure-CSharp + docs.

11. **Namespace layout matches existing conventions.**
    - `src/ApiTool.Backend/Data/GdprAttributes/GdprIncludedAttribute.cs`
    - `src/ApiTool.Backend/Data/GdprAttributes/GdprAnonymiseAttribute.cs`
    - `src/ApiTool.Backend/Data/GdprAttributes/GdprTableAttribute.cs` (for the class-level `ExcludedFromBoth`/`NotUserAttributable` opt-outs)

12. **No DI wiring needed.** `GdprAttributeScanner` is a static-class with a single pure `Scan(Assembly)` method (or instance with no DI dependencies). M18-004 and M18-006 consume it lazily via a static cache: `GdprAttributeScanner.Manifest` lazy-loaded once per process. This avoids surfacing a DI registration here for an artefact that has no runtime dependencies.

```csharp
// GdprDisposition.cs
namespace ApiTool.Backend.Data.GdprAttributes;

/// <summary>GDPR disposition for a user-attributable column on an EF entity.</summary>
public enum GdprDisposition
{
    /// <summary>Row appears in /me/export; row is hard-deleted on user deletion.</summary>
    InExportInDeletionHard,

    /// <summary>Row appears in /me/export; the user-attribution column is anonymised on deletion.</summary>
    InExportInDeletionAnonymise,

    /// <summary>Row is excluded from export; the column is anonymised on deletion (row survives).</summary>
    ExcludedFromExportAnonymisedInDeletion,

    /// <summary>Row is excluded from both export and deletion path (no user-attribution column).</summary>
    ExcludedFromBoth,
}
```

```csharp
namespace ApiTool.Backend.Compliance.Gdpr;

public sealed record GdprColumnEntry(
    string PropertyName,
    GdprDisposition Disposition,
    AnonymiseAs? AnonymiseAs);

public sealed record GdprManifestEntry(
    string TableName,
    Type EntityType,
    GdprDisposition Disposition,
    IReadOnlyList<GdprColumnEntry> Columns);

public sealed record GdprBundleManifest(IReadOnlyList<GdprManifestEntry> Entries)
{
    public IEnumerable<GdprManifestEntry> InExport =>
        Entries.Where(e =>
            e.Disposition is GdprDisposition.InExportInDeletionHard
                          or GdprDisposition.InExportInDeletionAnonymise);

    public IEnumerable<GdprManifestEntry> InDeletionHard =>
        Entries.Where(e => e.Disposition == GdprDisposition.InExportInDeletionHard);

    public IEnumerable<GdprManifestEntry> InDeletionAnonymise =>
        Entries.Where(e =>
            e.Disposition is GdprDisposition.InExportInDeletionAnonymise
                          or GdprDisposition.ExcludedFromExportAnonymisedInDeletion);

    public IEnumerable<GdprManifestEntry> ExcludedFromBoth =>
        Entries.Where(e => e.Disposition == GdprDisposition.ExcludedFromBoth);

    public GdprManifestEntry? FindByEntity(Type t) =>
        Entries.FirstOrDefault(e => e.EntityType == t);
}

public static class GdprAttributeScanner
{
    public static GdprBundleManifest Scan(Assembly assembly)
    {
        var entries = new List<GdprManifestEntry>();

        // Iterate every public class in the assembly under Data.Entities namespace.
        foreach (var type in assembly.GetTypes()
            .Where(t => t.IsClass && !t.IsAbstract && t.Namespace == "ApiTool.Backend.Data.Entities")
            .OrderBy(t => t.Name, StringComparer.Ordinal))
        {
            var columns = type.GetProperties(BindingFlags.Public | BindingFlags.Instance)
                .Select(p => new
                {
                    Property = p,
                    Included = p.GetCustomAttribute<GdprIncludedAttribute>(),
                    Anonymise = p.GetCustomAttribute<GdprAnonymiseAttribute>(),
                })
                .Where(x => x.Included is not null || x.Anonymise is not null)
                .Select(x => new GdprColumnEntry(
                    x.Property.Name,
                    x.Included?.Disposition
                        ?? GdprDisposition.InExportInDeletionAnonymise, // default for column tagged only with [GdprAnonymise]
                    x.Anonymise?.Kind))
                .OrderBy(c => c.PropertyName, StringComparer.Ordinal)
                .ToList();

            var classAttr = type.GetCustomAttribute<GdprTableAttribute>();

            if (columns.Count == 0 && classAttr is null)
                continue; // not user-attributable; ignored by scanner

            if (classAttr?.Kind == GdprTableKind.NotUserAttributable)
                continue; // explicit opt-out

            GdprDisposition tableDisposition;
            if (classAttr?.Kind == GdprTableKind.ExcludedFromBoth)
                tableDisposition = GdprDisposition.ExcludedFromBoth;
            else
                // Table's disposition is the "strongest" disposition among its columns
                // (InExportInDeletionHard > InExportInDeletionAnonymise > ExcludedFromExportAnonymisedInDeletion > ExcludedFromBoth)
                tableDisposition = columns
                    .Select(c => c.Disposition)
                    .DefaultIfEmpty(GdprDisposition.ExcludedFromBoth)
                    .Min(d => (int)d) is int min ? (GdprDisposition)min
                    : GdprDisposition.ExcludedFromBoth;

            entries.Add(new GdprManifestEntry(
                TableName: TableNameOf(type),
                EntityType: type,
                Disposition: tableDisposition,
                Columns: columns));
        }

        return new GdprBundleManifest(entries);
    }

    public static GdprBundleManifest Manifest { get; } = Scan(typeof(AppDbContext).Assembly);

    private static string TableNameOf(Type t) =>
        // Hardcoded snake-case map matching AppDbContext.OnModelCreating ToTable(...) calls.
        // Reading EF model metadata would require a DbContext instance; this mirror is acceptable
        // and the consistency test catches drift.
        t.Name switch
        {
            nameof(User) => "users",
            nameof(RefreshToken) => "refresh_tokens",
            nameof(OrganizationMember) => "organization_members",
            nameof(EmailVerificationToken) => "email_verification_tokens",
            nameof(PasswordResetToken) => "password_reset_tokens",
            nameof(NotificationRule) => "notification_rules",
            nameof(CustomRole) => "organization_custom_roles",
            nameof(Schedule) => "schedules",
            nameof(CoordinatorJob) => "coordinator_jobs",
            nameof(TeamVault) => "team_vaults",
            nameof(OrganizationAuditLogEntry) => "organization_audit_log",
            nameof(GithubInstallation) => "github_installations",
            nameof(GitLabInstallation) => "gitlab_installations",
            _ => t.Name.ToLowerInvariant(),
        };
}
```

```csharp
public class GdprInventoryCoverageTests
{
    private static readonly HashSet<string> UserAttributionPropertyNames = new(StringComparer.Ordinal)
    {
        "UserId", "ActorId", "CreatedBy", "UpdatedBy",
        "InvitedBy", "UploadedBy", "OwnerId",
        // Excluded: RequesterIp (forensic, not GDPR attribution per Decision 5)
    };

    public static IEnumerable<object[]> EntityTypes() =>
        typeof(AppDbContext).Assembly.GetTypes()
            .Where(t => t.IsClass && !t.IsAbstract && t.Namespace == "ApiTool.Backend.Data.Entities")
            .Select(t => new object[] { t });

    [Theory]
    [MemberData(nameof(EntityTypes))]
    public void Every_user_attributable_entity_is_tagged(Type entityType)
    {
        bool hasUserAttributionColumn = entityType
            .GetProperties(BindingFlags.Public | BindingFlags.Instance)
            .Any(p => UserAttributionPropertyNames.Contains(p.Name));

        if (!hasUserAttributionColumn)
            return; // not user-attributable; nothing to check

        bool optedOut = entityType.GetCustomAttribute<GdprTableAttribute>()
            is { Kind: GdprTableKind.NotUserAttributable };
        if (optedOut)
            return;

        bool excludedFromBoth = entityType.GetCustomAttribute<GdprTableAttribute>()
            is { Kind: GdprTableKind.ExcludedFromBoth };
        if (excludedFromBoth)
            return;

        bool tagged = entityType
            .GetProperties(BindingFlags.Public | BindingFlags.Instance)
            .Any(p =>
                p.GetCustomAttribute<GdprIncludedAttribute>() is not null
                || p.GetCustomAttribute<GdprAnonymiseAttribute>() is not null);

        tagged.Should().BeTrue(
            $"entity {entityType.Name} carries a user-attribution column but has no " +
            $"[GdprIncluded] / [GdprAnonymise] / [GdprTable(...)] attribute — " +
            $"add the appropriate GDPR attribute (see docs/security/data-inventory.md).");
    }
}
```

## Risks and Edge Cases

- **Risk:** Reflection-based scanner picks up types from third-party assemblies referenced by `AppDbContext.Assembly`. → **Mitigation:** Filter to `Namespace == "ApiTool.Backend.Data.Entities"` (explicit namespace match). Tests assert exact count = 13.
- **Risk:** Table-name mapping in scanner drifts from `AppDbContext.OnModelCreating`. → **Mitigation:** `Table_names_match_AppDbContext_ToTable_calls` test asserts a representative sample; doc-consistency test catches any further drift on the Notes-column path.
- **Risk:** Markdown parser in doc-consistency test is fragile (whitespace variations, GFM extensions). → **Mitigation:** Parser is line-oriented, splits on `|`, trims, drops header/separator/empty rows. The doc author writes the table by hand and the test exercises exactly the canonical shape committed in this slice.
- **Risk:** `GdprAttributeScanner.Manifest` static is evaluated eagerly on first access — if any consumer touches it during DI bootstrap before `AppDbContext` is loaded, the assembly scan could miss types. → **Mitigation:** `typeof(AppDbContext).Assembly` forces the entity assembly to load; the manifest is a pure value with no DI side-effects. Tests assert idempotency.
- **Edge case:** `OrganizationMember.InvitedBy` is nullable (`Guid?`). → **Handling:** `[GdprAnonymise(NullOrToken)]` is the correct annotation; M18-006 will NULL the column directly. Test asserts the kind.
- **Edge case:** `TeamVault` has *two* user-attribution columns (`CreatedBy` and `UpdatedBy`). → **Handling:** Scanner emits two `GdprColumnEntry` rows under the single `TeamVault` manifest entry. Tests assert column count.
- **Edge case:** Adding a new entity without any user-attribution column. → **Handling:** Coverage test short-circuits (returns) — no attribute is required. Documented in coverage-test source comment.
- **Edge case:** Renaming an entity type without updating the table-name map. → **Handling:** `Table_names_match_AppDbContext_ToTable_calls` test fails loudly with the entity name and expected table name.
- **Risk:** The two `ExcludedFromBoth` tables (GitHub/GitLab installations) are not strictly "user-attributable" — listing them as such may confuse readers. → **Mitigation:** The Notes column in `data-inventory.md` explicitly says "no user-attribution column." The disposition value `ExcludedFromBoth` is itself the disambiguator.
