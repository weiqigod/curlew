# Implementation Plan: M13-003

## Overview

Register the twelve `$faker.*` location-data dynamic functions
(`address`, `street`, `streetName`, `city`, `state`, `stateAbbr`,
`zipCode`, `country`, `countryCode`, `latitude`, `longitude`,
`timezone`) on the existing `Registry` in `internal/variable/dynamic.go`.
This slice ships seven new package-scope pools (cities, street-names,
street-suffixes, parallel state names + abbreviations indexed 1:1,
parallel country names + ISO 3166-1 alpha-2 codes indexed 1:1, and
common IANA timezones), composes higher-level helpers (`address`,
`street`) from the lower-level draws, and adds twelve `noArgs`
registrations. No new policy hooks (no auto-sensitive returns, no
sensitive-arg indices) — purely additive surface area on the existing
M13-001 dotted-namespace dispatch and the M13-002 registration pattern.

### How the existing `noArgs` registration pattern works (M13-002 mirror)

Each personal-data function at `dynamic.go:430-479` is registered as
`r.funcs["faker.<name>"] = noArgs("faker.<name>", func(rng *rand.Rand) string { … })`.
The `noArgs` wrapper (line 84) rejects argument-bearing calls with a
structured `DYNFN_ARITY` error. Closures route all randomness through
`intn(rng, n)` (line 630), which is the same dispatch surface that
seeded-vs-crypto-rand routing rides on. New location functions follow
this exact shape — twelve `noArgs` registrations, one for each.

### Pool composition for `address` and `street`

`$faker.address` per SPECIFICATION.md:778 is `<num> <streetName>, <city>, <stateAbbr> <zip>`
— a composition of four lower-level draws (street, city, stateAbbr,
zipCode) joined with `, ` and one space. Two design choices:

1. **Compose at registration time, not at the closure level.** The
   `address` closure draws `intn` four times (one for the building
   number, one for the street-suffix-paired street, one for the city,
   one for the paired state index, one for zip), formatting the result
   inline. This gives byte-equality under `--seed=42` deterministically:
   the order of `intn` calls is fixed by source-code position. A given
   call to `$faker.address` consumes a fixed number of RNG draws.

2. **`state` + `stateAbbr` 1:1 pool alignment.** The two lookups must
   come from parallel slices indexed at the same position so a single
   resolved address is internally consistent: "Springfield, IL" not
   "Springfield, CA". Per behavior 5 in the task YAML, **the spec is
   weaker than the test**: spec says `state` is a full name and
   `stateAbbr` is the 2-letter ISO code; behavior 5 adds "the two pools
   are aligned 1:1 by index". This plan honours behavior 5 and ships
   parallel `stateNames` / `stateAbbrs` slices with `len(stateNames) ==
   len(stateAbbrs)` asserted in tests.
   **Subtle point:** `$faker.state` and `$faker.stateAbbr`, when called
   independently, draw separate `intn` indices and therefore do not
   render the same row. The 1:1-alignment property is about the
   *pools*, not the *call sequence*. Behavior 5 phrasing is "for the
   same seeded RNG state … the two pools are aligned 1:1 by index" —
   this means the pool-length-equality property, exercised via an
   explicit test that asserts `len(stateNames) == len(stateAbbrs)` and
   that the indices line up (e.g. `stateNames[i]="Illinois" ↔
   stateAbbrs[i]="IL"`).
   Inside `$faker.address`, both the full name and the abbr can be
   resolved from a single `intn(len(stateNames))` draw — but the
   address composition only embeds the abbr (per SPEC), so a single
   draw is sufficient there too.
   Same argument applies to country + countryCode.

### Spec-vs-behavior tension on lat/long return type

SPECIFICATION.md:787-788 lists `latitude` and `longitude` as **Return
Type: number** with example `40.7128`. The task YAML observable says
"$faker.latitude is a string-encoded float in [-90, 90] with 4
decimals" and the dry-run note adds "lat is a numeric JSON value (no
quotes — note this is consistent with the rendered-string-into-JSON
convention used by other numeric faker functions; see scope)."

**Decision:** `DynFunc` returns `string` by contract — every dynamic
function does. The closure formats the float via
`strconv.FormatFloat(v, 'f', 4, 64)`. Whether the rendered string lands
in a JSON document **with** quotes (as a string) or **without** (as a
JSON number) depends on how it is interpolated, not on the function
return type:

- `{"lat":{{$faker.latitude}}}` — placeholder is a bare token in a JSON
  numeric position, so the rendered string `"40.7128"` substitutes in
  unquoted, producing `{"lat":40.7128}` — a valid JSON number.
- `{"lat":"{{$faker.latitude}}"}` — placeholder is inside a JSON string,
  so the result is `{"lat":"40.7128"}` — a JSON string.

This is the same convention as `$randomInt` and `$randomFloat` (see
the existing `randomFloat` registration at dynamic.go:203-206). No
special-case JSON-numeric handling is needed in the registry. Tests
assert the string is parseable as a float and falls in range.

### Range mapping for `latitude` and `longitude`

`float64InRange(rng)` returns `[0, 1)` — a uniform float. To map to
`[-90, 90]` we use `(2*v - 1) * 90`; for `[-180, 180]` we use
`(2*v - 1) * 180`. The result is in `[-90, 90)` and `[-180, 180)`
respectively. The task YAML observable phrases the range as `[-90,
90]` (closed) and `[-180, 180]`; behaviors 9 and 10 say "in the range
[-90.0000, 90.0000]". Half-open vs. closed is acceptable here: the
test assertion `f >= -90 && f <= 90` is satisfied by a half-open
sample. **Decision:** use `(2*v - 1) * range`; truncate via
`FormatFloat(_, 'f', 4, 64)` which rounds to 4 decimals.

`FormatFloat`'s rounding can produce values that, after rounding, fall
exactly on the boundary (e.g. 89.99996 → "90.0000"). This is still in
range. The test allows the closed boundary explicitly.

### Timezone pool

The timezone pool must be a list of valid IANA identifiers accepted by
`time.LoadLocation`. The shipped pool is small (≈30 entries) and
covers the major regions — North America, Europe, Asia, Oceania, etc.
A test calls `time.LoadLocation(val)` on each pool entry to enforce
the IANA-valid contract. An additional test exercises a single live
draw to satisfy behavior 11.

### ZIP code

Per SPECIFICATION.md:784 the example is `"62701"` (a real Springfield,
IL ZIP). The behavior 6 contract is "result matches `^\d{5}$`". The
plan uses `fmt.Sprintf("%05d", intn(rng, 100000))` — uniformly random
5-digit string. Per the scope section, "per-state ZIP-code prefix
realism" is explicitly out of scope.

### Country pool

A modest pool of ~30 country names with their matching ISO 3166-1
alpha-2 codes (US/USA, GB, DE, FR, JP, …). Same parallel-slice
arrangement as state. Behavior 8: "result matches `^[A-Z]{2}$` and is
a valid ISO 3166-1 alpha-2 code" — the format check is regex-based,
the validity check is membership in the shipped pool (since the pool
is curated to be valid alpha-2 codes).

// TestFakerLocation_PoolAlignment proves the parallel-slice invariant
// for state and country pools (behavior 5 + behavior 8 prerequisite).
// Lives in internal/variable/dynamic_test.go in a new section after
// the personal-data tests (after line 2400).
func TestFakerLocation_PoolAlignment(t *testing.T) {
    if len(stateNames) != len(stateAbbrs) {
        t.Fatalf("stateNames (%d) and stateAbbrs (%d) must be the same length",
            len(stateNames), len(stateAbbrs))
    }
    if len(countryNames) != len(countryCodes) {
        t.Fatalf("countryNames (%d) and countryCodes (%d) must be the same length",
            len(countryNames), len(countryCodes))
    }
    // Spot-check known pairings to catch index-skew regressions where
    // someone reorders one slice but forgets the other.
    if stateNames[0] != "Alabama" || stateAbbrs[0] != "AL" {
        t.Errorf("stateNames[0]/stateAbbrs[0] = %q/%q, want Alabama/AL",
            stateNames[0], stateAbbrs[0])
    }
    if stateNames[12] != "Illinois" || stateAbbrs[12] != "IL" {
        t.Errorf("stateNames[12]/stateAbbrs[12] = %q/%q, want Illinois/IL",
            stateNames[12], stateAbbrs[12])
    }
    if countryNames[0] != "United States" || countryCodes[0] != "US" {
        t.Errorf("countryNames[0]/countryCodes[0] = %q/%q, want United States/US",
            countryNames[0], countryCodes[0])
    }
}

    // $faker.* location-data family — M13-003 (en-US only).
    // SPECIFICATION.md:774-789. All 12 functions are deterministic under
    // --seed via intn / float64InRange. Pool invariants (parallel
    // stateNames/stateAbbrs, countryNames/countryCodes) are asserted in
    // TestFakerLocation_PoolAlignment.
    r.funcs["faker.streetName"] = noArgs("faker.streetName", func(rng *rand.Rand) string {
        return streetNames[intn(rng, len(streetNames))] + " " +
            streetSuffixes[intn(rng, len(streetSuffixes))]
    })
    r.funcs["faker.street"] = noArgs("faker.street", func(rng *rand.Rand) string {
        num := intn(rng, 9999) + 1
        return fmt.Sprintf("%d %s %s", num,
            streetNames[intn(rng, len(streetNames))],
            streetSuffixes[intn(rng, len(streetSuffixes))])
    })
    r.funcs["faker.city"] = noArgs("faker.city", func(rng *rand.Rand) string {
        return cities[intn(rng, len(cities))]
    })
    r.funcs["faker.state"] = noArgs("faker.state", func(rng *rand.Rand) string {
        return stateNames[intn(rng, len(stateNames))]
    })
    r.funcs["faker.stateAbbr"] = noArgs("faker.stateAbbr", func(rng *rand.Rand) string {
        return stateAbbrs[intn(rng, len(stateAbbrs))]
    })
    r.funcs["faker.zipCode"] = noArgs("faker.zipCode", func(rng *rand.Rand) string {
        return fmt.Sprintf("%05d", intn(rng, 100000))
    })
    // $faker.address composes a full US address: <num> <street>, <city>, <stateAbbr> <zip>.
    // The state-abbr lookup uses a single intn over the parallel pool so
    // the rendered address pairs correctly with the abbr (Springfield, IL).
    // The full-name $faker.state and the abbr $faker.stateAbbr are
    // independent draws when called separately — see plan Code Exploration.
    r.funcs["faker.address"] = noArgs("faker.address", func(rng *rand.Rand) string {
        num := intn(rng, 9999) + 1
        street := streetNames[intn(rng, len(streetNames))] + " " +
            streetSuffixes[intn(rng, len(streetSuffixes))]
        city := cities[intn(rng, len(cities))]
        stateIdx := intn(rng, len(stateAbbrs))
        zip := fmt.Sprintf("%05d", intn(rng, 100000))
        return fmt.Sprintf("%d %s, %s, %s %s", num, street, city, stateAbbrs[stateIdx], zip)
    })
    r.funcs["faker.country"] = noArgs("faker.country", func(rng *rand.Rand) string {
        return countryNames[intn(rng, len(countryNames))]
    })
    r.funcs["faker.countryCode"] = noArgs("faker.countryCode", func(rng *rand.Rand) string {
        return countryCodes[intn(rng, len(countryCodes))]
    })
    // Latitude/longitude: float64InRange returns [0, 1); map to centred range
    // via (2v - 1) * scale; format with 4 decimal places per SPEC:787-788.
    // Return type is string by DynFunc contract — JSON-numeric vs JSON-string
    // is decided by the placeholder's surrounding quotes at interpolation
    // time, matching $randomInt / $randomFloat behavior.
    r.funcs["faker.latitude"] = noArgs("faker.latitude", func(rng *rand.Rand) string {
        return strconv.FormatFloat((2*float64InRange(rng)-1)*90, 'f', 4, 64)
    })
    r.funcs["faker.longitude"] = noArgs("faker.longitude", func(rng *rand.Rand) string {
        return strconv.FormatFloat((2*float64InRange(rng)-1)*180, 'f', 4, 64)
    })
    r.funcs["faker.timezone"] = noArgs("faker.timezone", func(rng *rand.Rand) string {
        return ianaTimezones[intn(rng, len(ianaTimezones))]
    })
}

func isLatLong(lo, hi float64) func(t *testing.T, val string) {
    return func(t *testing.T, val string) {
        t.Helper()
        f, err := strconv.ParseFloat(val, 64)
        if err != nil {
            t.Errorf("value %q is not a parseable float: %v", val, err)
            return
        }
        if f < lo || f > hi {
            t.Errorf("value %q (%.4f) not in range [%.4f, %.4f]", val, f, lo, hi)

            t.Errorf("value %q does not have exactly 4 decimal places", val)
        }
    }
}

## Risks and Edge Cases

- **Risk: state/stateAbbr pool drift.** If someone reorders one slice
  but forgets the other, addresses will pair the wrong state name with
  the wrong abbreviation. **Mitigation:** `TestFakerLocation_PoolAlignment`
  asserts length equality plus three index-pinned spot checks (Alabama/AL
  at index 0, Illinois/IL at index 12, United States/US at index 0).
  This is the cheapest possible regression net for a pool-rewrite mistake.
- **Risk: timezone typo silently passes the regex.** `America/New_York`
  is structurally similar to `America/New_york` (a typo) but only the
  first is loadable. **Mitigation:**
  `TestRegistry_FakerLocation_TimezonePool_AllValid` calls
  `time.LoadLocation` on every shipped entry — typos surface at test
  time, not at runtime in a customer's collection.
- **Risk: `(2v - 1) * 90` boundary.** When `float64InRange` returns
  exactly 0, the result is `-90.0000`; when it approaches 1, the result
  approaches but does not reach `+90.0000` (because float64 can't
  represent the post-rounding boundary perfectly). After
  `FormatFloat(_, 'f', 4, 64)` rounds, values in `[89.99995, 89.99999…]`
  round to `90.0000`. **Mitigation:** test asserts `f >= -90 && f <= 90`
  (closed interval); the boundary case is acceptable per behavior 9/10's
  closed-interval phrasing.
- **Risk: `$faker.address` regex too strict.** City and street names
  contain spaces (e.g. "Mount Vernon", "New Hampshire"). The pattern
  `[A-Za-z][A-Za-z ]*` accepts internal spaces but the pattern must
  not also allow leading/trailing spaces. **Mitigation:** The regex
  `[A-Za-z][A-Za-z ]*` requires the first character to be a letter and
  allows only `letter+letter-or-space` thereafter. Trailing space would
  require a final space before the comma — the source data doesn't
  contain trailing whitespace, so this is fine.
- **Edge case: behavior 11 timezone validity.** "Valid IANA identifier
  accepted by `time.LoadLocation`" is the contract. The Go runtime
  loads timezones from `$GOROOT/lib/time/zoneinfo.zip` or the system
  tzdata; CI environments that strip tzdata can fail. **Mitigation:**
  the standard Go test environment ships with the embedded zoneinfo,
  and the project CI uses the standard `golang:1.24` image. If tzdata
  is ever an issue in a constrained env, the test message names
  `time.LoadLocation` so the failure is self-diagnosing.
- **Edge case: `$faker.country` and `$faker.countryCode` independence.**
  Behavior 7 + 8 don't require the country and its code to be
  consistent within a single Evaluate call (only `$faker.address`
  embeds the abbr). **Decision:** ship them as independent draws,
  matching the personal-data family's independent draws for first/last
  name. If a future task wants paired country output, it can add a
  composed `$faker.locale` or similar.
- **Edge case: per-request memoization.** `Registry.Evaluate` already
  caches results per (name, args) within a request via the `cache`
  parameter. Two `{{$faker.address}}` placeholders in the same request
  resolve to the same value — this is a documented property
  (MANUAL.md:1252) and is the behavior we want. New tests don't need
  to assert this.
