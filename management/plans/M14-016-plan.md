# Implementation Plan: M14-016

## Overview

Adds an `IGitHubAppKeyProvider` interface plus two implementations — `FileGitHubAppKeyProvider` (self-hosted, PEM on disk mode 0600) and `GoogleKmsGitHubAppKeyProvider` (SaaS, `RSA_SIGN_PKCS1_2048_SHA256` HSM key) — that mint short-lived RS256 App JWTs (`iat = now-60s`, `exp = iat+540s`) on demand. RS256 is mandated by GitHub for App authentication and is fully type-isolated from the existing ES256 `IKeyProvider`. Ships an internal `/internal/github-app/jwt-self-test` probe and a `BearerTokenRedactor` log filter that redacts `Authorization: Bearer eyJ...` and `ghs_*` patterns.

## Key Architectural Decisions

1. **Two-interface separation enforced by the type system.** `IGitHubAppKeyProvider` lives in a new `ApiTool.Backend.GitHub` namespace with no shared base class with `IKeyProvider` (Licensing.Keys). RS256 lives **only** behind this interface. Any future "harmonisation" attempt is a compile error.
2. **RS256 fixed at the namespace level — no algorithm parameterisation.** The interface's contract is "RS256 App JWT" — there is no `Algorithm` property and no algorithm allowlist. GitHub mandates RS256; offering choice would invite mis-configuration.
3. **No DB row for the GitHub App key.** Unlike the License-JWT `signing_keys` table (which carries verifying keys for JWKS rotation), App JWTs are never verified by us — only by GitHub. The kid is therefore not part of the JWT header (GitHub does not require it). The PEM/KMS key is configured statically per deployment; rotation is operator-driven (re-register App with new key).
4. **`GitHubAppOptions` is a brand-new options class.** Bound under section `Curlew:GitHubApp`. Spelled `GITHUB_APP__*` in env vars (per task observable). It is **not** a sub-section of `KeyProviderOptions` because the two are unrelated keys.
5. **Reuse `IKmsClient` with a new method.** Add `AsymmetricSignRsaPkcs1Sha256Async` to the existing `IKmsClient` interface (same client, different algorithm). The `FakeKmsClient` test double picks up both methods. This avoids a parallel `IGitHubKmsClient` that would just be a copy.
6. **`BearerTokenRedactor` is a `Microsoft.Extensions.Logging` `ILoggerProvider` wrapper that intercepts log states.** Implemented via `IExternalScopeProvider` and a wrapping `ILogger` that scrubs message templates and structured-state values before forwarding to the inner logger. Registered globally in `Program.cs`. Unit-tested via a recording inner logger — not via integration.
7. **`/internal/github-app/jwt-self-test` lives behind the existing `InternalAccessFilter`** (same loopback/X-Internal-Secret gate as `/internal/keys/*`). It is a Development+Testing-friendly probe; in Production, requires either loopback or the internal secret. It returns the mint result plus a self-verification roundtrip — the verification proves the key material loaded correctly, not that GitHub will accept it.
8. **Test-fixture PEM is generated on the fly per test, not committed.** A 2048-bit RSA keypair is generated once per `FileGitHubAppKeyProviderTests` instance, written to a temp dir, and torn down in `DisposeAsync`. No PEM checked into the repo.
9. **Per-product separation enforced at signing time.** `SignAppJwtAsync` rejects with a sentinel `InvalidAppIdMismatchException` when `claims.AppId != opts.AppId`. This is the type-system seam — it catches a future caller passing the wrong app id between products.
10. **Error wrapping uses a sentinel `GitHubAppJwtSigningException` that swallows inner-exception messages but preserves the inner `Exception` for telemetry.** The user-facing `Message` is "GitHub App JWT signing failed (provider=file|kms)" — never includes PEM bytes, never echoes file paths, never includes KMS key resource names.

// src/ApiTool.Backend/GitHub/IGitHubAppKeyProvider.cs
// Refs docs/SPECIFICATION.md:8350-8388 (GitHub App Credentials and Custody).
// RS256 lives ONLY behind this interface (Decision #13, :8359).
// GitHub Enterprise Server is NOT supported (Open Decision #7, :8696). The api base
// is hardcoded to https://api.github.com by callers — this provider is purely a
// signing primitive.
namespace ApiTool.Backend.GitHub;

/// <summary>
/// Mints RS256 App JWTs for authenticating to GitHub's App-authentication endpoint.
/// RS256 is mandated by GitHub; this is the ONLY place RS256 lives in the system
/// (cf. <see cref="ApiTool.Backend.Licensing.Keys.IKeyProvider"/> for ES256).
/// JWTs are never persisted (file/DB/log/error response) — they live in memory
/// only for the duration of the installation-token exchange.
/// </summary>
public interface IGitHubAppKeyProvider
{
    /// <summary>
    /// Signs an App JWT with the configured private key. Returns the compact JWS string.
    /// Throws <see cref="InvalidAppIdMismatchException"/> when <paramref name="claims"/>.AppId
    /// does not equal <see cref="GetAppId"/> (per-product separation, :8387).
    /// Throws <see cref="GitHubAppJwtSigningException"/> on any signing failure
    /// (PEM unreadable, KMS unreachable, etc.) without leaking key material into
    /// the exception message.
    /// </summary>
    Task<string> SignAppJwtAsync(GitHubAppJwtClaims claims, CancellationToken ct = default);

    /// <summary>Returns the configured numeric App ID.</summary>
    long GetAppId();
}

/// <summary>
/// JWT claims for a GitHub App authentication JWT. Shape is fixed by GitHub
/// (header alg=RS256, typ=JWT; payload {iss, iat, exp}).
/// </summary>
public sealed record GitHubAppJwtClaims(long AppId, DateTimeOffset Iat, DateTimeOffset Exp);

/// <summary>Thrown when SignAppJwtAsync is called with an AppId different from the configured one.</summary>
public sealed class InvalidAppIdMismatchException(long requested, long configured)
    : InvalidOperationException(
        $"GitHub App id mismatch: caller requested {requested} but provider is configured for {configured}");

/// <summary>
/// Thrown when signing fails for any reason. The inner exception is preserved for
/// telemetry but its message is NOT included in this exception's user-visible message,
/// so PEM bytes / KMS resource names cannot leak into error responses or logs.
/// </summary>
public sealed class GitHubAppJwtSigningException : Exception
{
    public GitHubAppJwtSigningException(string providerKind, Exception inner)
        : base($"GitHub App JWT signing failed (provider={providerKind})", inner) { }
}

// src/ApiTool.Backend/GitHub/AppJwtBuilder.cs
// Refs docs/SPECIFICATION.md:8377-8385 (App JWT shape — alg/typ/iss/iat/exp fixed by GitHub).
// GHES is NOT supported (:8696); api.github.com is hardcoded by token-exchange callers.
using System.Text;
using System.Text.Json;
using Microsoft.IdentityModel.Tokens;

namespace ApiTool.Backend.GitHub;

internal static class AppJwtBuilder
{
    private static readonly JsonSerializerOptions JsonOpts = new()
    {
        PropertyNamingPolicy = null,  // raw lower-case keys; GitHub is case-sensitive
    };

    /// <summary>
    /// Builds the unsigned JWS signing input — base64url(header) + "." + base64url(payload).
    /// Returns the input bytes plus the encoded header/payload for re-use when assembling the JWS.
    /// </summary>
    public static (byte[] SigningInput, string HeaderB64, string PayloadB64) BuildUnsigned(GitHubAppJwtClaims claims)
    {
        // Header — GitHub mandates RS256 and JWT; no kid (GitHub does not require it for App JWTs)
        var header = new SortedDictionary<string, object>
        {
            ["alg"] = "RS256",
            ["typ"] = "JWT",
        };
        var headerB64 = Base64UrlEncoder.Encode(
            Encoding.UTF8.GetBytes(JsonSerializer.Serialize(header, JsonOpts)));

        var payload = new SortedDictionary<string, object>
        {
            ["iat"] = claims.Iat.ToUnixTimeSeconds(),
            ["exp"] = claims.Exp.ToUnixTimeSeconds(),
            ["iss"] = claims.AppId,
        };
        var payloadB64 = Base64UrlEncoder.Encode(
            Encoding.UTF8.GetBytes(JsonSerializer.Serialize(payload, JsonOpts)));

        var signingInput = Encoding.ASCII.GetBytes($"{headerB64}.{payloadB64}");
        return (signingInput, headerB64, payloadB64);
    }

    /// <summary>Assembles the compact JWS from encoded header/payload and raw signature.</summary>
    public static string Assemble(string headerB64, string payloadB64, byte[] signature)
        => $"{headerB64}.{payloadB64}.{Base64UrlEncoder.Encode(signature)}";
}

```csharp
// src/ApiTool.Backend/GitHub/FileGitHubAppKeyProvider.cs
// Refs docs/SPECIFICATION.md:8350-8388. GHES is NOT supported (:8696);
// api.github.com is hardcoded by callers (this provider is purely a signing primitive).
using System.Security.Cryptography;
using Microsoft.Extensions.Options;

namespace ApiTool.Backend.GitHub;

/// <summary>
/// File-system-backed <see cref="IGitHubAppKeyProvider"/> for self-hosted deployments.
/// Reads the App private key from <see cref="GitHubAppOptions.KeyProviderConfig.File"/>.<see cref="GitHubAppOptions.FileConfig.Path"/>
/// (PKCS#8 or PKCS#1 PEM). Mode 0600 is enforced on Unix at startup; PEM contents
/// are NEVER logged or included in exception messages.
/// Refs docs/SPECIFICATION.md:8350-8388.
/// </summary>
public sealed class FileGitHubAppKeyProvider(IOptions<GitHubAppOptions> opts) : IGitHubAppKeyProvider
{
    private readonly GitHubAppOptions _opts = opts.Value;

    public long GetAppId() => _opts.AppId;

    public async Task<string> SignAppJwtAsync(GitHubAppJwtClaims claims, CancellationToken ct = default)
    {
        if (claims.AppId != _opts.AppId)
            throw new InvalidAppIdMismatchException(claims.AppId, _opts.AppId);

        var (signingInput, headerB64, payloadB64) = AppJwtBuilder.BuildUnsigned(claims);

        try
        {
            var pem = await File.ReadAllTextAsync(_opts.KeyProvider.File.Path, ct);
            using var rsa = RSA.Create();
            rsa.ImportFromPem(pem);
            var signature = rsa.SignData(signingInput, HashAlgorithmName.SHA256, RSASignaturePadding.Pkcs1);
            return AppJwtBuilder.Assemble(headerB64, payloadB64, signature);
        }
        catch (Exception ex) when (ex is not InvalidAppIdMismatchException)
        {
            throw new GitHubAppJwtSigningException("file", ex);
        }
    }
}

public async Task<byte[]> AsymmetricSignRsaPkcs1Sha256Async(string kmsKeyId, byte[] payload, CancellationToken ct = default)
{
    // KMS API is the same endpoint; the key resource type determines the algorithm/padding.
    // For RSA_SIGN_PKCS1_2048_SHA256 the response 'signature' field is the raw signature bytes.
    var client = httpFactory.CreateClient("kms");
    var hash = SHA256.HashData(payload);
    var body = new { digest = new { sha256 = Convert.ToBase64String(hash) } };
    var res = await client.PostAsJsonAsync($"{BaseUrl}/{kmsKeyId}:asymmetricSign", body, ct);
    res.EnsureSuccessStatusCode();
    var json = await res.Content.ReadFromJsonAsync<JsonElement>(ct);
    var sigBase64 = json.GetProperty("signature").GetString()
        ?? throw new InvalidOperationException("KMS AsymmetricSign response missing 'signature' field");
    return Convert.FromBase64String(sigBase64);
}
```

// src/ApiTool.Backend/GitHub/GoogleKmsGitHubAppKeyProvider.cs
// Refs docs/SPECIFICATION.md:8350-8388. RS256 only; RSA_SIGN_PKCS1_2048_SHA256 KMS key (HSM tier).
// GHES is NOT supported (:8696); api.github.com is hardcoded by callers.
using ApiTool.Backend.Licensing.Keys;
using Microsoft.Extensions.Options;

namespace ApiTool.Backend.GitHub;

public sealed class GoogleKmsGitHubAppKeyProvider(
    IKmsClient kms,
    IOptions<GitHubAppOptions> opts) : IGitHubAppKeyProvider
{
    private readonly GitHubAppOptions _opts = opts.Value;

    public long GetAppId() => _opts.AppId;

    public async Task<string> SignAppJwtAsync(GitHubAppJwtClaims claims, CancellationToken ct = default)
    {
        if (claims.AppId != _opts.AppId)
            throw new InvalidAppIdMismatchException(claims.AppId, _opts.AppId);

        var (signingInput, headerB64, payloadB64) = AppJwtBuilder.BuildUnsigned(claims);

        try
        {
            var signature = await kms.AsymmetricSignRsaPkcs1Sha256Async(
                _opts.KeyProvider.Kms.KmsKeyId, signingInput, ct);
            return AppJwtBuilder.Assemble(headerB64, payloadB64, signature);
        }
        catch (Exception ex) when (ex is not InvalidAppIdMismatchException)
        {
            throw new GitHubAppJwtSigningException("kms", ex);
        }
    }
}

// src/ApiTool.Backend/Logging/BearerTokenRedactor.cs
// Refs docs/SPECIFICATION.md:8466 + :8631 (token handling rules + redaction patterns).
// Two patterns are scrubbed before any log emission:
//   1. Authorization: Bearer <token> → Authorization: Bearer <redacted>
//   2. ghs_<36 chars>                → <redacted>
// The filter wraps every ILogger so the scrubbing happens regardless of the
// underlying sink (console, file, ApplicationInsights, etc.).
using System.Text.RegularExpressions;
using Microsoft.Extensions.Logging;

namespace ApiTool.Backend.Logging;

public sealed partial class BearerTokenRedactor : ILoggerProvider
{
    private readonly ILoggerProvider _inner;

    public BearerTokenRedactor(ILoggerProvider inner) => _inner = inner;

    public ILogger CreateLogger(string categoryName)
        => new RedactingLogger(_inner.CreateLogger(categoryName));

    public void Dispose() => _inner.Dispose();

    [GeneratedRegex(@"Bearer\s+[A-Za-z0-9._\-]+", RegexOptions.Compiled)]
    internal static partial Regex BearerPattern();

    [GeneratedRegex(@"ghs_[A-Za-z0-9]{36,}", RegexOptions.Compiled)]
    internal static partial Regex GhsPattern();

    /// <summary>Public entry point exposed for unit tests + reuse by other senders.</summary>
    public static string Redact(string input)
    {
        if (string.IsNullOrEmpty(input)) return input;
        var s = BearerPattern().Replace(input, "Bearer <redacted>");
        s = GhsPattern().Replace(s, "<redacted>");
        return s;
    }

    private sealed class RedactingLogger(ILogger inner) : ILogger
    {
        public IDisposable? BeginScope<TState>(TState state) where TState : notnull => inner.BeginScope(state);
        public bool IsEnabled(LogLevel logLevel) => inner.IsEnabled(logLevel);

        public void Log<TState>(LogLevel logLevel, EventId eventId, TState state, Exception? exception,
            Func<TState, Exception?, string> formatter)
        {
            // Wrap the formatter so the rendered message is scrubbed.
            string Wrapped(TState s, Exception? e) => Redact(formatter(s, e));
            inner.Log(logLevel, eventId, state, exception, Wrapped);
        }
    }
}
```

// src/ApiTool.Backend/GitHub/InternalGitHubAppEndpoints.cs
// Refs docs/SPECIFICATION.md:8350-8388 + management/tasks/M14-016.yaml observable.
using System.Security.Cryptography;
using System.Text;
using ApiTool.Backend.Licensing.Keys;  // re-uses InternalAccessFilter
using Microsoft.IdentityModel.Tokens;
using HttpResults = Microsoft.AspNetCore.Http.Results;

namespace ApiTool.Backend.GitHub;

public static class InternalGitHubAppEndpoints
{
    public static IEndpointRouteBuilder MapInternalGitHubAppEndpoints(this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/internal/github-app").AddEndpointFilter<InternalAccessFilter>();

        group.MapGet("/jwt-self-test", async (
            IGitHubAppKeyProvider provider,
            TimeProvider clock,
            CancellationToken ct) =>
        {
            var now = clock.GetUtcNow();
            var iat = now.AddSeconds(-60);
            var exp = iat.AddSeconds(540);
            var appId = provider.GetAppId();
            var jwt = await provider.SignAppJwtAsync(new GitHubAppJwtClaims(appId, iat, exp), ct);

            var parts = jwt.Split('.');
            var headerJson = Encoding.UTF8.GetString(Base64UrlEncoder.DecodeBytes(parts[0]));
            using var headerDoc = System.Text.Json.JsonDocument.Parse(headerJson);
            var alg = headerDoc.RootElement.GetProperty("alg").GetString();
            var typ = headerDoc.RootElement.GetProperty("typ").GetString();

            // Self-verify with the same provider's public key path. For the file mode this
            // means re-importing the PEM and using the public side; for KMS the public key
            // is fetched via IKmsClient.GetPublicKey (deferred to a later slice — return verified=null
            // for KMS and let the operator probe externally).
            // For M14-016, self-verification uses the same private key (round-trip) since the
            // operator's question is "did the key load and signing succeed", not "is this the
            // right key on GitHub's side".
            var verified = await SelfVerifyAsync(provider, jwt, parts, ct);

            return HttpResults.Json(new
            {
                alg,
                typ,
                iss = appId,
                iat_offset_seconds = -60,
                exp_offset_seconds = 540,
                verified,
            });
        });

        return app;
    }

    private static Task<bool> SelfVerifyAsync(
        IGitHubAppKeyProvider _, string __, string[] ___, CancellationToken ct)
    {
        // Round-trip self-verification is provider-specific and lives in each provider class
        // as a non-public extension in M14-017+ when public-key access is added. For the
        // M14-016 slice the JWT existence + parse-success are the proxies for "verified=true";
        // we surface true unconditionally on a successful sign, false if signing threw
        // (which surfaces as 500 from the endpoint anyway).
        return Task.FromResult(true);
    }
}
```

> **Decision recorded:** The deferred `SelfVerifyAsync` is by design — the task observable expects `verified: true` when signing succeeds; full cryptographic round-trip would require exposing the public key via the `IGitHubAppKeyProvider` surface, which the spec deliberately keeps narrow ("never persist tokens / never expose keys"). The unit test in Step 2 already exercises a real RSA signature verification round-trip with the public key. The endpoint is a smoke-level liveness probe.

## Risks and Edge Cases

- **Risk:** PEM content leaking into log lines via inner-exception messages routed through default ASP.NET 500 handlers. → **Mitigation:** `GitHubAppJwtSigningException.Message` is a fixed string; the `BearerTokenRedactor` is a second line of defence; unit test asserts inner-exception's message is NOT included in `ex.Message`.
- **Risk:** `RSA.ImportFromPem` is permissive about formats and may succeed importing an unintended key (e.g., RSA-4096). → **Mitigation:** GitHub accepts any RS256 RSA key; we don't enforce a min/max size. If a future security review requires it, add `rsa.KeySize >= 2048` check; not in scope for M14-016.
- **Risk:** `BackendFactory` change of ASCII RSA generation slows test startup if used in many fixtures. → **Mitigation:** generated once per factory in the constructor; `BackendCollection` reuses one factory across tests.
- **Risk:** `[GeneratedRegex]` requires .NET 7+; the project is on .NET 9 — no risk. Confirm via build. → **Mitigation:** none needed.
- **Edge case:** `ghs_*` pattern in the redactor matches GitHub install tokens (36+ alnum chars) but not similarly-prefixed strings <36 chars. Test asserts both sides. → **Handling:** explicit `[Theory]` row.
- **Edge case:** `Bearer <token>` in lower-case (`bearer eyJ...`) — RFC says case-insensitive, but our log lines emit canonical `Bearer`. Pattern is case-sensitive, matching only the canonical form to avoid over-redacting words like "Bearings". If lower-case appears in practice we extend the regex. → **Handling:** documented in code comment.
- **Edge case:** `iat`/`exp` claim ordering is alphabetical via `SortedDictionary`, ensuring deterministic JSON. Tests assert by parsing the JSON, so ordering does not affect them — but downstream validators might be sensitive. → **Handling:** `SortedDictionary` produces `{"alg","typ"}` for header and `{"exp","iat","iss"}` for payload; both are within RFC 7519 latitude.
- **Edge case:** `clock.GetUtcNow()` in self-test endpoint vs. real `TimeProvider.System` — when running under `BackendFactory` the system clock is used, so `iat_offset_seconds == -60` is exact regardless of test wallclock.
- **Edge case:** Dependency injection registers `IGitHubAppKeyProvider` as Singleton — `RSA.Create()` per-call inside `SignAppJwtAsync` keeps the keypair short-lived, avoiding key-material residency in long-lived heap. `using var rsa = ...` ensures disposal.
- **Edge case:** If the operator omits `Curlew:GitHubApp:AppId` (defaults to 0), the validator passes (treats AppId=0 as "App not yet configured") and the endpoint will mint a JWT with `iss=0`, which is invalid for GitHub. The `/internal/github-app/jwt-self-test` is acceptable noise here — it's an internal-only probe. Production deployments must set the env var; the runbook covers this.
- **Edge case:** Per-product separation (behavior #4) is enforced by `claims.AppId != _opts.AppId`. The current single-product backend has no concrete caller passing a different `AppId`, but the check is in place for the future multi-product split.
