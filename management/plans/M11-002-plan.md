# Implementation Plan: M11-002

## Overview

§2.4 gaps: a root `summary` block (`{total, passed, failed, skipped}`)
populated from `runner.Summary`, and per-iteration `iterations[]` entries
inside each `data_driven[]` aggregate so downstream tools can identify
which row-driven iteration passed or failed without parsing

## Architectural Decisions (resolved during planning)

1. **`Summary` is always populated, even on pre-exec error.** The task
   YAML specifies `JSONOutput.Summary *SummaryJSON` (always populated). The
   two `exec`-subcommand call sites at `main.go:3226` and `main.go:3332`
   currently pass `nil` summary to `buildJSONOutput`. The planned
   implementation treats `summary == nil` identically to
   `summary == &runner.Summary{}` — i.e. emits `{"summary": {"total": 0,
   "passed": 0, "failed": 0, "skipped": 0}}` rather than omitting the
   block. Rationale: the contract `jq '.summary.passed'` must never
   produce `null`, even on early-failure paths. The behavior bullet
   "always populated" outweighs the small wire size of four zero
   integers. **Pointer not value:** keeping `Summary *SummaryJSON` (rather
   than embedded `SummaryJSON`) preserves the option to omit the block in
   future schema versions if needed and matches the existing
   `GuardRail *GuardRailJSON` / `ParallelExecution *ParallelExecutionJSON`
   pattern. Even though it is *always* populated today, JSON tag stays
   plain `summary` (no `omitempty`) so encode/decode round-trips
   include the block.

2. **Iteration name uses `RequestResult.Name` verbatim.** The runner has
   already produced names of the form `BaseName [i/N]` at
   `internal/runner/runner.go:2118` and :2326, and they round-trip through
   `RequestResult.Name`. We reuse this string directly rather than
   re-formatting from `IterationIndex` / `IterationTotal`, which keeps
   the JSON name field byte-identical to the events-stream `name` field
   (a separate consumer-friendly invariant).

3. **Iteration `status` is `"passed"` | `"failed"` | `"skipped"`.** The
   task YAML lists `'passed'|'failed'`, but skipped iterations *are*
   possible if a data-driven iteration is short-circuited by a teardown
   guard or a context cancellation. We extend the enum to include
   `"skipped"` to preserve the truth value. (The current
   `computeDataDrivenStats` skips `r.Skipped` iterations from
   pass/fail counts; we mirror that classification for the per-iteration
   entry.) The `TestJSONOutput_DataDrivenIterations` test will assert
   pass/fail; a separate sub-test will assert the skipped path. This
   is a strict superset of the task wording and does not contradict it.

4. **`data_columns` carries `IterationData`.** The task YAML spec lists
   `data_columns map[string]string optional`. `RequestResult.IterationData`
   already carries the row data verbatim
   (`internal/runner/runner.go:2156, 2188, 2523`). We populate
   `data_columns` only when `IterationData` is non-nil and non-empty,
   tagged `json:"data_columns,omitempty"` so it is omitted on iterations
   without row data.

5. **Existing `TestRunCmdDirect_DataDriven_JSONFormat` is updated, not
   deleted.** Lines 6419-6473 already check the aggregate fields; we
   extend that test to also assert iterations[] is present and the
   summary block is non-zero. We do NOT delete or rewrite — the
   existing assertions keep their backstop.

6. **Observable testdata fixture is `cmd/apitest/testdata/datadriven_simple.yaml`
   pointing at `httpbin.org/get`.** The task YAML observable command
   references this file. The fixture must:
   - declare a `data_driven` block reading a co-located CSV;
   - target a stable public URL or accept `--var server=...` substitution.
   Decision: hard-code `https://httpbin.org/get?name={{name}}` — matches
   the existing smoke pattern (`smoke/run.sh:dd_test.yaml`). The
   accompanying `users.csv` lives at
   `cmd/apitest/testdata/datadriven_simple.csv` with three rows.
   Note: the observable command requires `APITEST_TIER=professional`
   (data_driven feature is gated) — the plan adds an env-var note next
   to the observable instructions and doc-mentions it in
   `docs/MANUAL.md`. We do NOT change gating in this task.

7. **No changes to MultiJSONOutput.** Multi-collection runs (glob runs
   producing `MultiJSONOutput`) are out of scope; per-collection
   `JSONOutput` entries inside `Collections[]` automatically get the new
   fields because they reuse the same struct, but no top-level
   summary is added to `MultiJSONOutput` itself. This matches the §2.4
   bullet wording (per-collection visibility, not aggregate).

```go
// SummaryJSON is the root execution summary block. Populated unconditionally
// by buildJSONOutput so consumers can rely on `jq '.summary.passed'` without
// traversing requests[]. (M11-002)
type SummaryJSON struct {
	Total   int `json:"total"`
	Passed  int `json:"passed"`
	Failed  int `json:"failed"`
	Skipped int `json:"skipped"`
}

// DataDrivenJSON holds data-driven aggregate metadata in JSON output.
type DataDrivenJSON struct {
	Type             string                     `json:"type"` // always "data_driven"
	Name             string                     `json:"name"` // base request name
	TotalIterations  int                        `json:"total_iterations"`
	PassedIterations int                        `json:"passed_iterations"`
	FailedIterations int                        `json:"failed_iterations"`
	TotalDurationMs  int64                      `json:"total_duration_ms"`
	AvgDurationMs    int64                      `json:"average_duration_ms"`
	Iterations       []DataDrivenIterationJSON  `json:"iterations,omitempty"`
}

// DataDrivenIterationJSON is one iteration entry inside a DataDrivenJSON.
// Surfaces per-iteration visibility that the events stream emits but the
// aggregate-only JSON formerly collapsed. (M11-002)
type DataDrivenIterationJSON struct {
	Name        string            `json:"name"`        // BaseName [i/N]
	Status      string            `json:"status"`      // "passed" | "failed" | "skipped"
	DurationMs  int64             `json:"duration_ms"`
	DataColumns map[string]string `json:"data_columns,omitempty"`
}
```

> Note: `Summary` field carries plain `json:"summary,omitempty"`. Per
> Architectural Decision 1 we always populate the field, so `omitempty`
> never fires in practice. We still mark it `omitempty` for two reasons:
> (1) symmetry with `GuardRail`, `ParallelExecution`, etc.; (2) future-
> proofing if we ever need to emit a Summary-less doc (e.g. validation
> output that reuses the type). The existing tests will assert the
> block is *present* in produced output regardless.

```go
func buildJSONOutput(name string, results []runner.RequestResult, summary *runner.Summary, preExecErr error, verbosity output.Verbosity) *output.JSONOutput {
	out := &output.JSONOutput{
		Name:     name,
		Requests: make([]output.JSONRequest, 0),
		Summary:  buildSummaryJSON(summary), // M11-002
	}

	if summary != nil {
		out.DurationMs = summary.Duration.Milliseconds()
	}

	if preExecErr != nil {
		out.Status = "error"
		out.Errors = []output.JSONError{{Message: preExecErr.Error()}}
		return out
	}
	// ... unchanged body ...
	out.DataDriven = buildDataDrivenJSON(results)
	return out
}

// buildSummaryJSON returns a SummaryJSON populated from runner.Summary.
// Returns a zeroed SummaryJSON when summary is nil so the JSON contract
// `jq '.summary.passed'` never produces null. (M11-002)
func buildSummaryJSON(summary *runner.Summary) *output.SummaryJSON {
	s := &output.SummaryJSON{}
	if summary != nil {
		s.Total = summary.Total
		s.Passed = summary.Passed
		s.Failed = summary.Failed
		s.Skipped = summary.Skipped
	}
	return s
}

func buildDataDrivenJSON(results []runner.RequestResult) []output.DataDrivenJSON {
	var ddEntries []output.DataDrivenJSON
	for i := 0; i < len(results); i++ {
		r := results[i]
		if !r.IsDataDriven || r.IterationIndex != 0 {
			continue
		}
		group, nextIdx := groupDataDrivenResults(results, i)
		s := computeDataDrivenStats(group)
		ddEntries = append(ddEntries, output.DataDrivenJSON{
			Type:             "data_driven",
			Name:             r.DataDrivenName,
			TotalIterations:  len(group),
			PassedIterations: s.passed,
			FailedIterations: s.failed,
			TotalDurationMs:  s.totalDuration,
			AvgDurationMs:    s.avgDuration,
			Iterations:       buildDataDrivenIterations(group), // M11-002
		})
		i = nextIdx - 1
	}
	return ddEntries
}

// buildDataDrivenIterations converts a contiguous data-driven result group
// into per-iteration entries for JSON output. (M11-002)
func buildDataDrivenIterations(group []runner.RequestResult) []output.DataDrivenIterationJSON {
	out := make([]output.DataDrivenIterationJSON, 0, len(group))
	for _, r := range group {
		entry := output.DataDrivenIterationJSON{Name: r.Name}
		switch {
		case r.Skipped:
			entry.Status = "skipped"
		case r.Err != nil:
			entry.Status = "failed"
		case r.AssertionResults != nil && !r.AssertionResults.Passed:
			entry.Status = "failed"
		default:
			entry.Status = "passed"
		}
		if r.Result != nil {
			entry.DurationMs = r.Result.Duration.Milliseconds()
		}
		if len(r.IterationData) > 0 {
			entry.DataColumns = r.IterationData
		}
		out = append(out, entry)
	}
	return out
}
```

```go
		},
		{

			},

				}
			},
		},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			out := buildJSONOutput("Suite", tt.results, &runner.Summary{Total: tt.wantIterations, Passed: tt.wantIterations}, nil, output.VerbosityDefault)
			if len(out.DataDriven) != 1 {
				t.Fatalf("expected 1 data_driven group, got %d", len(out.DataDriven))
			}
			tt.check(t, out.DataDriven[0])
		})
	}
}
```

## Risks and Edge Cases

- **Risk:** Existing snapshot-style tests doing exact byte comparison of
  JSON output break. → **Mitigation:** None observed in survey
  (`grep -rn "exact json\|byte compare\|equalBytes"` on test files yields
  no exact-shape JSON snapshot tests beyond field-presence
  string-contains assertions). Confirmed during planning.
- **Edge case:** `summary == nil` (the `exec` JSON pre-exec error paths).
  → **Handling:** `buildSummaryJSON(nil)` returns a zeroed `SummaryJSON`
  pointer rather than nil, so the contract holds.
- **Edge case:** Zero iterations in a data-driven group (theoretically
  impossible — a parsed `data_driven` block produces ≥1 iteration). →
  **Handling:** `buildDataDrivenIterations(nil)` returns an empty slice;
  `omitempty` strips the key. Defensive code, no test required.
- **Edge case:** `IterationData` is non-nil but empty map. → **Handling:**
  `len(r.IterationData) > 0` guard; empty maps drop through to
  `data_columns` omitempty path.
- **Edge case:** Sensitive variables in `IterationData`. → **Handling:**
  out of scope. The existing redaction pipeline (M6-003) operates on
  request body / response body / terminal output. `IterationData` is a
  parsed CSV/JSON row — if a user puts a secret literal in a CSV they
  control, the JSON output will reflect it. This matches HTML output
  behaviour (`HTMLReport.DataDrivenGroups[].Iterations[].Data` uses the
  same raw map) — see M2-028 / M9-004 wiring. Documenting this as a
  known limitation if needed; not a regression.
- **Edge case:** Network-error iterations have `r.Result == nil`. →
  **Handling:** `entry.DurationMs` stays 0 (zero value of int64). Test
  case "network error iteration emits status failed" exercises this.
- **Edge case:** Multi-collection (`MultiJSONOutput`) glob runs. →
  **Handling:** `MultiJSONOutput.Collections []JSONOutput` reuses the
  same struct. Each per-collection JSON gets its own `summary` block
  automatically. No top-level summary added.
- **Risk:** `golangci-lint` flags the new helper functions. → **Mitigation:**
  `buildSummaryJSON` and `buildDataDrivenIterations` follow the
  existing `buildDataDrivenJSON` / `computeDataDrivenStats` naming
  pattern. Both are package-private. All exported types have doc
  comments per project convention.
- **Risk:** Coverage drops below 80% in `cmd/apitest`. → **Mitigation:**
  Two new helper functions, each fully covered by the new tests
  (`TestJSONOutput_Summary`, `TestJSONOutput_DataDrivenIterations`).
  Net-positive coverage.
