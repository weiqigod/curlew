## Overview

may contain dotted namespaces (e.g. `$faker.firstName`, `$faker.imageUrl(640, 480)`),

`docs/MANUAL.md §3.7` that points forward to the `$faker.*` family. No
`$faker.*` registrations land here — those are M13-002..M13-008.

`grep -rn dynPattern` confirms zero usage outside `internal/variable/`. The
pattern is package-private and the captured `funcName` is opaque to every
downstream consumer:

- `cacheKey(funcName, args)` (`internal/variable/dynamic.go:106`) joins
  `funcName + NUL + args...`. A NUL cannot appear inside a dotted segment
  (each segment is `[a-zA-Z][a-zA-Z0-9_]*`), so `faker.firstName` plus NUL is
  a distinct, well-formed cache key and never collides with the legacy
  single-segment form.
- `Registry.Evaluate(name, args, cache)` (`internal/variable/dynamic.go:117`)
  uses `name` as the literal map key into `r.funcs` and emits
  `unknown dynamic function "<name>"` on miss. The dot is preserved.
- `parseDynArgs(funcName, raw)` (`internal/variable/variable.go:107`) uses
  `funcName` only as a label inside `Structured.Message` / `Hint` strings.
- `Registry.SensitiveArgIndex(funcName)` looks up a string key — no parsing.

### Pre-scan ordering (`Scope.Interpolate`, variable.go:306–442)

1. **Pre-scan** for sensitive-arg flags (`dynPattern.FindAllStringSubmatch`).
   The captured `funcName` flows into `parseDynArgs(funcName, rawArgs)`
   purely as an error label; the dot does not reach any path that would
   misinterpret it.
2. **Pass 0** resolves `{{secrets.X}}` (separate `secretsPattern`).
3. **Pass 1** resolves `{{$fn(...)}}` via `dynPattern.ReplaceAllStringFunc`.
   The dispatch reads `sub[1]` as `funcName` and `sub[2]` as `rawArgs`.
4. **Pass 2** resolves `{{varName}}`.

Because `varPattern` is `\{\{([a-zA-Z_][a-zA-Z0-9_]*)\}\}` (no leading `$`,
no parens), it cannot match `{{$faker.firstName}}` even after the change.
There is no risk of cross-pattern interference.

var (
	varPattern = regexp.MustCompile(`\{\{([a-zA-Z_][a-zA-Z0-9_]*)\}\}`)
	// dynPattern matches {{$funcName}} (legacy, no parens) or
	// {{$funcName(<rawArgList>)}}. Capture groups:
	//
	//	[1] funcName
	//	[2] rawArgList (empty string when there are no parens at all, or the
	//	    literal characters between the outer parens).
	//
	// The raw arg list uses a non-greedy .*? so that:
	//   - args may contain {{var}} references (nested braces are fine)
	//   - the match stops at the first `)}}` sequence
	//
	// NOTE: a literal `)}}` sequence inside a single-quoted arg would
	// terminate the match early; such sequences are not expected in practice.
	// Actual arg parsing (quotes, escapes, commas) is handled by parseDynArgs.
	dynPattern     = regexp.MustCompile(`\{\{\$([a-zA-Z][a-zA-Z0-9_]*)(?:\((.*?)\))?\}\}`)
	secretsPattern = regexp.MustCompile(`\{\{secrets\.([a-zA-Z_][a-zA-Z0-9_]*)\}\}`)
)

var (
	varPattern = regexp.MustCompile(`\{\{([a-zA-Z_][a-zA-Z0-9_]*)\}\}`)
	// dynPattern matches {{$funcName}} (legacy, no parens) or
	// {{$funcName(<rawArgList>)}}. Capture groups:
	//
	//	[1] funcName — may contain dotted namespaces (e.g. "faker.firstName"),
	//	    with each dot-separated segment satisfying
	//	    [a-zA-Z][a-zA-Z0-9_]*. Consecutive dots, leading dots, and
	//	    trailing dots are rejected (the entire match fails).
	//	[2] rawArgList (empty string when there are no parens at all, or the
	//	    literal characters between the outer parens).
	//
	// The raw arg list uses a non-greedy .*? so that:
	//   - args may contain {{var}} references (nested braces are fine)
	//   - the match stops at the first `)}}` sequence
	//
	// NOTE: a literal `)}}` sequence inside a single-quoted arg would
	// terminate the match early; such sequences are not expected in practice.
	// Actual arg parsing (quotes, escapes, commas) is handled by parseDynArgs.
	// The captured funcName (including any dots) is used verbatim as the
	// Registry.Evaluate lookup key — see internal/variable/dynamic.go.
	dynPattern     = regexp.MustCompile(`\{\{\$([a-zA-Z][a-zA-Z0-9_]*(?:\.[a-zA-Z][a-zA-Z0-9_]*)*)(?:\((.*?)\))?\}\}`)
	secretsPattern = regexp.MustCompile(`\{\{secrets\.([a-zA-Z_][a-zA-Z0-9_]*)\}\}`)

// TestDynPattern_DottedNamespace verifies that dynPattern accepts
// dot-separated namespace segments in funcName and captures the literal
// dot in capture group 1.
func TestDynPattern_DottedNamespace(t *testing.T) {
	tests := []struct {
		name        string
		input       string
		wantMatch   bool
		wantFunc    string
		wantRawArgs string
	}{
		{"single dot, no parens", "{{$faker.firstName}}", true, "faker.firstName", ""},
		{"single dot, empty parens", "{{$faker.firstName()}}", true, "faker.firstName", ""},
		{"two dots", "{{$pkg.sub.fn}}", true, "pkg.sub.fn", ""},
		{"consecutive dots rejected", "{{$faker..badName}}", false, "", ""},
		{"leading dot rejected", "{{$.faker.firstName}}", false, "", ""},
		{"trailing dot rejected", "{{$faker.}}", false, "", ""},
		{"dot then underscore-leading rejected", "{{$faker._bad}}", false, "", ""},
		{"dot then digit-leading rejected", "{{$faker.1bad}}", false, "", ""},
	}
	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			m := dynPattern.FindStringSubmatch(tt.input)
			gotMatch := m != nil
			if gotMatch != tt.wantMatch {
				t.Fatalf("FindStringSubmatch match=%v, want %v (input=%q)", gotMatch, tt.wantMatch, tt.input)
			}
			if !tt.wantMatch {
				return
			}
			if m[1] != tt.wantFunc {
				t.Errorf("funcName = %q, want %q", m[1], tt.wantFunc)
			}
			if m[2] != tt.wantRawArgs {
				t.Errorf("rawArgs = %q, want %q", m[2], tt.wantRawArgs)
			}
		})
	}
}

func TestRegistry_DottedName_NotYetRegistered(t *testing.T) {
	reg := NewRegistry(nil)
	_, err := reg.Evaluate("faker.firstName", nil, make(map[string]string))
	if err == nil {
		t.Fatal("expected error, got nil")

		t.Errorf("error message should name the dotted function; got: %q", msg)

**Dotted-namespace function names (M13+).**

Dynamic-function names may contain dot-separated namespace segments —

## Risks and Edge Cases

- **Risk: greedy regex backtracking on adversarial inputs.**
  The new alternation `(?:\.[a-zA-Z][a-zA-Z0-9_]*)*` is bounded by the
  closing `\}\}` and the optional parens, and Go's `regexp` (RE2-based)
  guarantees linear-time matching with no catastrophic backtracking.
  **Mitigation:** the negative cases in `TestDynPattern_DottedNamespace`
  (`{{$faker..badName}}`, `{{$.faker.firstName}}`, `{{$faker.}}`,
  `{{$faker._bad}}`, `{{$faker.1bad}}`) cover the malformed-input
  surface; RE2's complexity guarantee covers the runtime surface.

- **Risk: cache-key collision between legacy and dotted names.**
  `cacheKey` joins `funcName + NUL + args`. The dot is a printable ASCII
  byte that cannot appear in NUL-delimited segments, so `firstName\x00`
  (legacy) and `faker.firstName\x00` (dotted) are distinct keys.
  **Mitigation:** none required. The behaviour is asserted indirectly by
  `TestRegistry_DottedName_NotYetRegistered` (the unknown-name error path
  proves the lookup key is preserved).

- **Risk: a future contributor adds `_` to the segment-leading character class.**
  This would let `{{$faker._bad}}` match — currently rejected. We surface
  the constraint via the negative test case `dot then underscore-leading
  rejected` so any such regression fails CI immediately.
  **Mitigation:** test in `TestDynPattern_DottedNamespace`.

- **Edge case: empty parens after a dotted name (`{{$faker.firstName()}}`).**
  Already covered by the existing M12-001 grammar — `(?:\((.*?)\))?` is
  the parens group, independent of the funcName segment. The new test
  `single dot, empty parens` confirms.

- **Edge case: dotted name appearing inside a literal arg.**
  `{{$echo('{{$faker.firstName}}')}}` — the outer regex captures
  `funcName="echo"`, `rawArgs="'{{$faker.firstName}}'"`. Pass 1's
  `Scope.Interpolate(lit)` recurses on the literal, where the inner
  match runs again and resolves the dotted name. Already covered by the
  existing nested-var path; no new test required for the recursion shape.

- **Open Decision (resolved here): observable CLI command.** The task
  YAML's observable lists
  `printf '{{$faker.firstName}}\n' | ./apitest exec --stdin --format json`,
  but `exec --stdin` parses its input as JSON
  (`{"url":"...","method":"..."}`), not as a raw template, and `exec` does
  not wire up a `variable.Registry` (only `run` does — see
  `internal/runner/runner.go:1001`). Sending a raw `{{...}}` line yields a
  JSON-parse error that never reaches the regex. **Resolution:** treat the
  four `go test` commands plus the `grep` doc-fix command as the
  authoritative observables, and add one extra CLI observable using
  `apitest run` against a 3-line temp YAML — that path *does* attach the
  registry and exercises the full Interpolate → Evaluate flow. The plan's
  Verification block below uses the corrected form. This decision is
  documented here rather than escalated because (a) the four go-test
  commands already cover every behaviour the slice introduces, (b) wiring
  a registry into `exec` is out of scope and would be its own slice, and
  (c) the corrected `run`-based command is a strictly stronger end-to-end
  proof.
