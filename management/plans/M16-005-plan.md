## Architectural Decisions

1. **Column set — superset of YAML observable + spec DDL.** The task YAML observable lists 10 columns: `id`, `user_id`, `feature`, `kind`, `granted_at`, `expires_at`, `notified_3day_at`, `notified_1day_at`, `created_at`, `updated_at`. The spec appendix DDL (`:11010-11021`) lists 9 columns including `consumed_at` but omits `created_at`/`updated_at`. The spec narrative (`:11030`) explicitly references `consumed_at` (`UPDATE … WHERE … consumed_at IS NULL`). Resolution: include the **union** — all 11 columns: id, user_id, feature, kind, granted_at, expires_at, **consumed_at** (spec), notified_3day_at, notified_1day_at, **created_at**, **updated_at** (observable). The observable's `\d trials` check passes because the listed columns are present; the narrative's `consumed_at` query path works; and the project's existing entity convention of carrying audit timestamps (CreatedAt/UpdatedAt — see `GitLabInstallation`, `Subscription`) is preserved.
2. **`kind` storage: `TrialKind` enum mapped via string converter, not a Postgres enum type.** Matches the existing `SubscriptionTier`, `SubscriptionStatus`, `OrgRole`, `ScheduledRunStatus` pattern (`HasConversion<string>().HasMaxLength(...)`). Avoids a coupled enum-type migration. Behavior #2 ("kind is constrained to `full_initial / ondemand / preempted_by_subscription` via a CHECK constraint or enum") is satisfied by adding an explicit CHECK constraint in the migration; SQLite emits and enforces it at the DDL level. Postgres enforces it identically.
3. **Enum naming.** C# values are `FullInitial`, `OnDemand`, `PreemptedBySubscription`. Persisted strings must match the spec literally: `full_initial`, `ondemand`, `preempted_by_subscription`. EF Core's default `HasConversion<string>()` uses the C# enum name verbatim (`FullInitial` → `"FullInitial"`), which would NOT match the spec. Use a custom `ValueConverter<TrialKind, string>` (or two-arg `HasConversion(toProvider, fromProvider)`) that maps via an explicit lookup table. This is the same approach a custom converter would use; no other entity in the codebase needs custom-named string mapping today, but the precedent is in `RefreshToken.RevokeReason` (string column with documented enum-like values, just stored as raw string). For type safety we keep the C# enum.
4. **`feature` column type.** `string`, max length 64, NOT NULL. The spec uses `TEXT` without a length cap, but every other variable-length text column in the codebase has a `HasMaxLength(...)` (organization names, schedule names, etc.) for consistency and to keep schema explicit. 64 chars covers the longest gated feature slug (`vault_provider_profiles` is 23) with substantial headroom.
5. **CHECK constraint emission.** Use `migrationBuilder.Sql("ALTER TABLE trials ADD CONSTRAINT ck_trials_kind CHECK (kind IN ('full_initial','ondemand','preempted_by_subscription'))")` in the migration's `Up`. SQLite parses but does not enforce CHECK constraints inside `CreateTable`; explicit `ALTER TABLE ... ADD CONSTRAINT` after the table creation works on Postgres and is parsed (no-op on SQLite as long as the syntax is accepted). For a stronger SQLite assertion, add the CHECK clause inside `CreateTable`'s `constraints =>` builder using `table.CheckConstraint(...)`. EF Core 9 supports `table.CheckConstraint("name", "kind IN ('full_initial', ...)")` — use this so SQLite does enforce it.
6. **Partial indexes.** Three partial indexes per spec — but the task scope explicitly lists indexes for **3-day-not-notified** and **1-day-not-notified** filters (covering the daily-cron path), plus a separate non-unique index on `(user_id)`. The spec appendix omits the 1-day partial index but the scope requires it; add it. All three partial indexes use `HasFilter("\"<col>\" IS NULL")` matching the existing `idx_password_reset_tokens_active` pattern. Names: `idx_trials_user`, `idx_trials_notify_3day`, `idx_trials_notify_1day`. (The `idx_trials_expires` from the spec appendix is implicit in the notify indexes — both filter on `expires_at` — and an explicit redundant index would be unused. Skip it.)
7. **Unique index naming.** `idx_trials_user_feature` (matches spec `:11023`). Declared with `HasDatabaseName("idx_trials_user_feature").IsUnique()`.
8. **`UNIQUE (user_id, feature)` is a constraint, not just an index.** A unique **index** in SQLite is functionally equivalent to a unique constraint and `CREATE UNIQUE INDEX` is the standard EF Core emission for `IsUnique()`. Postgres emits both forms equivalently. The behavior test "second insert raises unique-violation" passes either way.
9. **No timezone in DateTime columns.** Existing entities use `DateTime` (UTC, by convention enforced at the call site). Same pattern here — `DateTime` for `GrantedAt`/`ExpiresAt`/`CreatedAt`/`UpdatedAt`, `DateTime?` for the four nullable columns.
10. **Entity sealed and pure.** No constructors, no behavior — pure data class with mutable properties matching every other entity in the codebase. Keeps EF Core happy; behavior lives in service classes (M16-006).
11. **`DbSet<Trial>` placement in `AppDbContext`.** Add at the bottom of the existing `DbSet` block, near the M16-013 GitLab entries. Wire `b.Entity<Trial>(...)` configuration in `OnModelCreating` after the email-verification block but before the GitLab block, matching commit-order conventions.
12. **No FK from `trials` to `subscriptions` or any tier-related table.** The trial table is keyed only by `(user_id, feature)`; preemption is a state stored in `kind`, not a relational link. The cascade `OnDelete(DeleteBehavior.Cascade)` from `users` mirrors the password_reset/email_verification entries — when a user is deleted, their trial rows go with them.
13. **Migration name and timestamp.** `AddTrials` with timestamp slot `20260510{HHMMSS}_AddTrials.cs` — pick a timestamp greater than the most recent migration (`20260510064317_AddGitlabInstallationsAndEvents`). Use `dotnet ef migrations add AddTrials` to let EF Core generate the timestamp; the resulting Designer + Snapshot updates are committed together.
14. **Designer and snapshot regeneration.** EF Core generates `<timestamp>_AddTrials.Designer.cs` and updates `AppDbContextModelSnapshot.cs`. Both are committed; both are deterministic outputs of `dotnet ef migrations add`.
15. **Test for behavior #6 (EXPLAIN uses the cron index).** The behavior is "EXPLAIN on the daily-cron query uses the partial index." Postgres EXPLAIN parsing in CI is out of scope for this slice (no cron query exists yet — that's M16-008). Equivalent SQLite proof: assert the partial index DDL contains the `WHERE notified_3day_at IS NULL` filter (mirrors `Active_partial_index_exists_on_sqlite` in `PasswordResetTokenEntityTests`). EXPLAIN integration is deferred to M16-008.
16. **No `dev:reset-trials` or seed code.** Per scope, no service-level code. The migration only ships DDL and the entity ships data shape. Open Decision 7 ("preempted trials remain preempted on cancellation/re-migrate") is enforced at the service layer in M16-006; for this slice it's a non-action — `Down()` drops the table cleanly per behavior #4.
17. **"No build warnings" gate.** All XML doc comments on public properties (matches every existing entity). No nullable-warning suppressions.

namespace ApiTool.Backend.Data.Entities;

/// <summary>
/// Per-(user, feature) trial grant.
/// Refs docs/SPECIFICATION.md:5800-5866 (narrative) and :11008-11030 (DDL).
/// </summary>
/// <remarks>
/// Uniqueness is enforced by an index on (user_id, feature) — one trial per
/// feature per user, ever. The 14-day full trial at registration is one row
/// per gated feature with <see cref="Kind"/> = <see cref="TrialKind.FullInitial"/>.
/// On-demand activation inserts <see cref="TrialKind.OnDemand"/>. Stripe
/// checkout success transitions live rows to <see cref="TrialKind.PreemptedBySubscription"/>.
/// </remarks>
public sealed class Trial
{
    /// <summary>Primary key — random UUID v4.</summary>
    public Guid Id { get; set; }

    /// <summary>The user this trial belongs to.</summary>
    public Guid UserId { get; set; }

    /// <summary>Gated feature slug — globally unique per user.</summary>
    public string Feature { get; set; } = string.Empty;

    /// <summary>How this trial was granted: full-initial, on-demand, or preempted.</summary>
    public TrialKind Kind { get; set; }

    /// <summary>UTC timestamp when the trial was granted.</summary>
    public DateTime GrantedAt { get; set; }

    /// <summary>UTC timestamp after which the trial no longer entitles the feature.</summary>
    public DateTime ExpiresAt { get; set; }

    /// <summary>UTC timestamp when the trial was consumed (subscription preemption); null while live.</summary>
    public DateTime? ConsumedAt { get; set; }

    /// <summary>UTC timestamp when the 3-day expiry-warning email was queued; null until queued.</summary>
    public DateTime? Notified3DayAt { get; set; }

    /// <summary>UTC timestamp when the 1-day expiry-warning email was queued; null until queued.</summary>
    public DateTime? Notified1DayAt { get; set; }

    /// <summary>UTC timestamp when the row was created.</summary>
    public DateTime CreatedAt { get; set; }

    /// <summary>UTC timestamp when the row was last updated.</summary>
    public DateTime UpdatedAt { get; set; }
}
```

b.Entity<Trial>(e =>
{
    e.ToTable("trials");
    e.HasKey(x => x.Id);
    e.Property(x => x.UserId).HasColumnName("user_id").IsRequired();
    e.Property(x => x.Feature).HasColumnName("feature").HasMaxLength(64).IsRequired();
    e.Property(x => x.Kind)
        .HasColumnName("kind")
        .HasMaxLength(32)
        .IsRequired()
        .HasConversion(
            v => v switch
            {
                TrialKind.FullInitial             => "full_initial",
                TrialKind.OnDemand                => "ondemand",
                TrialKind.PreemptedBySubscription => "preempted_by_subscription",
                _ => throw new InvalidOperationException($"Unknown TrialKind: {v}"),
            },
            v => v switch
            {
                "full_initial"              => TrialKind.FullInitial,
                "ondemand"                  => TrialKind.OnDemand,
                "preempted_by_subscription" => TrialKind.PreemptedBySubscription,
                _ => throw new InvalidOperationException($"Unknown trial kind string: {v}"),
            });
    e.Property(x => x.GrantedAt).HasColumnName("granted_at").IsRequired();
    e.Property(x => x.ExpiresAt).HasColumnName("expires_at").IsRequired();
    e.Property(x => x.ConsumedAt).HasColumnName("consumed_at");
    e.Property(x => x.Notified3DayAt).HasColumnName("notified_3day_at");
    e.Property(x => x.Notified1DayAt).HasColumnName("notified_1day_at");
    e.Property(x => x.CreatedAt).HasColumnName("created_at").IsRequired();
    e.Property(x => x.UpdatedAt).HasColumnName("updated_at").IsRequired();

    // CHECK constraint enforces the spec's three-value enum at the DDL level.
    e.ToTable(t => t.HasCheckConstraint(
        "ck_trials_kind",
        "\"kind\" IN ('full_initial', 'ondemand', 'preempted_by_subscription')"));

    // UNIQUE (user_id, feature) — one trial per feature per user, ever.
    e.HasIndex(x => new { x.UserId, x.Feature })
        .IsUnique()
        .HasDatabaseName("idx_trials_user_feature");

    // Non-unique covering index on user_id for "all my trials" lookups.
    e.HasIndex(x => x.UserId)
        .HasDatabaseName("idx_trials_user");

    // Partial indexes for the daily TrialExpiryNotifier cron (M16-008).
    e.HasIndex(x => x.ExpiresAt)
        .HasDatabaseName("idx_trials_notify_3day")
        .HasFilter("\"notified_3day_at\" IS NULL AND \"consumed_at\" IS NULL");
    e.HasIndex(x => x.ExpiresAt)
        .HasDatabaseName("idx_trials_notify_1day")
        .HasFilter("\"notified_1day_at\" IS NULL AND \"consumed_at\" IS NULL");

    e.HasOne<User>().WithMany().HasForeignKey(x => x.UserId).OnDelete(DeleteBehavior.Cascade);
});
```

    public async Task Entity_persists_and_round_trips()
    {
        await using var scope = TestDb.CreateOpen();
        await scope.Db.Database.MigrateAsync();
        var userId = await SeedUser(scope.Db);

        var trial = new Trial
        {
            Id = Guid.NewGuid(),
            UserId = userId,
            Feature = "vault_provider_profiles",
            Kind = TrialKind.OnDemand,
            GrantedAt = DateTime.UtcNow,
            ExpiresAt = DateTime.UtcNow.AddDays(7),
            CreatedAt = DateTime.UtcNow,
            UpdatedAt = DateTime.UtcNow,
        };
        scope.Db.Trials.Add(trial);
        await scope.Db.SaveChangesAsync();

        scope.Db.ChangeTracker.Clear();
        var loaded = await scope.Db.Trials.SingleAsync();
        loaded.UserId.Should().Be(userId);
        loaded.Feature.Should().Be("vault_provider_profiles");
        loaded.Kind.Should().Be(TrialKind.OnDemand);
        loaded.ConsumedAt.Should().BeNull();
        loaded.Notified3DayAt.Should().BeNull();
        loaded.Notified1DayAt.Should().BeNull();

## Risks and Edge Cases

- **Risk: `HasCheckConstraint` syntax changed across EF Core versions.** EF Core 7+ deprecates `e.HasCheckConstraint(...)` on the entity-builder in favour of `e.ToTable(t => t.HasCheckConstraint(...))`. The plan uses the new form. **Mitigation:** verify against the EF Core version pinned in `Directory.Packages.props`; fall back to the deprecated form if needed.
- **Risk: SQLite quoting in `HasFilter`.** Postgres uses double-quoted identifiers; SQLite accepts them. The existing partial-index uses (`idx_password_reset_tokens_active`, `idx_github_installations_org`) confirm `"\"col\" IS NULL"` works on both. **Mitigation:** mirror the exact quoting style of those existing indexes.
- **Edge case: empty `feature` string.** Spec implies a non-empty feature slug but adds no `MinLength`. **Handling:** `IsRequired()` enforces NOT NULL; the M16-007 service layer will validate the feature is in the allowlist of gated features. This slice does not need to enforce content-level validation.
- **Edge case: `kind` round-trip via custom converter when EF parses raw migrations.** The Designer file embeds the converter calls; no behaviour difference between EF reading via the converter and reading via raw SQL. The raw-SQL test (`Kind_round_trips_via_string_converter` / `ReadKindRawAsync`) double-checks the on-disk string matches the spec.
- **Edge case: down migration on an already-rolled-back DB.** Idempotency is EF's responsibility; `dotnet ef migrations remove` only adjusts source files, while `migrator.MigrateAsync(target)` is what actually rolls back at the DB level. The test uses `IMigrator.MigrateAsync` against a known prior migration name. **Mitigation:** if the prior migration name shifts (e.g., another M16 migration lands first), update the target string in the test; this is a single string literal.
- **Risk: timestamp ordering of the migration file.** If anyone else lands a migration with a timestamp greater than `20260510064317` before this one merges, EF will refuse to apply out-of-order. **Mitigation:** generate the migration immediately before commit; if conflict, regenerate.
- **Risk: `Database.IsNpgsql()` Postgres-vs-SQLite divergence.** No type-mapping divergence is needed for `trials` (no jsonb, no inet, no bytea). The migration will work on both backends without conditional code.
- **Edge case: cron-query EXPLAIN test (behavior #6).** Deferred to M16-008 as noted in Decision 15. Closing the gap in this slice would require introducing a query that doesn't yet exist; the partial-index DDL inspection is a strict-superset proof for the constraint level expressed in v4.3.
