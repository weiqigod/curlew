## Measured mechanics experiment

The task's hardest constraint is operational, not architectural: extended
fuzzing measured in hours cannot run in one command, because the Bash tool caps
a single invocation at 600 s. Before writing the plan, a throwaway Go module was
built in the scratchpad and the fuzzing engine's actual behaviour was measured on
this machine (`go version go1.25.5 darwin/arm64`). Every number below was
observed, not estimated. The probe module and its cache entry were deleted
afterwards.

### M1 — a crasher is written to `testdata/fuzz` and then runs as an ordinary test

A deliberate divide-by-zero was fuzzed. The engine found it in **2.94 s wall
clock** and wrote:

```
Failing input written to testdata/fuzz/FuzzSplit/5763756b3738a3fc
```

whose contents are the two-line reproducer format:

```
go test fuzz v1
string("abc00z0")
```

Plain `go test ./...` (no `-fuzz`) then failed on it. After the bug was fixed,
`go test ./... -run 'Fuzz' -v` printed:

```
=== RUN   FuzzSplit
=== RUN   FuzzSplit/seed#0
=== RUN   FuzzSplit/seed#1
=== RUN   FuzzSplit/5763756b3738a3fc
--- PASS: FuzzSplit (0.00s)
```

**Consequence for this task:** the DoD item "committed corpora run as ordinary
tests in the gate" needs **no change to `scripts/ci-local.sh`** to be true — the
existing `step "go test"` (`go test $(go_pkgs)`) already executes both `f.Add`
seeds and every `testdata/fuzz/<Target>/*` file. A named step is added anyway
(Step 8), for the reason the backlog-integrity step exists: so the gate log
records what was read rather than only that something passed.

### M2 — chunked runs accumulate, they do not restart

A branchy target was fuzzed in separate invocations:

| Invocation | `-fuzztime` | Result line | `$GOCACHE/fuzz` files after |
|---|---|---|---|
| chunk A | 20 s | `execs: 10852070 (536931/sec), new interesting: 7 (total: 8)` | 7 |
| chunk B | 15 s | `gathering baseline coverage: 8/8 completed` … `new interesting: 0 (total: 8)` | 7 |

Chunk B started from **8** corpus entries (1 seed + 7 discovered by chunk A),
not from 1. The generated corpus lives at:

```
/Users/peterlindqvist/Library/Caches/go-build/fuzz/<module>/<FuzzTarget>
```

i.e. `$(go env GOCACHE)/fuzz/...`. It is created **only once a new interesting
input is found** — an earlier probe on a trivial function ran 33 M execs across
two chunks with `new interesting: 0` and no `fuzz` directory ever appeared. An
absent cache directory is therefore not evidence that chunking failed.

**Consequence:** N chunks of T seconds are a legitimate substitute for one run of
N×T seconds, and the corpus file count after each chunk is the evidence that they
chained. The execute phase records it.

### M3 — `-fuzztime` vs `-fuzzminimizetime`, and the 600 s cap

The two budgets are **separate and additive**:

- `-fuzztime` bounds time spent generating and running inputs.
- `-fuzzminimizetime` bounds time spent shrinking **each** crasher after one is
  found (default **60 s**). It is not drawn from `-fuzztime`.

`go test -fuzz` stops at the first failure, so at most one minimization runs per
chunk. Worst-case chunk wall clock is therefore
`build + baseline-coverage + fuzztime + fuzzminimizetime`.

The chunk parameters chosen for this task:

```
-fuzztime 420s -fuzzminimizetime 30s
```

giving a worst case of ≈ 420 + 30 + ~20 s of build and baseline ≈ **470 s**,
against the 600 000 ms Bash ceiling — roughly two minutes of headroom. Measured
overhead on the probe was small: a `-fuzztime 30s` chunk reported
`ok fuzzprobe 30.391s`, i.e. **0.39 s** above the budget once the binary was
cached.

**Every chunk is a single foreground Bash call with `timeout: 600000`. No
`run_in_background`. No `&`.**

### M4 — worker processes do not survive, and a nonzero exit is not always a crasher

`go test -fuzz` ran with **10 workers** (GOMAXPROCS). After every probe run:

```
ps -A -o pid,command | grep -i "fuzzworker\|fuzzprobe" | grep -v grep
→ no fuzz worker processes survive
```

checked after 6 separate chunks — zero survivors each time.

One anomaly was observed and matters: a single chunk exited `FAIL / exit status
1` while `new interesting: 0` and **no file was written under `testdata/fuzz`**.
Three immediately following runs of the identical command exited `rc=0`. It did
not reproduce.

**Consequence — the crash-detection rule the execute phase must use:**

> A chunk found a crasher **iff** a new file appears under
> `internal/<pkg>/testdata/fuzz/<Target>/`. A nonzero exit with no new artifact
> is infrastructure noise: rerun the chunk once, and if it recurs, capture the
> full output before treating it as a finding.

Exit code alone is not the signal.

## Measured findings from reading the four surfaces

Two things were established before planning the targets, because they change what
the targets should do.

### F1 — the parser is already defensive against the obvious YAML shapes

There are 14 custom `UnmarshalYAML` methods in `internal/parser/collection.go`
that index `node.Content[i+1]`. Every even-step loop over them is guarded:

```
$ grep -c "for [ij] := 0; [ij]+1 < len(.*); [ij] += 2" internal/parser/collection.go
14
$ grep -n "for [ij] := 0; [ij] < len(.*); [ij] += 2" internal/parser/collection.go internal/parser/include.go
(no matches)
```

The remaining four use `< len(...)-1`. `include.go:197` guards `doc.Content[0]`
with an explicit `len(doc.Content) == 0` check.

Three adversarial YAML shapes were run through the real binary:

| Input | Result | Time |
|---|---|---|
| 50 000-deep nested flow sequence (100 KB) | `line 7: invalid YAML syntax: yaml: line 7: exceeded max depth of 10000` | — |
| 9-level alias bomb (9^9 expansion) | `OK bomb.yaml is valid` | 0.009 s |
| mutual and direct circular `variables:` | `OK circ.yaml is valid` | — |

`gopkg.in/yaml.v3 v3.0.1` caps nesting at 10 000, so the stack-overflow class is
closed by the dependency. **The parser fuzz target may well find nothing, and
that is a legitimate result.** The verification report records exec counts and
durations honestly rather than manufacturing a fix.

(Noted in passing, out of scope: `curlew validate` does **not** resolve
variables, which is why `circ.yaml` validates clean. The circular-reference
termination the task asks for therefore has to be asserted at the
`variable.Scope` level, which is what Step 4 does.)

### F2 — one surface has a confirmed unbounded allocation, reachable from a 9-character literal

`internal/variable/dynamic.go:444` registers `$randomBase64`:

```go
n, err := strconv.Atoi(args[0])
...
if n < 1 { return "", &apierrors.Structured{...} }
b := make([]byte, n)
```

`n` is user input from the collection file. The only guard is `n < 1`. There is
no upper bound. `makePassword` (`dynamic.go:1364`) has the same shape:
`buf := make([]byte, n)` guarded only by `n < 4`.

Measured against the real binary — a collection whose only unusual content is a
header `X-Pad: "{{$randomBase64('100000000')}}"`:

```
$ /usr/bin/time -l curlew run rb.yaml
[ERROR] r — Connection refused at 127.0.0.1:1
  1 request(s): 0 passed, 1 failed (5677ms)
        5.69 real         5.66 user         0.05 sys
   658800640  maximum resident set size
```

**658.8 MB peak RSS and 5.69 s from a nine-digit literal.** Ten digits
(`'9999999999'`) asks for ~10 GB. `docs/MANUAL.md:1099` documents the argument as
"1 integer string (>= 1)" with no upper bound, so the documentation and the
implementation agree — and both are wrong.

This is the single most likely thing the interpolation campaign will surface,
because mutating the digits of a seeded `{{$randomBase64('32')}}` is the easiest
mutation a fuzzer can make. **The plan predicts it; the execute phase must
confirm it by fuzzing before fixing it.** Step 7 carries the fix, contingent on
confirmation.

## Design decisions

**D1 — `FuzzCEL` compiles; it does not evaluate.** The task's own behaviour
statement scopes it to compilation ("when it is compiled, then it returns an
error or a program"). This is also the safe choice: `internal/cel/cel.go:108`
builds the environment with `celgo.StdLib()` and `ext.Strings()` and **no**
`celgo.CostLimit` or interrupt-check frequency. Nested comprehensions
(`[1,2].map(x, [1,2].map(y, ...))`) cost 2^depth with depth linear in source
length, so evaluating fuzzer-authored expressions is unbounded work and would
produce hang reports rather than defects. Evaluation cost limiting is a real gap
but a different task.

**D2 — `FuzzParseCollection` calls `parseCollectionBytes` plus ParseFile's
post-parse pipeline, not `ParseFile`.** `ParseFile` differs only by
`os.ReadFile` (which fuzzing supplies directly) and `resolveIncludes` (which
needs real files on disk). Writing a file per iteration would cost a syscall per
exec for no new coverage. To stop the harness drifting away from what `ParseFile`
actually does, Step 5 adds a parity test that runs every non-`include:` fixture
through both and requires them to agree.

**D3 — the operator matrix is iterated inside `FuzzJSONPath`, not fuzzed as an
argument.** `evalBodyAssertion` switches on 14 operators; making the operator a
fuzz argument wastes the mutation budget rediscovering 14 fixed strings. The
target takes `(path string, value string, body []byte)` and loops over the
operator set read out of the switch with `go/ast` — reusing
`operatorsFromSwitch`, which already exists in `internal/assertion/doc_operators_test.go`.

**D4 — seeds come from a shared `internal/fuzzseed` package that errors on an
empty source set.** Four packages would otherwise each re-implement repo-root
discovery and fixture walking. Precedent: `internal/docs` is a non-test package
that exists to serve tests. Critically, `fuzzseed` returns `ErrNoSeeds` when a
named source directory yields zero files rather than silently seeding nothing —
the same posture as `internal/backlog` erroring rather than reporting an empty
success.

**D5 — the gate does not fuzz.** `ci-local.sh` gains one named step that runs the
committed corpora as ordinary tests (~2 s), never `-fuzz`. The task is explicit:
"the gate keeps the corpora, not the fuzzing".

**D6 — the task's observable omits `internal/cel` from its second command.**
`go test ./internal/parser/ ./internal/variable/ ./internal/assertion/ -run Fuzz -v`
lists three of the four packages. Read as an oversight, not an instruction: the
gate step covers all four. Verification runs the observable exactly as written
**and** the four-package superset.

#### Proposed signatures

```go
// Package fuzzseed loads fixtures already in the repository as fuzz seed
// corpora. A seed corpus of real inputs finds interesting mutations far faster
// than a corpus of empty strings, and every source here is a file some other
// test already depends on, so a seed set that silently empties is a moved
// fixture rather than a design choice.
package fuzzseed

// ErrNoSeeds is returned when a named source set matched no files. Returning
// an error rather than an empty slice is deliberate: a fuzz target seeded with
// nothing still passes, which is the false clear internal/backlog exists to
// prevent.
var ErrNoSeeds = errors.New("fuzz seed set is empty")

// Seed is one fixture: its repo-relative path and its bytes. The path is
// carried so a failing seed names the file it came from.
type Seed struct {
	Path string
	Data []byte
}

// Root returns the repository root, found by walking up from dir until a
// directory containing go.mod is reached.
func Root(dir string) (string, error)

// Collections returns every collection-shaped YAML fixture in the repository:
// internal/parser/testdata/**/*.yaml, testapi/collections/**/*.yaml,
// testapi/*.yaml, testapi/environments/*.yaml, testapi/gaps/*.yaml and
// examples/**/*.yaml.
func Collections(root string) ([]Seed, error)

// Templates returns every scalar containing "{{" found in Collections.
func Templates(root string) ([]string, error)

// CELExpressions returns every scalar appearing under a cel: key in
// Collections, plus the CEL expressions in docs/MANUAL.md's tables.
func CELExpressions(root string) ([]string, error)

// JSONPaths returns every JSONPath used in Collections: the mapping keys under
// an assertions.body block, and any scalar beginning with "$.".
func JSONPaths(root string) ([]string, error)

// JSONBodies returns the bytes of every *.json fixture under internal/.
func JSONBodies(root string) ([]Seed, error)
```

`Templates`, `CELExpressions` and `JSONPaths` walk `yaml.Node` trees directly
rather than decoding into `parser.Collection`. That keeps `fuzzseed` free of any
dependency on `internal/parser` (which would be an import cycle for the parser's
own in-package fuzz test) and means a fixture that no longer parses as a
collection still yields seeds.

```go
package cel

func FuzzCEL(f *testing.F) {
	root, err := fuzzseed.Root(".")
	if err != nil {
		f.Fatalf("locating repo root: %v", err)
	}
	exprs, err := fuzzseed.CELExpressions(root)
	if err != nil {
		f.Fatalf("loading CEL seeds: %v", err)
	}
	for _, src := range exprs {
		f.Add(src)
	}

	// One evaluator for the whole target: NewEvaluator builds a cel-go
	// environment, which is far more expensive than a compile.
	ev, err := NewEvaluator()
	if err != nil {
		f.Fatalf("building evaluator: %v", err)
	}

	f.Fuzz(func(t *testing.T, src string) {
		// Compile only. See D1: the environment carries no cost limit, so
		// evaluating fuzzer-authored comprehensions is unbounded work.
		for _, want := range []*celgo.Type{celgo.BoolType, nil} {
			prog, err := ev.Compile(src, want)
			switch {
			case err != nil && prog != nil:
				t.Fatalf("Compile(%q) returned both a program and an error %v", src, err)
			case err == nil && prog == nil:
				t.Fatalf("Compile(%q) returned neither a program nor an error", src)
			case err != nil:
				var ce *CelError
				if !errors.As(err, &ce) {
					t.Fatalf("Compile(%q) error %T is not a *CelError: %v", src, err, err)
				}
				if !errors.Is(err, ErrCelParse) && !errors.Is(err, ErrCelType) {
					t.Fatalf("Compile(%q) error matches neither sentinel: %v", src, err)
				}
			}
		}
		// Same input, the other user-facing reader in this package.
		_ = CollectTopLevelRefs(src, ev)
	})
}
```

The invariant is stronger than "no panic": every error must carry one of the two
declared sentinels and be a `*CelError`, so an error escaping the package's own
error contract is a finding too.

#### Impact on Existing Tests

None. `errors`, `celgo` and `testing` are already imported by files in this
package; the fuzz file imports them independently.

```go
func FuzzJSONPath(f *testing.F) {
	root, err := fuzzseed.Root(".")
	...
	paths, err := fuzzseed.JSONPaths(root)
	bodies, err := fuzzseed.JSONBodies(root)
	// Cross the two sets, capped so the seed corpus stays a couple of hundred
	// entries rather than |paths| x |bodies|.
	for i, p := range paths {
		f.Add(p, p, bodies[i%len(bodies)].Data)
	}

	ops := operatorsFromSwitch(f, "evalBodyAssertion")

	f.Fuzz(func(t *testing.T, path, value string, body []byte) {
		// The path evaluator on its own, against whatever the body decodes to.
		var doc any
		_ = json.Unmarshal(body, &doc)
		if _, err := jsonpath.Evaluate(path, doc); err != nil {
			if !errors.Is(err, jsonpath.ErrNotFound) && !errors.Is(err, jsonpath.ErrInvalidPath) {
				t.Fatalf("Evaluate(%q) error matches neither sentinel: %v", path, err)
			}
		}
		// The whole assertion surface, every operator, including the
		// regexp.Compile that "matches" performs on a fuzzed value.
		for _, op := range ops {
			in := []BodyInput{{Path: path, Operator: op, Value: value}}
			got := CheckBody(in, body)
			if len(got) != len(in) {
				t.Fatalf("CheckBody returned %d results for %d assertions", len(got), len(in))
			}
			if got[0].Type != TypeBody {
				t.Fatalf("CheckBody result type = %q, want %q", got[0].Type, TypeBody)
			}
		}
	})
}
```

The one-result-per-input and correct-`Type` checks are the property worth
asserting beyond "no panic": `CheckBody` has three separate return paths per
assertion (non-JSON root, non-JSON deep path, normal eval) and a dropped result
would silently unassert something.

#### New Code

```go
package variable

// fuzzVars turns an arbitrary blob into a variable map deterministically:
// split on '\n', then on the first '='. Deterministic and dependency-free, so
// a corpus entry reproduces identically on any machine.
func fuzzVars(blob string) map[string]string

func FuzzInterpolate(f *testing.F) {
	root, err := fuzzseed.Root(".")
	...
	for _, tmpl := range fuzzseed.Templates(root) {
		f.Add(tmpl, "base_url=http://127.0.0.1\ntoken=abc\nname=curlew")
	}
	// Shapes the fixtures do not contain, added explicitly because they are
	// the recursion and cycle paths.
	f.Add("{{a}}", "a={{a}}")                              // direct self reference
	f.Add("{{a}}", "a={{b}}\nb={{a}}")                     // mutual cycle
	f.Add("{{$base64('{{$base64('a')}}')}}", "a=1")        // nested dyn-fn args
	f.Add("{{$randomBase64('32')}}", "a=1")                // F2: the digits mutate
	f.Add("{{secrets.API_KEY}}", "a=1")                    // secrets namespace
	f.Add("{{a|default:x}}", "")                           // default fallback

	f.Fuzz(func(t *testing.T, tmpl, blob string) {
		seed := int64(1)
		s := NewScope(fuzzVars(blob)).
			WithDynamic(NewRegistry(&seed)).       // fixed seed: reproducible
			WithSecrets(map[string]string{"API_KEY": "s3cr3t"})

		if err := s.Resolve(); err != nil {
			// Resolution may legitimately fail, but only in declared ways.
			if !errors.Is(err, ErrCircularReference) &&
				!errors.Is(err, ErrDepthExceeded) &&
				!errors.Is(err, ErrUndefinedVariable) {
				t.Fatalf("Resolve() error matches no declared sentinel: %v", err)
			}
			return
		}
		s.BeginRequest()
		defer s.EndRequest()
		_, _ = s.Interpolate(tmpl)
		_, _ = s.InterpolateMap(map[string]string{"k": tmpl})
		_, _ = s.InterpolateBody(map[string]any{"k": []any{tmpl, 1, true}})
	})
}
```

A registry is attached deliberately: `Interpolate` returns early at
`if s.registry == nil { return match }` before it ever parses dynamic-function
arguments, so a scope without one leaves the entire `{{$fn(...)}}` path —
including its recursive `s.Interpolate(lit)` on each argument — unfuzzed.

#### Tests to write FIRST (RED phase)

```go
func TestScope_self_reference_terminates_with_ErrCircularReference(t *testing.T) {
	tests := []struct {
		name string
		vars map[string]string
		want error // nil means "resolves"
	}{
		{"direct self reference",            map[string]string{"a": "{{a}}"},                        ErrCircularReference},
		{"mutual two-cycle",                 map[string]string{"a": "{{b}}", "b": "{{a}}"},          ErrCircularReference},
		{"three-cycle",                      map[string]string{"a": "{{b}}", "b": "{{c}}", "c": "{{a}}"}, ErrCircularReference},
		{"self reference inside a dyn-fn arg", map[string]string{"a": "{{$base64('{{a}}')}}"},       ErrCircularReference},
		{"chain of 9 resolves",              chainVars(9),                                           nil},
		{"chain of 12 exceeds depth",        chainVars(12),                                          ErrDepthExceeded},
		{"self reference behind a default",  map[string]string{"a": "{{a|default:x}}"},              nil},
	}
	// Each case runs in a goroutine with a 5s deadline. Termination is
	// asserted, not assumed: on timeout the test fails with
	// "did not terminate within 5s" rather than waiting for the package
	// timeout to dump every stack.
}
```

The `{{a|default:x}}` case is included because `findVarRefs` uses `varPattern`,
which cannot match a name followed by `|`. That value is therefore not a
self-reference at resolve time and must resolve, not cycle. It is exactly the
kind of asymmetry between two regexes that a table pins down and prose does not.


unrelated failure aborts the chunk before a single exec.

#### Rules

1. **Foreground only.** No `run_in_background`, no `&`. One chunk per Bash call.
2. **Crash iff artifact** (M4). A nonzero exit with no new file under

3. **Orphan check every chunk.** Zero surviving `fuzzworker` processes, verified
   by `ps`, before the next chunk starts.
4. **When a crasher appears, stop that target.** Fix it (Step 7), commit the
   artifact, then resume that target's remaining chunks — a corpus that keeps
   rediscovering the same crash learns nothing.
5. **Record everything as it happens** into `management/plans/M27-002-verified.md`
   as the campaign runs, not reconstructed afterwards.

## Risks and Edge Cases

- **Risk: a fuzz chunk exceeds the 600 s Bash cap and the call is killed
  mid-run.** → **Mitigation:** `-fuzztime 420s -fuzzminimizetime 30s` gives a
  measured worst case of ≈ 470 s. The generated corpus is written to
  `$GOCACHE/fuzz` continuously (M2), so even a killed chunk loses only its
  unflushed tail, and the next chunk resumes from the cache.

- **Risk: fuzz workers survive a killed chunk and pile up.** → **Mitigation:**
  every chunk ends with a `ps` check for `fuzzworker`; six probe chunks left zero
  survivors. If any appear, the chunk sequence stops and they are killed before
  the next one starts.

- **Risk: the campaign finds nothing and the task looks unfinished.** →
  **Mitigation:** F1 establishes the parser is already guarded at every
  `Content[i+1]` site and that yaml.v3 caps nesting at 10 000, so a clean result
  is plausible. The DoD item "every crasher fixed" is vacuously satisfied by zero
  crashers **provided** the exec counts and durations are recorded. Nothing is
  invented to fill the gap.

- **Edge case: `FuzzParseCollection` reaching the real filesystem.** External
  refs (`path:`, `body_file:`, `graphql.query_file:`, `message_template:`) accept
  absolute paths, and `httpbody.LoadBody` size-checks via `info.Size()` — which is
  0 for a character device, so `/dev/zero` would read until memory ran out. →
  **Handling:** the collection path lives in an empty `f.TempDir()`, so relative
  refs all miss; no seed contains an absolute path, so the fuzzer would have to
  synthesise one character by character. If a chunk hangs with high RSS, the
  input is recovered from `$GOCACHE/fuzz` and the harness gains an
  absolute-path reject before the campaign resumes.

- **Edge case: seed corpus size inflating the gate.** ~150 parser fixtures plus
  templates, paths and CEL expressions is a few hundred subtests on every
  `go test` **and** every `go test -race`. → **Handling:** the execute phase
  measures the four packages' test time before and after and records both. If
  the delta exceeds ~2 s, `fuzzseed.Collections` is capped by deduplicating on
  content hash.

- **Edge case: `f.Add` with an unstable seed set.** A seed corpus assembled by
  walking the repo changes when fixtures are added. That is intended — new
  fixtures should seed the fuzzer — but a *shrinking* set is a moved directory.
  → **Handling:** `ErrNoSeeds` per source, plus per-reader `atLeast` floors in
  `fuzzseed_test.go`.

- **Edge case: non-determinism inside the interpolation target.** `$timestamp`,
  `$isoTimestamp` and `$timestampMs` read `time.Now()`. → **Handling:** they
  cannot fail, so they do not affect reproduction of a crasher; the random
  family is pinned by `NewRegistry(&seed)` with a fixed seed. `ExecuteCommand`
  is **not** reachable from `Interpolate` — it is called only from
  `internal/runner` — so no fuzz input can cause a shell to run. Verified by
  grep: the only call sites are `runner.go:1165`, `1181`, `1359`.
