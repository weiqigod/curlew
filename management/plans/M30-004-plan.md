## Contract

- POSIX user commands keep `/bin/sh -c`; Windows uses system Windows PowerShell
  with no profile, non-interactive encoded scripts, and UTF-8 output.
- Windows script syntax is explicit, not translated Bash. Native exit codes,
  script errors, cancellation, and empty output have regression tests.
- Trim trailing newline sequences, not spaces or internal newlines. Reject
  invalid UTF-8 instead of silently corrupting secrets.
- Providers use executable, argv, and child environment overrides by default.
  Non-nil legacy callbacks still receive their existing POSIX command strings.
- Test Windows `.exe` and `.cmd` invocation separately. Do not equate ordinary
  executable quoting with cmd batch quoting. Reject unsupported unsafe arguments
  rather than run a changed command.
- Contain command descendants on Windows before allowing execution; cancel and
  reap them on deadline and on normal parent exit. Bound output pipe draining.
- No live providers, cloud requests, config/model changes, or unrelated plugin/UI
  portability work. No push or PR without approval.

## Risks And Verification

1. Process launch must not leave a race in which a child escapes containment.
2. Windows batch quoting is distinct from PowerShell and native argv quoting.
3. Keep provider diagnostics useful without exposing credentials.
4. Preserve context error identity and never contact installed provider accounts.

Focused checks: native variable/vault tests, runner vault tests, build, and a
real-binary loopback collection using local provider stubs. Record coverage for
touched packages. Cross-build POSIX code but do not call that POSIX execution.

## Execution Updates

- Added platform process runners/tests, structured program tests, and compiled
  helpers in internal/variable/testdata/programhelper and testdata/providerstub.
  Existing golang.org/x/sys dependency is now direct; its version is unchanged.
- Windows containment uses CREATE_SUSPENDED plus Job Object assignment before
  resuming the primary thread; actual parent/child/grandchild tests pass.
- POSIX containment owns output pipes so it can terminate the process group after
  root exit but before draining. An actual Linux RED reproduced ErrWaitDelay;
  the fix passed the same regression.
- Runner now registers resolved command/vault/shared values before events and
  retains them in early-error summaries. Real-binary echo tests exposed the leak
  before the fix. An added early-error regression passes with both set lifetimes.
- CLI run now propagates os.Interrupt to command resolution. A POSIX real CLI RED
  left the command child alive; GREEN returns exit 5 and removes the process group.
- A supplementary source audit identified the POSIX drain issue and a shared
  fixture CRLF assumption; both were fixed. This is not a passing workflow review.
- Existing Ubuntu WSL was discovered during verification. A checksum-verified
  temporary Linux Go toolchain enabled actual POSIX tests, independently of native
  Windows tests. Full affected suites pass on both systems after warming builds.
- Test fixture builds omit irrelevant VCS stamping and are time-bounded. Cold
  Linux CLI compilation was warmed outside the fixture's two-minute deadline.
- Initial batch forwarding rejected quotes and most controls. That was an
  incomplete implementation of the requested contract, not an accepted scope
  reduction. The resumed work below replaces those restrictions with exact argv
  tests and an encoder covering both CMD parsing passes.
- The authoritative Go gate was attempted. It stops at README quickstart test
  discovery with the unchanged syscall.Kill Windows compilation failure. No
  review/done status transition or push/PR was performed.
