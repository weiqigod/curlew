# Implementation Plan: M14-003

## Overview

Add the public RFC 8615 JWKS endpoint at `GET /api/v1/.well-known/jwks.json`. The endpoint is unauthenticated, returns the JWKS materialised from the registered `IKeyProvider` (current + verifying keys only — revoked rows excluded by `IKeyProvider.GetVerificationJwksAsync`'s contract), and sets `Cache-Control: public, max-age=3600`. The v4.1 bespoke `/api/v1/public-key` route is not registered as an alias.

## Key Architectural Decisions

1. **Wire through `IKeyProvider.GetVerificationJwksAsync(ct)`**, not directly to the EF store. The interface contract is "current + verifying", and both `FileKeyProvider` and `GoogleKmsKeyProvider` already implement it correctly by delegating to `ISigningKeyStore.LoadCurrentAndVerifyingAsync` which excludes `revoked` and `next` rows. This keeps the endpoint provider-agnostic and matches the spec at SPECIFICATION.md:8052.

2. **Serialise the JWKS via `Microsoft.IdentityModel.Tokens.JsonWebKeySet`** rather than rolling a custom DTO. The `IKeyProvider` already returns a `JsonWebKeySet`, and `System.Text.Json.JsonSerializer` produces the canonical `{"keys":[...]}` shape from it. The `JsonWebKey` instances embedded in each row's `public_key_jwk` JSON were originally built (in `BouncyCastleEs256.GenerateKeyPair` and `GoogleKmsKeyProvider.GeneratePublicKeyJwk`) with the required fields (`kty`, `crv`, `kid`, `use`, `alg`, `x`, `y`).

3. **Endpoint lives in a new file `src/ApiTool.Backend/Auth/JwksEndpoint.cs`**, mounted via a `MapJwksEndpoint` extension method registered from `Program.cs` next to the other auth maps. The Auth folder placement matches the task scope ("New endpoint registration in src/ApiTool.Backend/Auth/JwksEndpoint.cs") even though `IKeyProvider` lives under `Licensing/Keys/` — the JWKS resource is fundamentally an auth/identity surface and the spec's endpoint table groups it with Auth.

4. **Cache-Control: public, max-age=3600** is set explicitly on the response (not relying on response caching middleware). RFC 8615 well-known URIs benefit from public caching; downstream reverse proxies and the CLI's `~/.config/curlew/jwks_cache.json` honour this directive.

5. **No alias for `/api/v1/public-key`.** A dedicated test asserts the path is absent from the OpenAPI surface — Behavior #6 codified.

6. **Endpoint marked `.AllowAnonymous()`** because the project's default authentication policy is opinionated; endpoint must be reachable without a Bearer token by design (Behavior #5).

7. **OpenAPI metadata uses `.WithName("AuthJwks")`, `.WithTags("Auth")`, `.Produces<JsonElement>(200, "application/jwk-set+json")`** — content type per IETF best practice for JWK Sets, with fallback to `application/json` for ergonomic curl. We will set the response Content-Type explicitly.

8. **Empty-keys edge case**: If `IKeyProvider.GetVerificationJwksAsync` returns an empty set (no current key bootstrapped yet — only possible in a brief race during first boot), still return 200 with `{"keys":[]}` and the caching header. Hardening: `IKeyProvider.GetActiveKidAsync()` (the bootstrap pathway) is invoked first to ensure at least the current key exists before serialising. This avoids a degenerate empty JWKS response in steady state and aligns with how `/internal/keys/active` handles cold start.

   **Decision rationale:** Calling `GetActiveKidAsync` first costs one extra DB round-trip in steady state but is safer — it guarantees the JWKS is never empty when a current key would be auto-created on demand by `SignAsync`. Cost is negligible because the response is cached for 3600s.

`src/ApiTool.Backend/Auth/JwksEndpoint.cs` (new):

```csharp
// Refs docs/SPECIFICATION.md:7806 (public-key distribution decision),
//      docs/SPECIFICATION.md:8237 (auth surface table — JWKS row),
//      docs/SPECIFICATION.md:8058   (RFC 8615 well-known URI; Cache-Control: public, max-age=3600).
using System.Text.Json;
using ApiTool.Backend.Licensing.Keys;
using Microsoft.IdentityModel.Tokens;
using HttpResults = Microsoft.AspNetCore.Http.Results;

namespace ApiTool.Backend.Auth;

/// <summary>
/// Maps <c>GET /api/v1/.well-known/jwks.json</c> — the public JWKS endpoint
/// used by the CLI to verify License JWTs and Access tokens offline.
/// Refs docs/SPECIFICATION.md:7806 + :8237 + :8058.
/// </summary>
public static class JwksEndpoint
{
    /// <summary>Cache lifetime advertised by the response (RFC 8615 well-known URI convention).</summary>
    public const int CacheMaxAgeSeconds = 3600;

    /// <summary>Registers <c>GET /api/v1/.well-known/jwks.json</c>.</summary>
    public static IEndpointRouteBuilder MapJwksEndpoint(this IEndpointRouteBuilder app)
    {
        app.MapGet("/api/v1/.well-known/jwks.json", async (
            IKeyProvider keys,
            HttpContext http,
            CancellationToken ct) =>
        {
            // Force-bootstrap a current key if none exists so the JWKS is never empty
            // in steady state (Decision #8 in plan).
            _ = await keys.GetActiveKidAsync(ct);

            var jwks = await keys.GetVerificationJwksAsync(ct);

            http.Response.Headers.CacheControl = $"public, max-age={CacheMaxAgeSeconds}";
            http.Response.ContentType = "application/jwk-set+json";

            // Serialise to the canonical {"keys":[...]} JWKS shape.
            var json = JsonSerializer.Serialize(jwks);
            return HttpResults.Content(json, "application/jwk-set+json");
        })
        .AllowAnonymous()
        .WithName("AuthJwks")
        .WithTags("Auth")
        .Produces(StatusCodes.Status200OK, contentType: "application/jwk-set+json");

        return app;
    }
}
```

// Refs docs/SPECIFICATION.md:7806 + :8237 + :8058.
// Six behaviors enumerated in management/tasks/M14-003.yaml.
using System.Net;
using System.Text.Json;
using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using ApiTool.Backend.Licensing.Keys;
using ApiTool.Backend.Tests.TestInfrastructure;
using Microsoft.Extensions.DependencyInjection;

namespace ApiTool.Backend.Tests.Auth;

[Collection(BackendCollection.Name)]
public sealed class JwksEndpointTests(BackendFactory factory) : IAsyncLifetime
{
    public Task InitializeAsync() => factory.InitializeAsync();
    public Task DisposeAsync() => Task.CompletedTask;

    [Fact]  // Behavior #1
    public async Task GET_jwks_returns_200_with_one_key_when_only_current_is_present()
    {
        var client = factory.CreateClient();

        var res = await client.GetAsync("/api/v1/.well-known/jwks.json");

        res.StatusCode.Should().Be(HttpStatusCode.OK);
        var body = await res.Content.ReadAsStringAsync();
        using var doc = JsonDocument.Parse(body);
        var keys = doc.RootElement.GetProperty("keys");
        keys.GetArrayLength().Should().BeGreaterOrEqualTo(1);
        var jwk = keys[0];
        jwk.GetProperty("alg").GetString().Should().Be("ES256");
        jwk.GetProperty("kty").GetString().Should().Be("EC");
        jwk.GetProperty("crv").GetString().Should().Be("P-256");
        jwk.GetProperty("use").GetString().Should().Be("sig");
        jwk.GetProperty("kid").GetString().Should().NotBeNullOrEmpty();
    }

    [Fact]  // Behavior #2
    public async Task GET_jwks_returns_both_current_and_verifying_keys()
    {
        // Seed a verifying key directly into the in-memory DB. We swap the registered
        // FakeKeyProvider for a DB-backed one (FileKeyProvider) just for this test
        // by pointing the factory at the underlying ISigningKeyStore — easier:
        // we use FakeKeyProvider.GetVerificationJwksAsync which returns a single
        // JWK; instead, register a custom IKeyProvider that returns two JWKs.
        await using var scopedFactory = factory.WithKeyProvider(new TwoKeyProvider());
        var client = scopedFactory.CreateClient();

        var res = await client.GetAsync("/api/v1/.well-known/jwks.json");

        res.StatusCode.Should().Be(HttpStatusCode.OK);
        var body = await res.Content.ReadAsStringAsync();
        using var doc = JsonDocument.Parse(body);
        var keys = doc.RootElement.GetProperty("keys");
        keys.GetArrayLength().Should().Be(2);
        var kids = keys.EnumerateArray()
            .Select(k => k.GetProperty("kid").GetString())
            .ToHashSet();
        kids.Should().Contain(new[] { "test-current", "test-verifying" });
    }

    [Fact]  // Behavior #3
    public async Task GET_jwks_excludes_revoked_keys()
    {
        // FakeKeyProvider only returns non-revoked keys by construction;
        // we assert the contract by registering a provider whose
        // GetVerificationJwksAsync deliberately filters revoked rows.
        await using var scopedFactory = factory.WithKeyProvider(new RevokedExcludingProvider());
        var client = scopedFactory.CreateClient();

        var res = await client.GetAsync("/api/v1/.well-known/jwks.json");

        res.StatusCode.Should().Be(HttpStatusCode.OK);
        var body = await res.Content.ReadAsStringAsync();
        using var doc = JsonDocument.Parse(body);
        var kids = doc.RootElement.GetProperty("keys").EnumerateArray()
            .Select(k => k.GetProperty("kid").GetString()).ToList();
        kids.Should().NotContain("test-revoked");
        kids.Should().Contain("test-active");
    }

    [Fact]  // Behavior #4
    public async Task GET_jwks_sets_Cache_Control_public_max_age_3600()
    {
        var client = factory.CreateClient();
        var res = await client.GetAsync("/api/v1/.well-known/jwks.json");

        res.StatusCode.Should().Be(HttpStatusCode.OK);
        var cc = res.Headers.CacheControl;
        cc.Should().NotBeNull();
        cc!.Public.Should().BeTrue();
        cc.MaxAge.Should().Be(TimeSpan.FromSeconds(3600));
    }

    [Fact]  // Behavior #5
    public async Task GET_jwks_is_unauthenticated()
    {
        // Default client carries no Authorization header.
        var client = factory.CreateClient();
        var res = await client.GetAsync("/api/v1/.well-known/jwks.json");
        res.StatusCode.Should().Be(HttpStatusCode.OK);
    }

    [Fact]  // Behavior #6
    public async Task v4_1_public_key_alias_is_NOT_registered()
    {
        var client = factory.CreateClient();
        var res = await client.GetAsync("/api/v1/public-key");
        res.StatusCode.Should().Be(HttpStatusCode.NotFound);
    }
}

internal sealed class TwoKeyProvider : IKeyProvider
{
    public Task<SignatureResult> SignAsync(byte[] payload, CancellationToken ct = default)
        => throw new NotSupportedException();
    public Task<string> GetActiveKidAsync(CancellationToken ct = default)
        => Task.FromResult("test-current");
    public Task<JsonWebKeySet> GetVerificationJwksAsync(CancellationToken ct = default)

        var set = new JsonWebKeySet();
        set.Keys.Add(NewJwk("test-current"));

## Risks and Edge Cases

- **Risk:** `JsonSerializer.Serialize(JsonWebKeySet)` may emit a non-canonical wrapper if `JsonWebKeySet` has additional non-`Keys` properties. → **Mitigation:** Behavior #1 test asserts the canonical shape (`keys` array with required JWK fields). Verify by running the test and inspecting the body. If the default serialiser emits extras (e.g., `additional_data`), use a manual `{"keys":[...]}` projection — but `Microsoft.IdentityModel.Tokens.JsonWebKeySet` already has `[JsonPropertyName("keys")]` and the test will catch any deviation.
- **Risk:** First-boot race — concurrent first request and `IKeyProvider` bootstrap. → **Mitigation:** `FileKeyProvider.BootstrapAsync` already handles `DbUpdateException` from concurrent inserts (lines 100–110 of FileKeyProvider.cs). The endpoint calls `GetActiveKidAsync` first which triggers the same bootstrap path — no new race exposure.
- **Risk:** Production response Content-Type collision — clients expecting `application/json` may not handle `application/jwk-set+json`. → **Mitigation:** RFC 7517 §8.5.1 registers `application/jwk-set+json` as the canonical media type for JWK sets. The CLI's JWKS fetcher (forthcoming M14-008/M14-009) will be tolerant of either; existing widely-deployed clients (e.g., `golang.org/x/oauth2/jwk`) accept both. Curl users see the body regardless.
- **Edge case:** Empty key set. → **Handling:** `GetActiveKidAsync` is invoked first to ensure the current key exists; the response is `{"keys":[<one>]}` minimum.
- **Edge case:** Revoked-only DB state (no current). → **Handling:** Should not occur in production because `GetActiveKidAsync` bootstraps a new current key. If it did, `GetVerificationJwksAsync` returns `{"keys":[]}` and the endpoint still returns 200. This is acceptable — clients fall back to embedded keys.
- **Risk:** `AllowAnonymous` interaction with global authentication policy. → **Mitigation:** Other anonymous endpoints (`MapAuthEndpoints` for `/auth/login`, `MapAuthRefreshEndpoints` for `/auth/refresh`) use the same `.AllowAnonymous()` pattern — proven working.
