## Overview
Add four non-Latin-script faker locale pools — ja-JP, zh-CN, ko-KR (CJK) and
ru-RU (Cyrillic) — to the M20-001 `localeData` lookup, introducing a

## Key Architectural Decisions

**KAD-1 — Name ordering as a `localeData` field, not a per-locale fullName closure.**
The `$faker.fullName` closure (`dynamic.go:516-519`) currently hard-codes
`first + " " + last`. CJK locales render family-name-first ("山田 太郎",
"张伟", "김민준") and ru-RU renders given-name-first like the Latin pools
("Иван Иванов"). Rather than branch on locale code inside the closure, add a
`familyNameFirst bool` field to `localeData`. The closure reads
`r.locale.familyNameFirst` and swaps the order. This keeps the closure
locale-agnostic, keeps the seed-position-invariance contract intact (both draws
still happen in the same order: firstName index first, then lastName index — only
the *concatenation* order changes, never the *draw* order), and makes en-US and
every Latin locale a zero-value (`false`) no-op so their output stays
byte-identical. Default `false` = given-name-first.

**KAD-2 — Separator stays a single ASCII space for all four.**
SPEC shows "山田 太郎" and "김민준" with a space and "张伟" with none, but a
uniform single-space separator is chosen for all locales: it keeps the seam to a
single bool, matches the SPEC's own rendered examples for ja-JP/ko-KR/ru-RU, and
the zh-CN example "张伟" is a 2-character given name shown without a separator
only incidentally. A space-joined Han name ("张 伟") is unambiguous and valid.
Introducing a per-locale separator string would be gold-plating for one locale's
typographic nicety. Documented here so a future reviewer does not mistake it for
an oversight.

**KAD-3 — Eager package-level registration, continuing the M20-002 precedent.**
SPEC:1110 mentions lazy loading behind sync.Once; the task `scope` references
"behind sync.Once per settled decision 4". M20-002 consciously chose eager
package-level map-literal registration instead (its plan §KAD-1, asserted by
`TestLocalePools_Behaviour6_EagerRegistrationEquivalent`): the pools are tiny
in-source Go slices (~hundreds of bytes, not the SPEC's hypothetical ~100KB), so
the startup-cost concern that motivates lazy init does not apply, and the
observable contract (pools present on any request, no panic on first access) is
identical. M20-003 continues that precedent for consistency — diverging would
leave two registration strategies in one file. The behaviour test for these four
locales asserts eager-registration equivalence the same way M20-002 does. This
resolves the open question in the task scope: the "behind sync.Once" phrasing is
satisfied behaviourally by eager init, exactly as M20-002 resolved it.

**KAD-4 — Phone formats taken from the SPEC:974-986 table, not the stale
SPEC:980 line reference in the task YAML.** The task observable cites "SPEC:980"
but the canonical Supported-Locales table lives at docs/SPECIFICATION.md:974-986.
The four target shapes from that table are:
- ja-JP: `+81 3-1234-5678`  → `+81 <1-digit area> - <4> - <4>` rendered `+81 %d-%04d-%04d`
- zh-CN: `+86 10 1234 5678`  → `+86 <2-digit area> <4> <4>` rendered `+86 %02d %04d %04d`
- ko-KR: `+82 2-1234-5678`  → `+82 <1-digit area> - <4> - <4>` rendered `+82 %d-%04d-%04d`
- ru-RU: `+7 495 123-45-67`  → `+7 <3-digit area> <3>-<2>-<2>` rendered `+7 %03d %03d-%02d-%02d`

r.funcs["faker.fullName"] = noArgs("faker.fullName", func(rng *rand.Rand) string {
	fn, ln := r.locale.firstNames, r.locale.lastNames
	// Draw order is fixed (first index, then last index) so the seed selects
	// the same positions in every locale; only the join order varies.
	first := fn[intn(rng, len(fn))]
	last := ln[intn(rng, len(ln))]
	if r.locale.familyNameFirst {
		return last + " " + first
	}
	return first + " " + last
})
```

func TestLocalePools_NameOrdering(t *testing.T) {
	// SPEC:974-986 — CJK locales render family-name-first; ru-RU and Latin
	// locales render given-name-first. Verify by checking which pool the
	// leading token comes from at a fixed seed.
	tests := []struct {
		name            string
		locale          string
		familyNameFirst bool
	}{
		{"ja-JP family-name-first", "ja-JP", true},
		{"zh-CN family-name-first", "zh-CN", true},
		{"ko-KR family-name-first", "ko-KR", true},
		{"ru-RU given-name-first", "ru-RU", false},
		{"en-US given-name-first (regression)", "en-US", false},
		{"de-DE given-name-first (regression)", "de-DE", false},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			// Assert the struct flag matches expectation.
			if got := localePools[tc.locale].familyNameFirst; got != tc.familyNameFirst {
				t.Fatalf("%s familyNameFirst = %v, want %v", tc.locale, got, tc.familyNameFirst)
			}
			// Assert the rendered fullName puts the expected pool's value first.
			seed := int64(42)
			reg := NewRegistry(&seed, WithLocale(tc.locale))
			full, err := reg.Evaluate("faker.fullName", nil, make(map[string]string))
			if err != nil {
				t.Fatalf("Evaluate: %v", err)
			}
			// Recompute the expected tokens at the same seed.
			rng := rand.New(rand.NewPCG(uint64(seed), uint64(seed>>32^0xdeadbeef)))
			pool := localePools[tc.locale]
			first := pool.firstNames[intn(rng, len(pool.firstNames))]
			last := pool.lastNames[intn(rng, len(pool.lastNames))]
			want := first + " " + last
			if tc.familyNameFirst {
				want = last + " " + first
			}
			if full != want {
				t.Errorf("%s fullName = %q, want %q", tc.locale, full, want)
			}
		})
	}
}

func TestLocalePools_NonLatinScript_Class(t *testing.T) {
	// Each name entry must contain at least one rune in the locale's script
	// block, proving the pool is native-script, not romanized or en-US.
	inRange := func(s string, lo, hi rune) bool {
		for _, r := range s {
			if r >= lo && r <= hi {
				return true
			}
		}
		return false
	}
	cases := []struct {
		locale   string
		check    func(string) bool
		descr    string
	}{
		// CJK Unified Ideographs U+4E00–U+9FFF (+ Hiragana/Katakana for ja-JP).
		{"ja-JP", func(s string) bool {
			return inRange(s, 0x4E00, 0x9FFF) || inRange(s, 0x3040, 0x30FF)
		}, "kanji/kana"},
		{"zh-CN", func(s string) bool { return inRange(s, 0x4E00, 0x9FFF) }, "Han"},
		// Hangul Syllables U+AC00–U+D7A3.
		{"ko-KR", func(s string) bool { return inRange(s, 0xAC00, 0xD7A3) }, "Hangul"},
		// Cyrillic U+0400–U+04FF.
		{"ru-RU", func(s string) bool { return inRange(s, 0x0400, 0x04FF) }, "Cyrillic"},
	}
	for _, c := range cases {
		t.Run(c.locale, func(t *testing.T) {
			pool := localePools[c.locale]
			for _, group := range [][]string{pool.firstNames, pool.lastNames, pool.cities} {
				for _, e := range group {
					if !c.check(e) {
						t.Errorf("%s: %q has no %s rune", c.locale, e, c.descr)
					}
				}
			}
		})
	}
}

	code := runCmdInnerWithErr([]string{col, "--locale", "ja-JP", "--seed", "42", "-v"}, &bytes.Buffer{}, &stderr)
	if code != 0 {
		t.Fatalf("expected exit 0, got %d; stderr: %s", code, stderr.String())
	}
	if strings.Contains(stderr.String(), "falling back") {
		t.Errorf("ja-JP emitted a fallback warning; its native pool now exists. stderr: %s", stderr.String())
	}
}
```

## Risks and Edge Cases
- **Risk: source-file UTF-8 / editor mojibake when typing native scripts.**
  → **Mitigation:** the `..._JSONRoundTrip` and `..._Class` tests fail loudly on
  any corrupted or romanized entry; `go vet`/compile catches invalid UTF-8 string
  literals. Verify with `git diff --check` and the round-trip test before commit.
- **Edge case: seed-position-invariance must survive the name-ordering swap.**
  → **Handling:** the `fullName` closure draws the firstName index *then* the
  lastName index in the same order for every locale; only concatenation order
  differs (KAD-1). `TestRegistry_Locale_SeedPositionInvariant` (covering
  `faker.firstName`) and `TestLocalePools_NameOrdering` (recomputing both draws at
  the seed) jointly guard this.
- **Edge case: en-US byte-identity regression from the new struct field.**
  → **Handling:** `familyNameFirst` zero value is `false`; en-US stays on the
  unchanged branch. `TestRegistry_Locale_EnUS_ByteIdenticalToBaseline` is the guard.
- **Risk: phone format drift from the SPEC table.** → **Mitigation:** the
  `nonLatinPhonePatterns` regexes are derived directly from SPEC:974-986 (KAD-4)
  and checked across 200 seeds.
- **Edge case: zh-CN given names are often a single Han character, yielding a
  short "李 伟"-style fullName.** → **Handling:** acceptable and valid (KAD-2);
  the space separator keeps family/given boundary unambiguous. Pools include a
  mix of 1- and 2-character given names so output is realistic.
- **Risk: ru-RU patronymics.** Russian full names often include a patronymic
  (Иван Иванович Иванов). → **Handling:** out of scope — SPEC:982 renders ru-RU
  as "Иван Иванов" (given + family only), matching the `firstName`/`lastName`
  two-pool model. No patronymic pool is added; documented to pre-empt review.
