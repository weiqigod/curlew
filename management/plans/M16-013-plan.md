## Key Architectural Decisions

These resolve the under-specified areas of the task YAML by following the canonical spec (docs/SPECIFICATION.md §"GitLab Commit Status API Integration" + Database Schema Reference Appendix at lines 10893–10943).

### Decision A — Schema follows spec, not task YAML wording
The task YAML lists columns `id, org_id, project_id, project_path, gitlab_base_url, gitlab_ca_bundle, access_token_ciphertext, access_token_kid, webhook_secret_ciphertext, created_at, updated_at, deleted_at` with `UNIQUE (org_id, project_id) WHERE deleted_at IS NULL`. The spec (line 10896) is the authoritative shape and adds `access_token_revoked_at` and `webhook_secret_rotated_at`, and uses `UNIQUE (org_id, project_id, gitlab_base_url) WHERE deleted_at IS NULL`. The spec wins because the same `project_id` integer can collide across different GitLab instances (gitlab.com vs self-managed) and a per-instance uniqueness key prevents legitimate cross-instance installations from blocking each other.

For `gitlab_webhook_events`, the spec's columns are `id, event_uuid, event_type, installation_id (FK), received_at, processed_at, failure_count, quarantined_at, payload`. The task YAML's `created_at` is interpreted as the spec's `received_at` (the receive timestamp is the row's create-time anyway).

### Decision B — `IGitLabKeyProvider` is an encrypt/decrypt provider, not a signer
The GitHub analog (`IGitHubAppKeyProvider`) is a *signer* (RS256 JWT). The GitLab equivalent is an *envelope-encryption* provider for the PAT — fundamentally different surface. The interface therefore exposes `EncryptAsync(plaintext) → (ciphertext, kid)` and `DecryptAsync(ciphertext, kid) → plaintext`, returning the `kid` so the row can record which wrapping key produced its ciphertext (supports KEK rotation via the standard re-encrypt migration).

### Decision C — DEK-per-row pattern for both modes
Both `FileGitLabKeyProvider` and `GoogleKmsGitLabKeyProvider` follow an envelope pattern — a fresh 32-byte AES-256 DEK is generated per encryption call, used to AES-256-GCM-encrypt the plaintext, then wrapped by the KEK. The wire format of the ciphertext is a single byte string carrying:

```
[1 byte version=0x01]
[2 bytes BE: wrapped_dek length]
[wrapped_dek bytes]
[12 bytes nonce]
[N bytes ciphertext]
[16 bytes GCM tag]
```

This single self-describing blob is what gets stored in `access_token_ciphertext`. The `kid` returned from Encrypt is recorded separately in `access_token_kid` so the provider knows which KEK to use for unwrapping.

For **file mode**: KEK is the 32-byte file contents; DEK is wrapped by AES-KeyWrap (RFC 3394) using the KEK. `kid = "gitlab-kek-file-v1"` (static; rotation requires re-encryption migration that bumps the version suffix).

For **KMS mode**: KEK lives in Google Cloud KMS HSM tier; DEK is wrapped by `IKmsClient.EncryptAsync(kmsKeyId, dek)`. `kid = kmsKeyId` (the full KMS resource path, e.g. `projects/p/locations/global/keyRings/kr/cryptoKeys/k/cryptoKeyVersions/1`).

### Decision D — `IKmsClient` gains symmetric encrypt/decrypt methods
The existing `IKmsClient` in `ApiTool.Backend.Licensing.Keys` has only asymmetric-sign methods (`AsymmetricSignAsync`, `AsymmetricSignRsaPkcs1Sha256Async`, `GetPublicKeyJwkAsync`). Add two methods to the interface:

```csharp
Task<byte[]> EncryptAsync(string kmsKeyId, byte[] plaintext, CancellationToken ct = default);
Task<byte[]> DecryptAsync(string kmsKeyId, byte[] ciphertext, CancellationToken ct = default);
```

`GoogleKmsClient` implements them via the KMS REST API (`POST /v1/{kmsKeyId}:encrypt` and `:decrypt`). `FakeKmsClient` implements them with a deterministic local AES-256-GCM key (no GCP calls; honours the no-cost rule).

### Decision E — FK `gitlab_webhook_events.installation_id → gitlab_installations(id)` uses ON DELETE CASCADE
The behaviors list explicitly invites a documented choice. We choose **CASCADE** because: (a) installations are normally soft-deleted (`deleted_at` set, row remains), so the FK is rarely exercised by hard delete; (b) when a hard delete *does* happen — operator-driven cleanup of an old soft-deleted row — the orphan webhook events have no business surviving; (c) this matches the project's pattern of cascading from organization down through its dependent rows.

### Decision F — Stub list endpoint shape
`GET /api/v1/integrations/gitlab` returns `200` with body `{ "installations": [] }` for any authenticated caller in any org. The create endpoint `POST /api/v1/integrations/gitlab` and delete `DELETE …/{id}` are explicitly out of scope for this slice (M16-016). A stub create endpoint that returns `501 Not Implemented` is added (mirrors the GitHub `StubClaim` pattern in `GithubIntegrationsEndpoints.MapPost("claim", StubClaim)`) so the route surface is visible in Swagger and reserved.

```csharp
namespace ApiTool.Backend.GitLab;

/// <summary>
/// Encrypts and decrypts the GitLab Project Access Token (PAT) for storage in
/// gitlab_installations.access_token_ciphertext. KEK custody differs by deployment
/// (file for self-hosted, KMS for SaaS); per-row DEK pattern bounds blast radius.
/// Refs docs/SPECIFICATION.md:9196-9205 (Encryption — IGitLabKeyProvider).
/// </summary>
public interface IGitLabKeyProvider
{
    /// <summary>
    /// Wraps <paramref name="plaintext"/> into a self-describing AES-256-GCM envelope.
    /// The returned <see cref="GitLabEncryptionResult.Kid"/> identifies the wrapping key
    /// and must be persisted alongside the ciphertext for later decryption.
    /// </summary>
    Task<GitLabEncryptionResult> EncryptAsync(byte[] plaintext, CancellationToken ct = default);

    /// <summary>
    /// Inverse of <see cref="EncryptAsync"/>. Throws <see cref="GitLabPatDecryptException"/>
    /// when <paramref name="kid"/> does not match the configured KEK or the ciphertext is
    /// corrupt/tampered. Inner exceptions are preserved for telemetry but never appear in
    /// the user-visible message.
    /// </summary>
    Task<byte[]> DecryptAsync(byte[] ciphertext, string kid, CancellationToken ct = default);
}

/// <summary>Result of <see cref="IGitLabKeyProvider.EncryptAsync"/>.</summary>
public sealed record GitLabEncryptionResult(byte[] Ciphertext, string Kid);
```

```csharp
// src/ApiTool.Backend/GitLab/GitLabEnvelopeCodec.cs
using System.Security.Cryptography;

namespace ApiTool.Backend.GitLab;

/// <summary>
/// Wire format for the AES-256-GCM envelope used by IGitLabKeyProvider implementations.
/// Bytes: [0x01][be u16: wrappedDekLen][wrappedDek][12-byte nonce][N bytes ciphertext][16-byte tag].
/// </summary>
internal static class GitLabEnvelopeCodec
{
    public const byte Version = 0x01;

    /// <summary>Pack: generate DEK + nonce, GCM-encrypt plaintext, call wrapDek for the wrapped DEK, lay out the envelope.</summary>
    public static byte[] Encrypt(byte[] plaintext, Func<byte[], byte[]> wrapDek)
    {
        var dek = RandomNumberGenerator.GetBytes(32);
        var nonce = RandomNumberGenerator.GetBytes(12);
        var ct = new byte[plaintext.Length];
        var tag = new byte[16];
        using (var aes = new AesGcm(dek, tagSizeInBytes: 16))
            aes.Encrypt(nonce, plaintext, ct, tag);
        var wrappedDek = wrapDek(dek);
        CryptographicOperations.ZeroMemory(dek);

        // Layout
        var blob = new byte[1 + 2 + wrappedDek.Length + 12 + ct.Length + 16];
        blob[0] = Version;
        blob[1] = (byte)(wrappedDek.Length >> 8);
        blob[2] = (byte)(wrappedDek.Length & 0xFF);
        Buffer.BlockCopy(wrappedDek, 0, blob, 3, wrappedDek.Length);
        Buffer.BlockCopy(nonce, 0, blob, 3 + wrappedDek.Length, 12);
        Buffer.BlockCopy(ct, 0, blob, 3 + wrappedDek.Length + 12, ct.Length);
        Buffer.BlockCopy(tag, 0, blob, 3 + wrappedDek.Length + 12 + ct.Length, 16);
        return blob;
    }

    /// <summary>Unpack: parse the envelope, call unwrapDek to recover the DEK, GCM-decrypt the body.</summary>
    public static byte[] Decrypt(byte[] blob, Func<byte[], byte[]> unwrapDek)
    {
        if (blob.Length < 1 + 2 + 12 + 16) throw new CryptographicException("envelope: truncated");
        if (blob[0] != Version) throw new CryptographicException($"envelope: unsupported version 0x{blob[0]:X2}");
        int wrappedDekLen = (blob[1] << 8) | blob[2];
        int hdr = 3 + wrappedDekLen;
        if (blob.Length < hdr + 12 + 16) throw new CryptographicException("envelope: truncated wrapped DEK");
        var wrappedDek = new byte[wrappedDekLen];
        Buffer.BlockCopy(blob, 3, wrappedDek, 0, wrappedDekLen);
        var nonce = new byte[12];
        Buffer.BlockCopy(blob, hdr, nonce, 0, 12);
        int ctLen = blob.Length - hdr - 12 - 16;
        var ct = new byte[ctLen];
        Buffer.BlockCopy(blob, hdr + 12, ct, 0, ctLen);
        var tag = new byte[16];
        Buffer.BlockCopy(blob, hdr + 12 + ctLen, tag, 0, 16);

        var dek = unwrapDek(wrappedDek);
        try
        {
            var plaintext = new byte[ctLen];
            using var aes = new AesGcm(dek, tagSizeInBytes: 16);
            aes.Decrypt(nonce, ct, tag, plaintext);
            return plaintext;
        }
        finally
        {
            CryptographicOperations.ZeroMemory(dek);
        }
    }
}
```

### Step 5: `FileGitLabKeyProvider` + `GitLabOptions`

**Rationale:** Self-hosted implementation. Reads the 32-byte KEK file at startup; uses AES-KW (RFC 3394 — `AesKeyWrap` / `AesKeyUnwrap` via .NET's `System.Security.Cryptography.AesKw` available in net9 only as `AesKeyWrap`; if unavailable in the project's TFM, fall back to AES-256-GCM with a fixed nonce derived from `SHA256("dek-wrap")[..12]` is unsafe — instead, use AES-256-GCM with a random nonce prepended to the wrapped DEK). Decision: use **AES-GCM with random 12-byte nonce prepended to wrapped DEK** to avoid the AES-KW availability question; this is cryptographically safe (DEK is only ever wrapped once, under a fresh nonce, and the tag covers the wrapped bytes).

**Wrapped DEK format inside the envelope's `wrappedDek` field:** `[12-byte wrap-nonce][32-byte wrapped DEK ct][16-byte wrap-tag]` = 60 bytes.

```csharp
// src/ApiTool.Backend/GitLab/FileGitLabKeyProvider.cs
public sealed class FileGitLabKeyProvider : IGitLabKeyProvider
{
    public const string KidValue = "gitlab-kek-file-v1";
    private readonly byte[] _kek;  // 32 bytes
    public FileGitLabKeyProvider(IOptions<GitLabOptions> opts)
    {
        var path = opts.Value.KeyProvider.File.KekPath;
        if (string.IsNullOrEmpty(path) || !File.Exists(path))
            throw new InvalidOperationException(
                $"GitLab KEK file not found at '{path}'. Set Curlew:GitLab:KeyProvider:File:KekPath (env GITLAB__KEK_PATH) " +
                $"to a 32-byte file (mode 0600).");
        var bytes = File.ReadAllBytes(path);
        if (bytes.Length != 32)
            throw new InvalidOperationException(
                $"GitLab KEK file at '{path}' is {bytes.Length} bytes; required size is exactly 32 bytes (AES-256).");
        _kek = bytes;
    }

    public Task<GitLabEncryptionResult> EncryptAsync(byte[] plaintext, CancellationToken ct = default)
    {
        var blob = GitLabEnvelopeCodec.Encrypt(plaintext, WrapDek);
        return Task.FromResult(new GitLabEncryptionResult(blob, KidValue));
    }

    public Task<byte[]> DecryptAsync(byte[] ciphertext, string kid, CancellationToken ct = default)
    {
        if (kid != KidValue)
            throw new GitLabPatDecryptException("file", new InvalidOperationException("kid mismatch"));
        try
        {
            var pt = GitLabEnvelopeCodec.Decrypt(ciphertext, UnwrapDek);
            return Task.FromResult(pt);
        }
        catch (Exception ex)
        {
            throw new GitLabPatDecryptException("file", ex);
        }
    }

    private byte[] WrapDek(byte[] dek)
    {
        var nonce = RandomNumberGenerator.GetBytes(12);
        var ct = new byte[dek.Length];
        var tag = new byte[16];
        using var aes = new AesGcm(_kek, tagSizeInBytes: 16);
        aes.Encrypt(nonce, dek, ct, tag);
        var wrapped = new byte[12 + ct.Length + 16];
        Buffer.BlockCopy(nonce, 0, wrapped, 0, 12);
        Buffer.BlockCopy(ct, 0, wrapped, 12, ct.Length);
        Buffer.BlockCopy(tag, 0, wrapped, 12 + ct.Length, 16);
        return wrapped;
    }

    private byte[] UnwrapDek(byte[] wrapped)
    {
        if (wrapped.Length < 12 + 16) throw new CryptographicException("wrapped DEK truncated");
        var nonce = new byte[12];
        var tag = new byte[16];
        var ctLen = wrapped.Length - 12 - 16;
        var ct = new byte[ctLen];
        Buffer.BlockCopy(wrapped, 0, nonce, 0, 12);
        Buffer.BlockCopy(wrapped, 12, ct, 0, ctLen);
        Buffer.BlockCopy(wrapped, 12 + ctLen, tag, 0, 16);
        var dek = new byte[ctLen];
        using var aes = new AesGcm(_kek, tagSizeInBytes: 16);
        aes.Decrypt(nonce, ct, tag, dek);
        return dek;
    }
}
```

```csharp
public sealed class GoogleKmsGitLabKeyProvider(IKmsClient kms, IOptions<GitLabOptions> opts) : IGitLabKeyProvider
{
    private readonly string _kmsKeyId = opts.Value.KeyProvider.Kms.KmsKeyId;

    public async Task<GitLabEncryptionResult> EncryptAsync(byte[] plaintext, CancellationToken ct = default)
    {
        try
        {
            // Synchronous-style wrap delegate: we have to round-trip the DEK through KMS.
            // Capture the wrapped value and rebuild the envelope around it.
            byte[]? wrappedDek = null;
            var capture = (byte[] dek) =>
            {
                wrappedDek = kms.EncryptAsync(_kmsKeyId, dek, ct).GetAwaiter().GetResult();
                return wrappedDek!;
            };
            var blob = GitLabEnvelopeCodec.Encrypt(plaintext, capture);
            return new GitLabEncryptionResult(blob, _kmsKeyId);
        }
        catch (Exception ex)
        {
            throw new GitLabPatDecryptException("kms", ex);  // reuse for symmetry; rename if needed.
        }
    }
    // … DecryptAsync analogously
}
```

Note on the sync-over-async in the wrap delegate: codec is synchronous because `AesGcm` is sync. The KMS call is performed synchronously via `.GetAwaiter().GetResult()` *inside* the wrap callback. Since `EncryptAsync` itself is `async`, the outer Task is still cooperative — the only blocked work is the KMS HTTP call, which the codec must wait for anyway. This is acceptable for the scope; if it becomes a perf concern we can refactor `GitLabEnvelopeCodec` to take an `async` wrap delegate (defer to a follow-up if needed).

Alternative considered: accept this small sync block, or split the codec into `Pack` (sync, builds envelope from already-wrapped DEK) + `Unpack` (sync). The `Pack`/`Unpack` split is cleaner and is what we'll implement — refactor `GitLabEnvelopeCodec` to expose:

```csharp
internal static byte[] Pack(byte[] wrappedDek, byte[] nonce, byte[] ciphertext, byte[] tag);
internal static (byte[] wrappedDek, byte[] nonce, byte[] ciphertext, byte[] tag) Unpack(byte[] blob);
internal static (byte[] dek, byte[] nonce, byte[] ciphertext, byte[] tag) GenerateAndEncrypt(byte[] plaintext);
internal static byte[] DecryptWithDek(byte[] dek, byte[] nonce, byte[] ciphertext, byte[] tag);
```

This avoids sync-over-async entirely. **Adopt the split** — update Step 4 implementation accordingly during execute.

## Risks and Edge Cases

- **Risk:** Postgres `bytea` round-trip vs SQLite `BLOB` differs in EF mapping. → **Mitigation:** explicit column-type configuration in `OnModelCreating` (`HasColumnType("bytea")` when `IsNpgsql()`); the `GitLabSchemaTests` exercise SQLite directly; the migration's auto-up against Postgres is exercised in CI via `docker-compose.test.yml`.
- **Risk:** Migration regenerates `AppDbContextModelSnapshot.cs` and includes irrelevant noise diffs. → **Mitigation:** run `dotnet ef migrations add` from the repo root; commit only the new migration files + the snapshot diff scoped to GitLab entities; reject any unrelated lines in review.
- **Risk:** `AesGcm` constructor on .NET 9 may reject 16-byte tag size if not explicitly allowed. → **Mitigation:** pass `tagSizeInBytes: 16` explicitly; verified pattern in test code.
- **Edge case:** Operator sets `GITLAB__KEY_PROVIDER=file` but no KEK file exists at startup. → **Handling:** `FileGitLabKeyProvider` constructor throws `InvalidOperationException` with a clear message; DI surfaces this as a startup failure (the provider is `Singleton` — instantiated lazily on first resolve). To make startup *eager*, also wire a `ValidateOnStart` predicate that asserts file existence when mode == "file" — included in the Step 7 options block.
- **Edge case:** Encrypted plaintext is empty (`new byte[0]`). → **Handling:** `AesGcm.Encrypt` accepts zero-length plaintext; round-trip tests cover this implicitly via the codec tests.
- **Edge case:** Two concurrent `EncryptAsync` calls with the same plaintext must produce different ciphertexts. → **Handling:** fresh DEK + nonce per call; covered by `Encrypt_produces_different_ciphertext_each_call_for_same_plaintext` in Step 1 tests.
- **Risk:** `GoogleKmsGitLabKeyProvider` lifecycle — KMS calls are HTTP and can hang. → **Mitigation:** `IKmsClient.EncryptAsync` accepts `CancellationToken`; the provider passes it through. The named `kms` HttpClient has a 10s timeout (already configured in Program.cs).
- **Edge case:** Concurrent insert of the same `(org_id, project_id, gitlab_base_url)` on Postgres throws a unique-constraint violation; tests assert this is `DbUpdateException`. → **Handling:** the partial-unique-index pattern with `WHERE deleted_at IS NULL` is identical to `idx_github_installations_org`; same behaviour.
