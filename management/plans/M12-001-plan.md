# Implementation Plan: M12-001

## Overview

Replace the no-arg-only `{{$func}}` dynamic syntax with a parenthesized arg-bearing
`{{$func(arg1, 'literal', {{var}})}}` syntax, migrate all 16 existing functions to a
new `DynFunc(rng, args)` signature, and switch per-request memoization keys to
include canonicalised args. No new helpers are added — that work belongs to
M12-002 through M12-008. Backward compatibility: `{{$timestamp}}` and friends
must still resolve identically with no syntax change in user collections.

## Architectural Decisions

The exploration surfaced four design choices worth recording up front. Each is
the lowest-risk option that satisfies the behaviors and keeps the existing wiring
(`runner.go:991-992`, `cmd/curlew/main.go`) untouched:

1. **Two-stage parsing, not one regex.** The behaviors require single-quoted
   string literals with `\'`/`\\` escapes, optional whitespace, and arbitrary
   inner content (including `{{var}}`). A pure regex is fragile here. Stage 1 is
   a `dynPattern` regex that matches the *envelope* — `{{$funcName}}` or
   `{{$funcName(<rawArgList>)}}`. Stage 2 is a small hand-written scanner
   (`parseDynArgs(rawArgList) ([]string, error)`) that consumes single-quoted
   literals, comma separators, and surrounding whitespace, and emits a structured
   error on malformed input. This keeps the regex small enough to read and the
   parser small enough to test exhaustively.

2. **`Evaluate(name, args, cache)` — no overload, no compatibility shim.** The
   only non-test call site is one location in `internal/variable/variable.go:223`.
   Adding a third parameter is cheaper than maintaining two methods. All test
   callers update in the same patch. (The task observable in the YAML names
   exactly this signature.)

3. **`noArgs` wrapper for the 16 existing functions.** Migration is mechanical
   if we introduce one helper at the top of `dynamic.go`:

   ```go
   func noArgs(fn func(*rand.Rand) string) DynFunc {
       return func(rng *rand.Rand, args []string) (string, error) {
           if len(args) > 0 {
               return "", arityError(0, len(args))
           }
           return fn(rng), nil
       }
   }
   ```

   Each `r.funcs["timestamp"] = func(_ *rand.Rand) string { ... }` becomes
   `r.funcs["timestamp"] = noArgs(func(_ *rand.Rand) string { ... })`. Body
   text of the existing closures is untouched, which keeps the diff readable
   and the migration auditable.

4. **Cache key = `funcName + "\x00" + canonicalArgs`.** The key uses an ASCII
   NUL between funcName and args, then the resolved args joined by NUL. NUL
   cannot appear in a YAML scalar, so collisions are impossible. Empty args
   produce `funcName + "\x00"` — distinct from any non-empty key, and distinct
   from any other funcName. No `strings.Builder` needed; a one-line
   `strings.Join` over `append([]string{name}, args...)` keeps the hot path
   small. We do *not* include the unresolved literal — the resolved value is
   what the user asked for and what they expect to memoize.

// internal/variable/dynamic.go

// DynFunc generates a dynamic variable value. args is the resolved argument
// list parsed from {{$fn('a', 'b')}} (nil/empty for the no-args form).
// Returns a structured error on arity mismatch or per-function failure.
type DynFunc func(rng *rand.Rand, args []string) (string, error)

// arityError builds the canonical arity-mismatch error used by the noArgs/N-args wrappers.
func arityError(funcName string, want, got int) error {
    return &apierrors.Structured{
        Category: apierrors.CategoryInput,
        Code:     "DYNFN_ARITY",
        Message:  fmt.Sprintf("$%s: expected %d arguments, got %d", funcName, want, got),
        Hint:     fmt.Sprintf("Call $%s with the correct number of arguments.", funcName),
    }
}

// noArgs wraps a zero-arg generator so it conforms to DynFunc and rejects any args.
func noArgs(funcName string, fn func(*rand.Rand) string) DynFunc {
    return func(rng *rand.Rand, args []string) (string, error) {
        if len(args) > 0 {
            return "", arityError(funcName, 0, len(args))
        }
        return fn(rng), nil
    }
}

// Evaluate returns the value for the named function with the given args.
// cache provides per-request memoization keyed by funcName plus canonicalised args.
func (r *Registry) Evaluate(name string, args []string, cache map[string]string) (string, error) {
    key := cacheKey(name, args)
    if cache != nil {
        if v, ok := cache[key]; ok { return v, nil }
    }
    fn, ok := r.funcs[name]
    if !ok {
        avail := strings.Join(r.Available(), ", ")
        return "", fmt.Errorf("unknown dynamic function %q; available: %s", name, avail)
    }
    val, err := fn(r.rng, args)
    if err != nil {
        return "", fmt.Errorf("$%s: %w", name, err)
    }
    if cache != nil { cache[key] = val }
    return val, nil
}

// cacheKey produces a per-request memoization key. funcName + NUL + args joined by NUL.
// NUL cannot appear in YAML scalars or arg literals, so collisions are impossible.
func cacheKey(funcName string, args []string) string {
    if len(args) == 0 { return funcName + "\x00" }
    return funcName + "\x00" + strings.Join(args, "\x00")
}

// e.g. migrated registration:
r.funcs["timestamp"] = noArgs("timestamp", func(_ *rand.Rand) string {
    return strconv.FormatInt(time.Now().Unix(), 10)
})

```go
// internal/variable/variable.go (Pass 1 rewrite)
// Pass 1: resolve {{$funcName}} or {{$funcName(args...)}} dynamic patterns.
if dynPattern.MatchString(input) {
    var retErr error
    result := dynPattern.ReplaceAllStringFunc(input, func(match string) string {
        if retErr != nil { return match }
        sub := dynPattern.FindStringSubmatch(match)
        funcName := sub[1]
        rawArgs := sub[2] // empty when no parens at all

        // Explicit variable named "$funcName" wins for the legacy no-args form only.
        // (Args change identity — `$base64('a')` and `$base64('b')` cannot both alias
        // a single literal `$base64` variable.)
        if rawArgs == "" && !strings.Contains(match, "(") {
            if val, ok := s.resolved["$"+funcName]; ok { return val }
        }
        if s.registry == nil { return match }

        // Parse the literal arg list, then interpolate each arg recursively so
        // that `{{$base64('{{secret}}')}}` resolves the inner var first.
        argLits, err := parseDynArgs(funcName, rawArgs)
        if err != nil { retErr = err; return match }
        resolvedArgs := make([]string, len(argLits))
        for i, lit := range argLits {
            // Recursive interpolation handles nested {{var}} and {{$fn}}.
            v, ierr := s.Interpolate(lit)
            if ierr != nil { retErr = ierr; return match }
            resolvedArgs[i] = v
        }

        cache := s.funcCache
        if cache == nil { cache = make(map[string]string) }
        val, err := s.registry.Evaluate(funcName, resolvedArgs, cache)
        if err != nil { retErr = err; return match }
        return val
    })
    if retErr != nil { return "", retErr }
    input = result
}
```

This preserves the existing `TestScope_Interpolate_dynamic/explicit_var_overrides_function`

**Parenthesized arguments (M12+).**

Dynamic functions can accept arguments in parentheses: `{{$func('arg1', 'arg2')}}`.
Each argument is a single-quoted string literal; `\'` and `\\` are honoured as
escapes. Arguments may contain other variable references — those are resolved
*before* the literal is passed in:

```yaml
headers:
  X-Signature: "{{$hmacSha256('payload', '{{secret}}')}}"
  Authorization: "Basic {{$base64('{{user}}:{{pass}}')}}"
```

The 16 built-in helpers in the table above take no arguments — call them with
`{{$timestamp}}` (legacy form) or equivalently `{{$timestamp()}}`. Calling a
zero-arg helper with arguments produces a structured input error. Per-request
memoization keys include the resolved arguments, so `{{$base64('a')}}` and
`{{$base64('b')}}` do not collide in the same request.
```

(Helpers that *consume* the new syntax — `$base64`, `$hmacSha256`, etc. — land
in M12-002 onward.)

## Risks and Edge Cases

- **Risk:** The two-capture regex `\{\{\$([a-zA-Z][a-zA-Z0-9_]*)(?:\(([^}]*)\))?\}\}` uses `[^}]*` for the raw arg list, which would not match a literal `}` inside a single-quoted arg. → **Mitigation:** Single-quoted arg lists in YAML almost never contain `}`; if a user genuinely needs `}` in an arg, they can use `\}` outside a string literal — but the simpler answer is "we explicitly do not support `}` inside arg literals in M12-001; M12 backlog notes can extend if a real user hits it." Document the limit briefly in the inline comment on `dynPattern`.

- **Risk:** Recursive `s.Interpolate` on each arg literal could trip the existing depth limit if a user crafts a pathological nest. → **Mitigation:** Each arg literal is interpolated independently with the existing pass machinery, which already enforces `MaxDepth` during variable chain resolution. The recursion here is over arg *strings*, not over variable chains — depth limit is unaffected.

- **Risk:** The `cacheKey` change subtly alters memoization for existing no-args calls — old key was `funcName`, new key is `funcName + "\x00"`. → **Mitigation:** This is internal to one Interpolate call; the cache lifetime is one request; no user-visible behavior change. `TestScope_Interpolate_dynamic/two_references_same_value` confirms.

- **Edge case:** `{{$func()}}` (empty parens) vs `{{$func}}` (no parens). → **Handling:** `parseDynArgs("", "")` returns `nil, nil`; both forms produce the same resolved args slice and therefore the same cache key. The `$funcName` explicit-variable shadow rule applies only when the input has no `(` (the "(legacy form)" rule above) — `{{$func()}}` does not get shadowed by an explicit `$func` variable, which is the principle-of-least-surprise behavior.

- **Edge case:** Single-quote followed immediately by another single-quote (`''`) is the empty string. → **Handling:** `parseDynArgs` test `empty literal allowed` covers this.

- **Risk:** A user-written collection with a literal `{{$something(invalid` (missing close paren) would now match `dynPattern` differently from before. → **Mitigation:** The non-greedy `[^}]*` consumes until the next `}` only inside the parens; if the parens never close, the regex does not match (anchoring requires `\)\}\}`). The resulting input passes through to Pass 2 (varPattern), which does not match either, so the literal stays unchanged — same as before. Test: `dynPattern` regex test "missing close brace" / "unbalanced parens not captured by regex".

- **Edge case:** Test-only `echo` registration — only the parser tests need it. We register it directly via `reg.funcs["echo"] = ...` inside the test (white-box access). No production code path adds `echo`. The behavior from the YAML calls this the "test-only echo registration" — intent matches.

## Deviations

### Small Correction: regex uses `.*?` instead of `[^}]*`

**Planned:** `\{\{\$([a-zA-Z][a-zA-Z0-9_]*)(?:\(([^}]*)\))?\}\}` using `[^}]*`.

**Actual:** `\{\{\$([a-zA-Z][a-zA-Z0-9_]*)(?:\((.*?)\))?\}\}` using non-greedy `.*?`.

**Reason:** The test case `{{$base64('{{user}}')}}` requires the arg list to contain `}}` (from the inner variable reference). `[^}]*` stops at the first `}`, so it fails to match. Go's RE2 engine does not support negative lookaheads (`(?!...)`), which would have been the other fix. Non-greedy `.*?` is idiomatic RE2 and stops at the first `)\}\}` sequence, correctly matching nested braces. The limitation in the original risk note (`}` inside arg literals) is resolved — `{{var}}` references inside arg literals now work. The remaining limitation is that a literal `)\}\}` sequence inside a single-quoted arg would terminate the match early, but such sequences are not expected in practice.
