## The decision (the one judgement call in this task)

The task states plainly: *"DECISION REQUIRED FROM THE PROJECT OWNER. This task
frames the options; it does not presume one."* This plan is produced by an
automated pipeline with no owner in the loop, so the decision is made here, on
stated grounds, and recorded as owner-pending.

**Chosen: Option B — keep and explain.**

Reasoning, to be transcribed into `docs/TECH_CHOICES.md`:

1. **B is the only reversible option.** Doing B forecloses neither A nor C. Doing
   A or C first and finding it wrong costs a second migration. When the deciding
   input — "is the platform live, paused, or finished?" — is the input we do not
   have, the reversible move is the correct one.
2. **A is a licensing action, not a path move.** `src/LICENSE`, `web/LICENSE` and
   `deploy/LICENSE` are each proprietary while the repository root is Apache-2.0.
   Splitting the repository means reconciling three separate licence grants and
   creating an external repository — outside what this pipeline may do without
   the owner.
3. **C's cost is real, its gain is cosmetic, and its failure mode is silent.**
   Relocating 865 tracked C# files plus `web/` rewrites `ApiTool.Backend.sln`,
   `docker-compose.test.yml`, `.dockerignore`, eight workflows, five
   `.gitignore` rules, `deploy/`, several `scripts/` entries and every
   `src/ApiTool.Backend/...` path in an 11,529-line specification. The decisive
   evidence is `scripts/ci-local.sh:53-55`, which carries a comment recording
   that a *previous* rename already broke the scope greps — *"Matching on
   `src/Curlew.Backend` here silently skipped the backend and E2E gates for
   every backend change."* Option C rewrites those same greps. Its failure mode
   is a gate that reports PASS while quietly testing nothing, which is precisely
   the false clear this codebase is organised against.
4. **The guard is the durable deliverable and is option-independent.** The task
   says so itself: *"that is what stops the same ambiguity growing back, and it
   is the part of this task that is not a judgement call."* If the owner later
   chooses A or C, the guard survives the move and enforces the new shape.

**Status assigned to the platform: frozen.** Evidence, not preference. Against
"archived": `scripts/ci-local.sh --full` still runs `dotnet test`, the five web
gate steps and five Playwright convergence specs, and `docs/SPECIFICATION.md:11`
says the platform *"still implement[s]"* the spec. Against "maintained": no
`src/` change since the 2026-08-03 strip, and no `src/` or `web/` work anywhere
in the M25–M29 roadmap. "Frozen" is the honest word: kept green, not developed.

The status word must be **identical** in all three documents, or "both agree with
it" is true only loosely. It is therefore stated once as a canonical sentence
exported from `internal/docs`, with a test requiring all three documents to
contain it verbatim — the same mechanism `docs.Prose` already uses.

## Design decisions, with alternatives considered

### How to enumerate top-level directories

| Approach | Verdict |
|---|---|
| `os.ReadDir(root)` + hardcoded skip list | **Rejected, and measurably broken.** `dist/` is created by `ci-local.sh:308` *after* the `go test` steps at 210/213/216. On a clean checkout the first `--full` run passes and every run after it fails. A skip list also duplicates `.gitignore` and drifts from it. |
| `git ls-tree --name-only HEAD` | **Rejected.** Sees only committed state, so a directory added in the working tree passes — precisely the case behaviour 2 exists to catch. |
| **`git ls-files --cached --others --exclude-standard`** | **Chosen.** `--cached` covers tracked and staged-new; `--others --exclude-standard` covers untracked-but-not-ignored, so a genuinely new directory fails *before* it is committed. Honours `.gitignore` without restating it, never lists `.git`, excludes `dist/`. Verified to return exactly the 19 expected entries. |

**Rule, stated for the record: the repository is what git knows about.** Ignored
paths are build output, not repository content, and two developers on the same
commit must get the same answer.

When `git` is missing or the directory is not a checkout, `TopLevelDirs` returns
a wrapped error and the test calls `t.Fatal`. It does **not** `t.Skip`, and there
is **no `os.ReadDir` fallback** — a silent fallback would be the false clear this
package exists to prevent, and it would be a code path CI never exercises.

### Whether dotted directories count

**They count.** The rule "every directory git tracks" has no exception to argue
about; "except dotfiles" is a hole the next `.vscode/` or `.devcontainer/` falls
straight into — exactly the class of unaccounted-for directory this task exists
to close. `.github/` is visible on GitHub and holds the CI definitions; `.claude/`
holds the slash commands CLAUDE.md advertises. Cost: two rows.

### Sub-paths are rejected, not normalised

`cmd/curlew/` must **fail** rather than silently resolve to `cmd`. A normaliser
would just as happily accept `cmd/curlew/internal/whatever/` as an entry for
`cmd`, which hollows the guard out. Rejecting sub-paths forces the table to be an
accounting *of the root*. The existing `cmd/curlew/` row is rewritten to `cmd/`.

### How "its relationship to the CLI is stated" is verified

`strings.Contains(readme, dir)` is far too weak — `docs`, `internal` and `web`
appear throughout the README's prose, so every directory would pass without any
being explained. Instead: a fixed heading, a three-column header matched **by
name not position** (`docs.Column`'s established rationale), and a required
non-empty, non-placeholder `Relationship to the CLI` cell per row.
`Unexplained` is a finding distinct from `Unaccounted` so the message can say
*"the row exists but says nothing"* rather than *"missing"*.

### Failing in both directions

`Stale` (a row for a directory that no longer exists) is enforced, on this
codebase's own reasoning at `inventory_test.go:142`: *"A baseline entry that is no
longer owed has been paid off, and leaving it listed would let the same table
silently stop being executed later."* A row for a directory that does not exist is
a README that lies about the repository — the same defect measured from the other
side. It also stops the table accumulating rows for hypothetical directories,
which would hollow the guard out one row at a time. `Duplicate` is reported for
the same reason.

### How behaviour 2 is itself tested

The test cannot create a real top-level directory in the repository it is
testing. So `AuditLayout` is a **pure function over two slices**, and "a new
top-level directory with no row" is one extra element in a slice literal. A thin
integration test then feeds it the real checkout and the real README. This is what
makes behaviour 2 an executed claim rather than an asserted one.

## Proposed Go signatures

```go
// Root is the repository root: the directory Dir sits in.        [tables.go]
var Root = filepath.Dir(Dir)

// LayoutHeading is the README section that accounts for the repository's
// top-level directories. The guard keys on this heading rather than on the
// first three-column table in the file, so a table added elsewhere in the
// README cannot be mistaken for the accounting.
const LayoutHeading = "Repository layout"

// LayoutColumns are the header cells that identify the accounting table.
// Columns are resolved by name, not position, so reordering the table cannot
// silently change what the guard asserts.
var LayoutColumns = []string{"Directory", "What it is", "Relationship to the CLI"}

// PlatformStatus is M28-001's decision, stated once so that the three documents
// which must agree about it cannot drift into three different answers.
const PlatformStatus = "The `src/` backend and `web/` dashboard stay in this " +
    "repository, frozen: they build and pass their tests in " +
    "`./scripts/ci-local.sh --full`, no new feature work is planned, and the " +
    "`curlew` CLI does not call them."

// PlatformStatusDocs are the documents required to state PlatformStatus,
// relative to Root.
var PlatformStatusDocs = []string{"README.md", "docs/TECH_CHOICES.md", "docs/SPECIFICATION.md"}

// ErrNoLayoutTable reports that the source carries no table under LayoutHeading
// with LayoutColumns, or one with a header and no rows. Zero rows is an error
// rather than an empty slice: a guard that reads nothing and reports clean is
// the false clear this package exists to prevent.
var ErrNoLayoutTable = errors.New("no repository-layout table")

// ErrNoTopLevelDirs reports that a repository yielded no top-level directories
// at all, for the same reason.
var ErrNoTopLevelDirs = errors.New("no top-level directories")

// LayoutRow is one top-level directory as README.md accounts for it.
type LayoutRow struct {
    Line         int    // 1-based line of the row
    Dir          string // top-level directory name, backticks and trailing slash removed
    What         string // the "What it is" cell
    Relationship string // the "Relationship to the CLI" cell — the load-bearing one
}

// String renders a row the way a test failure should print it: clickable, with
// enough context to find it without counting rows.
func (r LayoutRow) String() string

// LayoutRows returns the rows of the repository-layout table in README source.
//
// It takes the text rather than a filename so the guards can be proven against
// synthetic documents, the same way ExtractProse and AuditProse are. Tables
// inside fenced code blocks and tables under other headings are not the
// accounting. A cell naming a sub-path rather than a top-level directory is an
// error: normalising cmd/curlew/ to cmd would just as happily accept
// cmd/curlew/internal/whatever/, which hollows the guard out.
func LayoutRows(src string) ([]LayoutRow, error)

// TopLevelDirs returns the top-level directories of the repository at root:
// every directory git tracks or has been told about, minus the ones it is told
// to ignore.
//
// Ignored paths are excluded deliberately. dist/ is created by the release step
// of scripts/ci-local.sh and survives between runs, so a plain directory listing
// reports a clean repository on the first gate and a broken one on every gate
// after it. Untracked-but-unignored directories ARE included, so a new one fails
// this guard before it is ever committed.
//
// An unavailable git, or a root that is not a repository, is an error rather
// than an empty set.
func TopLevelDirs(ctx context.Context, root string) ([]string, error)

// LayoutAudit is the outcome of holding a repository's top-level directories to
// README.md's accounting of them. It fails in both directions, the same contract
// the table and prose registers carry.
type LayoutAudit struct {
    Unaccounted []string    // a top-level directory with no row
    Stale       []string    // a row naming a directory that does not exist
    Unexplained []LayoutRow // a row that names a directory but states nothing about the CLI
    Duplicate   []string    // a directory named by more than one row
}

// Clean reports whether the audit found nothing.
func (a LayoutAudit) Clean() bool

// AuditLayout holds a set of top-level directories to a set of README rows.
//
// It takes two slices rather than reading the filesystem so behaviour 2 — a new
// top-level directory that no README row accounts for — can be proven by
// mutation, without the test having to create a directory in the repository it
// is testing.
func AuditLayout(dirs []string, rows []LayoutRow) LayoutAudit
```
