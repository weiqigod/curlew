## Architectural Decisions

The task observable references several capabilities the codebase does not expose end-to-end; per pipeline mode I resolve them now with best judgement and document the decisions here. These mirror the precedent set by M16-021's Architectural Decisions section.

1. **No `/auth/register` endpoint exists.** Per the M14-021 / M16-021 precedent and the task's own behavior #9 ("the convergence scenario runs the happy path only — does not assert on individual cluster failure modes — it only proves the parts wire together end-to-end"), the e2e uses `POST /internal/test/seed-refresh` as the "register" step. The endpoint upserts a fresh user with `EmailVerified=false`, runs the trial seeder, and returns a refresh token — exactly the post-registration state.

2. **"Verify email" step (observable step 2).** No `/auth/email-verification/confirm` is wired against `seed-refresh` users in a fully self-serve way. Following M16's pattern, the orchestrator: (a) calls `POST /api/v1/auth/email-verification/resend`, (b) reads the verification token from `/internal/test/email-audit`, (c) `POST`s it to `/api/v1/auth/email-verification/confirm`. The Playwright half asserts the confirm page renders without error.

3. **Stack already includes MinIO and FileTeamVaultKeyProvider — no separate fake-KMS shim container needed.** The task scope says "MinIO (IObjectStore), and a fake-KMS shim". Investigation shows: (i) `docker-compose.test.yml` already wires MinIO under `OBJECTSTORE__PROVIDER=s3`; (ii) `Program.cs` registers `FileTeamVaultKeyProvider` and `FileScheduleEnvKeyProvider` outside Production (this IS the file-backed KEK fallback that M18-009 ships, equivalent to a fake-KMS shim — see the M18-009 plan). The orchestrator therefore does not need to bring up a separate fake-KMS container; the file-provider path is sufficient and exactly what M18-009's "self-hosted profile" tests against. The plan adds no new docker services.

4. **No Postgres in the test stack.** The task observable mentions `psql` for raw-column ciphertext inspection. The stack uses SQLite (per `Program.cs:71` and confirmed by M16-021's plan). The orchestrator substitutes `sqlite3` (`brew install sqlite` is universal; CI runners ship it). The SQLite DB lives in the `backend_data` volume; the orchestrator runs `docker exec backend sqlite3 /app/data/apitool.db <query>` to inspect raw ciphertext. The behavior assertion "raw DB columns are ciphertext" is satisfied identically — bytea/hex is just `quote()` in SQLite. Decision recorded explicitly so M18-009's `psql` examples don't mislead the reader.

5. **TelemetryEvent has no UserId — cross-cluster proof uses install_id, not user_id.** Inspection of `src/ApiTool.Backend/Data/Entities/TelemetryEvent.cs` confirms the entity is keyed by `InstallId` (anonymous by design). The current GDPR export builder consumes the `GdprBundleManifest` filtered by `UserId` and would not naturally surface `telemetry_events` rows in the bundle. The observable's step 5 — "bundle contains telemetry_events rows for the user's install_id PLUS the InExport subset" — is therefore interpreted as: the bundle continues to carry the InExport subset (existing M18-004 behavior); the telemetry-events cross-cluster proof runs separately via an internal endpoint that selects `telemetry_events` where `install_id = <X>`. This needs a new tiny internal test hook (Step 1 below) so the orchestrator can assert the row count without sqlite3 round-tripping. Mirrors M16-021's "no shape drift" stance on cross-cluster proof: the parts must wire together, not the bundle's schema must change. The CHANGELOG entry will flag this nuance.

6. **"Advance the clock 30 days" via test hook.** No clock-advance hook exists in the backend. The deterministic equivalent is to back-date the user's `pending_deletion_at` column to `now() - 31 days` so the existing finalizer-tick hook (`POST /api/v1/internal/test-hooks/run-deletion-finalizer`) finds the row immediately. This needs a new tiny internal hook `POST /api/v1/internal/test-hooks/backdate-deletion-request` (Step 2 below) — Dev+Testing-only, gated behind `InternalAccessFilter` like every other test hook.

7. **Enterprise audit-log JSONL streaming export must use a real Enterprise-tier org (observable step 10).** The existing `seed-enterprise.sh` script provisions an Enterprise-tier subscription on the `acme` org via the checkout endpoint; the orchestrator reuses it. The audit log gets >=1 row from prior orchestrator activity (user creation, deletion request, anonymisation event); the orchestrator additionally hits a seeded endpoint to ensure a documented row count before asserting the `wc -l` line count.

8. **The Playwright spec drives web assertions; the shell script orchestrates CLI + backend.** Per task scope. Final summary line `M18 e2e PASS in <duration>s` printed by the shell script — that is the contract.

9. **Per `feedback_no_phased_shipping_framing`, this slice IS the launch-blocking signal.** No hedging in the CHANGELOG entry: "Lands the M18 convergence proof; M18 closes as a unit."

10. **CI workflow.** Adds `.github/workflows/m18-e2e.yml` mirroring `.github/workflows/m16-e2e.yml` — `workflow_dispatch`-only (auto-triggers disabled per existing project posture).

```csharp
namespace ApiTool.Backend.Internal;

/// <summary>
/// Maps <c>GET /api/v1/internal/test-hooks/list-telemetry-events</c> (Development + Testing only).
/// Returns <c>{ "rows": [ { "install_id": "...", "event_type": "...", "received_at": "..." } ] }</c>
/// filtered by <c>?install_id=</c>. Used by M18-012's e2e to assert cross-cluster
/// integration of the telemetry pipeline without inspecting raw DB rows.
/// </summary>
public static class InternalListTelemetryEventsEndpoint
{
    public static IEndpointRouteBuilder MapInternalListTelemetryEventsEndpoint(
        this IEndpointRouteBuilder app, IWebHostEnvironment env)
    {
        if (!env.IsDevelopment() && !env.IsEnvironment("Testing"))
            return app;

        app.MapGet("/api/v1/internal/test-hooks/list-telemetry-events",
            async (string? install_id, AppDbContext db, CancellationToken ct) =>
            {
                if (string.IsNullOrWhiteSpace(install_id) ||
                    !Guid.TryParse(install_id, out var id))
                    return Results.BadRequest(new { error = "install_id query param required" });

                var rows = await db.Set<Data.Entities.TelemetryEvent>()
                    .Where(e => e.InstallId == id)
                    .OrderByDescending(e => e.ReceivedAt)
                    .Select(e => new {
                        install_id = e.InstallId,
                        event_type = e.EventType,
                        received_at = e.ReceivedAt,
                    })
                    .Take(500)
                    .ToListAsync(ct);

                return Results.Ok(new { count = rows.Count, rows });
            })
            .AllowAnonymous()
            .AddEndpointFilter<InternalAccessFilter>()
            .WithName("InternalListTelemetryEvents")
            .WithTags("Internal");

        return app;
    }
}
```

### Step 2: Add `/api/v1/internal/test-hooks/backdate-deletion-request` endpoint

**Rationale:** The orchestrator needs to deterministically push `pending_deletion_at` past the 30-day cooldown so `run-deletion-finalizer` picks the row up. No clock-jump hook exists; back-dating the column is the smallest, safest equivalent.

| `src/ApiTool.Backend/Program.cs` | modify | Wire `MapInternalBackdateDeletionEndpoint` |
| `src/ApiTool.Backend.Tests/Internal/InternalBackdateDeletionEndpointTests.cs` | create | Behavior tests |

```csharp
namespace ApiTool.Backend.Internal;

internal sealed record BackdateDeletionRequest(Guid UserId, int DaysAgo = 31);

public static class InternalBackdateDeletionEndpoint
{
    public static IEndpointRouteBuilder MapInternalBackdateDeletionEndpoint(
        this IEndpointRouteBuilder app, IWebHostEnvironment env)
    {
        if (!env.IsDevelopment() && !env.IsEnvironment("Testing"))
            return app;

        app.MapPost("/api/v1/internal/test-hooks/backdate-deletion-request",
            async (BackdateDeletionRequest? body, AppDbContext db,
                   TimeProvider clock, CancellationToken ct) =>
            {
                if (body is null || body.UserId == Guid.Empty)
                    return Results.BadRequest(new { error = "user_id required" });

                var newTs = clock.GetUtcNow().UtcDateTime - TimeSpan.FromDays(body.DaysAgo);
                var user = await db.Users
                    .Where(u => u.Id == body.UserId && u.PendingDeletionAt != null)
                    .FirstOrDefaultAsync(ct);
                if (user is null)
                    return Results.NotFound(new { error = "no pending deletion for user" });

                user.PendingDeletionAt = newTs;
                await db.SaveChangesAsync(ct);

                return Results.Ok(new { user_id = user.Id, pending_deletion_at = newTs });
            })
            .AllowAnonymous()
            .DisableAntiforgery()
            .AddEndpointFilter<InternalAccessFilter>()
            .WithName("InternalBackdateDeletion")
            .WithTags("Internal");

        return app;
    }
}
```

```typescript
// web/tests/e2e/helpers/m18-seed.ts
// Test helpers for M18-012 convergence spec. Mirrors helpers/m16-seed.ts shape.

const BACKEND_URL = process.env.APITEST_BACKEND_URL ?? 'http://localhost:5000';

export async function pollExportReady(
    exportId: string, bearerToken: string, timeoutMs = 30_000
): Promise<{ status: string; signed_url?: string; expires_at?: string }> {
    const deadline = Date.now() + timeoutMs;
    while (Date.now() < deadline) {
        const res = await fetch(
            `${BACKEND_URL}/api/v1/users/me/export-requests/${exportId}`,
            { headers: { Authorization: `Bearer ${bearerToken}` } });
        if (res.ok) {
            const body = await res.json() as { status: string; signed_url?: string; expires_at?: string };
            if (body.status === 'ready') return body;
        }
        await new Promise(r => setTimeout(r, 500));
    }
    throw new Error(`export ${exportId} did not reach status=ready within ${timeoutMs}ms`);
}

export async function backdateDeletionRequest(
    userId: string, daysAgo = 31
): Promise<void> {
    const res = await fetch(
        `${BACKEND_URL}/api/v1/internal/test-hooks/backdate-deletion-request`,
        {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ user_id: userId, days_ago: daysAgo }),
        });
    if (!res.ok) throw new Error(`backdate-deletion-request: HTTP ${res.status}`);
}

export async function runDeletionFinalizer(): Promise<void> {
    const res = await fetch(
        `${BACKEND_URL}/api/v1/internal/test-hooks/run-deletion-finalizer`,
        { method: 'POST' });
    if (!res.ok) throw new Error(`run-deletion-finalizer: HTTP ${res.status}`);
}

export async function listTelemetryEvents(installId: string): Promise<{
    count: number;
    rows: Array<{ install_id: string; event_type: string; received_at: string }>;
}> {
    const url = `${BACKEND_URL}/api/v1/internal/test-hooks/list-telemetry-events?install_id=${encodeURIComponent(installId)}`;
    const res = await fetch(url);
    if (!res.ok) throw new Error(`list-telemetry-events: HTTP ${res.status}`);
    return res.json();
}

export async function streamAuditJsonl(
    orgId: string, bearerToken: string
): Promise<{ status: number; contentType: string; transferEncoding: string; lineCount: number }> {
    const res = await fetch(
        `${BACKEND_URL}/api/v1/organizations/${orgId}/audit-log?format=jsonl&from=2025-01-01`,
        { headers: { Authorization: `Bearer ${bearerToken}` } });
    const body = await res.text();
    const lineCount = body.split('\n').filter(l => l.trim().length > 0).length;
    return {
        status: res.status,
        contentType: res.headers.get('content-type') ?? '',
        transferEncoding: res.headers.get('transfer-encoding') ?? '',
        lineCount,
    };
}
```

```bash
#!/usr/bin/env bash
# scripts/m18-e2e.sh — M18-012 compliance convergence scenario.
#
# Prereqs: ./scripts/ci-local.sh --full has brought up the stack
#   (backend, web, MinIO, sendgrid-fake, stripe-mock, github-mock, fake-idp).
#
# Exit codes:
#   0   — PASS
#   1   — general failure
#   2-12 — failing step number per the 12-step observable

set -euo pipefail
START_TS=$(date +%s)
REPO_ROOT="$(cd "$(dirname "$0")/.." && pwd)"

BACKEND_URL="${BACKEND_URL:-http://localhost:5000}"
WEB_BASE_URL="${WEB_BASE_URL:-http://localhost:3000}"
OWNER_EMAIL="${M18_E2E_EMAIL:-m18-e2e-$(date +%s)@example.com}"
ORG_SLUG="${M18_E2E_ORG_SLUG:-acme}"
ENTERPRISE_ORG_SLUG="${M18_E2E_ENT_SLUG:-acme}" # seeded enterprise-tier org

step() { echo "=== M18 step $1: $2 ==="; }
fail() { echo "FAIL: $1" >&2; exit "${2:-1}"; }

# ── Setup: seed Enterprise tier on acme so audit-log JSONL streaming is gated through ──
"$REPO_ROOT/scripts/seed-enterprise.sh" "$ENTERPRISE_ORG_SLUG" m18-auditor "audit_log.view,audit_log.export" || true

# ── Step 1: register via seed-refresh ────────────────────────────────────────
step 1 "register via seed-refresh"
REFRESH_RESP=$(curl -fsS -X POST "$BACKEND_URL/internal/test/seed-refresh" \
    -H "Content-Type: application/json" \
    -d "{\"email\":\"$OWNER_EMAIL\"}")
REFRESH_TOKEN=$(echo "$REFRESH_RESP" | python3 -c 'import sys,json; print(json.load(sys.stdin)["plaintext"])')
DEVICE_ID=$(echo "$REFRESH_RESP" | python3 -c 'import sys,json; print(json.load(sys.stdin)["device_id"])')
USER_ID=$(echo "$REFRESH_RESP" | python3 -c 'import sys,json; print(json.load(sys.stdin).get("user_id",""))')
REFRESH_OUT=$(curl -fsS -X POST "$BACKEND_URL/api/v1/auth/refresh" \
    -H "Content-Type: application/json" \
    -d "{\"refresh_token\":\"$REFRESH_TOKEN\",\"device_id\":\"$DEVICE_ID\"}")
ACCESS_TOKEN=$(echo "$REFRESH_OUT" | python3 -c 'import sys,json; print(json.load(sys.stdin).get("access_token") or "")')
[ -n "$ACCESS_TOKEN" ] || fail "no access_token from /auth/refresh" 1
```

## Risks and Edge Cases

- **Risk:** `seed-refresh` users have no password set, so `POST /api/v1/auth/reauth` (which validates the password) cannot mint a re-auth token. → **Mitigation:** Inspect `ReauthEndpoints.cs` during execution to confirm the password-check policy. If a dev/test bypass is missing, add a small `?dev_skip_password=1` dev/test-only branch under the same `InternalAccessFilter` gate, or have the orchestrator seed a password via a small helper hook. Document the decision in `M18-012-improved.md` if it arises during execute. Smallest blast radius: a third tiny internal hook `POST /api/v1/internal/test-hooks/mint-reauth-token` that bypasses the password check for the test user.

- **Risk:** `scripts/seed-enterprise.sh` requires `acme` to already exist via `seed-test-data.sh`. → **Mitigation:** `ci-local.sh --full` already runs `seed-test-data.sh` before any spec is invoked; the orchestrator runs after. Document the ordering as a comment in the script header.

- **Risk:** The audit-log JSONL stream test asserts `actor_email` matches `deleted-user-[0-9a-f]{8}` — but if the e2e user has not actually performed an auditable action attributed to them (the orchestrator-driven flow may rely on `seed-refresh`, which sets `actor_id` but does not produce an audit row), there may be no matching row. → **Mitigation:** Have the orchestrator deliberately produce an audit-eligible action before deletion (e.g., invite a member or create a custom role), so the anonymiser has at least one row to scrub. Document in the spec.

- **Risk:** Wall-clock budget. ci-local.sh --full + m16-e2e.sh already consume ~5 min. → **Mitigation:** Keep M18-012's orchestrator <90s wall-clock by using poll intervals of 0.5s, hard timeouts of 10–15s per step, and skipping the expensive "advance clock 30 days" (replaced by the 1-call backdate hook). Total m18-e2e.sh budget: <90s.

- **Risk:** The CHANGELOG entry framing. → **Mitigation:** Use the launch-blocking framing from project_milestone_release_model.md verbatim; do NOT soften with "ship X now, harden Y later" per feedback_no_phased_shipping_framing.

- **Edge case:** SQLite `template_jsonb_ciphertext` column is bytea — querying via `sqlite3 quote()` returns a hex literal (`X'...'`). The sentinel-cleartext substring check still works because the hex of "sentinel-cleartext..." would not appear in the AES-256-GCM ciphertext unless encryption is bypassed; therefore a `grep -q sentinel` against the raw column proves cleartext absence. Documented inline in the script.

- **Edge case:** Mac vs Linux `stat`. Different flag syntax (`-f` vs `-c`). → **Handling:** The script uses both with `||` fallback as in m16-e2e.sh.

- **Edge case:** Idempotent re-runs of the script. → **Handling:** Per-run unique email + auto-resolved org id; the deletion-cancel-redelete loop is the only step with potential to leak state, mitigated by per-run user identity.
