# Implementation Plan: M12-008

## Overview

Adds two argument-bearing dynamic functions — `$randomPassword(length)` and `$randomBase64(byteLength)` — to `internal/variable/dynamic.go`. Both are seeded-aware (deterministic under `--seed`), share existing `intn`/`randomString` plumbing, and emit structured `[INPUT]` errors for length-out-of-range and non-integer arguments.

## Architectural Decisions

1. **Reuse the existing `oneArg` wrapper for both functions.** Both `$randomPassword` and `$randomBase64` take a single string argument that we parse to an `int` and validate. `oneArg`, however, is a *pure-function* helper — it does not pass the registry RNG to the wrapped closure (see dynamic.go:79-86: `func(_ *rand.Rand, args []string) ...`). Both new functions need the seeded RNG. Decision: register them as raw `DynFunc` closures (matching `noArgs` / `twoArgs` peers) that perform their own arity check via the existing `arityError(funcName, want, got)` helper. This keeps the wrapper helpers' contracts pure (no RNG) and gives the new functions direct access to `rng` for seeded determinism. Cost: ~3 lines of arity boilerplate per function vs. inventing a new `oneArgRng` wrapper. Benefit: no churn in the wrapper layer.

2. **Length validation — `$randomPassword` requires `length >= 4`.** The four-class guarantee (one upper, one lower, one digit, one symbol) is unsatisfiable when `length < 4`. Behavior 3 says lengths in `{0, 1, 2, 3}` must return a structured error. Code: `DYNFN_RANDOMPASSWORD_BAD_LENGTH`. Message: `"length %d is too short: must be >= 4 to satisfy upper/lower/digit/symbol classes"`. Hint: `"Pass an integer string >= 4, e.g. {{$randomPassword('16')}}."`. Negative lengths flow through the same path (also `< 4`).

3. **Non-integer length — separate error code from out-of-range.** A non-digit input (e.g. `'xyz'`) is a different failure mode than an out-of-range integer. Code: `DYNFN_RANDOMPASSWORD_BAD_INPUT`. Message: `"invalid length %q: must be an integer"`. Inner: the `*strconv.NumError` for `errors.Is/As` traversal. Same shape for `$randomBase64` with code `DYNFN_RANDOMBASE64_BAD_INPUT`.

4. **`$randomBase64` requires `byteLength >= 1`.** Behavior 6 says `byteLength` must be `>= 1`; `0` and negatives error. Code: `DYNFN_RANDOMBASE64_BAD_LENGTH`. Message: `"byteLength %d is invalid: must be >= 1"`. Hint: `"Pass an integer string >= 1, e.g. {{$randomBase64('32')}}."`.

5. **Symbol set is a fixed compile-time constant.** Spec lists exactly: `!@#$%^&*()-_=+[]{}<>?,.` (24 chars). We define `const passwordSymbols = "!@#$%^&*()-_=+[]{}<>?,."` at the same scope as `alphanum` and `hexChars` (currently inside `register()`; we'll lift these three to file-scope `const` block to avoid re-construction on every Registry instantiation — pure refactor, drop-in replacement). Configurable symbol sets are explicitly out of scope.

6. **Four-class generation algorithm — guaranteed-then-fill-then-shuffle.** Standard recipe:
   1. Place one character from each of `upperClass`, `lowerClass`, `digitClass`, `symbolClass` into a `[]byte` of length `n`.
   2. Fill the remaining `n - 4` positions by sampling uniformly from the union `allClasses = upper + lower + digit + symbol`.
   3. Shuffle the entire `[]byte` via Fisher-Yates using `intn(rng, ...)` so the four guaranteed characters are not always at positions 0..3.
   4. Return as `string(buf)`.
   This gives exact-length output, four-class guarantee, and an even mix.

7. **`$randomBase64` source bytes — `intn(rng, 256)` per byte.** The existing `intn` helper already routes through `crypto/rand` when `rng == nil` and through the seeded PCG when `rng != nil`. We allocate `[]byte` of length `byteLength` and fill via `b[i] = byte(intn(rng, 256))`. Then `base64.StdEncoding.EncodeToString(b)`. This uses the same RNG dispatch as every other random helper, so seeded determinism is automatic.

   *Considered and rejected:* a `crand.Read(b)` fast-path when `rng == nil`. Faster (single syscall vs. N), but introduces a code path divergence between seeded and unseeded modes that complicates the test matrix. The N-byte loop costs O(byteLength) — for typical password/token lengths (16–64 bytes) the difference is sub-microsecond and not worth the asymmetry.

8. **No sensitive-arg propagation.** Neither function takes credential material as input — the *output* of `$randomPassword` is a fresh secret, not a transformation of one. We do *not* update `r.sensitiveArgIdx`. (Compare to `$hmacSha256` where the key argument is auto-redaction-marked.) If a user assigns the output to a sensitive-named variable (`temp_password`), the existing sensitive-name heuristic in the variable resolver will redact it downstream — that's not this task's concern.

9. **Per-request memoisation honoured.** `Evaluate` already keys the cache by `funcName + NUL + args`, so two calls to `$randomPassword('16')` in the same request return the same string (intentional — same as the existing argument-bearing helpers). Two calls with different lengths produce different cache keys. No additional plumbing needed.

10. **`Available()` count moves 26 → 28 in the same commit as the registrations.** The existing `TestRegistry_available_sorted` (dynamic_test.go:294) asserts `len(avail) == 26`; we update it to `28` in the same step that registers the two new functions. This is a single-line edit.

11. **Step ordering — `$randomBase64` first.** Smaller blast radius: straight-line sample-bytes-then-encode logic, no four-class invariant, no Fisher-Yates shuffle. Implementing it first lets us verify the seeded-determinism plumbing and the integer-arg-error pattern before the more complex `$randomPassword`.

12. **Integer parsing — `strconv.Atoi`.** Match the precedent set by `applyDateOffset` (dynamic.go:436): `strconv.Atoi(s)` returns the canonical `*strconv.NumError` for non-digit input, which we wrap as `Inner` for the structured error. No `strings.TrimSpace` — leading/trailing whitespace is rejected, matching `$dateAdd`'s behaviour ("` 1`" is not a valid amount).

```go
// Random-secret helpers — single integer-string argument; seeded-aware.
//
// $randomBase64(byteLength)   — sample byteLength uniformly random bytes
//                                via intn (which routes through the
//                                registry's seeded PCG when --seed is
//                                set, else crypto/rand). Encode via
//                                base64.StdEncoding (RFC 4648 §4).
//
// Both helpers carry no credential material as input — the OUTPUT is the
// secret. No sensitiveArgIdx entry.
r.funcs["randomBase64"] = func(rng *rand.Rand, args []string) (string, error) {
    if len(args) != 1 {
        return "", arityError("randomBase64", 1, len(args))
    }
    n, err := strconv.Atoi(args[0])
    if err != nil {
        return "", &apierrors.Structured{
            Category: apierrors.CategoryInput,
            Code:     "DYNFN_RANDOMBASE64_BAD_INPUT",
            Message:  fmt.Sprintf("invalid byteLength %q: must be an integer", args[0]),
            Hint:     "Pass an integer string, e.g. {{$randomBase64('32')}}.",
            Inner:    err,
        }
    }
    if n < 1 {
        return "", &apierrors.Structured{
            Category: apierrors.CategoryInput,
            Code:     "DYNFN_RANDOMBASE64_BAD_LENGTH",
            Message:  fmt.Sprintf("byteLength %d is invalid: must be >= 1", n),
            Hint:     "Pass an integer string >= 1, e.g. {{$randomBase64('32')}}.",
        }
    }
    b := make([]byte, n)
    for i := 0; i < n; i++ {
        b[i] = byte(intn(rng, 256))
    }
    return base64.StdEncoding.EncodeToString(b), nil
}
```

```go
// makePassword returns an n-character password (n >= 4) guaranteed to
// contain at least one ASCII upper, one lower, one digit, and one
// symbol from passwordSymbols. The remaining n-4 characters are sampled
// uniformly from the union of all four classes; the result is then
// Fisher-Yates shuffled so the four guaranteed characters are not
// always at positions 0..3. RNG dispatch via intn (seeded-aware).
//
// Caller must validate n >= 4; the function trusts its input.
func makePassword(rng *rand.Rand, n int) string {
    const allClasses = upperChars + lowerChars + digitChars + passwordSymbols
    buf := make([]byte, n)
    // Step 1: place one guaranteed character from each class.
    buf[0] = upperChars[intn(rng, len(upperChars))]
    buf[1] = lowerChars[intn(rng, len(lowerChars))]
    buf[2] = digitChars[intn(rng, len(digitChars))]
    buf[3] = passwordSymbols[intn(rng, len(passwordSymbols))]
    // Step 2: fill the rest from the union.
    for i := 4; i < n; i++ {
        buf[i] = allClasses[intn(rng, len(allClasses))]
    }
    // Step 3: Fisher-Yates shuffle in place so the guaranteed positions move.
    for i := n - 1; i > 0; i-- {
        j := intn(rng, i+1)
        buf[i], buf[j] = buf[j], buf[i]
    }
    return string(buf)
}
```

```go
// TestRegistry_RandomPassword verifies length and four-class invariants.
// Behaviors 1 + 2 + observable.
func TestRegistry_RandomPassword(t *testing.T) {
    reg := NewRegistry(nil)
    for _, n := range []int{4, 8, 16, 32, 64} {
        t.Run(fmt.Sprintf("length=%d", n), func(t *testing.T) {
            got, err := reg.Evaluate("randomPassword", []string{strconv.Itoa(n)}, make(map[string]string))
            if err != nil {
                t.Fatalf("Evaluate: %v", err)
            }
            if len(got) != n {
                t.Errorf("len(%q) = %d, want %d", got, len(got), n)
            }
            // Four-class guarantee.
            hasUpper := strings.ContainsAny(got, upperChars)
            hasLower := strings.ContainsAny(got, lowerChars)
            hasDigit := strings.ContainsAny(got, digitChars)
            hasSymbol := strings.ContainsAny(got, passwordSymbols)
            if !hasUpper || !hasLower || !hasDigit || !hasSymbol {
                t.Errorf("randomPassword(%d) %q missing class: upper=%v lower=%v digit=%v symbol=%v",
                    n, got, hasUpper, hasLower, hasDigit, hasSymbol)
            }
            // Every byte must come from the union.
            const allClasses = upperChars + lowerChars + digitChars + passwordSymbols
            for i := 0; i < len(got); i++ {
                if !strings.ContainsRune(allClasses, rune(got[i])) {
                    t.Errorf("randomPassword(%d) %q contains out-of-class byte %q at %d", n, got, string(got[i]), i)
                }
            }
        })
    }
}
```

```markdown
Fisher-Yates shuffled). The symbol set is fixed; configurable symbol sets
are not yet supported. `$randomBase64(byteLength)` returns the standard-base64
encoding (RFC 4648 §4) of `byteLength` random bytes; the encoded string
is roughly `4 × ceil(byteLength / 3)` characters. Both functions honour
`--seed` for reproducibility — under a fixed seed, the same length always
produces the same output. Without a seed, both draw from `crypto/rand`.

`$randomPassword('3')` (or any `n < 4`) returns a structured `[INPUT]`
error — at least four characters are needed to satisfy the four-class
guarantee. Non-integer arguments (`{{$randomPassword('xyz')}}`,
`{{$randomBase64('1.5')}}`) return `[INPUT]` errors quoting the bad
input. `$randomBase64('0')` and negative byte lengths also error.
```

## Risks and Edge Cases

- **Risk: Seeded determinism contract drift.** `intn(rng, ...)` consumes RNG state on each call. Any later refactor that changes the call sequence inside `makePassword` (e.g. fills then guarantees instead of guarantees then fills) will silently change every `--seed`-locked password output. → **Mitigation:** Pin the `--seed 42` output of `$randomPassword('16')` as a golden vector in `TestRegistry_RandomPassword_Seeded`. Future refactors that shift the RNG sequence will break the test loudly.

- **Risk: `intn(rng, 256)` upper-bound bias.** `rand/v2.IntN` uses rejection sampling and is unbiased by construction. The `crypto/rand` fallback in `intn` (dynamic.go:493-500) uses `binary.LittleEndian.Uint64(b[:]) % uint64(n)` — biased by `2^64 mod n`, but for `n=256` the bias is `0` (256 divides 2^64 exactly). For `len(allClasses) = 26+26+10+24 = 86`, the bias is `2^64 mod 86 ≈ small` — same magnitude of bias as the existing `$randomString` and `$randomEmail`. → **Mitigation:** Acknowledge as out-of-scope for this task; bias is below cryptographic relevance for password generation in this tool's threat model. Document deferred-fix in CHANGELOG if reviewer flags it.

- **Edge case: byteLength encoded length.** `base64.StdEncoding.EncodeToString` of `n` bytes returns `4 * ceil(n / 3)` characters. The observable `$randomBase64('32')` returns 44 characters (32 bytes → 44 chars, with one `=` pad). The example in MANUAL.md notes this. → **Handling:** test asserts on the *decoded* byte length, not the encoded character length; allows the alphabet regex to permit 0–2 trailing `=`.

- **Edge case: `$randomBase64('1')`.** A single byte encodes to `XX==` (4 chars, two pad). The alphabet-regex test allows 0–2 trailing `=`. → **Handling:** test case `byteLength=1` is included in the table.

- **Edge case: very large length.** `$randomPassword('1000000')` is technically valid. We do not impose a max length — `make([]byte, n)` will allocate; bad inputs that overflow `int` would be caught by `strconv.Atoi`. → **Handling:** out of scope; the existing dynamic-function evaluator does not impose timeouts. A future task can add a sanity cap (e.g. 64KiB).

- **Edge case: per-request memoisation collision.** Two identical calls to `$randomPassword('16')` in the same request return the same string (intentional, matches `$uuid`/`$base64`). Two calls with different lengths produce different cache keys — verified by `cacheKey(name, args)` (dynamic.go:106). → **Handling:** no new test; covered by the existing `TestRegistry_evaluate_caches_within_request` pattern.

- **Edge case: `args[0] == ""` (empty string).** `strconv.Atoi("")` returns a `*strconv.NumError`. Falls into the `DYNFN_RANDOMPASSWORD_BAD_INPUT` / `DYNFN_RANDOMBASE64_BAD_INPUT` path. Test case included.
