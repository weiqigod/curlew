# Implementation Plan: M14-011

## Overview

Adds the `POST /webhooks/stripe` endpoint plus its supporting infrastructure: a new `stripe_webhook_events` table (EF migration 0015), a `StripeWebhookOptions` config block (`APITOOL__STRIPE__WEBHOOK_SECRETS` multi-secret list + tolerance with footgun guard), a raw-body-preserving signature verifier built on `Stripe.Net.EventUtility.ConstructEvent`, an `INSERT … ON CONFLICT (event_id) DO NOTHING RETURNING received_at` idempotency pattern, a 5-failure quarantine budget, and a daily 90-day cleanup hosted service. This slice ships the *ingest pipeline* only — handler dispatch is a no-op stub (status flips from `pending` to `processed`); the real `customer.subscription.*` / `invoice.*` handlers ship in M14-012/M14-013.

## Architectural Decisions (resolved up-front)

The task YAML carries several open shapes; resolved here so the implementation steps are mechanical.

1. **Endpoint path: `POST /webhooks/stripe` (top-level, no `/api/v1` prefix).** The task observable uses `http://localhost:5000/webhooks/stripe`. Stripe webhooks are conceptually outside the user-facing API surface (no `Authorization` header, signed by HMAC instead of JWT). Mounting at `/webhooks/stripe` matches the spec at `:6811` literally and lets us keep the existing `/api/v1/*` group authenticated without weakening it. The endpoint is **not** in the auth pipeline (`AllowAnonymous`) and is **not** rate-limited via `.RequireRateLimiting(...)` (Stripe is a trusted source; signature verification is the gate).

2. **Raw body preservation strategy.** `EventUtility.ConstructEvent` requires the *exact* bytes Stripe signed — any reformatting (newline normalisation, JSON re-serialisation) breaks HMAC. We read the raw body via `await new StreamReader(context.Request.Body, Encoding.UTF8).ReadToEndAsync()` *before* any model binder runs, by accepting `HttpContext` instead of `[FromBody]` in the endpoint delegate. This is the same pattern the spec mandates at `:6818` ("raw JSON from Stripe"). We do **not** call `Request.EnableBuffering()` — we only need to read the body once.

3. **Multi-secret rotation: comma-separated env var, fail-on-any-pass.** Per spec `:6850`, `STRIPE__WEBHOOK_SECRETS` is plural and comma-separated (`whsec_old,whsec_new`). The verifier loops the list and accepts the first match; reports failure only when *every* secret fails. Order does not matter (constant-time HMAC compare per secret). Whitespace around commas is trimmed. Empty entries are skipped. Boot fails when the list is empty (no secrets configured) and `Mode == "live"`.

4. **Tolerance footgun guard at boot, not per-request.** Spec `:6854`: tolerance=0 is forbidden because Stripe.Net treats 0 as "skip timestamp check entirely". We expose `StripeWebhookOptions.ToleranceSeconds` (default 300 = 5 minutes) bound from `APITOOL__STRIPE__WEBHOOK_TOLERANCESECONDS`. Using `AddOptions().Validate(o => o.ToleranceSeconds >= 30, ...).ValidateOnStart()` rejects zero (and other dangerously low values) at app startup, mirroring how `StripeOptions.Mode == "live"` already validates `ApiKey != ""`. The minimum of 30 seconds gives ~10× the legitimate clock-drift envelope while still being far above zero.

5. **`stripe_webhook_events` entity name: `StripeWebhookEvent` (PascalCase, table snake_case).** Mirrors existing `OrganizationAuditLogEntry` naming. The DbSet is `StripeWebhookEvents`; table is `stripe_webhook_events`.

6. **Column types: TEXT in SQLite (existing migration convention), conditional `jsonb` for `payload` on Postgres via `Database.IsNpgsql()` in `OnModelCreating` (mirrors the `SigningKey.PublicKeyJwkJson` pattern).** Migration `Up` uses `TEXT` for portability with the SQLite-based test infrastructure (`TestDb.cs` uses SQLite in-memory). This matches every existing migration file and works under both providers because the EF SQL generator picks the right type per provider when run via `Database.MigrateAsync()`. The model-level `HasColumnType("jsonb")` only fires when the active provider is Npgsql (Postgres production).

7. **`status` column: TEXT with a check constraint OR enum-string conversion.** The spec at `:9993` declares `status TEXT NOT NULL DEFAULT 'pending'` with allowed values `pending|processed|quarantined`. We model it as a C# string property (not an enum) to keep the migration trivial and avoid an EF-side enum conversion that would add a column type quirk on SQLite. Defensive validation (only the three legal values) lives in the service layer (`UpdateStatusAsync`). This matches how `Subscription.Status` is modelled: enum on the C# side, string on the DB. Going string-only here saves writing an enum that's only used by one consumer.

8. **The "process pending row" pipeline is a no-op stub for this slice.** Per task scope: "this slice does NOT register any handlers yet — M14-012 and M14-013 add handlers; this slice's 'process pending row' pipeline is a no-op that marks status='processed' so the integration test exercises end-to-end ingest." We define `IStripeWebhookDispatcher` with one method `Task DispatchAsync(StripeWebhookEvent row, Stripe.Event @event, CancellationToken ct)`; the M14-011 implementation `NoopStripeWebhookDispatcher` returns `Task.CompletedTask`. M14-012/M14-013 will replace the registration with a router that maps event types to handlers. Behaviour #5 ("handler exception increments attempt_count") is testable today by adding a *test-only* `ThrowingStripeWebhookDispatcher` that throws on demand; we override the registration in the integration test using the same `services.RemoveAll<IStripeWebhookDispatcher>()` pattern `BackendFactory` already uses for senders.

9. **Quarantine alert: structured warning log with `event_id={EventId} event_type={EventType} attempt_count=5`.** The task says "a high-priority alert is logged." We do not have a dedicated alerting channel yet (Sentry / PagerDuty are M16+); a structured `_logger.LogError("stripe_webhook_quarantined event_id={EventId} event_type={EventType} attempt_count={AttemptCount} last_error={LastError}", ...)` line is the deliverable. The `event=stripe_webhook_quarantined` token is the search anchor that ops alerting will match in M16. This is consistent with how M14-009/010 emit their `Stripe rate-limited` warnings.

10. **Daily cleanup hosted service: `StripeWebhookCleanupHost` BackgroundService running every 24h.** Matches `SchedulerHost`/`ShardReaper` patterns. Tick interval is configurable (default 24h, override via constructor for tests). On each tick: `DELETE FROM stripe_webhook_events WHERE status = 'processed' AND received_at < now() - 90d`. Quarantined rows are *not* touched. We use `await db.StripeWebhookEvents.Where(...).ExecuteDeleteAsync(ct)` which compiles to `DELETE FROM` on both providers. Skipped under `IsEnvironment("Testing")` (matching `SchedulerHost`'s skip).

11. **`scripts/sign-stripe-webhook.sh` helper.** A 12-line bash script that takes `secret` and `payload` args, computes `t=<now-epoch>` and `v1=hmac_sha256_hex(secret, t + "." + payload)`, and emits the Stripe-Signature header value `t=<epoch>,v1=<hex>`. Uses `openssl dgst -sha256 -hmac` (universally available on macOS/Linux). The header echoes the format Stripe sends per spec `:6813`. Marked executable.

12. **Idempotency `INSERT … ON CONFLICT DO NOTHING RETURNING`: raw SQL via `FromSqlInterpolated` on Postgres; LINQ fallback on SQLite for tests.** The exact spec pattern is Postgres-specific syntax. EF Core does not natively translate `ON CONFLICT … RETURNING`. Two options: (a) use raw SQL, branched on `Database.IsNpgsql()`; (b) use a transaction with `SELECT ... FOR UPDATE` semantics. Option (a) is what the spec explicitly mandates at `:9988` ("INSERT ... ON CONFLICT (event_id) DO NOTHING RETURNING received_at") and is observably atomic. For SQLite (test-only), we use a `TryGetAsync(eventId)` followed by `AddAsync`+`SaveChangesAsync` with a `DbUpdateException` catch on the unique constraint — semantically equivalent for single-writer test fixtures. This dual path lives in a private helper `IdempotentInsertAsync(StripeWebhookEvent row, CancellationToken ct)` on a new `StripeWebhookStore` service. The branch is gated on `db.Database.IsNpgsql()` and documented with a code comment citing `:6821`.

13. **Endpoint outcome semantics.**
    - **Invalid signature** → HTTP 400 (no body row written; structured `LogWarning("stripe_webhook_signature_invalid …")`).
    - **Duplicate event_id** → HTTP 200 immediately (no second row, no handler run, structured `LogInformation("stripe_webhook_duplicate event_id={EventId}")`).
    - **Handler success** → HTTP 200 with `processed_at = now`, `status = processed`.
    - **Handler exception, attempt_count < 5** → HTTP 500 (Stripe retries), `attempt_count++`, `last_error / last_error_at` set.
    - **Handler exception, attempt_count >= 5** → HTTP 200 (break retry storm), `status = quarantined`, alert log emitted.
    - **Boot misconfig (no secrets in live mode, tolerance=0)** → app fails to start.

14. **No new RFC 7807 problem types.** Webhook responses to Stripe are simple status codes (200/400/500) — Stripe ignores response bodies. No `application/problem+json` builder needed.

15. **Spec citation header.** `StripeWebhookEndpoint.cs` opens with `// Spec refs: docs/SPECIFICATION.md:6818-6854 (signature verification + idempotency + quarantine + multi-secret rotation + retention + tolerance footgun guard); :9985-10004 (stripe_webhook_events schema).` per definition_of_done item.

16. **Test-host divergence.** `BackendFactory` uses EF Core InMemory which lacks raw SQL support; the integration test that exercises `Idempotent insert` uses SQLite via `TestDb.CreateOpen()` (the existing pattern from `SubscriptionsMigrationTests`). For the end-to-end webhook ingest test (HTTP-level), we register the in-process `StripeWebhookStore` against the EF-InMemory DbContext, which falls into the LINQ branch (Decision #12). Two distinct test surfaces:
    - **Unit-level**: `StripeWebhookStoreTests` against SQLite (covers the idempotency race / duplicate detection / quarantine bookkeeping).
    - **Endpoint-level**: `StripeWebhookEndpointTests` against `BackendFactory` (covers HTTP 200/400/500 contract + signature verification + duplicate request behaviour).

17. **No coupling to existing `SubscriptionsService`.** The webhook ingest pipeline is fully self-contained in a new `Webhooks/` folder. It does not call `SubscriptionsService` (no handlers wired yet). Folder name matches scope: `src/ApiTool.Backend/Webhooks/`.

18. **Configuration binding section.** `StripeWebhookOptions` binds from `ApiTool:Stripe:Webhook:*` (specifically `Secrets` and `ToleranceSeconds`). Env-var spelling per the task: `APITOOL__STRIPE__WEBHOOK_SECRETS` maps to `ApiTool:Stripe:Webhook_Secrets` under standard `__` → `:` rules — which doesn't compose cleanly. We resolve this by binding `Secrets` from a top-level config key and *also* explicitly checking the env var `APITOOL__STRIPE__WEBHOOK_SECRETS` in `Program.cs` and feeding it via `AddInMemoryCollection` at startup so both spellings work. This matches the task observable (`APITOOL__STRIPE__WEBHOOK_SECRETS=whsec_test`) and the spec's documented spelling at `:6850`. The clean ASP.NET Core spelling (`APITOOL__STRIPE__WEBHOOK__SECRETS`) is also accepted as a fallback.

```csharp
namespace ApiTool.Backend.Data.Entities;

/// <summary>
/// One row per Stripe webhook event delivery — idempotency store and audit trail.
/// Refs docs/SPECIFICATION.md:9985-10004.
/// </summary>
public sealed class StripeWebhookEvent
{
    /// <summary>Stripe's event id (e.g. <c>evt_1NXp…</c>). Primary key.</summary>
    public string EventId { get; set; } = string.Empty;

    /// <summary>Event type, e.g. <c>customer.subscription.created</c>.</summary>
    public string EventType { get; set; } = string.Empty;

    /// <summary>UTC moment we received the delivery (DB default <c>NOW()</c>).</summary>
    public DateTime ReceivedAt { get; set; }

    /// <summary>UTC moment processing succeeded; null while pending or after a failure.</summary>
    public DateTime? ProcessedAt { get; set; }

    /// <summary>One of <c>pending</c>, <c>processed</c>, <c>quarantined</c>.</summary>
    public string Status { get; set; } = "pending";

    /// <summary>Raw JSON event payload — TEXT on SQLite, jsonb on Postgres.</summary>
    public string PayloadJson { get; set; } = "{}";

    /// <summary>Number of failed handler attempts. Increments to 5 then quarantines.</summary>
    public int AttemptCount { get; set; }

    /// <summary>Last error message; null if never failed.</summary>
    public string? LastError { get; set; }

    /// <summary>UTC moment the most recent failure was recorded.</summary>
    public DateTime? LastErrorAt { get; set; }
}
```

```csharp
namespace ApiTool.Backend.Webhooks;

/// <summary>
/// Configuration for the Stripe webhook ingest pipeline. Bound from
/// <c>ApiTool:Stripe:Webhook:*</c> with environment-variable equivalents
/// <c>APITOOL__STRIPE__WEBHOOK__SECRETS</c> (canonical) and
/// <c>APITOOL__STRIPE__WEBHOOK_SECRETS</c> (single-underscore alias per spec :6850).
/// </summary>
public sealed class StripeWebhookOptions
{
    /// <summary>Configuration section name.</summary>
    public const string Section = "ApiTool:Stripe:Webhook";

    /// <summary>
    /// Comma-separated list of webhook signing secrets. Multiple values support
    /// the 24-hour rotation grace window — verification iterates the list and
    /// succeeds on any match. Empty entries are skipped.
    /// </summary>
    public string Secrets { get; set; } = string.Empty;

    /// <summary>
    /// Timestamp tolerance for HMAC verification, in seconds. Default 300 (5 minutes).
    /// Setting to 0 is rejected at boot — Stripe.Net treats 0 as "skip the
    /// timestamp check entirely", which is a footgun. Spec ref :6854.
    /// </summary>
    public int ToleranceSeconds { get; set; } = 300;

    /// <summary>Splits <see cref="Secrets"/> on comma, trims whitespace, drops empties.</summary>
    public IReadOnlyList<string> SecretList()
    {
        if (string.IsNullOrWhiteSpace(Secrets)) return Array.Empty<string>();
        return Secrets.Split(',', StringSplitOptions.TrimEntries | StringSplitOptions.RemoveEmptyEntries);
    }
}
```

```csharp
// ── Stripe Webhooks ───────────────────────────────────────────────────────
// Bridge the spec's documented env-var spelling APITOOL__STRIPE__WEBHOOK_SECRETS
// (single underscore between WEBHOOK and SECRETS) into the canonical config key.
var webhookSecretsAlias = builder.Configuration["APITOOL__STRIPE__WEBHOOK_SECRETS"];
if (!string.IsNullOrEmpty(webhookSecretsAlias))
{
    builder.Configuration.AddInMemoryCollection(new Dictionary<string, string?>
    {
        ["ApiTool:Stripe:Webhook:Secrets"] = webhookSecretsAlias,
    });
}

builder.Services.AddOptions<StripeWebhookOptions>()
    .Bind(builder.Configuration.GetSection(StripeWebhookOptions.Section))
    .Validate(
        o => o.ToleranceSeconds >= 30,
        "ApiTool:Stripe:Webhook:ToleranceSeconds must be >= 30 (env: APITOOL__STRIPE__WEBHOOK__TOLERANCESECONDS). " +
        "Setting to 0 disables Stripe.Net timestamp verification entirely (spec :6854).")
    .Validate(
        o => stripeMode != "live" || o.SecretList().Count > 0,
        "ApiTool:Stripe:Mode=live requires at least one webhook secret in APITOOL__STRIPE__WEBHOOK_SECRETS.")
    .ValidateOnStart();
```

```csharp
// Spec refs: docs/SPECIFICATION.md:6821 (INSERT … ON CONFLICT DO NOTHING RETURNING),
// :6843 (5-failure quarantine budget), :6852 (90-day cleanup retention).
using ApiTool.Backend.Data;
using ApiTool.Backend.Data.Entities;
using Microsoft.EntityFrameworkCore;

namespace ApiTool.Backend.Webhooks;

/// <summary>Encapsulates all DB writes against <c>stripe_webhook_events</c>.</summary>
public sealed class StripeWebhookStore(AppDbContext db, TimeProvider clock)
{
    /// <summary>Quarantine threshold per spec :6843.</summary>
    public const int QuarantineThreshold = 5;

    /// <summary>
    /// Atomically inserts a new pending row keyed by <paramref name="eventId"/>. Returns
    /// <see cref="IdempotentInsertResult.Inserted"/> = true when this was the first time
    /// we saw the event, false when a row already existed (duplicate delivery).
    /// </summary>
    public async Task<IdempotentInsertResult> TryInsertPendingAsync(
        string eventId, string eventType, string payloadJson, CancellationToken ct)
    {
        var now = clock.GetUtcNow().UtcDateTime;

        if (db.Database.IsNpgsql())
        {
            // Postgres path — single statement, atomic per spec :6821.
            // Returns 1 row if inserted, 0 rows if duplicate.
            var inserted = await db.StripeWebhookEvents
                .FromSqlInterpolated($@"
                    INSERT INTO stripe_webhook_events
                        (event_id, event_type, received_at, status, payload, attempt_count)
                    VALUES
                        ({eventId}, {eventType}, {now}, 'pending', {payloadJson}::jsonb, 0)
                    ON CONFLICT (event_id) DO NOTHING
                    RETURNING *")
                .AsNoTracking()
                .ToListAsync(ct);

            return inserted.Count > 0
                ? new IdempotentInsertResult(true, null)
                : new IdempotentInsertResult(false, await ExistingReceivedAtAsync(eventId, ct));
        }

        // SQLite / InMemory path — LINQ guarded by a TryAdd then catch unique-violation.
        var existing = await db.StripeWebhookEvents
            .Where(x => x.EventId == eventId)
            .Select(x => (DateTime?)x.ReceivedAt)
            .FirstOrDefaultAsync(ct);
        if (existing is not null)
            return new IdempotentInsertResult(false, existing);

        db.StripeWebhookEvents.Add(new StripeWebhookEvent
        {
            EventId = eventId,
            EventType = eventType,
            ReceivedAt = now,
            Status = "pending",
            PayloadJson = payloadJson,
            AttemptCount = 0,
        });
        try
        {
            await db.SaveChangesAsync(ct);
            return new IdempotentInsertResult(true, null);
        }
        catch (DbUpdateException) // race: another writer inserted between our SELECT and INSERT.
        {
            // Detach the failed entity so subsequent SaveChanges work.
            db.ChangeTracker.Clear();
            return new IdempotentInsertResult(false, await ExistingReceivedAtAsync(eventId, ct));
        }
    }

    /// <summary>Marks the row as processed.</summary>
    public async Task MarkProcessedAsync(string eventId, CancellationToken ct)
    {
        var now = clock.GetUtcNow().UtcDateTime;
        await db.StripeWebhookEvents
            .Where(x => x.EventId == eventId)
            .ExecuteUpdateAsync(s => s
                .SetProperty(x => x.Status, "processed")
                .SetProperty(x => x.ProcessedAt, (DateTime?)now), ct);
    }

    /// <summary>
    /// Records a handler failure. Returns the new attempt_count after increment;
    /// when it reaches <see cref="QuarantineThreshold"/>, the status is updated to
    /// <c>quarantined</c> in the same transaction.
    /// </summary>
    public async Task<int> RecordFailureAsync(string eventId, string errorMessage, CancellationToken ct)
    {
        var now = clock.GetUtcNow().UtcDateTime;
        var row = await db.StripeWebhookEvents.FirstOrDefaultAsync(x => x.EventId == eventId, ct)
            ?? throw new InvalidOperationException($"stripe_webhook_events row missing for {eventId}");
        row.AttemptCount += 1;
        row.LastError = errorMessage;
        row.LastErrorAt = now;
        if (row.AttemptCount >= QuarantineThreshold)
            row.Status = "quarantined";
        await db.SaveChangesAsync(ct);
        return row.AttemptCount;
    }

    /// <summary>Deletes processed rows older than <paramref name="cutoff"/>. Quarantined rows are retained.</summary>
    public Task<int> DeleteOlderThanAsync(DateTime cutoff, CancellationToken ct) =>
        db.StripeWebhookEvents
            .Where(x => x.Status == "processed" && x.ReceivedAt < cutoff)
            .ExecuteDeleteAsync(ct);

    private Task<DateTime?> ExistingReceivedAtAsync(string eventId, CancellationToken ct) =>
        db.StripeWebhookEvents
            .Where(x => x.EventId == eventId)
            .Select(x => (DateTime?)x.ReceivedAt)
            .FirstOrDefaultAsync(ct);
}

/// <summary>Result of <see cref="StripeWebhookStore.TryInsertPendingAsync"/>.</summary>
/// <param name="Inserted">True if a new row was inserted; false if duplicate.</param>
/// <param name="ExistingReceivedAt">When duplicate, the original row's received_at (else null).</param>
public sealed record IdempotentInsertResult(bool Inserted, DateTime? ExistingReceivedAt);
```

```csharp
// Spec refs: docs/SPECIFICATION.md:6818-6854 (signature verification + idempotency
// + 5-failure quarantine + multi-secret rotation + 90-day retention + tolerance
// footgun guard); :9985-10004 (stripe_webhook_events schema).
using System.Text;
using Microsoft.Extensions.Options;
using Stripe;

namespace ApiTool.Backend.Webhooks;

/// <summary>Maps the <c>POST /webhooks/stripe</c> endpoint.</summary>
public static class StripeWebhookEndpoint
{
    /// <summary>Registers the webhook endpoint.</summary>
    public static IEndpointRouteBuilder MapStripeWebhookEndpoint(this IEndpointRouteBuilder app)
    {
        app.MapPost("/webhooks/stripe", HandleAsync)
            .AllowAnonymous()
            .WithName("StripeWebhook")
            .WithTags("Webhooks");
        return app;
    }

    private static async Task<IResult> HandleAsync(
        HttpContext context,
        IOptions<StripeWebhookOptions> webhookOptions,
        StripeWebhookStore store,
        IStripeWebhookDispatcher dispatcher,
        ILogger<StripeWebhookOptions> logger,
        CancellationToken ct)
    {
        // 1) Read raw body — Stripe signs the exact bytes, no re-encoding.
        string rawBody;
        using (var reader = new StreamReader(context.Request.Body, Encoding.UTF8, leaveOpen: true))
            rawBody = await reader.ReadToEndAsync(ct);

        var signature = context.Request.Headers["Stripe-Signature"].FirstOrDefault();
        if (string.IsNullOrEmpty(signature))
        {
            logger.LogWarning("stripe_webhook_signature_missing");
            return Results.BadRequest();
        }

        // 2) Verify against the multi-secret list — succeed on any match.
        var opts = webhookOptions.Value;
        Event? evt = null;
        var secrets = opts.SecretList();
        foreach (var secret in secrets)
        {
            try
            {
                evt = EventUtility.ConstructEvent(rawBody, signature, secret, opts.ToleranceSeconds);
                break;
            }
            catch (StripeException)
            {
                // Try the next secret.
            }
        }
        if (evt is null)
        {
            logger.LogWarning("stripe_webhook_signature_invalid secrets_tried={Count}", secrets.Count);
            return Results.BadRequest();
        }

        // 3) Idempotency insert.
        var insert = await store.TryInsertPendingAsync(evt.Id, evt.Type, rawBody, ct);
        if (!insert.Inserted)
        {
            logger.LogInformation(
                "stripe_webhook_duplicate event_id={EventId} original_received_at={ReceivedAt}",
                evt.Id, insert.ExistingReceivedAt);
            return Results.Ok();
        }

        // 4) Dispatch — M14-011 ships a no-op; M14-012/013 wire real handlers.
        try
        {
            await dispatcher.DispatchAsync(evt, ct);
            await store.MarkProcessedAsync(evt.Id, ct);
            return Results.Ok();
        }
        catch (Exception ex)
        {
            var attempts = await store.RecordFailureAsync(evt.Id, ex.Message, ct);
            if (attempts >= StripeWebhookStore.QuarantineThreshold)
            {
                logger.LogError(ex,
                    "stripe_webhook_quarantined event_id={EventId} event_type={EventType} attempt_count={AttemptCount}",
                    evt.Id, evt.Type, attempts);
                return Results.Ok(); // break the retry storm.
            }
            logger.LogWarning(ex,
                "stripe_webhook_handler_failed event_id={EventId} event_type={EventType} attempt_count={AttemptCount}",
                evt.Id, evt.Type, attempts);
            return Results.StatusCode(StatusCodes.Status500InternalServerError);
        }
    }
}
```

```csharp
// Spec ref: docs/SPECIFICATION.md:6852 (90-day retention; processed only).
using ApiTool.Backend.Webhooks;
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Options;

namespace ApiTool.Backend.Webhooks;

/// <summary>
/// Daily cleanup of <c>stripe_webhook_events</c> with status = 'processed' older
/// than <see cref="StripeWebhookCleanupOptions.RetentionDays"/>. Quarantined rows
/// are retained indefinitely for forensic investigation.
/// </summary>
public sealed class StripeWebhookCleanupHost(
    IServiceScopeFactory scopeFactory,
    IOptions<StripeWebhookCleanupOptions> options,
    TimeProvider clock,
    ILogger<StripeWebhookCleanupHost> logger,
    TimeSpan? tickInterval = null) : BackgroundService
{
    private readonly TimeSpan _tickInterval = tickInterval ?? TimeSpan.FromHours(24);

    /// <inheritdoc/>
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        logger.LogInformation(
            "StripeWebhookCleanupHost started; retention={Days} days; tick={Interval}h",
            options.Value.RetentionDays, _tickInterval.TotalHours);

        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await using var scope = scopeFactory.CreateAsyncScope();
                var store = scope.ServiceProvider.GetRequiredService<StripeWebhookStore>();
                var cutoff = clock.GetUtcNow().UtcDateTime.AddDays(-options.Value.RetentionDays);
                var deleted = await store.DeleteOlderThanAsync(cutoff, stoppingToken);
                if (deleted > 0)
                    logger.LogInformation(
                        "stripe_webhook_cleanup_deleted count={Count} cutoff={Cutoff:o}",
                        deleted, cutoff);
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested) { break; }
            catch (Exception ex) { logger.LogError(ex, "StripeWebhookCleanupHost tick failed"); }

            try { await Task.Delay(_tickInterval, stoppingToken); }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested) { break; }
        }
        logger.LogInformation("StripeWebhookCleanupHost stopped");
    }
}
```

## Risks and Edge Cases

- **Risk: raw body is consumed by another middleware before the endpoint runs** → no other middleware reads `Request.Body` (verified by inspecting `Program.cs`). The `AntiforgeryMiddleware` and `AuditCaptureMiddleware` do not consume the body. `Mitigation`: declare the endpoint with `AllowAnonymous` and `WithMetadata(new ProducesAttribute("application/json"))` only — do not bind body via `[FromBody]`.
- **Risk: Stripe.Net.EventUtility.ConstructEvent throws for *valid* timestamps under fake clock** → `EventUtility` reads system UTC time directly. The endpoint test must sign with `DateTimeOffset.UtcNow.ToUnixTimeSeconds()` (real time), not `FakeClock`. `Mitigation`: integration test signs with real time; only the *store* tests use `FakeClock`.
- **Edge case: empty `Stripe-Signature` header** → returns 400 (covered by Behaviour #3 test).
- **Edge case: `tolerance=300` accepts a 4-minute-old timestamp** → matches Stripe.Net default and is the legitimate replay window.
- **Edge case: secret list with only whitespace** → `SecretList()` returns empty → boot validation fails in live mode → Mitigation: explicit `Validate(o => stripeMode != "live" || o.SecretList().Count > 0, …)`.
- **Edge case: ON CONFLICT race under Postgres concurrent delivery** → handled by spec-mandated `INSERT … ON CONFLICT DO NOTHING RETURNING`. The `RETURNING *` predicate distinguishes new vs duplicate atomically (Postgres MVCC guarantees).
- **Edge case: handler raises *after* dispatch but *before* `MarkProcessedAsync`** → caught by the broad `catch (Exception ex)` in the endpoint; `RecordFailureAsync` runs; status stays `pending` until next attempt or quarantine. Test: simulate by having the dispatcher throw; assert `MarkProcessedAsync` was not called and `attempt_count` incremented.
- **Edge case: dispatcher succeeds but `MarkProcessedAsync` fails (DB hiccup)** → falls into `catch`; we increment `attempt_count`. Stripe will retry; the second delivery is a duplicate → 200 immediate. The original processed-state never gets recorded but no double-side-effect occurs (handlers in M14-012+ are idempotent per the spec's re-fetch design at `:6845-6848`). Acceptable trade-off; future hardening is out of scope.
- **Edge case: ASP.NET Core JSON body-too-large middleware truncates the body** → Stripe webhook bodies are small (~2-4 KB). Default `MaxRequestBodySize` is 30 MB. No risk.
- **Risk: `[Trait("Category", "stripe-integration")]` test running against stripe-mock pollutes the table** → all webhook tests use `BackendFactory`'s in-memory DB, isolated per test class. No pollution.
- **Risk: `EventUtility.ConstructEvent` requires `apiVersion` to match the SDK's expected version → throws** → set `throwOnApiVersionMismatch: false` in the call (spec doesn't mandate strict-mode; the apiVersion in synthetic test events differs from Stripe.Net 43.x's expected `2024-…`). `Mitigation`: pass the optional fifth parameter `throwOnApiVersionMismatch: false`. The two-arg overload uses the default tolerance; the four-arg overload sets tolerance; we use the explicit four-arg path with the false flag at the end:
  ```csharp
  EventUtility.ConstructEvent(rawBody, signature, secret, opts.ToleranceSeconds, throwOnApiVersionMismatch: false);
  ```
