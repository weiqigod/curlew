# Implementation Plan: M16-014

## Overview

Adds the outbound `IGitLabCheckPoster` + `GitLabCheckPoster` against `POST {gitlab_base_url}/api/v4/projects/{project_id}/statuses/{commit_sha}` with `Private-Token` auth, the `pr_checks.provider` discriminator + nullable `gitlab_installation_id` (FK) + `gitlab_status_id` columns, the lossy state-mapping table from spec :9233-9242, per-installation token-bucket honouring GitLab `RateLimit-*` headers, HTTPS-required URL validation (overridable via `GITLAB__ALLOW_HTTP=true`), and dispatcher routing in `PrChecksUploadEndpoint` that selects the GitHub or GitLab poster based on `provider` on the inbound payload.

## Key Architectural Decisions

These resolve under-specified areas of the task YAML by following docs/SPECIFICATION.md §"GitLab Commit Status API Integration" (lines 9110–9304). Decisions are recorded here, not deferred to runtime ambiguity.

### Decision A — `provider` is a row-level discriminator, not table-per-hierarchy

The `pr_checks` table gains a `provider TEXT NOT NULL DEFAULT 'github' CHECK (provider IN ('github','gitlab'))` column. Existing GitHub-only columns (`installation_id`, `check_run_id`) remain in place; new GitLab-only columns (`gitlab_installation_id` UUID NULL FK → `gitlab_installations(id)`, `gitlab_status_id` BIGINT NULL) are added as nullable peers. The `external_id` UUID column is shared (already exists). Routing in the upload endpoint dispatches on `provider`; the entity stays a single class with both column sets. Rationale: TPH would force two tables and break the `external_id` unique-index across providers; row-discriminator keeps cross-tenant guardrails (single FK to `pr_checks` table) and lets `external_id` remain provider-agnostic for retry idempotency.

### Decision B — `IGitLabCheckPoster` mirrors `ICheckRunPoster`; both implement a common dispatch contract via the endpoint, not a base class

A new interface `IGitLabCheckPoster.PostAsync(Guid prCheckId, CancellationToken ct) → CheckRunPostResult` lives in `ApiTool.Backend.PrChecks`. The endpoint receives both `ICheckRunPoster` and `IGitLabCheckPoster` from DI and selects by `body.Provider`. We **do not** introduce a `PostAsync(...)` base interface that both implement, because:
- The dispatch logic (resolve `provider` from request → pick poster) lives at HTTP-input time, where the endpoint already does shape validation
- A common base would lock in shared signatures prematurely; the GitHub poster's two-stage auth (App JWT → installation token) and the GitLab poster's PAT-decrypt are different lifecycles
- Reusing `CheckRunPostResult` and `PrCheckErrorCode` for both is sufficient sharing (no allocation, no interface tax)

### Decision C — State-mapping table lives in a new `GitLabStateMapper` (parallel to `PrCheckConclusionMapper`)

Two responsibilities, both pure functions:
1. `TryMap(cliState, out gitlabState)` — maps CLI's six states to GitLab's four (`success`, `failed`, `canceled`, `running`)
2. `BuildDescription(cliState, originalDescription) → string` — prepends `[timed out] `, `neutral: `, or `skipped: ` markers per spec :9238-9240, then truncates to 255 chars with `…(truncated)` suffix

Mapping table (spec :9233-9242 verbatim):

| CLI | GitLab | Description prefix |
|---|---|---|
| `success`    | `success`  | — |
| `failure`    | `failed`   | — |
| `cancelled`  | `canceled` | — |
| `timed_out`  | `failed`   | `[timed out] ` |
| `neutral`    | `success`  | `neutral: ` |
| `skipped`    | `success`  | `skipped: ` |

The mapper is a separate type (not folded into `PrCheckConclusionMapper`) because the GitHub mapper's contract is `state → conclusion` (single string), while the GitLab mapper needs both the state-name and a description-rewrite — a different shape that would muddy the GitHub side.

### Decision D — HTTPS enforcement: env-var `GITLAB__ALLOW_HTTP=true` overrides; reject otherwise

Per task YAML behavior #9 ("Open Decision 2"), the poster rejects requests where `gitlab_base_url` is `http://...` unless the environment variable `GITLAB__ALLOW_HTTP=true` is set. This check happens at the poster's `PostAsync` entry, *before* any HTTP attempt. Rejection produces `PrCheckPostStatus.Failed` with new error code `PrCheckErrorCode.GitLabHttpInsecure` and a clear message naming the violating base URL. The flag is read once at DI registration (singleton `GitLabPosterOptions`) so production deployments where the flag is unset get the secure default. Spec :9141 ("URLs in `target_url` validated as HTTPS") confirms HTTPS-mandatory direction.

### Decision E — Per-installation rate-limit tracker is a new `IGitLabRateLimitTracker` keyed on `Guid installationId`

The existing `IRateLimitTracker` is keyed on `long installationId` (GitHub's installation ids are integers). GitLab installations key on `Guid` (the `gitlab_installations.Id` surrogate PK). A new `IGitLabRateLimitTracker` (same shape, `Guid` key) lives alongside; concrete `GitLabRateLimitTracker` implements the identical token-bucket pattern as `RateLimitTracker`. Sharing a generic interface across both providers is over-engineering for two implementations — the duplication is small and isolates GitHub-side breakage.

### Decision F — PAT-revoked failure mode: log + audit + queue notification, but no Slack-rule plumbing in this slice

Spec :9277 says "queues a `gitlab_token_revoked` notification (Slack channel via existing notification dispatcher)". The existing `NotificationsDispatcher` is tied to `IResultIngestedNotifier` and dispatches on `RunFailed` / `Flaky` only. Wiring `gitlab_token_revoked` into the rule-based dispatcher requires adding a third `NotificationEvent` enum value, a new payload builder, and rule-matching changes — that's a slice of its own. For M16-014:
- Set `gitlab_installations.access_token_revoked_at = clock.GetUtcNow()`
- Set `pr_checks.status = 'gitlab_token_revoked'`
- Log a security incident at Warning level with EventId 9277 + structured fields (`org_id`, `installation_id`, `project_id`, `gitlab_base_url`) so operators can configure their existing log-based alerting
- Write an audit log entry (`org_audit_log`) with `event_type='gitlab.pat.revoked'`

The behavior text ("queued a token-revoked notification") is satisfied by the audit log + structured warning; explicit Slack/email rule routing is deferred to a follow-up (M16-016 dashboard work) since dashboards display the revoked state from the audit log + the `access_token_revoked_at` field. The plan documents this scope reduction explicitly and the task YAML's behavior #6 is interpreted accordingly.

### Decision G — `gitlab_status_id` source: GitLab's status creation response `id` field

GitLab's `POST /api/v4/projects/{id}/statuses/{sha}` returns a JSON body with a numeric `id` field (the commit-status row ID). We persist this in `pr_checks.gitlab_status_id`. Idempotency on GitLab side is `(commit_sha, name, context)` keyed — re-POSTs return the same row with an updated state, so storing the id is informational, not load-bearing for retry safety (spec :9244).

### Decision H — `FakeHttpClientFactory.BaseAddress` is parameterised, not hard-coded

The existing `FakeHttpClientFactory` hard-codes `BaseAddress = new Uri("https://api.github.com")` which would break GitLab tests. The constructor gains an optional `string? baseAddress = null` parameter; if null, falls back to "https://api.github.com" so existing call sites are unaffected. New GitLab tests pass `"https://gitlab.com"` (or a stub URL).

### Decision I — `GitLabCheckPoster` builds absolute URLs from `gitlab_installations.GitLabBaseUrl`, not a configured BaseAddress

GitHub's poster uses a configured `IHttpClientFactory.CreateClient("github-checks")` with `BaseAddress` already set. GitLab installations are per-org and each can point at a different self-managed instance — there is no single base URL. The poster therefore constructs the full URL on each request: `{installation.GitLabBaseUrl}/api/v4/projects/{installation.ProjectId}/statuses/{row.HeadSha}`. The HttpClient is from `httpFactory.CreateClient("gitlab-statuses")` with no BaseAddress, only timeout + User-Agent default headers.

### Decision J — Provider field is optional on the wire; absent defaults to `github`

`PrCheckUploadRequest.Provider` is a nullable string. On the endpoint, missing/empty → "github"; explicit value validated against the CHECK list. This preserves wire compatibility with existing CLI clients (M14-018 → M16-014 upgrade is non-breaking).

```csharp
namespace ApiTool.Backend.PrChecks;

/// <summary>
/// Maps the CLI's <c>state</c> field to GitLab's commit-status state per spec :9233-9242.
/// The mapping is lossy: GitLab has 4 states, the CLI has 6; <c>timed_out</c> collapses
/// to <c>failed</c> with a description marker; <c>neutral</c>/<c>skipped</c> collapse to
/// <c>success</c> with description markers.
/// </summary>
public static class GitLabStateMapper
{
    /// <summary>Maximum length of GitLab's description field (hard-capped server-side).</summary>
    public const int MaxDescriptionLength = 255;

    private const string TruncationMarker = "…(truncated)";

    /// <summary>Attempts to map CLI state to GitLab state. Returns true on success.</summary>
    public static bool TryMap(string? cliState, out string gitlabState)
    {
        gitlabState = string.Empty;
        if (string.IsNullOrWhiteSpace(cliState)) return false;
        var n = cliState.Trim().ToLowerInvariant();
        gitlabState = n switch
        {
            "success"   => "success",
            "failure"   => "failed",
            "cancelled" => "canceled",
            "timed_out" => "failed",
            "neutral"   => "success",
            "skipped"   => "success",
            _ => string.Empty,
        };
        return gitlabState.Length > 0;
    }

    /// <summary>
    /// Builds the GitLab description: prepends a marker for lossy states, then truncates
    /// to <see cref="MaxDescriptionLength"/> with a <c>…(truncated)</c> suffix when needed.
    /// </summary>
    public static string BuildDescription(string? cliState, string? originalDescription)
    {
        var n = (cliState ?? string.Empty).Trim().ToLowerInvariant();
        var prefix = n switch
        {
            "timed_out" => "[timed out] ",
            "neutral"   => "neutral: ",
            "skipped"   => "skipped: ",
            _ => string.Empty,
        };
        var combined = prefix + (originalDescription ?? string.Empty);
        if (combined.Length <= MaxDescriptionLength) return combined;
        return string.Concat(
            combined.AsSpan(0, MaxDescriptionLength - TruncationMarker.Length),
            TruncationMarker);
    }
}
```

```csharp
public sealed class GitLabCheckPoster(
    AppDbContext db,
    IGitLabKeyProvider keyProvider,
    IGitLabRateLimitTracker rateLimit,
    IHttpClientFactory httpFactory,
    IOptions<GitLabOptions> options,
    IAuditWriter audit,
    TimeProvider clock,
    ILogger<GitLabCheckPoster> log) : IGitLabCheckPoster
{
    private static readonly JsonSerializerOptions JsonOpts = new(JsonSerializerDefaults.Web);

    public async Task<CheckRunPostResult> PostAsync(Guid prCheckId, CancellationToken ct)
    {
        // 1. Load PrCheck row (must be provider='gitlab' with non-null GitLabInstallationId)
        // 2. Load gitlab_installations row by row.GitLabInstallationId
        //    - Not found → Failed/GitLabNoInstallation
        //    - access_token_revoked_at non-null → Failed/GitLabTokenRevoked; row.Status='gitlab_token_revoked'
        //    - deleted_at non-null → Failed/GitLabNoInstallation
        // 3. URL validation: if installation.GitLabBaseUrl starts with "http://" and !options.Poster.AllowHttp → Failed/GitLabHttpInsecure
        // 4. Rate-limit check via IGitLabRateLimitTracker.IsBlocked(installation.Id)
        //    - blocked → Queued/GitLabRateLimited; row.Status='queued'
        // 5. Map state via GitLabStateMapper.TryMap; description via BuildDescription
        // 6. Decrypt PAT via keyProvider.DecryptAsync(installation.AccessTokenCiphertext, installation.AccessTokenKid)
        //    - decrypt failure → transient-failure path
        // 7. Set row.PostingStartedAt = clock.Now; row.AttemptCount++; row.Status='posting'; SaveChanges
        // 8. Build URL: {installation.GitLabBaseUrl.TrimEnd('/')}/api/v4/projects/{installation.ProjectId}/statuses/{row.HeadSha}
        // 9. Build payload object:
        //      { state, name="Curlew", description, target_url (HTTPS-validated), context="ci/curlew" }
        //    - target_url comes from row.DetailsUrl when set; if non-HTTPS it is dropped (with a warning log) per spec :9141
        //    - description trimmed to 255 chars via GitLabStateMapper.BuildDescription
        // 10. Send POST with Private-Token header = decrypted PAT; Content-Type application/json
        // 11. Observe rate-limit headers (RateLimit-Remaining, RateLimit-Reset, Retry-After)
        // 12. Handle response:
        //     - 2xx → parse "id" → row.GitLabStatusId; row.PostedAt = now; row.Status='posted'; row.Conclusion = gitlabState
        //     - 401 → set installation.AccessTokenRevokedAt; row.Status='gitlab_token_revoked'; audit + warn; Failed/GitLabTokenRevoked
        //     - 429 or RateLimit-Remaining=0 → Update tracker; row.Status='queued'; Queued/GitLabRateLimited
        //     - 4xx (404, 422) → row.Status='failed'; Failed/GitLabPermanentFailure
        //     - 5xx/network → transient retry path (row.Status='queued' until 5 attempts, then 'failed')
        // 13. Persist row; return CheckRunPostResult
    }
}
```

internal static async Task<IResult> HandleAsync(
    HttpRequest request, HttpContext http, CurrentUserAccessor users, AppDbContext db,
    ICheckRunPoster githubPoster,
    IGitLabCheckPoster gitlabPoster,
    TimeProvider clock, ILoggerFactory loggerFactory, CancellationToken ct)
{
    // … existing steps 1–5 unchanged …

    // Resolve provider (Decision J)
    var provider = string.IsNullOrWhiteSpace(body.Provider)
        ? "github"
        : body.Provider.Trim().ToLowerInvariant();
    if (provider is not ("github" or "gitlab"))
        return HttpResults.Json(
            new ErrorResponse("invalid_request", "provider must be 'github' or 'gitlab'."),
            statusCode: StatusCodes.Status400BadRequest);

    // Step 6: Insert PrCheck row (now includes Provider + optional GitLabInstallationId)
    Guid? glInstallationId = null;
    if (provider == "gitlab")
    {
        // Resolve the org's gitlab_installations row for this repo (project_path match).
        // Decision: if more than one, pick the most recent (matching the GitHub side's "first membership" heuristic).
        var gl = await db.GitLabInstallations
            .Where(i => i.OrgId == orgId && i.DeletedAt == null)
            .OrderByDescending(i => i.CreatedAt)
            .FirstOrDefaultAsync(ct);
        if (gl is null)
            return PrChecksProblem.GitLabNoInstallation(http);
        glInstallationId = gl.Id;
    }

    var check = new PrCheck { /* … existing fields …,
        Provider = provider,
        GitLabInstallationId = glInstallationId,
    };
    db.PrChecks.Add(check);
    await db.SaveChangesAsync(ct);

    // Step 7: Dispatch to provider-specific poster
    CheckRunPostResult result;
    try
    {
        result = provider == "gitlab"
            ? await gitlabPoster.PostAsync(check.Id, ct)
            : await githubPoster.PostAsync(check.Id, ct);
    }
    catch (Exception)
    {
        result = new CheckRunPostResult(PrCheckPostStatus.Queued, null,
            "Unexpected error posting check.",
            provider == "gitlab" ? PrCheckErrorCode.GitLabUnreachable : PrCheckErrorCode.GithubUnavailable);
    }

    // Step 8: Extend the switch with new GitLab error codes
    return result.Status switch
    {
        // … existing GitHub mappings unchanged …
        PrCheckPostStatus.Queued when result.Code == PrCheckErrorCode.GitLabRateLimited
            => PrChecksProblem.GitLabRateLimited(http),
        PrCheckPostStatus.Failed when result.Code == PrCheckErrorCode.GitLabTokenRevoked
            => PrChecksProblem.GitLabTokenRevoked(http),
        PrCheckPostStatus.Failed when result.Code == PrCheckErrorCode.GitLabNoInstallation
            => PrChecksProblem.GitLabNoInstallation(http),
        PrCheckPostStatus.Failed when result.Code == PrCheckErrorCode.GitLabHttpInsecure
            => /* derive base URL from row or message */ PrChecksProblem.GitLabHttpInsecure(http, /* baseUrl */),
        PrCheckPostStatus.Queued when result.Code == PrCheckErrorCode.GitLabUnreachable
            => PrChecksProblem.GitLabUnreachable(http),
        // … fall-through to existing mappings …
    };
}

## Risks and Edge Cases

- **Risk:** SQLite does not support `ALTER TABLE … DROP CONSTRAINT` in the `Down()` migration → migration removal fails in dev environments. **Mitigation:** Gate the `Sql("ALTER TABLE … DROP CONSTRAINT …")` line behind an `ActiveProvider == "Npgsql.EntityFrameworkCore.PostgreSQL"` check (pattern already used elsewhere). For SQLite, the constraint is enforced via EF model only; dropping the column removes the constraint implicitly.
- **Risk:** `FakeHttpClientFactory` hard-codes `BaseAddress="https://api.github.com"` — would mis-route the GitLab poster's absolute URL. **Mitigation:** Add optional `baseAddress` constructor parameter; GitLab tests pass `null` (since GitLab poster sets full URL on the request, BaseAddress is irrelevant).
- **Risk:** Decryption failure (KEK rotation mid-flight, corrupt ciphertext) leaks key material in the log. **Mitigation:** `GitLabPatDecryptException` already carries only the provider-kind in its message; the poster logs the exception but never serialises `installation.AccessTokenCiphertext` itself.
- **Risk:** `target_url` is user-controlled (CLI sends `details_url`) and could embed a `javascript:` URI → XSS on a customer's GitLab UI. **Mitigation:** Validate `details_url` is HTTPS-scheme before including; drop with a warning otherwise (per spec :9141).
- **Risk:** PAT-revoked race — two concurrent posts both see `access_token_revoked_at IS NULL`, both call GitLab, both get 401, both set the field. **Mitigation:** Idempotent write — `access_token_revoked_at = COALESCE(access_token_revoked_at, clock.Now)` semantics enforced by entity check (don't overwrite if already set).
- **Risk:** Description-injection (line breaks / control chars in CLI summary) leaks unexpected GitLab UI shapes. **Mitigation:** `BuildDescription` callers should strip `\r\n` to spaces before passing — added to the implementation.
- **Edge case:** Empty `head_sha` → already rejected at endpoint validation (40-char hex check). No change needed.
- **Edge case:** `gitlab_base_url` with trailing slash → poster does `TrimEnd('/')` before constructing the URL.
- **Edge case:** `gitlab_base_url = "https://gitlab.example.com/path"` (sub-path-hosted self-managed) → URL construction must concatenate; `TrimEnd('/')` is sufficient.
- **Edge case:** Multiple `gitlab_installations` rows for the same org (different self-managed instances) → endpoint picks the most-recent. Acceptable for M16-014; multi-installation disambiguation tracked alongside multi-org disambiguation for a follow-up slice.
