# Implementation Plan: M15-002

## Overview

Insert an Enterprise tier-gate precondition at the top of every SSO service
method (`SsoService` SAML + `OidcService` OIDC) that loads the org's active
`Subscription` row, treats no-row as `SubscriptionTier.Free`, and signals
`TierIneligible` when `Tier != SubscriptionTier.Enterprise`. Translate the
signal at the endpoint layer: HTTP 402 + structured `ErrorResponse` for the
authenticated `/api/v1/organizations/{id}/sso{,/saml,/oidc}` group; HTTP 404 +
`Cache-Control: no-store` + empty body for the public
`/api/v1/sso/{saml,oidc}/{orgId}/*` group. Update `scripts/seed-enterprise.sh`
to provision an Enterprise subscription instead of Team for the SSO-using
fixture org so dev/E2E flows continue to function.

### How tier reaches the gate

The gate is in-process EF lookup against `db.Subscriptions` keyed by `OrgId`.
There is no client-supplied tier signal. This matches the "load the org's
active Subscription row" instruction in the task scope and avoids any
license-claim plumbing on the backend — the tier source is the local
subscriptions table (the same table updated by Stripe webhooks per M14-012).

### Existing tests that will break and why

All unit tests in `SsoServiceTests.cs` and `OidcServiceTests.cs` build a
fixture org **without** a subscription row, so under the new gate the
no-subscription path resolves to Free → every method returns
`SsoError.TierIneligible` before the existing assertions ever run.

Endpoint integration tests in `SamlEndpointsTests.cs` and `OidcEndpointsTests.cs`
create their fixture orgs through `POST /api/v1/organizations` (no subscription
row created) and then call the SSO endpoints — these would all flip to 402/404
under the gate.

The fix is the same in both layers: seed an Enterprise `Subscription` row for
the test org before calling SSO methods. Tests that *target* the gate (the
new tier-matrix tests) seed a non-Enterprise row instead.

### Endpoint translation paths

- Authenticated config endpoints: `GET /api/v1/organizations/{id}/sso`,
  `PUT /api/v1/organizations/{id}/sso/saml`, `PUT /api/v1/organizations/{id}/sso/oidc`.
  Translation: `HttpResults.Json(new ErrorResponse(SsoErrorCodes.SsoTierIneligible, "..."), 402)`.
- Public flow endpoints: `GET /api/v1/sso/saml/{orgId}/login`,
  `POST /api/v1/sso/saml/{orgId}/acs`, `GET /api/v1/sso/oidc/{orgId}/login`,
  `GET /api/v1/sso/oidc/{orgId}/callback`. Translation: 404 + empty body +
  `Cache-Control: no-store` header. Implemented as a small `IResult`
  (`SsoNotFoundResult`) co-located with the endpoint file (mirrors the
  existing `SamlRedirectResult` / `OidcLoginResult` pattern).

### Behaviour decisions taken upfront

1. **Gate placement.** Inside each service method (top, before any DB writes
   or audit appends). Rationale: keeps the gate symmetric with how
   `SsoError.OrgNotFound` and `SsoError.PermissionDenied` are emitted today —
   the endpoint never sees raw subscription rows, only `SsoError` codes — and
   minimises diff surface in the endpoint files (each gets one `=>`-arm
   added).
2. **No-subscription = Free, gated.** Match the task scope's "treats no-row as
   SubscriptionTier.Free" verbatim.
3. **Subscription row matching.** Match by `OrgId` only; use
   `OrderByDescending(s => s.UpdatedAt).FirstOrDefaultAsync(ct)`. Reasoning:
   (a) `Subscription.OrgId` has no unique index in the schema (a future
   re-subscribe could insert a new row) but in practice today
   `SubscriptionsService.CreateCheckoutAsync` rejects duplicate rows with
   `AlreadySubscribed`, so at most one row exists per org. The
   `OrderByDescending` is a defensive pick of the most-recent row that costs
   nothing and matches what `OrganizationService.GetMembershipsAsync`-style
   reads tolerate.
4. **Subscription status filter.** **Read tier from the row regardless of
   status** (`Active`, `PastDue`, `Canceled`, `Expired`, `Incomplete`,
   `Quarantined`). Justification: the task YAML's behaviour list says
   "active Subscription where Tier=Enterprise". On a strict reading that
   would bar past-due Enterprise customers from using SSO. That is a
   revenue-hostile read and not what the existing seat-limit lookup at
   `OrganizationService.cs:147` does (it takes the row at face value). For
   M15-002 we follow the seat-limit precedent: any row → its tier; no row →
   Free. If billing wants "lapsed Enterprise SSO is gated" later, that is a
   separate slice and we have a sentinel (`Subscription.Status`) to filter
   on. Documented in the plan; will be re-confirmed in `/improve` if review
   pushes back.
5. **Error idiom.** Extend `SsoError` with `TierIneligible` (matches the
   existing tuple-form return that every SSO method already uses). No typed
   exception. The task scope's "prefer extending SsoError" sentence drives
   this.
6. **No new audit row on TierIneligible.** Match the existing
   `PermissionDenied` and `OrgNotFound` pattern — they also short-circuit
   without an audit append. Justification: the gate is a precondition
   failure, not an attempted login event. Adding a row would be a separate
   "audit gating refusals" feature.
7. **Public-flow body / header contract.** Return HTTP 404 with **empty
   body** and `Cache-Control: no-store`. Rationale: mirror what an SSO-naive
   org would look like to an external caller; do not leak that an org *exists
   but is on a non-Enterprise tier*. The `Cache-Control: no-store` defeats
   intermediary caches that might otherwise pin the 404 across a tier
   upgrade. Implemented via a small custom `IResult` so the header lands
   reliably alongside the body-less response.
8. **Dev seed update.** `scripts/seed-enterprise.sh` line 73 currently passes
   `"tier": "team"`. Change to `"tier": "enterprise"`. The seed name
   ("seed-enterprise") and its M5-020 callsite both already imply Enterprise
   — keeping it on `team` was a leftover from before SSO needed Enterprise.

### Function-signature changes

None. The four `SsoService` methods and three `OidcService` methods keep
their signatures; the new error variant flows through the existing tuple
return.

#### New Code

`src/ApiTool.Backend/Sso/SsoService.cs` — new private helper:

```csharp
    /// <summary>
    /// Loads the org's active subscription and returns <see cref="SsoError.TierIneligible"/>
    /// when the tier is not <see cref="SubscriptionTier.Enterprise"/>. A missing row is
    /// treated as <see cref="SubscriptionTier.Free"/> (no SSO).
    /// </summary>
    private async Task<SsoError> EnsureEnterpriseTierAsync(Guid orgId, CancellationToken ct)
    {
        var tier = await db.Subscriptions
            .Where(s => s.OrgId == orgId)
            .OrderByDescending(s => s.UpdatedAt)
            .Select(s => (SubscriptionTier?)s.Tier)
            .FirstOrDefaultAsync(ct) ?? SubscriptionTier.Free;
        return tier == SubscriptionTier.Enterprise ? SsoError.None : SsoError.TierIneligible;
    }
```

/// <summary>
/// Custom <see cref="IResult"/> that returns HTTP 404 with no body and
/// <c>Cache-Control: no-store</c>. Used by the public SAML/OIDC flow endpoints
/// to mask non-Enterprise orgs the same way an unconfigured org appears (M15-002).

{
    public static readonly SsoNotFoundResult Instance = new();
    public Task ExecuteAsync(HttpContext httpContext)
    {
        httpContext.Response.StatusCode = StatusCodes.Status404NotFound;
        httpContext.Response.Headers.CacheControl = "no-store";
        httpContext.Response.ContentLength = 0;
        return Task.CompletedTask;
    }
}

## Risks and Edge Cases

- **Risk: Stale, lapsed Enterprise subscription.** If an Enterprise sub
  later moves to `Status=Canceled`, the gate (per Decision #4) still admits
  it. → **Mitigation:** explicitly documented in Decision #4 above as a
  follow-on slice, not in M15-002 scope. Test `_short_circuits_before_db_writes`
  uses `Status=Active` only. If review pushes back, the helper is the single
  place to add a status filter — `.Where(s => s.OrgId == orgId && s.Status
  == SubscriptionStatus.Active)`.
- **Risk: Cache leak via 404.** If a CDN or proxy caches the public-flow
  404, an org upgrading from Team to Enterprise might still see 404 for the
  cache TTL. → **Mitigation:** `Cache-Control: no-store` on the `IResult`,
  enforced by a test that asserts the header.
- **Edge case: Gate fires before `OrgNotFound` for unknown org.** When
  `orgId` doesn't match any organisation, `EnsureEnterpriseTierAsync` reads
  zero subscription rows and returns `TierIneligible` (because no row →
  Free). This means `GET /api/v1/organizations/<unknown-org>/sso` now returns
  402 instead of 404. → **Handling:** This is **wrong** — an unknown org
  must not leak its existence as a tier-locked org. We add an org-existence
  check inside the helper: if no org row exists, return `OrgNotFound` rather
  than `TierIneligible`. Updated helper:

  ```csharp
  private async Task<SsoError> EnsureEnterpriseTierAsync(Guid orgId, CancellationToken ct)
  {
      var orgExists = await db.Organizations.AnyAsync(o => o.Id == orgId, ct);
      if (!orgExists) return SsoError.OrgNotFound;
      var tier = await db.Subscriptions
          .Where(s => s.OrgId == orgId)
          .OrderByDescending(s => s.UpdatedAt)
          .Select(s => (SubscriptionTier?)s.Tier)
          .FirstOrDefaultAsync(ct) ?? SubscriptionTier.Free;
      return tier == SubscriptionTier.Enterprise ? SsoError.None : SsoError.TierIneligible;
  }
  ```

  A test asserts that an unknown-org `GET /api/v1/organizations/{id}/sso`
  still returns 404 with `code = "organization_not_found"` (existing
  contract preserved) rather than 402.
- **Edge case: Membership check before tier check.** Today,
  `UpsertSamlConfigAsync` runs the RBAC owner check before any other
  validation. With the new gate placed at the top, a non-owner on a non-
  Enterprise org gets 402 rather than 403. → **Decision:** that's the right
  ordering for a tier matrix — the tier is a property of the org, not the
  caller; revealing 403 to a non-owner of a non-Enterprise org would leak
  org-status information. The existing
  `Put_saml_config_as_non_owner_returns_403_permission_denied` test runs
  against an org seeded at Enterprise via the patched
  `CreateOrgAndReturnGuidAsync`, so that 403 path is preserved for the
  Enterprise case.
- **Edge case: `org_id` shape variance for OIDC public flow.** `SamlEndpoints`
  uses `Guid.TryParse(orgId, ...)` for public routes. `OidcEndpoints` does
  the same. Both already short-circuit on parse failure with their own 404
  before the service is called. Our gate code does not see those — gate runs
  inside the service after `Guid.TryParse` upstream succeeds. No change
  needed.
- **Edge case: Two non-Enterprise rows for the same org (theoretical).**
  `OrderByDescending(s => s.UpdatedAt)` picks the newest. If anyone in the
  future relaxes the dedupe in `SubscriptionsService.CreateCheckoutAsync`,
  this still does the right thing. No fail-closed risk because the helper
  defaults `null → Free`, never accidentally Enterprise.
- **Edge case: EF Core InMemory provider does not enforce indexes.** Test
  fixture uses InMemory; production uses PostgreSQL with the migration-
  created indexes. `OrderByDescending(s => s.UpdatedAt)` is index-agnostic —
  works on both. Not a risk.
- **Risk: Forgetting to seed Enterprise in any future SSO test.** A later
  contributor adding a new endpoint test could forget to call
  `SeedSubscriptionAsync` and end up with a confusing 402. → **Mitigation:**
  the patched fixture helpers (`CreateOrgAndReturnGuidAsync` for SAML,
  `CreateOrgAsync` for OIDC) now seed Enterprise by default. Anyone going
  off-script and rolling their own org-creation helper would have to opt
  out — the default is safe.
