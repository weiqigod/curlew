# Implementation Plan: M11-001

## Overview

Remove the `junit_xml` Professional-tier feature gate so free-tier users can
emit JUnit XML by default. JUnit is CI table-stakes (IMPROVEMENT.md §2.4
bullet 3) and gating it is atypical. Other tier gates
(`parallel_execution`, `data_driven`, `html_report`, `custom_backoff`, etc.)
are intentional product decisions and remain untouched.

## Architectural Decisions (resolved)

1. **Keep `writeJUnitError(...)` in main.go.** It is still used by the
   non-gate JUnit error paths (parse error, env load failure, network
   failure, variable cliff, etc.) and by the discovery-glob
   `writeGateForFormat` helper for gates *other* than `junit_xml` (e.g. a
   `--parallel` gate denial routed through `--format junit`). We are
   removing only the `junit_xml`-keyed `auth.CheckFeature` calls — the
   formatter helper itself is unchanged.

2. **Migrate the `feature-gate-denied` agent-harness fixture from
   `--format junit` to `--parallel 2`.** That fixture's purpose is to
   exercise the `FEATURE_GATE_DENIED` event-classification path — it must
   still fire a gate on free tier after this change. `parallel_execution`
   is Professional-gated, fires on `--parallel N` for any N≥2 on free
   tier, requires no extra collection content, and is distinct from
   features potentially ungated later. `--format junit` will no longer
   produce any gate event.

3. **Migrate `TestRunCmd_Events_FormatGateError_EmitsRunError` (run_test.go
   ≈ line 1273) to use `--parallel 2` instead of `--format junit`.** Same
   rationale: the test asserts the gate-error event flow, not the JUnit
   format. Renaming to `TestRunCmd_Events_GateError_EmitsRunError` keeps
   the intent clear and removes the format-specific framing now that the
   gate no longer involves JUnit.

4. **Update the `*GateError` literal in `internal/auth/gate_test.go::
   TestGateError_ClassifiedAsAuth` from `Feature: "junit_xml"` to
   `Feature: "parallel_execution"`.** This test only verifies type-level
   classification (the registry is not consulted), but using a still-
   registered feature keeps the literal grep-stable to the registry
   contents.

5. **Add `TestRun_JUnitFormat_FreeTier` (the explicit observable test
   named in the task YAML).** Drives `apitest run` with
   `APITEST_TIER=free` (default — but assert it explicitly) and
   `--format junit`, asserts exit 0 plus well-formed JUnit XML on stdout.
   Place it in `cmd/apitest/main_test.go` next to the existing JUnit
   tests.

6. **Drop the JUnit-tier-elevation in
   `TestRunCmd_format_junit_*` tests.** Most JUnit tests in
   `main_test.go` currently swap `currentTier = func() auth.Tier { return
   auth.TierProfessional }`. Without the gate, this is dead code; remove
   the swaps.

7. **Delete the now-impossible gate tests outright:**
   - `TestRunCmd_format_junit_recognized` (asserted "not exit 1" only because
     gating exit 6 was the expected mode; replaced semantically by the
     new free-tier success test).
   - `TestRunCmd_format_junit_feature_gate_free_tier`
   - `TestRunCmd_format_junit_feature_gate_before_parse`
   - `TestRunCmd_format_junit_feature_gate_professional_tier`
   - `TestCheckFeature_junitXML` in `internal/auth/gate_test.go`.

8. **Remove the explanatory tier-elevation comment in the redaction test
   `junit_format` subtest** at `main_test.go::~7633` and drop the
   `currentTier` swap. The assertion (no secret leak) is still valid and
   no tier elevation is needed.

9. **Documentation copy.** Strip Professional-tier framing from
   `docs/SPECIFICATION.md` (line 5555 list entry, line 5571 example,
   line 5782 survey question, line 9184 Phase-3 list, line 398 persona
   table) and `docs/MANUAL.md` (line 1123 format table, line 2812 tier
   matrix, line 2813 HTML workaround mention, line 2878). The `apitest
   --help` blurb in main.go (lines 3689–3690) does not mention a tier;
   only the tier matrix in MANUAL needs touching for tier text.

10. **Skill golden file untouched.** `cmd/apitest/testdata/skill_claude_golden.md`
    line 105 mentions "json/tap/junit emit a structured gate envelope" in
    a generic capacity (any future gate denial routed through `--format
    junit` still uses that envelope) and is not a claim about JUnit being
    gated. No change needed.

11. **`stream_discipline_matrix_test.go` keeps its `APITEST_TIER=
    professional` env on the `run_junit_happy` cell.** That env var is
    silent on free tier (test still passes) so updating is hygienic but
    not required. Drop the line and the in-line comment for cleanliness.

12. **Sentinel error or compatibility shim?** None needed. `auth.
    CheckFeature(reg, "junit_xml", tier)` returns `nil` once the registry
    entry is gone (unknown features return nil — see
    `TestCheckFeature` line 24: `{"unknown feature returns nil"...}`). We
    delete the call sites instead of relying on this; no transitional
    period required.

```go
func TestRun_JUnitFormat_FreeTier(t *testing.T) {
    // M11-001: --format junit must succeed on the default (free) tier.
    // Explicitly pin APITEST_TIER=free to guard against environment
    // contamination where a developer has APITEST_TIER set to a higher
    // tier in their shell.
    t.Setenv("APITEST_TIER", "free")

    srv := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, _ *http.Request) {
        w.WriteHeader(200)
    }))
    defer srv.Close()

    tmpDir := t.TempDir()
    f := filepath.Join(tmpDir, "test.yaml")
    content := fmt.Sprintf(
        "name: Free Tier JUnit\nrequests:\n  - name: Ping\n    request:\n      method: GET\n      url: %q\n",
        srv.URL,
    )
    if err := os.WriteFile(f, []byte(content), 0o644); err != nil {
        t.Fatal(err)
    }

    stdout, _, exitCode := captureRunCmd(t, f, "--format", "junit")
    if exitCode != 0 {
        t.Fatalf("exit = %d, want 0 (free tier must not gate junit)", exitCode)
    }

    // Well-formed JUnit XML (matches the existing TestRunCmd_format_junit_passed
    // assertion shape).
    if !strings.Contains(stdout, `<?xml version="1.0"`) {
        t.Error("expected XML declaration on stdout")
    }
    var suites output.JUnitTestSuites
    if err := xml.Unmarshal([]byte(stdout), &suites); err != nil {
        t.Fatalf("stdout is not valid XML: %v\nstdout=%s", err, stdout)
    }
    if len(suites.TestSuites) != 1 || len(suites.TestSuites[0].TestCases) != 1 {
        t.Fatalf("want 1 suite × 1 testcase; got %d suites", len(suites.TestSuites))
    }
}
```

## Risks and Edge Cases

- **Risk:** A YAML-declared `output: { format: junit }` block on free
  tier currently exits 6. After ungating, it succeeds. If any
  integration test or smoke fixture asserts the gating exit code
  through the YAML path, that test breaks silently.
  → **Mitigation:** Audit `internal/scaffold/scaffold_test.go` and
  `cmd/apitest/output_precedence_test.go` for explicit free-tier YAML-
  driven JUnit gate assertions. (Initial grep shows only the scaffold
  block contents are checked, not exit codes.)
- **Risk:** The agent-harness fixture migration relies on
  `parallel_execution` continuing to be Professional-gated. If a
  future task ungates parallel, this fixture goes silent (exit 0
  instead of 6) and we lose the FEATURE_GATE_DENIED contract.
  → **Mitigation:** Document the dependency in the fixture's
  `expect.yaml` `description:` block ("Migrated from --format junit in
  M11-001"); future ungatings must re-migrate this fixture.
- **Risk:** The `--parallel 2` trigger in
  `TestRunCmd_Events_GateError_EmitsRunError` relies on the parallel-
  gate code path emitting `run.error` before `run.end`. This is
  already exercised in production by `cmd/apitest/main.go` line 1126–
  1163 (the parallel-gate block emits `run.error` and sets
  `evExitCode = 6` symmetrically).
  → **Mitigation:** None needed; the path is identical to JUnit's old
  path. The contract test in `feature-gate-denied/expect.yaml`
  asserts exactly the same fields.
- **Edge case:** `--format=junit` combined with a parse error on free
  tier still emits a JUnit `<error>` envelope (lines 783–784 of
  main.go) — the parse-error path wraps any error in `writeJUnitError`
  for stdout so CI consumers always get well-formed XML. No change.
- **Edge case:** `apitest run --format junit --report results.xml` on
  free tier now writes the report file unconditionally. Existing
  test `TestRunCmd_format_junit_report_file` covers the success path;
  the elevation removal in Step 3 makes it a free-tier test by
  default.
- **Edge case:** The schema fixture
  `internal/schema/testdata/output_collection_junit.yaml` declares
  `output.format: junit` and is validated for schema correctness only;
  the runtime gating is not exercised in `internal/schema/` tests.
  No change.
