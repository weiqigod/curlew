# Implementation Plan: M26-002

## Overview

Hold every surface that publishes the CLI's exit-code contract to the
*reachable* set derived from `cmd/curlew`'s source — equal in both directions
for the full-contract surfaces, contained for the per-command ones — and
delete the two unreachable claims that are the last structural traces of the
removed licensing system: `6: 6, // feature gate` in
`cmd/curlew/discovery_run.go`, and `| 9 | license grace period expired |` in
`docs/UI_SPECIFICATION.md`.

## Decisions Made (pipeline mode — resolved, not asked)

### D1. Extend the existing machinery. Build no second extractor and no second reader.

The DoD item *"the reachable exit-code set is derived from source, not
hand-listed"* is **already satisfied** by `internal/exitcodes` (M26-001). A
second extractor would be a second source of truth for one fact — precisely the
defect this task exists to eliminate.

Every reader the new tests need already exists in `package main`:

| Need | Existing helper | File:line |
|---|---|---|
| source-derived set + three vacuity guards | `reachableExitCodes(t)` | `cmd/curlew/skill_exit_codes_test.go:100` |
| doc-table code column + vacuity guard | `documentedExitCodes(t, …)` | `cmd/curlew/doc_exit_codes_test.go:41` |
| the three doc-table locations | `exitCodeTables` | `cmd/curlew/doc_exit_codes_test.go:28` |
| the skill's four statements | `skillExitCodeStatements()`, `skillFiles(t)`, `readStatement(t, …)` | `cmd/curlew/skill_exit_codes_test.go:37,79,120` |
| sorted-unique reduction | `sortedUniqueInts()` | `cmd/curlew/skill_exit_codes_test.go:278` |
| whole-document text | `docs.ReadDoc(doc)` | `internal/docs/tables.go:88` |
| table by section | `docs.TableUnder(doc, where, cells…)` | `internal/docs/tables.go:140` |

The new file contains **no table-parsing regex and no AST code**. It wires
existing readers to one existing reference. If review finds either, the wiring
went wrong.

One signature does change: `documentedExitCodes` gains a column-name parameter,
because `UI_SPECIFICATION.md` §2.4's column is headed `Exit`, not `Code`.
Extending the one reader beats adding a near-copy. Two existing call sites move
with it.

### D2. What `doc_exit_codes_test.go` already covers, and the precise gap

Read in full before planning. It covers:

1. `TestDocTables_theThreeExitCodeTablesAgree` — the three doc tables agree
   **with each other**.
2. `TestDocTables_everyDocumentedExitCodeIsProduced` — every documented code
   except 130 is produced by one of six real invocations of the built binary,
   and the reverse.

Three gaps:

- **The docs are never compared to the source-derived set.** Test 1 is
  self-referential: all three tables could drift together and stay green.
- **The docs are never compared to the skill.** Two islands of agreement,
  each checked internally, never across.
- **Test 2's reverse direction is bounded by its own scenario list.** It
  asserts *produced ⊆ documented*, where `produced` is whatever those six
  invocations yielded. A new code returned from a path none of the six
  exercises is invisible to it. Behaviour 4 — *"given a new exit code
  introduced anywhere in `cmd/curlew`… it fails until every surface documents
  it"* — is exactly what an empirical check cannot cover and a static walk can.
  G7's mutation is dynamically unreachable on purpose, to prove this.

**Extend, do not replace.** `doc_exit_codes_test.go` keeps both tests: the
empirical one proves a documented code is *producible*, which no static walk
can, and the pairwise one localises *which* pair disagrees, which an equality
test does not. Only the `documentedExitCodes` signature moves.

### D3. `TestExitCodes_no_unreachable_mapping` reads the map directly, and asserts containment

*Direct read.* The test is in `package main` and ranges over `exitCodeSeverity`
itself. Re-parsing `discovery_run.go` to recover keys the compiler already
handed us would be a second extractor for a free fact (D1).

*Containment, not equality.* `130 ∈ reachable` but is legitimately unranked: it
is raised by a signal inside a single `curlew perf` run (`perf.go:142`) and
never reaches the worst-wins fold across discovered collections
(`discovery_run.go:196`). Requiring equality would force a severity rank for
130 — which is *changing an exit code's meaning*, explicitly out of scope. The
map is wrong in only one direction, and that is the direction asserted. The
asymmetry is stated in three places (D3, the test's doc comment, the map's own
comment) because "someone will try to fix this" is the predictable failure.

*Rejected alternative:* root a second walk at the discovery-run path to get a
tighter reachable set, then assert equality. Rejected because
`internal/exitcodes`'s own doc comment limits its correctness claim to *"the
straight-line branches cmd/curlew's exit-code plumbing actually uses"*. A new,
unproven root that under-collects would make containment **stricter than the
truth** and fail spuriously. Under-collection is the safe failure direction
only while the assertion is containment.

#### Tests to Write FIRST (RED phase)

```go
// TestExitCodes_no_unreachable_mapping asserts every key in exitCodeSeverity
// is a code cmd/curlew can actually return.
//
// Containment, not equality, and the asymmetry is deliberate. 130 is
// reachable (a SIGINT during `curlew perf`, perf.go) but has no severity
// rank, because it is raised inside a single perf run and never takes part
// in the worst-wins fold across discovered collections. Requiring equality
// would force a rank for it, which is inventing an exit code's meaning. The
// direction that goes wrong is a code the map ranks but the binary cannot
// return, and that is the one asserted.
func TestExitCodes_no_unreachable_mapping(t *testing.T) {
	if len(exitCodeSeverity) == 0 {
		t.Fatal("exitCodeSeverity is empty — the map moved or was renamed; " +
			"this test is asserting nothing")
	}

	reachable := reachableExitCodes(t) // guarded: root, size, depth
	set := map[int]bool{}
	for _, v := range exitcodes.Set(reachable) {
		set[v] = true
	}

	for _, code := range sortedSeverityKeys() {
		if !set[code] {
			t.Errorf("exitCodeSeverity ranks exit %d, which cmd/curlew cannot return "+
				"(reachable: %v) — a severity rank for an unreachable code is not "+
				"documentation, it is a claim the feature might come back",
				code, exitcodes.Set(reachable))
		}
	}
}

// sortedSeverityKeys makes failure order deterministic; map iteration is not.
func sortedSeverityKeys() []int {
	out := make([]int, 0, len(exitCodeSeverity))
	for k := range exitCodeSeverity {
		out = append(out, k)
	}
	sort.Ints(out)
	return out
}
```

// complete exit-code contract to the set cmd/curlew can actually return, and

// wrong set before M26-001. Equality to the binary is not. Agreement between

//
// Same technique as internal/schema/parity_test.go, which holds the published
// JSON Schemas to the parser structs, for the same reason.
func TestExitCodes_all_surfaces_agree(t *testing.T) {
	reachable := reachableExitCodes(t)
	want := exitcodes.Set(reachable)
	wantSet := map[int]bool{}
	for _, v := range want {
		wantSet[v] = true
	}

	surfaces := exitCodeSurfaces()
	if countFull(surfaces) < 4 {
		t.Fatalf("only %d full-contract surfaces enumerated; the task names four "+
			"(specification, manual §4.3, manual appendix D, agent skill) — a "+
			"surface was dropped from the registry, not from the project",
			countFull(surfaces))
	}

	for _, s := range surfaces {
		t.Run(subtestName(s.name), func(t *testing.T) {
			got := s.read(t)
			if len(got) == 0 {
				t.Fatalf("%s: no exit codes read — the reader is broken, not the surface", s.name)
			}
			gotSet := map[int]bool{}
			for _, v := range got {
				gotSet[v] = true
			}

			// Direction 1, asserted for every surface: a code promised that
			// the binary cannot deliver.
			for _, v := range got {
				if !wantSet[v] {
					t.Errorf("%s documents exit %d, which cmd/curlew cannot return "+
						"(reachable: %v) — a reader told to expect it will wait forever",
						s.name, v, want)
				}
			}
			// Direction 2, full-contract surfaces only: a code the binary can
			// return that the surface never mentions. A per-command surface
			// omitting codes is correct by construction.
			if !s.full {
				return
			}
			for _, v := range want {
				if !gotSet[v] {

					t.Errorf("cmd/curlew can return exit %d (%s:%d, in %s) but %s does "+
						"not document it — a pipeline hitting it sees an unexplained number",
						v, prov.File, prov.Line, prov.Fn, s.name)

			}
		})

## Risks and Edge Cases

- **Risk: the green-on-arrival guards are vacuous and nobody notices.** →
  **Mitigation:** four layers. `reachableExitCodes` fatals on root-not-found,
  on fewer than 2 codes, and on MaxDepth 0. Each surface reader fatals on an
  empty read. The registry fatals below four full surfaces, and the Step 5
  coverage guard fatals below 5 headings. Step 8 then observes each guard
  failing for its stated reason. `internal/backlog/backlog.go` states the
  project's position: *"A checker that answers 'clear' when it has in fact read
  nothing is worse than no checker, because it converts an unread file into a
  green light."*

- **Risk: a second extractor gets built by accident.** → **Mitigation:** D1
  tabulates every reused reader with file and line. The new file must contain
  no table-parsing regex and no AST code.

- **Edge case: `docs.TableUnder` has no internal vacuity guard.** It delegates
  to `rowsAt`, which returns `nil, nil` for a header with no body rows —
  a successful call with an empty result. → **Handling:** every caller keeps
  the `len(codes) == 0 → t.Fatalf` guard `documentedExitCodes` already has
  (`doc_exit_codes_test.go:64`). Likewise `docs.Column` returns `-1`, which is
  only safe because callers check it.

- **Edge case: `docs.Table` returns the wrong table.** `MANUAL.md:1820`'s CEL
  error table shares the `| Code | Meaning |` header and *precedes* §4.3. →
  **Handling:** `TableUnder` everywhere, `Table` nowhere. Called out in D1 and
  G8 because it is a silent wrong answer, not an error.

- **Edge case: Appendix B correctly names exit 6 and exit 10.** → **Handling:**
  the Step 7 anchor `Exit codes: ` cannot match `- Exit code \`6\``, by
  construction rather than by exception (D7). The
  `<!-- doc-check: ignore-names -->` cap is 2 and both slots are used, so a
  reader needing a third marker would force an unrelated change.

- **Edge case: `130` is reachable but unranked in `exitCodeSeverity`.** →
  **Handling:** containment not equality, stated in D3, in the test's doc
  comment, and in the map's own comment.

- **Edge case: deleting `6: 6` silently changes `worseExitCode(6, x)`.** →
  **Handling:** 6 is unreachable and the single production call path cannot
  supply it (G5). The two tests that did are deleted, not re-baselined.

- **Edge case: `.claude/worktrees/sleepy-hawking-c63960/` is a second full
  checkout**, carrying its own `discovery_run.go` with the `6: 6` entry and its
  own copy of every document. → **Handling:** `exitcodes.Reachable(dir, root)`
  takes an explicit `dir` for exactly this reason (`reachable.go:63-64`) and
  `parseDir` does not recurse; the Step 5 walk is rooted at `docs.Dir`, never a
  repo-wide glob. Confirmed by measurement: the walk reports `cmd/curlew/` files
  only.

- **Risk: Step 5's exclusion list becomes a dumping ground.** →
  **Mitigation:** it is a `map[string]string` of path → reason, so an entry
  without a justification does not compile. Two entries, both argued in D4.

- **Risk: scope creep.** → **Mitigation:** D5 argues `UI_SPECIFICATION.md` in
  and D4 argues `SPECIFICATION.md` out; D8 records the §20 omission as found
  and deliberately unfixed. Steps 4, 5 and 7 are separable and each states what
  dropping it would cost.
