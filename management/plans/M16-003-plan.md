## Architectural Decisions (resolved during planning, no user prompts)

These are the decision points the spec text leaves implicit. Each is resolved in this plan and noted here so the executor doesn't waste cycles re-litigating them.

1. **Token format generation.** `prst_<43 base64url chars>` and `evtk_<43 base64url chars>` are produced by reusing the existing `Microsoft.IdentityModel.Tokens.Base64UrlEncoder.Encode(RandomNumberGenerator.GetBytes(32))` pattern from `RefreshTokenIssuer.cs:33` and prefixing with the type tag. Hashing for storage uses `SHA256.HashData(Encoding.UTF8.GetBytes(plaintext))` (mirrors `RefreshTokenIssuer.Hash` at line 60). The hash is over the **full prefixed plaintext** (`prst_xxx`), not over the 32 raw bytes — keeps the lookup-by-hash path stupid: `db.PasswordResetTokens.FirstOrDefaultAsync(t => t.TokenHash == sha256(plaintext))`.

2. **Rate limiting.** Spec :8524 says "via the existing `Internal/RateLimit` fixed-window infrastructure (13 policies already shipped)." There is no `Internal/RateLimit` folder — the actual infra is `Microsoft.AspNetCore.RateLimiting` with `AddPolicy` calls in `Program.cs:455-527`. The spec uses "Internal/RateLimit" loosely to mean "the ASP.NET RateLimiter middleware policies registered in Program.cs." We extend that registration with four new policies:
   - `auth-password-reset-request-email` (3/24h, partition by lowercased email from request body) and `auth-password-reset-request-ip` (10/24h, partition by client IP).
   - `auth-email-verification-resend-email` (5/24h, partition by lowercased email) and `auth-email-verification-resend-ip` (10/24h, partition by client IP).
   - Per-email policies need a custom middleware to read the body before the limiter runs, but the cheaper and standard approach is to handle per-email rate limiting **inside the service** (we already need to query the DB for the user) and use the ASP.NET RateLimiter only for per-IP. Per-email limit becomes a `COUNT(*) FROM password_reset_tokens WHERE user_id = ? AND issued_at > NOW() - 24h` check that fires before INSERT. This matches the existing `InvitationsService` resend-rate-limit pattern (`InvitationError.ResendLimitReached` at `InvitationsEndpoints.cs:166`) and avoids the body-buffering ratelimit middleware footgun.

3. **`[RequireVerifiedEmail]` filter shape.** ASP.NET Core 9 minimal-APIs support endpoint filters via `IEndpointFilter`. The `[RequireVerifiedEmail]` attribute approach the task title suggests is technically supported via `AddEndpointFilter<T>()` with a marker type, but the more idiomatic minimal-API pattern is a static extension method `.RequireVerifiedEmail()`. Both reach the same outcome. We ship **both**: the extension method for new endpoint registrations and an `IEndpointFilter` class so the same logic can be reused. The attribute literally on the handler method is not idiomatic for minimal APIs — the spec says "[RequireVerifiedEmail] filter" generically, not specifically as a C# attribute. We satisfy "one-line attribute" (spec :8580) with `.RequireVerifiedEmail()` extension.

4. **Refresh-family revocation on confirm.** `RefreshTokenService` does not expose a public "revoke all for user" method. The cleanest path is to add `RevokeAllFamiliesForUserAsync(Guid userId, string reason, CancellationToken)` to `RefreshTokenService` and call it from `PasswordResetService.ConfirmAsync`. Marks every non-revoked row for the user as revoked with `revoke_reason="password_reset"`. Adding a method to an existing service is lower blast radius than introducing a new collaborator.

5. **zxcvbn library choice.** The .NET package `zxcvbn-core` (or `Zxcvbn.NET`) is widely used. Adding a dependency is allowed by the spec (it explicitly names "zxcvbn score >= 3"). Decision: add **`zxcvbn-core` 7.0.x** to `ApiTool.Backend.csproj`. Wraps it behind an `IPasswordStrengthChecker` interface so unit tests can inject a fake. The frontend (M16-004) uses the JS zxcvbn so server- and client-side scoring agree.

6. **Email enqueue helper.** `IPasswordResetService.RequestAsync` enqueues a `password_reset` email; `IEmailVerificationService.ResendAsync` enqueues an `email_verification` email. Both via the existing `IEmailQueue.EnqueueAsync` (mirrors `RefreshTokenService.RevokeEntireFamilyAsync` at `RefreshTokenService.cs:170-180`). The reset-link URL is built from `AppOptions.WebAppUrl` + `/auth/password-reset/confirm?token=<plaintext>`; verification-link is `/auth/email-verification/confirm?token=<plaintext>`. Both URLs are `https://` only (validated at startup via `ValidateOnStart` for `AppOptions.WebAppUrl`).

7. **Cleanup tick interval and parameterization.** Mirrors `StripeWebhookCleanupHost`: 1h tick, configurable via `AuthTokenCleanupOptions { RetentionDays = 7 }` bound from `ApiTool:AuthTokenCleanup` config section. Single hosted service prunes both `password_reset_tokens` and `email_verification_tokens` in one tick. Skipped in `Testing` environment (matches the existing `StripeWebhookCleanupHost` registration guard at `Program.cs:186-187`).

8. **Enumeration defense — known-vs-unknown email.** Spec :8468 says "constant-time per-email check." On unknown-email path we still run an Argon2id verification against a placeholder hash (matches `AuthLoginEndpoints.cs:14` pattern) so total request time is dominated by the same fixed-cost step. We do NOT block returning 200 on the rate-limit path either — both rate-limited and unknown-email paths take the same observable code path.

9. **Token consumption transactionality.** `ConfirmAsync` performs a sequence: lookup-by-hash → check expiry/consumed/revoked → set `consumed_at = NOW()` → update `users.password_hash` → `RefreshTokenService.RevokeAllFamiliesForUserAsync`. Wrapped in `BeginTransactionAsync` only when the provider supports transactions (mirrors `RefreshTokenService.RotateHappyPathAsync` at line 116-132 — InMemory skip, otherwise transactional). Race between two simultaneous valid-token confirms is prevented by the unique-index check on `consumed_at IS NULL` enforced via the second consumer racing the row update; the loser sees `expires_at > NOW() AND consumed_at IS NULL` fail and returns 400.

10. **Verification token issuance trigger.** This task's behaviors only define the **resend** path (POST /api/v1/auth/email-verification/resend). The initial verification-token issuance at user-registration time is implicitly out of scope — the M14 user-creation flow is via JWT-claim upsert (`CurrentUserAccessor.cs:45-64`) which doesn't trigger a verification email. We add a hook in `IEmailVerificationService.ResendAsync` only; first-issue is left for a future slice. The observable test path uses `resend` to mint the first verification token for an unverified user, which matches the behaviors verbatim.

```csharp
namespace ApiTool.Backend.Auth;

using System.Security.Cryptography;
using System.Text;
using Microsoft.IdentityModel.Tokens;

/// <summary>
/// Mints opaque single-use tokens for password reset (<c>prst_</c>) and
/// email verification (<c>evtk_</c>). 32 random bytes encoded as base64url
/// give a 43-char body; the prefix gives 5 more for a 48-char total.
/// Refs docs/SPECIFICATION.md:8493 (prst_ format), :8507 (evtk_ format).
/// </summary>
public static class AuthTokenIssuer
{
    /// <summary>The password-reset token prefix (per spec :8493).</summary>
    public const string PasswordResetPrefix = "prst_";

    /// <summary>The email-verification token prefix (per spec :8507).</summary>
    public const string EmailVerificationPrefix = "evtk_";

    /// <summary>
    /// Mints a fresh token with the given prefix. Returns the raw plaintext
    /// (sent in the email body) and its SHA-256 hash (stored in the DB).
    /// </summary>
    public static (string Plaintext, byte[] Hash) Mint(string prefix)
    {
        ArgumentException.ThrowIfNullOrEmpty(prefix);
        var rawBytes  = RandomNumberGenerator.GetBytes(32);
        var plaintext = prefix + Base64UrlEncoder.Encode(rawBytes);
        var hash      = Hash(plaintext);
        return (plaintext, hash);
    }

    /// <summary>SHA-256 of the UTF-8 bytes of the full prefixed plaintext.</summary>
    public static byte[] Hash(string plaintext)
        => SHA256.HashData(Encoding.UTF8.GetBytes(plaintext));
}
```

```csharp
/// <summary>
/// Revokes every non-revoked refresh-token row for the user, marking each with
/// the supplied <paramref name="reason"/>. Used after password reset (RFC 9700 §4.14)
/// and on explicit user-initiated session revoke. Returns the number of rows revoked.
/// </summary>
public async Task<int> RevokeAllFamiliesForUserAsync(
    Guid userId,
    string reason,
    CancellationToken ct)
{
    ArgumentException.ThrowIfNullOrEmpty(reason);
    var now = clock.GetUtcNow().UtcDateTime;

    var rows = await db.RefreshTokens
        .Where(r => r.UserId == userId && r.RevokedAt == null)
        .ToListAsync(ct);

    foreach (var r in rows)
    {
        r.RevokedAt    = now;
        r.RevokeReason = reason;
    }

    await db.SaveChangesAsync(ct);

    if (rows.Count > 0)
        logger.LogInformation(
            "refresh-token: revoked {Count} families for userId={UserId} reason={Reason}",
            rows.Count, userId, reason);

    return rows.Count;
}
```

```csharp
namespace ApiTool.Backend.Auth;

/// <summary>
/// Result of password-reset flow operations. <c>None</c> = success.
/// </summary>
public enum PasswordResetError
{
    /// <summary>Operation succeeded.</summary>
    None,
    /// <summary>Token is unknown, expired, consumed, or revoked.</summary>
    TokenInvalid,
    /// <summary>The candidate password scored below the minimum strength.</summary>
    PasswordTooWeak,
}

/// <summary>
/// Password-reset service. Exposes idempotent <see cref="RequestAsync"/>
/// (always succeeds; rate-limit and unknown-email paths are silent) and
/// transactional <see cref="ConfirmAsync"/> that revokes refresh families.
/// </summary>
public interface IPasswordResetService
{
    /// <summary>
    /// Always returns success. Never tells the caller whether the email exists.
    /// Internally: looks up the user, checks per-email rate limit, mints+stores a
    /// hashed token, and enqueues the password_reset email.
    /// </summary>
    Task RequestAsync(string email, string? requesterIp, string? requesterUa, CancellationToken ct);

    /// <summary>
    /// Verifies the token, scores the new password, updates the user's password_hash,
    /// consumes the token, and revokes all refresh-token families for the user.
    /// Returns <see cref="PasswordResetError.None"/> on success; the score is set to the
    /// out parameter when the result is <see cref="PasswordResetError.PasswordTooWeak"/>.
    /// </summary>
    Task<(PasswordResetError Error, int? Score)> ConfirmAsync(
        string token, string newPassword, CancellationToken ct);
}
```

#### New Code (PasswordResetService — sketch)

```csharp
public sealed class PasswordResetService(
    AppDbContext db,
    PasswordHasher hasher,
    IPasswordStrengthChecker strengthChecker,
    RefreshTokenService refreshSvc,
    IEmailQueue emailQueue,
    IOptions<AppOptions> appOptions,
    TimeProvider clock,
    ILogger<PasswordResetService> logger) : IPasswordResetService
{
    private const int MaxRequestsPerEmailPerDay = 3;
    private static readonly TimeSpan RequestWindow = TimeSpan.FromHours(24);
    private static readonly TimeSpan TokenLifetime = TimeSpan.FromMinutes(30);
    private const int MinimumStrengthScore = 3;

    public async Task RequestAsync(
        string email, string? requesterIp, string? requesterUa, CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(email)) return; // silent no-op
        var normalised = email.Trim().ToLowerInvariant();

        var user = await db.Users.FirstOrDefaultAsync(u => u.Email == normalised, ct);
        if (user is null) return; // silent — enumeration defense

        // Per-email rate limit
        var since = clock.GetUtcNow().UtcDateTime - RequestWindow;
        var recent = await db.PasswordResetTokens
            .CountAsync(t => t.UserId == user.Id && t.IssuedAt >= since, ct);
        if (recent >= MaxRequestsPerEmailPerDay)
        {
            logger.LogInformation(
                "password_reset_request_rate_limited userId={UserId} count={Count}",
                user.Id, recent);
            return; // silent — same response as success path
        }

        // Mint token + persist row
        var (plaintext, hash) = AuthTokenIssuer.Mint(AuthTokenIssuer.PasswordResetPrefix);
        var now     = clock.GetUtcNow().UtcDateTime;
        var expires = now + TokenLifetime;
        db.PasswordResetTokens.Add(new PasswordResetToken
        {
            Id          = Guid.NewGuid(),
            UserId      = user.Id,
            TokenHash   = hash,
            IssuedAt    = now,
            ExpiresAt   = expires,
            RequesterIp = requesterIp,
            RequesterUa = requesterUa,
        });
        await db.SaveChangesAsync(ct);

        // Enqueue email
        var resetUrl = $"{appOptions.Value.WebAppUrl.TrimEnd('/')}/auth/password-reset/confirm?token={plaintext}";
        await emailQueue.EnqueueAsync(new EmailMessage(
            To: user.Email,
            TemplateSlug: "password_reset",
            Variables: new Dictionary<string, string>
            {
                ["user_email"]       = user.Email,
                ["reset_url"]        = resetUrl,
                ["expires_at_local"] = expires.ToString("yyyy-MM-dd HH:mm 'UTC'"),
                ["requester_ip"]     = requesterIp ?? "unknown",
                ["requester_ua"]     = requesterUa ?? "unknown",
            },
            EnqueuedAt: clock.GetUtcNow()), ct);
    }

    public async Task<(PasswordResetError Error, int? Score)> ConfirmAsync(
        string token, string newPassword, CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(token) ||
            !token.StartsWith(AuthTokenIssuer.PasswordResetPrefix, StringComparison.Ordinal))
            return (PasswordResetError.TokenInvalid, null);

        if (string.IsNullOrEmpty(newPassword))
            return (PasswordResetError.PasswordTooWeak, 0);

        var hash = AuthTokenIssuer.Hash(token);
        var now  = clock.GetUtcNow().UtcDateTime;

        var row = await db.PasswordResetTokens
            .FirstOrDefaultAsync(r => r.TokenHash == hash, ct);
        if (row is null
            || row.ConsumedAt is not null
            || row.RevokedAt  is not null
            || row.ExpiresAt  <= now)
        {
            return (PasswordResetError.TokenInvalid, null);
        }

        // Need user.Email for zxcvbn user-input penalty
        var user = await db.Users.FindAsync([row.UserId], ct);
        if (user is null) return (PasswordResetError.TokenInvalid, null);

        var score = strengthChecker.Score(newPassword, [user.Email]);
        if (score < MinimumStrengthScore)
            return (PasswordResetError.PasswordTooWeak, score);

        // Transactional update
        var useTransaction = db.Database.ProviderName != "Microsoft.EntityFrameworkCore.InMemory";
        if (useTransaction)
        {
            await using var tx = await db.Database.BeginTransactionAsync(ct);
            await ApplyConfirmAsync(row, user, newPassword, now, ct);
            await tx.CommitAsync(ct);
        }
        else
        {
            await ApplyConfirmAsync(row, user, newPassword, now, ct);
        }

        await refreshSvc.RevokeAllFamiliesForUserAsync(user.Id, "password_reset", ct);

        logger.LogInformation("password_reset_confirmed userId={UserId}", user.Id);
        return (PasswordResetError.None, null);
    }

    private async Task ApplyConfirmAsync(
        PasswordResetToken row, User user, string newPassword, DateTime now, CancellationToken ct)
    {
        user.PasswordHash = hasher.Hash(newPassword);
        row.ConsumedAt = now;
        await db.SaveChangesAsync(ct);
    }
}
```

#### New Code (PasswordResetEndpoints — sketch)

```csharp
public static class PasswordResetEndpoints
{
    public static IEndpointRouteBuilder MapPasswordResetEndpoints(this IEndpointRouteBuilder app)
    {
        app.MapPost("/api/v1/auth/password-reset/request", async (
            PasswordResetRequest? body, HttpContext http,
            IPasswordResetService svc, CancellationToken ct) =>
        {
            var email = body?.Email?.Trim() ?? string.Empty;
            var ip = http.Connection.RemoteIpAddress?.ToString();
            var ua = http.Request.Headers.UserAgent.ToString();
            await svc.RequestAsync(email, ip, ua, ct);
            return HttpResults.Ok(new PasswordResetResponse(
                Ok: true,
                Message: "If an account exists for that email, a reset link has been sent."));
        })
        .AllowAnonymous()
        .DisableAntiforgery()
        .RequireRateLimiting("auth-password-reset-request-ip")
        .WithName("PasswordResetRequest")
        .WithTags("Auth")
        .Accepts<PasswordResetRequest>("application/json")
        .Produces<PasswordResetResponse>();

        app.MapPost("/api/v1/auth/password-reset/confirm", async (
            PasswordResetConfirmRequest? body, HttpContext http,
            IPasswordResetService svc, CancellationToken ct) =>
        {
            var token = body?.Token ?? string.Empty;
            var pw    = body?.NewPassword ?? string.Empty;
            var (err, score) = await svc.ConfirmAsync(token, pw, ct);
            return err switch
            {
                PasswordResetError.None         => HttpResults.Ok(new PasswordResetResponse(true, "Password updated.")),
                PasswordResetError.TokenInvalid => PasswordResetProblem.TokenInvalid(http),
                PasswordResetError.PasswordTooWeak => PasswordResetProblem.PasswordTooWeak(http, score ?? 0),
                _ => HttpResults.StatusCode(StatusCodes.Status500InternalServerError),
            };
        })
        .AllowAnonymous()
        .DisableAntiforgery()
        .WithName("PasswordResetConfirm")
        .WithTags("Auth")
        .Accepts<PasswordResetConfirmRequest>("application/json")
        .Produces<PasswordResetResponse>()
        .ProducesProblem(StatusCodes.Status400BadRequest)
        .ProducesProblem(StatusCodes.Status422UnprocessableEntity);

        return app;
    }
}
```

```csharp
namespace ApiTool.Backend.Auth;

using ApiTool.Backend.Data;
using Microsoft.EntityFrameworkCore;

/// <summary>
/// Endpoint filter that returns 403 with <c>email-not-verified</c> problem detail
/// when the authenticated user's <c>email_verified</c> column is false.
/// Refs docs/SPECIFICATION.md:8576-8580 (verification gating policy).
/// </summary>
public sealed class RequireVerifiedEmailFilter : IEndpointFilter
{
    public async ValueTask<object?> InvokeAsync(
        EndpointFilterInvocationContext ctx, EndpointFilterDelegate next)
    {
        var http = ctx.HttpContext;
        var users = http.RequestServices.GetRequiredService<CurrentUserAccessor>();
        var userId = await users.ResolveAsync(http.RequestAborted);
        if (userId is null)
            return EmailNotVerifiedProblem.Unauthenticated(http);

        var db = http.RequestServices.GetRequiredService<AppDbContext>();
        var verified = await db.Users
            .Where(u => u.Id == userId.Value)
            .Select(u => u.EmailVerified)
            .FirstOrDefaultAsync(http.RequestAborted);

        if (!verified)
            return EmailNotVerifiedProblem.Forbidden(http);

        return await next(ctx);
    }
}

public static class RequireVerifiedEmailExtensions
{
    /// <summary>
    /// Gates the endpoint on <c>users.email_verified == true</c>. Returns 403 with
    /// <c>application/problem+json</c> body type <c>.../errors/email-not-verified</c>
    /// when the caller is authenticated but unverified.
    /// </summary>
    public static RouteHandlerBuilder RequireVerifiedEmail(this RouteHandlerBuilder builder)
        => builder.AddEndpointFilter<RequireVerifiedEmailFilter>();
}
```

```csharp
public sealed class AuthTokenCleanupService(
    IServiceScopeFactory scopeFactory,
    IOptions<AuthTokenCleanupOptions> options,
    TimeProvider clock,
    ILogger<AuthTokenCleanupService> logger,
    TimeSpan? tickInterval = null) : BackgroundService
{
    private readonly TimeSpan _tickInterval = tickInterval ?? TimeSpan.FromHours(1);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        logger.LogInformation(
            "AuthTokenCleanupService started; retention={Days} days; tick={Hours}h",
            options.Value.RetentionDays, _tickInterval.TotalHours);
        while (!stoppingToken.IsCancellationRequested)
        {
            try
            {
                await using var scope = scopeFactory.CreateAsyncScope();
                var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
                var cutoff = clock.GetUtcNow().UtcDateTime.AddDays(-options.Value.RetentionDays);

                var prRows = await db.PasswordResetTokens
                    .Where(t => (t.ConsumedAt != null || t.RevokedAt != null || t.ExpiresAt < cutoff)
                                && t.IssuedAt < cutoff)
                    .ToListAsync(stoppingToken);
                db.PasswordResetTokens.RemoveRange(prRows);

                var evRows = await db.EmailVerificationTokens
                    .Where(t => (t.ConsumedAt != null || t.RevokedAt != null || t.ExpiresAt < cutoff)
                                && t.IssuedAt < cutoff)
                    .ToListAsync(stoppingToken);
                db.EmailVerificationTokens.RemoveRange(evRows);

                if (prRows.Count + evRows.Count > 0)
                {
                    await db.SaveChangesAsync(stoppingToken);
                    logger.LogInformation(
                        "auth_token_cleanup_deleted password_reset={Pr} email_verification={Ev} cutoff={Cutoff:o}",
                        prRows.Count, evRows.Count, cutoff);
                }
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested) { break; }
            catch (Exception ex) { logger.LogError(ex, "AuthTokenCleanupService tick failed"); }

            try { await Task.Delay(_tickInterval, stoppingToken); }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested) { break; }
        }
        logger.LogInformation("AuthTokenCleanupService stopped");
    }
}
```

## Risks and Edge Cases

- **Risk:** Per-email rate-limit DB query is a full table scan if `password_reset_tokens(user_id, issued_at)` index is not used. → **Mitigation:** the existing index `idx_password_reset_tokens_user` (column `user_id, issued_at DESC`) already covers this; verified at `Migrations/20260507174354_AddPasswordResetAndEmailVerificationTokens.cs:99-103`.

- **Risk:** Body-buffering for per-email IP rate limits could enable DoS by consuming bytes. → **Mitigation:** we don't buffer the body in middleware; we use ASP.NET RateLimiter for per-IP only and per-email is a DB count after the body is read into the strongly-typed handler argument.

- **Risk:** Two simultaneous `confirm` calls with the same token. → **Mitigation:** the unique-index on `token_hash` plus the `consumed_at IS NULL` check inside the transaction; the loser sees a stale row when re-querying after commit. EF's optimistic concurrency on the entity is sufficient given the small window.

- **Risk:** zxcvbn-core licence (LGPL?). → **Mitigation:** zxcvbn-core 7.x is MIT-licensed (verified before adding). Confirmed compatible with the existing dependency set.

- **Edge case:** User is unverified and uses password reset to set a new password — should they be auto-verified? → **Decision:** No. The spec explicitly distinguishes "controls password" from "controls email"; one should not imply the other. The reset email going through is implicit verification of email control, but the spec defers to explicit verification flow. We leave `email_verified` untouched on reset confirm.

- **Edge case:** Email-verification confirm is called with no body / empty token. → **Handling:** return 400 with `email-verification-token-invalid` problem detail (same as expired).

- **Edge case:** `email_verification` template is in the M14 inventory at `EmailTemplateInventory.cs:18` already — no template change needed for the resend path. Only `password_reset` was added in M16-002.

- **Edge case:** In the BackendFactory test environment, the rate-limiter middleware uses no-op partitioners (`Program.cs:530-543`); we must extend that no-op block to include the four new policy names so `.RequireRateLimiting("auth-password-reset-request-ip")` doesn't 500 in tests.

- **Edge case:** `email` field arriving with mixed case or with surrounding whitespace — must be normalised consistently with how `users.Email` is stored. The existing user table stores email as-given; we normalise both sides with `Trim().ToLowerInvariant()` for comparison and at insert time. Audit step: confirm `CurrentUserAccessor` and bootstrap insert lowercase emails. (If they don't, a follow-up may be needed; for now we lower-case at lookup time only.)

- **Edge case:** `WebAppUrl` ends with `/`. → **Handling:** `TrimEnd('/')` before concatenation.
