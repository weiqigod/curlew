# Implementation Plan: M20-002

## Overview
Add nine Latin-script European locale data tables (en-GB, fr-FR, es-ES, it-IT, pt-BR, nl-NL, pl-PL, sv-SE, tr-TR) to the `localePools` lookup established by M20-001, each providing first/last name pools, a city pool, and a per-locale phone formatter that emits its spec-documented format. This is a data-and-formatter slice only — no flag/config/precedence work, all of which shipped in M20-001.

## Key Architectural Decisions

1. **Follow the M20-001 eager-map pattern, not literal `sync.Once`.** The task scope and SPEC:1110 mention "lazy" / `sync.Once` initialisation. M20-001 actually shipped pools as a package-level map literal (`localePools`) whose values are produced by `enUSLocale()` / `deDELocale()` constructor functions. The spec's "lazy load ~100KB/locale" language targets *external data files*; these pools are tiny in-source Go slices (a few hundred bytes each), so the cost concern does not apply. Following the existing pattern keeps the blast radius minimal and the code uniform. **Decision: register the nine new locales by adding constructor functions (`enGBLocale()`, `frFRLocale()`, …) and nine entries to the `localePools` map literal — exactly as `deDELocale()` is wired today.** No `sync.Once` is introduced; this is documented here so the choice is auditable.

2. **One new file, `internal/variable/locale_pools.go`.** `locale.go` already holds the resolver, the en-US/de-DE constructors, and the `localePools` map. Adding nine more constructor functions (~30 names + ~15 cities + a phone closure each) would roughly triple that file. The nine new constructors go in a dedicated `locale_pools.go`; the `localePools` map literal in `locale.go` gains nine entries that reference them. Same package, so no visibility changes.

3. **Phone formats are transcribed from the SPEC:973-987 table verbatim in shape.** Each locale's `phoneFormat` closure reproduces the exemplar's structure (country code, grouping, separators) using `intn(rng, …)` for the variable digits, mirroring `deDELocale`'s `+49 %d %08d` approach. The shape (not the literal exemplar digits) is what the pool-shape regex test asserts.

4. **tr-TR Turkish casing is a data property, not a code transform.** The dotted-İ / dotless-ı requirement (behavior 2) is satisfied by storing the correct Unicode codepoints directly in the tr-TR name slices (e.g. `"Yılmaz"` with U+0131, `"İsmail"` with U+0130). No `strings.ToUpper`/`ToLower` is applied to name pools anywhere in the faker path, so Go's locale-insensitive casing cannot corrupt them. The shape test asserts valid UTF-8, which guarantees the codepoints survive round-trip. (Note: `faker.userName` does call `strings.ToLower` on names — Turkish dotted-İ lowercases to ASCII `i̇` under Go's Unicode-default rules, which is acceptable for usernames and out of scope here; behavior 2 concerns `fullName`/`lastName` output, which is never re-cased.)

5. **No new exported symbols.** All nine constructors are unexported (`frFRLocale` etc.), consistent with `deDELocale`. The only package-level change visible outside the file is the nine new `localePools` map entries.

```go
package variable

import (
	"regexp"
	"testing"
	"unicode/utf8"
)

// phoneShapePatterns maps each Latin-script locale to a regex its phoneFormat
// output must match, derived from the SPEC:973-987 phone-format column.
var phoneShapePatterns = map[string]*regexp.Regexp{
	"en-GB": regexp.MustCompile(`^\+44 \d{2} \d{4} \d{4}$`),
	"fr-FR": regexp.MustCompile(`^\+33 \d \d{2} \d{2} \d{2} \d{2}$`),
	"es-ES": regexp.MustCompile(`^\+34 \d{2} \d{3} \d{2} \d{2}$`),
	"it-IT": regexp.MustCompile(`^\+39 \d{2} \d{4} \d{4}$`),
	"pt-BR": regexp.MustCompile(`^\+55 \d{2} \d{5}-\d{4}$`),
	"nl-NL": regexp.MustCompile(`^\+31 \d{2} \d{3} \d{4}$`),
	"pl-PL": regexp.MustCompile(`^\+48 \d{2} \d{3} \d{2} \d{2}$`),
	"sv-SE": regexp.MustCompile(`^\+46 \d \d{3} \d{2} \d{2}$`),
	"tr-TR": regexp.MustCompile(`^\+90 \d{3} \d{3} \d{2} \d{2}$`),
}

func TestLocalePools_LatinScript_Shape(t *testing.T) {
	locales := []string{"en-GB", "fr-FR", "es-ES", "it-IT", "pt-BR", "nl-NL", "pl-PL", "sv-SE", "tr-TR"}
	for _, code := range locales {
		t.Run(code, func(t *testing.T) {
			pool, ok := localePools[code]
			if !ok {
				t.Fatalf("locale %q not registered in localePools", code)
			}
			// Non-empty pools
			if len(pool.firstNames) == 0 || len(pool.lastNames) == 0 || len(pool.cities) == 0 {
				t.Fatalf("%s: empty firstNames/lastNames/cities pool", code)
			}
			// No empty/whitespace entries, valid UTF-8
			for _, group := range [][]string{pool.firstNames, pool.lastNames, pool.cities} {
				for _, e := range group {
					if strings.TrimSpace(e) == "" {
						t.Errorf("%s: empty/whitespace entry %q", code, e)
					}
					if !utf8.ValidString(e) {
						t.Errorf("%s: invalid UTF-8 entry %q", code, e)
					}
				}
			}
			// Phone format present and shape-correct across many draws
			if pool.phoneFormat == nil {
				t.Fatalf("%s: phoneFormat is nil", code)
			}
			pat := phoneShapePatterns[code]
			for seed := int64(0); seed < 200; seed++ {
				rng := rand.New(rand.NewPCG(uint64(seed), uint64(seed>>32^0xdeadbeef)))
				got := pool.phoneFormat(rng)
				if !pat.MatchString(got) {
					t.Errorf("%s: phone %q does not match %s", code, got, pat)
				}
			}
		})
	}
}
```

(Imports `strings`, `regexp`, `unicode/utf8`, `testing`, plus `math/rand/v2` as `rand` matching the package's existing alias usage in `locale.go`.)

## Risks and Edge Cases
- **Risk:** A phone closure's `intn` ranges produce a digit count that drifts from the spec exemplar (e.g. leading-zero loss). → **Mitigation:** the `phoneShapePatterns` regex in Step 1 runs over 200 seeds per locale and asserts exact group widths with `%0Nd` formatting; leading zeros are preserved by the format verbs.
- **Risk:** tr-TR Turkish characters mangled by an editor or an accidental `ToUpper`/`ToLower` in the name path. → **Mitigation:** `TestRegistry_TrTR_PreservesTurkishCasing` asserts valid UTF-8 and the presence of ı/İ; the faker name path (`fullName`/`firstName`/`lastName`) applies no casing transform (verified — only `userName`/`email`, out of scope, lowercase).
- **Risk:** Coverage dips below 80% because pool tables are data, not branches. → **Mitigation:** pools are exercised by the shape test (every entry read) and per-locale draw tests; phone closures are covered by 200-seed loops. Data slices contribute no uncovered branches.
- **Edge case:** A locale's `firstName` and `lastName` pools differ in length, so the same seed yields different *indices* per call. → **Handling:** seed/position-invariance is asserted per-function (firstName), not across functions — consistent with how M20-001 framed the invariant; each function draws once from its own pool with the same index.
- **Edge case:** pt-BR uses a hyphen in the phone format (`91234-5678`). → **Handling:** the regex `^\+55 \d{2} \d{5}-\d{4}$` encodes the hyphen explicitly.
- **Edge case:** `faker.phoneInternational` shares the per-locale `phoneFormat` closure (M20-001 wired both to it). → **Handling:** no extra work; both functions emit the same locale format, which is correct for these international-format locales.
