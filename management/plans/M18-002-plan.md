# Implementation Plan: M18-002

## Overview
Add per-org audit-log retention (`organizations.audit_log_retention_days`, default 365, capped at 365 for non-Enterprise) with a daily `AuditLogCleanupHost : BackgroundService`, introduce `audit_log.view` and `audit_log.export` permissions, lift the hardcoded Owner/Admin gate at `AuditLogQueryService.cs:24` to a permission check, and seed a "Security Auditor" custom-role template with view-only access. Closes spec decisions v4-2 and v4-3.

## Task Details
- **ID:** M18-002
- **Title:** Audit-log RBAC permissions + per-org retention + AuditLogCleanupHost
- **Phase:** M18: Compliance & launch
- **Priority:** 1
- **Complexity:** medium

## Dependencies

No declared dependencies. M18-001 (audit-log bulk export) is already `done`; its TODOs at `AuditLogQueryService.cs:44` and `AuditLogEndpoints.cs:96` explicitly defer the RBAC lift to this task.

## Architecture Decisions

These are decisions made in pipeline mode (no user prompt available):

1. **Permission check site.** Lift the gate inside `AuditLogQueryService` so both `QueryAsync` and `EnsureExporterAuthorisedAsync` consult `RoleResolver.HasPermissionAsync`. Keeps the existing call-flow at `AuditLogEndpoints.cs` shape-stable (still returns `AuditLogError.PermissionDenied`); the endpoint already maps that to 403 with the right RFC 7807 body shape. The export-path 403 will mention the missing `audit_log.export` permission explicitly via a refined `AuditLogError.PermissionDenied` message argument.
2. **No `IPermissionService` rename.** Scope mentions `IPermissionService`, but the codebase exposes `RoleResolver` (registered scoped). The Plan agent would normally surface this; we proceed with `RoleResolver` rather than introducing a new abstraction. Future consolidation can extract an interface.
3. **Enterprise retention cap enforcement site.** Enforce at `MembersService.UpdateOrgAsync` (which already handles `PUT/PATCH /api/v1/organizations/{id}`). Extend `UpdateOrganizationRequest` with `AuditLogRetentionDays`. Validation consults `ITierGate` directly; ineligible request returns `MemberError.RetentionDaysExceedsCap` mapping to a 400 with a problem detail (not 402, since the cap is a policy not a paywall — non-Enterprise can still set values ≤365).
4. **Background-service pattern.** Mirror `GithubWebhookCleanupHost` exactly: constructor takes `IServiceScopeFactory`, `IOptions<AuditLogCleanupOptions>`, `TimeProvider`, `ILogger`, optional `TimeSpan?` tick interval. Registered via `AddHostedService` outside the `Testing` environment to keep test runs deterministic. Per-org iteration honours each org's `AuditLogRetentionDays`.
5. **Per-org cleanup SQL.** Use raw `db.OrganizationAuditLog.Where(...).ExecuteDeleteAsync(ct)` per-org (EF 9 bulk delete). Avoids loading rows into memory. Per-org loop ensures retention is honoured even with mixed values.
6. **Metrics dependency.** Use built-in `System.Diagnostics.Metrics.Meter` (no `prometheus-net` dependency). The project doesn't currently use Prometheus; we expose the counter via a `Meter` named `ApiTool.Backend.Audit` and document that scraping wiring is a future-build concern (the YAML's "surfaces a Prometheus counter" requirement is honoured by emitting the metric, even though no scraper is configured yet — the OpenTelemetry exporter wiring is left to a follow-up).
7. **Test-only hook.** Add `POST /api/v1/internal/test-hooks/run-audit-cleanup` (matching the observable). Note the YAML mentions `/api/v1/internal/test-hooks/...` while existing internal endpoints live at `/internal/test/...`. We follow the YAML literally because the observable curl uses that path, and add an `InternalAccessFilter` gate as the second layer.
8. **Role template seeding.** "Security Auditor" template ships as a static catalogue accessible via a new `BuiltInRoleTemplates.SecurityAuditor` constant + an idempotent seeder invocation point. No DB schema for role templates yet exists; we expose templates as a static catalogue and seed an actual `OrganizationCustomRole` only when an org explicitly applies it. The observable assigns the role to a Member-tier user via a normal custom-role-create POST. We add seeded role creation logic only as a helper that tests/e2e can call; we do not auto-seed roles into every org.
9. **AuditLogError surface.** Extend `AuditLogError` with `RetentionDaysExceedsCap` only if the org-settings update lives outside `AuditLogQueryService`. It does — so we use `MemberError` instead. No `AuditLogError` change required.

internal static class AuditLogMetrics

`TickOnceAsync` iterates orgs and runs:
```csharp
var now = clock.GetUtcNow().UtcDateTime;
foreach (var org in await db.Organizations.Select(o => new { o.Id, o.AuditLogRetentionDays }).ToListAsync(ct))
{
    var cutoff = now.AddDays(-org.AuditLogRetentionDays);
    var deleted = await db.OrganizationAuditLog
        .Where(e => e.OrgId == org.Id && e.CreatedAt < cutoff)
        .ExecuteDeleteAsync(ct);
    if (deleted > 0)
    {
        AuditLogMetrics.RowsDeleted.Add(deleted, new KeyValuePair<string, object?>("org_id", org.Id));
        logger.LogInformation("audit_log_cleanup org_id={OrgId} deleted={Count} cutoff={Cutoff:o}",
            org.Id, deleted, cutoff);
    }
}

public static class InternalAuditCleanupTickEndpoint
{
    public static IEndpointRouteBuilder MapInternalAuditCleanupTickEndpoint(
        this IEndpointRouteBuilder app, IWebHostEnvironment env)
    {
        if (!env.IsDevelopment() && !env.IsEnvironment("Testing"))
            return app;

        app.MapPost("/api/v1/internal/test-hooks/run-audit-cleanup", async (
            IServiceProvider services, CancellationToken ct) =>
        {
            // Construct an ad-hoc tick (host registration may be skipped in Testing)
            await using var scope = services.CreateAsyncScope();
            var scopeFactory = services.GetRequiredService<IServiceScopeFactory>();
            var clock = services.GetRequiredService<TimeProvider>();
            var logger = services.GetRequiredService<ILogger<AuditLogCleanupHost>>();
            var opts = services.GetRequiredService<IOptions<AuditLogCleanupOptions>>();
            var host = new AuditLogCleanupHost(scopeFactory, opts, clock, logger);
            await host.TickOnceAsync(ct);
            return HttpResults.Ok(new { ticked = true });
        })
        .AllowAnonymous()
        .DisableAntiforgery()
        .AddEndpointFilter<InternalAccessFilter>()
        .WithName("InternalAuditCleanupTick")
        .WithTags("Internal");

        return app;
    }
}
```

## Risks and Edge Cases
- **Risk:** Existing `AuditLogEndpointsTests` assert `body.Should().Contain("permission_denied")` on the export path — the message body changes from "Admins and owners only." to "Missing permission: audit_log.export." → **Mitigation:** The substring match is on the error code, not message, so passes. Verified above.
- **Risk:** `RoleResolver` cold lookup per request adds a DB roundtrip on every audit-log call — **Mitigation:** Same cost as the existing `OrganizationMembers.FirstOrDefaultAsync`. No regression; could be cached in a follow-up.
- **Risk:** EF `ExecuteDeleteAsync` semantics on SQLite (test DB) — **Mitigation:** EF Core 9 supports it on SQLite; existing migrations already use modern bulk operators.
- **Risk:** Test-only hook URL `/api/v1/internal/test-hooks/run-audit-cleanup` doesn't follow existing `/internal/test/...` convention — **Mitigation:** Follow the YAML literally (it's the documented observable); `InternalAccessFilter` still protects it.
- **Risk:** Prometheus scraper isn't wired in the project — **Mitigation:** Documented in decision 6; emitting a `Meter` counter is the standard portable surface and OpenTelemetry can be added later without code changes.
- **Edge case:** Org with `audit_log_retention_days = 0` (or negative) — **Handling:** Reject at write-site (Step 4); existing rows protected by the constraint.
- **Edge case:** Org deleted while cleanup is running — **Handling:** `Where(e => e.OrgId == org.Id)` on a non-existent org returns 0; safe.
- **Edge case:** Custom-role `RoleId` points to a non-existent role — **Handling:** `RoleResolver` already falls back to the member's `OrgRole` built-in set; preserves the existing behaviour.
- **Edge case:** Test sequencing — order independence between Step 1 (Permissions) and Step 2 (QueryService) ensures Step 2 tests reference real constants.
