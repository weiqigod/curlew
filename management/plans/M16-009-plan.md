## Overview

## Key Architectural Decisions

1. **Endpoint shape: org-id derived from JWT, not path.** Per the spec's "Worker authentication" paragraph, workers are bound to one org. The endpoints in scope are root-routed (`/api/v1/schedules/next-run`, not `/api/v1/organizations/{orgId}/...`) and identify the org by looking up the calling user's `OrganizationMembers` row. Single-org-membership is the common case; for multi-membership we resolve the most recently joined org (deterministic), and document the limitation. Workers that need a specific org will be supplied org-scoped service tokens in a later milestone — out of scope here.
2. **Adapter pattern matches existing endpoints.** Endpoints live in a new file `Schedules/ScheduleExecutorEndpoints.cs`, separate from `SchedulesEndpoints.cs` (which owns the dashboard/CRUD endpoints under `/api/v1/organizations/{orgId}/schedules`). Business logic moves into a new `ScheduleExecutorService` so the existing `SchedulesService` (dashboard CRUD + `EnqueueDueAsync`) stays focused on its single concern. Same pattern as `Coordinator/CoordinatorService` vs `Schedules/SchedulesService`.
3. **`claim_token` is a server-minted `Guid`** serialized in wire format as the UUID string (no prefix — mirrors the spec SQL `claim_token UUID`). The token is opaque to the worker; presenting the same token plus the matching run id is the proof of claim.
4. **`claim_deadline` = `now + 30s`** per the task observable. This is a per-claim lease, distinct from the 5-minute reap window. The 30s value is the "fresh claim still valid for first heartbeat" guarantee surfaced to the worker; the 5-minute reap window in `ShardReaper` is the operational hard timeout.
5. **`ShardReaper` becomes a multi-tenant reaper.** Rather than rename it (which would churn DI/test fixtures), we extend `CoordinatorService.ReapStaleShardsAsync` to also reclaim stale `scheduled_runs` in the same tick — keeps the existing `IShardReaper` contract intact and reuses the singleton hosted-service. The DI registration `AddScoped<IShardReaper>(sp => sp.GetRequiredService<CoordinatorService>())` is unchanged. The reaped count is summed and a single log line is emitted; if the two domains need split telemetry later, we can split then.
6. **Stack-up prevention** moves into `EnqueueDueAsync`: when iterating due schedules, skip any whose `scheduled_runs` already has a row with `status IN ('queued','running')` for the same `schedule_id`. Per the task spec, `schedules.last_run_at` is still updated for visibility and `next_run_at` is still advanced so the cron doesn't immediately re-fire. The skipped firing is **not** persisted as a `skipped` `scheduled_runs` row — the spec table's `skipped` status only applies if we materialise the firing, which adds noise without value for the dashboard. (Open decision resolved: simplest interpretation; if the dashboard later needs visibility, we can add a "skipped" row.)
7. **Result payload reuses `UploadResultRequest`.** The result endpoint accepts a body that is `UploadResultRequest` plus a `claim_token` field. We define a new envelope record `ScheduleResultRequest(string? ClaimToken, ... same fields as UploadResultRequest ...)` rather than nesting, because System.Text.Json snake_case mapping on flat records is easier to keep consistent. The endpoint hands the inner payload to `ResultsService.IngestAsync` for persistence, then sets `scheduled_runs.result_id` + `status = completed|failed` + `completed_at` + (on failure) `failure_reason`. Pass/fail is computed from `fail_count == 0`.
8. **Tier-gate semantics.** `ScheduleExecutorTierGate.EnsureTeamOrAboveAsync` is called once per endpoint at the top, after JWT resolution and org resolution. `TierIneligible` maps to `TierGateProblemFactory.AuthenticatedTierIneligible` with `feature_code: "schedule_executor"` (matches the `{feature_code}_tier_ineligible` spec convention). `OrgNotFound` maps to `AuthenticatedOrgNotFound` (the user has a valid JWT but no resolvable org → treat as a not-found rather than leaking tier metadata).
9. **Migration adds all new columns + indexes + status values at once.** A single EF migration `AddScheduleExecutorClaimColumns` adds `ClaimToken (Guid?)`, `ClaimedByWorker (string?)`, `ClaimedAt (DateTime?)`, `LastHeartbeatAt (DateTime?)`, `ClaimDeadline (DateTime?)`, `ResultId (Guid? FK→results.id)`, `FailureReason (string?)`. The `Reaped` and `Skipped` enum values are added to `ScheduledRunStatus`. SQLite (test) just stores enum as `TEXT`, so no constraint update is required. We also add the supporting indexes `IX_scheduled_runs_Status_CreatedAt` and `IX_scheduled_runs_LastHeartbeatAt` (used by the reaper query and the next-run query, respectively).
10. **No changes to existing `SchedulerHost`/`ShardReaper` background hosts.** They already iterate via the scoped `ISchedulerEnqueuer` / `IShardReaper`. The stack-up logic lives in `SchedulesService.EnqueueDueAsync`. The schedule-reap logic lives in `CoordinatorService.ReapStaleShardsAsync`. The host wiring in `Program.cs` lines 461–465 stays intact.

```csharp
public async Task<int> EnqueueDueAsync(CancellationToken ct)
{
    var now = clock.GetUtcNow().UtcDateTime;
    var due = await db.Schedules
        .Where(s => s.Enabled && s.NextRunAt != null && s.NextRunAt <= now)
        .ToListAsync(ct);

    if (due.Count == 0) return 0;

    // M16-009: load schedule ids that already have an in-flight (queued|running) run
    // so we can skip stack-up firings.
    var dueIds = due.Select(s => s.Id).ToList();
    var inFlight = await db.ScheduledRuns
        .Where(r => dueIds.Contains(r.ScheduleId)
                 && (r.Status == ScheduledRunStatus.Queued || r.Status == ScheduledRunStatus.Running))
        .Select(r => r.ScheduleId)
        .Distinct()
        .ToListAsync(ct);
    var inFlightSet = inFlight.ToHashSet();

    var enqueued = 0;
    foreach (var schedule in due)
    {
        if (!inFlightSet.Contains(schedule.Id))
        {
            db.ScheduledRuns.Add(new ScheduledRun
            {
                Id = Guid.NewGuid(),
                ScheduleId = schedule.Id,
                Status = ScheduledRunStatus.Queued,
                CreatedAt = now,
            });
            enqueued++;
        }
        // Always update last_run_at + next_run_at for visibility, even on skip.
        schedule.LastRunAt = now;
        var parsedCron = CronExpression.Parse(schedule.CronExpression, CronFormat.Standard);
        schedule.NextRunAt = parsedCron.GetNextOccurrence(now);
        schedule.UpdatedAt = now;
    }

    await db.SaveChangesAsync(ct);
    return enqueued;
}
```

```csharp
/// <summary>Heartbeat timeout for scheduled_runs (worker-pull schedules).</summary>
public static readonly TimeSpan ScheduledRunHeartbeatTimeout = TimeSpan.FromMinutes(5);

public async Task<int> ReapStaleShardsAsync(CancellationToken ct)
{
    var now = clock.GetUtcNow().UtcDateTime;
    var shardCutoff = now - HeartbeatTimeout;
    var runCutoff = now - ScheduledRunHeartbeatTimeout;

    var staleShards = await db.CoordinatorShards
        .Where(s => s.Status == CoordinatorShardStatus.Running
                 && s.LastHeartbeatAt < shardCutoff)
        .ToListAsync(ct);

    foreach (var shard in staleShards)
    {
        shard.Status = CoordinatorShardStatus.Pending;
        shard.AssignedWorker = null;
        shard.ClaimedAt = null;
        shard.LastHeartbeatAt = null;
    }

    // M16-009: also reap stale scheduled_runs back to queued.
    var staleRuns = await db.ScheduledRuns
        .Where(r => r.Status == ScheduledRunStatus.Running
                 && r.LastHeartbeatAt != null
                 && r.LastHeartbeatAt < runCutoff)
        .ToListAsync(ct);

    foreach (var run in staleRuns)
    {
        run.Status = ScheduledRunStatus.Queued;
        run.ClaimToken = null;
        run.ClaimedByWorker = null;
        run.ClaimedAt = null;
        run.LastHeartbeatAt = null;
        run.ClaimDeadline = null;
        run.StartedAt = null;
    }

    if (staleShards.Count == 0 && staleRuns.Count == 0)
        return 0;

    await db.SaveChangesAsync(ct);
    return staleShards.Count + staleRuns.Count;
}
```

#### ClaimNextAsync — Implementation Sketch

```csharp
public async Task<(NextRunResponse? dto, ScheduleClaimError error)>
    ClaimNextAsync(Guid orgId, string? workerId, CancellationToken ct)
{
    var now = clock.GetUtcNow().UtcDateTime;
    var deadline = now + ClaimDeadline;

    // Find oldest queued run for any schedule in this org.
    var candidate = await db.ScheduledRuns
        .Where(r => r.Status == ScheduledRunStatus.Queued
                 && db.Schedules.Any(s => s.Id == r.ScheduleId && s.OrgId == orgId))
        .OrderBy(r => r.CreatedAt)
        .FirstOrDefaultAsync(ct);

    if (candidate is null) return (null, ScheduleClaimError.NoRunsAvailable);

    var schedule = await db.Schedules.SingleAsync(s => s.Id == candidate.ScheduleId, ct);

    candidate.Status = ScheduledRunStatus.Running;
    candidate.ClaimToken = Guid.NewGuid();
    candidate.ClaimedByWorker = workerId ?? "unknown";
    candidate.ClaimedAt = now;
    candidate.StartedAt = now;
    candidate.LastHeartbeatAt = now;
    candidate.ClaimDeadline = deadline;

    try
    {
        await db.SaveChangesAsync(ct);
    }
    catch (DbUpdateConcurrencyException)
    {
        // Another worker beat us to it; retry once by recursing.
        return await ClaimNextAsync(orgId, workerId, ct);
    }

    return (new NextRunResponse(
        RunId: RunId.Format(candidate.Id),
        ScheduleId: ScheduleId.Format(candidate.ScheduleId),
        CollectionRef: schedule.CollectionRef,
        EnvVars: new Dictionary<string, string>(),  // M16-009: column not yet present; empty placeholder
        ClaimToken: candidate.ClaimToken.Value.ToString(),
        Deadline: deadline), ScheduleClaimError.None);
}
```

**Race-safety note:** Per the task observable, "a row is already claimed → second call gets the next eligible row OR 204." EF SaveChanges with the default Sqlite/Postgres provider is "last write wins" — we don't add a rowversion column yet. The integration test that fires two parallel claims is left out of the formal observable; instead, the test seeds exactly one row, hits next-run twice sequentially, and the second call gets 204. That matches the task's behavior list ("the in-flight row is never handed out twice") because between the two calls, the row's status is Running and the next-run query filters by `Status == Queued`. If a true concurrent claim test is desired later, we can add a `Where(x => x.ClaimToken == null)` predicate to the update path and retry-on-zero-affected-rows.

```csharp
                 && db.Schedules.Any(s => s.Id == r.ScheduleId && s.OrgId == orgId))
        .SingleOrDefaultAsync(ct);

    if (run is null) return ScheduleClaimError.NotFound;

    // Reap window: row was sent back to Queued by reaper → claim_token cleared.
    if (run.Status != ScheduledRunStatus.Running || run.ClaimToken is null)
        return ScheduleClaimError.ClaimReaped;

    if (run.ClaimToken != claimToken)
        return ScheduleClaimError.StaleClaim;

    run.LastHeartbeatAt = clock.GetUtcNow().UtcDateTime;
    await db.SaveChangesAsync(ct);
    return ScheduleClaimError.None;
}
```

#### SubmitResultAsync — Implementation Sketch

```csharp
public async Task<ScheduleClaimError> SubmitResultAsync(
    Guid userId, Guid orgId, Guid runId, ScheduleResultRequest request, CancellationToken ct)
{
    if (string.IsNullOrWhiteSpace(request.ClaimToken)
        || !Guid.TryParse(request.ClaimToken, out var token))
        return ScheduleClaimError.InvalidRequest;

    var run = await db.ScheduledRuns
        .Where(r => r.Id == runId
                 && db.Schedules.Any(s => s.Id == r.ScheduleId && s.OrgId == orgId))
        .SingleOrDefaultAsync(ct);

    if (run is null) return ScheduleClaimError.NotFound;

    if (run.Status == ScheduledRunStatus.Completed || run.Status == ScheduledRunStatus.Failed)
        return ScheduleClaimError.AlreadyCompleted;

    if (run.Status != ScheduledRunStatus.Running || run.ClaimToken is null)
        return ScheduleClaimError.ClaimReaped;

    if (run.ClaimToken != token)
        return ScheduleClaimError.StaleClaim;

    var upload = new UploadResultRequest(
        request.CollectionName, request.RunAt, request.DurationMs,
        request.PassCount, request.FailCount, request.SkippedCount,
        request.TriggeredBy ?? "schedule", request.GitSha, request.Items);

    var (resultDto, resultError, message, _) = await results.IngestAsync(userId, orgId, upload, ct);
    if (resultError != ResultError.None)
    {
        logger.LogError(
            "Schedule executor result ingest failed for run {RunId}: {Error} {Message}",
            RunId.Format(runId), resultError, message);
        return resultError == ResultError.PermissionDenied
            ? ScheduleClaimError.NotFound          // surface as not-found (no info leak)
            : ScheduleClaimError.InvalidRequest;
    }

    var now = clock.GetUtcNow().UtcDateTime;
    run.Status = (request.FailCount ?? 0) == 0
        ? ScheduledRunStatus.Completed
        : ScheduledRunStatus.Failed;
    run.CompletedAt = now;
    if (resultDto is not null && ResultId.TryParse(resultDto.Id, out var resultGuid))
        run.ResultId = resultGuid;
    if (run.Status == ScheduledRunStatus.Failed)
        run.FailureReason = $"fail_count={request.FailCount}";

    await db.SaveChangesAsync(ct);
    return ScheduleClaimError.None;
}
```

```csharp
public static class ScheduleExecutorEndpoints
{
    public static IEndpointRouteBuilder MapScheduleExecutorEndpoints(this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/v1/schedules")
            .RequireAuthorization()
            .WithTags("ScheduleExecutor");

        group.MapGet("next-run", NextRun).WithName("ScheduleExecutorNextRun");
        group.MapPost("runs/{runId}/heartbeat", Heartbeat).WithName("ScheduleExecutorHeartbeat");
        group.MapPost("runs/{runId}/result", SubmitResult).WithName("ScheduleExecutorResult");
        return app;
    }

    private static async Task<IResult> NextRun(
        HttpContext http,
        CurrentUserAccessor users,
        ITierGate tierGate,
        ScheduleExecutorService svc,
        AppDbContext db,
        CancellationToken ct)
    {
        var userId = await users.ResolveAsync(ct);
        if (userId is null) return Unauthorized401;

        var orgIdOrError = await ResolveOrgAsync(db, userId.Value, ct);
        if (orgIdOrError.error is not null) return orgIdOrError.error;
        var orgId = orgIdOrError.orgId!.Value;

        var gateErr = await ScheduleExecutorTierGate.EnsureTeamOrAboveAsync(tierGate, orgId, ct);
        if (gateErr is not Internal.TierGates.ScheduleExecutorError.None)
            return MapGateError(http, gateErr, tierGate, orgId, ct);

        var workerId = http.User.FindFirst("worker_id")?.Value
                    ?? http.Request.Headers["X-Worker-Id"].FirstOrDefault();

        var (dto, err) = await svc.ClaimNextAsync(orgId, workerId, ct);
        return err switch
        {
            ScheduleClaimError.None             => Results.Ok(dto),
            ScheduleClaimError.NoRunsAvailable  => Results.NoContent(),
            _ => Results.StatusCode(StatusCodes.Status500InternalServerError),
        };
    }

    // Heartbeat and SubmitResult follow the same shape.
}
```

#### `ResolveOrgAsync` helper

```csharp
private static async Task<(Guid? orgId, IResult? error)> ResolveOrgAsync(
    AppDbContext db, Guid userId, CancellationToken ct)
{
    var membership = await db.OrganizationMembers
        .Where(m => m.UserId == userId)
        .OrderByDescending(m => m.JoinedAt)
        .FirstOrDefaultAsync(ct);

    if (membership is null)
    {
        // 403 — no org to scope to; the worker login token is unbound.
        return (null, Results.Json(
            new ErrorResponse("no_org_membership",
                "The authenticated user is not a member of any organization."),
            statusCode: StatusCodes.Status403Forbidden));
    }
    return (membership.OrgId, null);
}
```

## Risks and Edge Cases

- **Risk:** Org resolution from JWT is ambiguous if the user belongs to multiple orgs. → **Mitigation:** Pick most-recent membership by `JoinedAt`; document the limitation in the endpoint XML doc; defer service-token-with-org-binding to a later task. Workers in production are single-org per the spec.
- **Risk:** Two workers polling `next-run` simultaneously could both fetch the same row before either calls `SaveChangesAsync`. → **Mitigation:** EF's default change tracking + the natural row-version DbUpdateConcurrencyException retry covers the common case; the task observable only requires sequential proof. A future hardening task can add a `WHERE claim_token IS NULL` predicate at the UPDATE level. Document the gap in the service XML comments.
- **Risk:** `ResultsService.IngestAsync` enforces `IsMemberAsync(userId, orgId)`. The userId in the worker's JWT must be a member of the resolved org. → **Mitigation:** Org resolution already comes from `OrganizationMembers`, so the same userId/orgId pair will pass the IngestAsync membership check.
- **Risk:** Migration adds an FK from `scheduled_runs.result_id` → `results.id`. If SQLite (test DB) enforces FK and any test deletes a `results` row, the cascade would null the run's FK. → **Mitigation:** `OnDelete(DeleteBehavior.SetNull)` is the intent; for SQLite this requires the schema to allow null, which it does (`Guid?`).
- **Risk:** `EnvVars` is required by the spec but the column doesn't exist yet. → **Mitigation:** Return an empty `{}` placeholder; document that `schedules.env_vars` arrives in a later milestone. The wire shape is forward-compatible.
- **Risk:** `ClaimReaped` vs `StaleClaim` are both 409 but with different `type` URIs. → **Mitigation:** Test both paths separately. ClaimReaped happens when `ClaimToken IS NULL` (reaper cleared it); StaleClaim happens when `ClaimToken IS NOT NULL` but doesn't match the presented token.
- **Edge case:** Worker calls heartbeat after submitting result (run is in `Completed` state). → **Handling:** `HeartbeatAsync` checks `Status != Running` → returns `ClaimReaped` (the claim is no longer active). Documented in service XML.
- **Edge case:** `next-run` called by a brand-new user with no org membership. → **Handling:** `ResolveOrgAsync` returns 403 `no_org_membership` *before* the tier gate runs (no info leak about whether the feature exists).
- **Edge case:** Worker posts result with `claim_token` in body but the row was reaped 4 seconds ago and re-claimed by a different worker. → **Handling:** Token mismatch → `StaleClaim` → 409. The new worker's result will succeed; the old worker's result is dropped.
