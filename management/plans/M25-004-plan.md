# Implementation Plan: M25-004

## Overview

Make a binary that was **not** built by goreleaser report the version it was
actually built from, by falling back to `debug.ReadBuildInfo().Main.Version`
when the compile-time default is still in place — without ever letting that
fallback beat the `-X main.version` ldflag, and without letting a
non-version (`(devel)`, empty, absent, pseudo-version, `+dirty`) reach a user.

- **Phase:** M25: A deliverable that exists
- **Priority:** 2

### D0 — The task file's stated premise is false on this toolchain

Behavior 3 reads:

> Given a plain local `go build`, when `--version` runs, then it reports the
> compile-time default, **because build info reports `(devel)`** which is not a
> version.

Measurement 1 contradicts the clause after "because". Go 1.24+ stamps the main
module's version from VCS, so a plain `go build` in this repo yields
`v0.1.1-0.20260817171911-ee182919250e`. `(devel)` only appears when VCS
stamping is unavailable (measurement 3) or suppressed, as in a test binary
(measurement 4).

The **required behavior is unchanged and still correct** — a plain `go build`
must report the compile-time default — but it is no longer free. It has to be
implemented by rejecting pseudo-versions, a case the task file does not
enumerate. The scope note "Enumerate what 'not a real version' covers … rather
than special-casing the one you happened to see" is exactly right, and this is
the case it was warning about.

Consequence for the DoD: the item *"A test proves `(devel)`, empty, and absent
build info all keep the default"* is necessary but **not sufficient**. This
plan adds pseudo-version and `+dirty` cases to that list.

## Design Decisions

### D1 — Reject pseudo-versions; keep the compile-time default

The strongest case for the **other** side: the task's own motivation is that a
bug report from a source build "carries a version string that identifies
nothing", and `v0.1.1-0.20260817171911-ee182919250e` identifies commit
`ee18291` exactly, while `0.1.0-dev` identifies nothing. Rejection therefore
leaves the clone-and-build path (README:133) exactly as broken as it was.

Rejection still wins, on four grounds that are not taste:

1. **It advertises a release that does not exist.** A pseudo-version's numeric
   prefix is the *next patch above the last tag* — `0.1.1`, never released.
   Under semver it sorts *above* `v0.1.0`, so anyone comparing two version
   strings concludes this build is newer than the last release. That is the
   task's own test — "reporting that is worse than the current placeholder".
2. **It is explicitly out of scope.** The task excludes "the git-describe shape
   of dev builds, or the `+dirty` suffixes some projects add". A Go
   pseudo-version is git-describe in module clothing, and `+dirty` is appended
   to it verbatim (measurement 2).
3. **It would make the reported version non-deterministic for a local build** —
   four different strings on one machine (clean / `+dirty` / shallow /
   `-buildvcs=false`). Three existing assertions depend on that determinism:
   `cmd/curlew/main_test.go:8835`, `cmd/curlew/skill_playbook_test.go:449-450`,
   and `scripts/ci-local.sh:320`, whose purpose-built message
   (`-X main.version never reached the binary`) would go dead.
4. **It leaks into a file the user commits.** `cmd/curlew/main.go:2632` feeds
   `scaffold.Init`, which substitutes the version into `SKILL.md`
   (`internal/scaffold/scaffold.go:140`). Every project scaffolded from a source
   build would carry `curlew 0.1.1-0.20260817171911-ee182919250e` in a doc
   header forever.

Rejection is also the safe failure direction: every rejected case falls back to
a string that is honest about being a development build.

### D2 — What "not a real version" covers

Deliberately enumerated, not observed one at a time. A build-info version is
usable **iff**:

```
releaseVersionRE = ^v?[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$
pseudoVersionRE  = -[0-9]{14}-[0-9a-f]{12}$

usable(v)  ==  releaseVersionRE.MatchString(v) && !pseudoVersionRE.MatchString(v)
```

| Input | Source | Verdict |
|-------|--------|---------|
| `ok == false` from `ReadBuildInfo` | non-module build | reject |
| `nil` `*BuildInfo` | defensive | reject |
| `""` | defensive | reject |
| `(devel)` | measurements 3, 4 | reject |
| `v0.1.1-0.20260817171911-ee182919250e` | measurement 1 | reject (pseudo) |
| `v0.0.0-20260817171911-ee182919250e` | untagged repo | reject (pseudo) |
| `…+dirty` | measurements 2, 6c | reject (no `+` in the regex) |
| `v1.2.3+incompatible` | v2+ module without `/vN` | reject (no `+`) — see limitation below |
| `v0.1.0` | measurements 5, 7 | **accept** → `0.1.0` |
| `v0.99.0` | measurement 6 | **accept** → `0.99.0` |
| `v0.2.0-rc.1` | a pre-release tag | **accept** → `0.2.0-rc.1` |

`+incompatible` is rejected deliberately. curlew is a `v0.x` module and its
release process never produces it; rejecting it costs a hypothetical v2-without-
`/v2` install the correct version and gives it the honest placeholder instead,
which is the safe direction. Documented as a known limitation rather than
handled.

The regex rejects `+` entirely rather than pattern-matching `+dirty`, so any
future build-metadata suffix is rejected by construction instead of needing a
new special case.

### D3 — How we know `version` is untouched

```go
const defaultVersion = "0.1.0-dev"

var version = defaultVersion
```

"Untouched" is `version == defaultVersion`. There is exactly **one** occurrence
of the literal in the Go tree, so the two sides of the comparison cannot drift:
editing the default moves both at once.

This shape is only safe because `-X` still reaches a var initialized from a
named constant — the linker requires "uninitialized or initialized to a
constant string expression", and `defaultVersion` qualifies. **Measured**
(measurement 9), not assumed: this is the exact class of silent failure
`TestVersion_is_injectable_at_link_time` exists to catch (a `const` would be
ignored in silence), so it was verified before being designed around.

Two more copies of the literal exist outside Go and cannot import the constant:
`README.md:125` (prose, rewritten in Step 7) and `scripts/ci-local.sh:320`
(a shell equality check). The shell one gets a comment binding it to
`cmd/curlew/version.go`; deriving it in shell is not worth the machinery.

### D4 — Normalise the build-info value only

goreleaser's `{{ .Version }}` strips the leading `v`: measurement 8 shows the
published v0.1.0 archive was linked with `-X main.version=0.1.0` while its own
build info says `v0.1.0`. Build info never strips it.

So the fallback strips exactly one leading `v`, and the injected value is passed
through **verbatim**. Normalising the injected value too would mean the binary
does not report what the release pipeline asked for, which is the one thing
`-X` is for.

That measurement also supplies the byte-identity proof for free: for the same
release, `-X` yields `0.1.0` and the fallback yields `strip("v0.1.0")` =
`0.1.0`. Step 2 pins the goreleaser half of that equality offline by asserting
`.goreleaser.yaml` uses `{{ .Version }}` and not `{{ .Tag }}` — `{{ .Tag }}`
keeps the `v`, and swapping them is precisely the regression the "byte-
identical" DoD item exists to catch.

### D5 — Resolve once, eagerly; rewire all seven call sites

```go
var resolvedVersion = resolveVersion(version, buildInfoVersion)
```

An eager package-level initializer sees the `-X`-injected value — **measured**
(measurement 9a), because the linker patches the data section before any
initializer runs. `sync.OnceValue` was considered and rejected: it buys
laziness nothing needs, and costs a closure, an atomic load at every read, and
call syntax at seven sites.

The task names three surfaces. There are **seven** production reads of
`version`:

| Site | Surface |
|------|---------|
| `cmd/curlew/main.go:75` | `--version` |
| `cmd/curlew/main.go:574` | `events.NewEmitter` (run) |
| `cmd/curlew/main.go:929` | `events.NewEmitter` (run, second path) |
| `cmd/curlew/main.go:2632` | `scaffold.Init` → `SKILL.md` |
| `cmd/curlew/main.go:2725` | `info --format json` |
| `cmd/curlew/main.go:3374` | help `Version:` line |
| `cmd/curlew/ui.go:227` | `uiserver.Options.Version` |

All seven change. Rewiring only the three named would replace "consistently
wrong" with "internally contradictory": `info --format json` would report
`0.2.0` while the events file for the *same run* reported `0.1.0-dev`, and no
test in the repo compares those two. The DoD says the surfaces must *agree*;
one accessor makes that structural instead of merely tested.

An AST guard test (Step 4) makes an eighth site impossible. It must be an AST
walk, not a grep: `version` occurs as a substring in `--version` and in the
string literal `TAP version 13` (`main.go:2057`).

### D6 — Empty injected value counts as untouched

`-X main.version=` (empty value) is contemplated by
`release_artifacts_test.go:827`. Today it produces `curlew ` and an empty
version in the scaffolded `SKILL.md`. `internal/scaffold/scaffold.go:35-39`
documents `CurlewVersion` as "Required when SkillName is non-empty" but
**no validation enforcing that was found** — the substitution simply writes an
empty string. Treating an empty injected value as untouched is one extra clause
and strictly better than emitting `curlew `.

### D7 — How this is tested, and what cannot be tested today

The impure part is two lines (`debug.ReadBuildInfo()` → `Main.Version`).
Everything else is pure. Four layers:

1. **Pure table tests** over `resolveVersion` — every row of D2's table, plus
   precedence. No I/O. This is where the contract lives.
2. **`-buildvcs=false` build** (measurement 3) → `(devel)` deterministically →
   assert exact equality with `curlew ` + `defaultVersion`. Deterministic on
   *any* checkout, which a plain `buildBinary` assertion would not be: during a
   release, HEAD is a clean tagged commit and the default would legitimately not
   be reported (measurement 5).
3. **Wiring assertion**: build with the existing `buildBinary` helper, read the
   binary's own stamp with `debug/buildinfo.Read` (already used at
   `release_artifacts_test.go:21`), and assert `--version` equals
   `"curlew " + resolveVersion(defaultVersion, thatStamp)`. This crosses the
   process boundary and proves the binary's internal `ReadBuildInfo` sees the
   same value the file carries. On its own it is weak — on an untagged checkout
   both sides reduce to the default — which is why layer 4 exists.
4. **End-to-end fixture** (Step 6): a real tag → real Go VCS stamping → real
   `ReadBuildInfo` → `--version`.

**What cannot be tested today, stated plainly.** Behavior 2 names
`go install <module>@<tag>`. That path is unreachable: the only tag is `v0.1.0`,
whose source predates this fix, so an installed v0.1.0 binary will report
`0.1.0-dev` forever and correctly (measurement 7); and creating a new tag is out
of bounds. What measurement 7 *does* establish is that `go install @<tag>`
populates `Main.Version` with a clean `v0.1.0` — the identical input the
fixture feeds the resolver via VCS stamping. The fixture is therefore a
faithful proxy for the proxy-install path, and the test comment must say so
rather than let the name imply a `go install` ran. The real path becomes
covered by `TestReadme_install_commands_execute` the moment a post-fix tag is
cut — which is also when Step 7's attribution fix stops that test from going
vacuous.

### D8 — The fixture: `git init` from the live working tree, not a clone

Measurement 11. Copy the file set from `git ls-files -z` plus
`git ls-files -z --others --exclude-standard` into `t.TempDir()`, `git init`,
commit, tag, build **outside** the copied tree.

Chosen over `git clone` for three reasons, each backed by a measurement:

- A clone reflects **HEAD**, not the working tree, so during TDD the fixture
  would not contain the fix and would fail for the wrong reason. `ls-files`
  reads the live tree, uncommitted work included.
- A clone of a **shallow** repo is shallow, and Go ignores tags in a shallow
  repo (measurement 6d) → pseudo-version → spurious failure. `actions/checkout`
  defaults to depth 1, so this is the most likely CI flake. `git init` is
  immune.
- It cannot touch the source repo's refs. `git worktree` is **forbidden** here:
  it writes into the developer's `.git/worktrees/` and a tag created in a
  worktree is a tag in the real repo. Constraint: `git tag -l` must print
  exactly `v0.1.0` before and after (measurement 12).

Fixture requirements, each from a measurement or a named failure mode:

| Requirement | Why |
|---|---|
| tag major must be 0 or 1 (`v0.99.0`) | `v9.9.9` is silently ignored for a module path without `/v9` (measurement 6b) |
| binary written outside the copied tree | a binary inside it makes the tree dirty → `+dirty` → rejected (measurement 6c) |
| `-c user.email` / `-c user.name` on the commit | containers have no git identity |
| `-c commit.gpgsign=false -c tag.gpgsign=false`, `--no-verify`, `-c core.hooksPath=/dev/null` | a developer's global signing config or hooks would prompt, hang, or run the whole gate |
| `GOWORK=off`, cleared `GOFLAGS` on the fixture build | ambient `-mod=vendor` or a workspace file would change what is built |

Vacuity guards, all `t.Fatal` (never a skip — `readme_install_exec_test.go:9-11`
sets that convention):

1. `git describe --tags --exact-match HEAD` == the tag.
2. `git status --porcelain` empty before the build.
3. The built binary's own build info reads `v0.99.0` (`debug/buildinfo.Read`).
   Without this a failure cannot distinguish "our resolver is broken" from "the
   toolchain did not stamp".
4. `cmd/curlew/version.go` exists in the copied tree — otherwise the copy
   silently dropped the fix.
5. The **dirty leg**: make the fixture tree dirty, rebuild, expect the default.
   Together with the clean leg this is two-sided — accept-everything fails the
   dirty leg, accept-nothing fails the clean leg.

### D9 — The fixture stays untagged; no new build tag

Measured cost: 5.25s for one clean leg (measurement 11); the dirty leg reuses
the copied tree and adds one `go build` (~1.9s), so ~7s total. `ci-local.sh`
runs this package three times (lines 190, 193, 196) against a 125.2s baseline
(measurement 10), so the gate grows by roughly 21s on ~376s — about 5-6%.

`release_artifacts` and `readme_install` are tagged because they need a
third-party tool, the public internet, `gh`, and git credentials for a private
repo. This fixture needs **git and nothing else** — no network, no credentials
(measurement 11 ran offline). A third tag would also add a third entry to
`.golangci.yml:10-18`, whose comment warns that symbols must be unique across
all tagged files, and would put the task's `observable` commands one forgotten
`-tags` flag away from exiting 0 having run nothing — the failure M25-002 and
M25-003 both hit.

Therefore: **no build tag, no `.golangci.yml` change, no new `ci-local.sh`
step.** The task's `observable` block runs verbatim as written. `testing.Short()`
is not an option — this repo treats conditional skips as vacuous passes.

## Deviations found during /execute

### E1 — D2's pseudoVersionRE was wrong; caught by the plan's own test table

**Medium correction.** The plan's regex (`-[0-9]{14}-[0-9a-f]{12}$`) only
matches Go's "no known base version" pseudo-version form
(`vX.0.0-<timestamp>-<hash>`). Running `TestVersion_falls_back_to_build_info`
exactly as specified failed one of the plan's own table rows:

```
version_test.go:161: resolveVersion("0.1.0-dev", ->("v0.1.1-0.20260817171911-ee182919250e",true))
  = "0.1.1-0.20260817171911-ee182919250e", want "0.1.0-dev"
```

That input is measurement 1 from the plan itself — a plain `go build` on this
tree. Go defines three canonical pseudo-version forms
(https://go.dev/ref/mod#pseudo-versions), and two of them insert `0.` (or
`<pre>.0.`) between the dash and the 14-digit timestamp:

```
vX.0.0-yyyymmddhhmmss-abcdefabcdef          no known base version
vX.Y.(Z+1)-0.yyyymmddhhmmss-abcdefabcdef    base is a release vX.Y.Z
vX.Y.Z-pre.0.yyyymmddhhmmss-abcdefabcdef    base is a pre-release vX.Y.Z-pre
```

The plan's regex required a literal `-` immediately before the 14 digits,
which only the first form has — the other two have `.` there instead (from
`0.`). Fixed by matching either character immediately before the timestamp:
`[.-][0-9]{14}-[0-9a-f]{12}$`. Verified with a standalone probe (not just the
unit test) against all three canonical forms plus every plain
release/pre-release string in the table before applying the fix to
`version.go`. A table row for the third form (pre-release base) was added to
`TestVersion_falls_back_to_build_info` since it was not in the plan's table
and shares the same bug.

This does not change D2's design intent (pseudo-versions are rejected,
release/pre-release versions are accepted) — only the regex that implements
it. D2's table and the "reject by pattern, not by the one you saw" framing
are unchanged and correct; the pattern itself needed a second character
class.

### E2 — Steps 1 and 3 merged into a single GREEN commit

**Small correction (commit granularity only).** The plan staged Step 1
("a new file with new symbols and zero call-site changes") and Step 3
(rewiring all seven production reads) as separate commits, specifically so
Step 1's ~125s test run would stay green in isolation. That staging leaves

```
cmd/curlew/version.go:30:5: var resolvedVersion is unused (unused)
```

CLAUDE.md's quality gate requires `golangci-lint run` to pass before any

The resulting code is byte-for-byte what the plan's Step 1 + Step 3 describe
independently — only the commit boundary moved earlier. Step 2 (the
goreleaser-pin test) and Step 4 (the AST guard, which structurally depends on
Step 3 already being done) proceed as their own steps per the original plan.

### E3 — `docs/MANUAL.md:180` needed no change; the plan's premise about it was wrong

**Small correction, verified before acting on it.** Step 7 said
`docs/MANUAL.md:180` "shows `# curlew 0.1.0-dev` immediately after
instructions to download and install a **release** archive, where the real

That is not what the surrounding section says. `docs/MANUAL.md`'s "1.1

`curlew 0.1.0` as the plan directed would have made the example false.
`docs/MANUAL.md` was left unchanged; see the commit message on

## Deviations found during /review and /improve

### E4 — Step 7's and D7's "next tag" claim about the README test was wrong

**Medium correction, found by /review (Finding 1), verified before acting on
it.** Step 7 said the comment at `readme_install_exec_test.go:101-107`
"breaks at the next tag, when the `go install …@latest` block starts
satisfying `readmeReleasedVersionRE`"; D7 repeated it: "The real path
becomes covered by `TestReadme_install_commands_execute` the moment a
post-fix tag is cut." Both are false, and not because of tag state.

Of the three blocks under README.md's `## Install`, only the first runs the
binary it produces -- it ends `./curlew --version`. "Install from source"
ends at `go install`, which prints nothing on success; "clone and build"
ends at `go build`. Neither invokes `--version`, so neither can print a line
for `readmeReleasedVersionRE` to match -- before this fix, after it, or at
any future tag. Verified by running both blocks verbatim in isolation this
session: zero bytes of combined output from the install-from-source block,
and only git's own `Cloning into 'curlew'...` from the clone-and-build
block.

Extending those two blocks with a version-check line -- making the original
claim true instead of correcting it -- was considered and rejected, for two
reasons each verified this session rather than assumed:

- The install-from-source block has no version-check line that is both
  correct for a reader and safe under the test harness. `go install` honours
  `GOBIN`, and `TestReadme_install_commands_execute` sets `GOBIN` to a
  per-block temp dir precisely so it cannot overwrite the developer's own
  `~/go/bin/curlew` (`readme_install_exec_test.go:98-103`). Under that
  override the natural line to add, `` $(go env GOPATH)/bin/curlew
  --version ``, fails **today**, not just at a future tag: reproduced
  directly, `go env GOPATH` resolves to `/Users/…/go/bin`, which the
  redirected install never writes to, so the line exits 127 ("No such file
  or directory") under `bash -euo pipefail`.
- The clone-and-build block clones the default branch, not a tag, and
  `main`'s HEAD is already past the latest tag in steady state -- confirmed
  freshly this session, not merely cited from measurement: `git describe
  --tags main` reports `v0.1.0-2-gf8584df`, two commits past `v0.1.0`, with
  `git rev-parse main` != `git rev-parse v0.1.0`. A checkout that is not
  exactly at a tag stamps a Go pseudo-version, which this task's own
  resolver deliberately rejects (D1/D2). A version check on that block would
  therefore print the compile-time default in ordinary operation, matching
  `readmeReleasedVersionRE` only in the narrow window between a tag and the
  next commit to `main` -- it would not reliably demonstrate the fallback
  this task adds.

Resolution: the three comments in `readme_install_exec_test.go` and the

```go
package main

import (
	"regexp"
	"runtime/debug"
	"strings"
)

// defaultVersion is the compile-time placeholder. It is the single source of
// truth for "this build was not stamped with a version": `version` is
// initialised from it, so `version != defaultVersion` is exactly "the linker
// injected something", and editing the default cannot desynchronise the two.
const defaultVersion = "0.1.0-dev"

// version is the build's reported version before build-info fallback. It is
// deliberately a var, not a const: release builds overwrite it at link time
// (.goreleaser.yaml) and -ldflags -X is silently ignored for constants — the
// build would succeed and every released binary would claim to be the
// development version. Initialising it from a named constant keeps -X working
// (the linker accepts "a constant string expression") while leaving one
// literal in the tree.
//
// Read resolvedVersion, not this. TestVersion_only_version_go_reads_the_raw_symbol
// enforces that.
var version = defaultVersion

// resolvedVersion is the string every surface reports. Computed once, eagerly:
// a package-level initializer runs after the linker has already patched
// `version`, so it observes an injected value.
var resolvedVersion = resolveVersion(version, buildInfoVersion)

// releaseVersionRE matches a version we are willing to report. Build metadata
// is excluded by construction — there is no '+' in the pattern — so "+dirty"
// and "+incompatible" are rejected without needing a case each.
var releaseVersionRE = regexp.MustCompile(`^v?[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.-]+)?$`)

// pseudoVersionRE matches Go's pseudo-version tail, <14-digit timestamp>-<12
// hex>. Go 1.24+ stamps one into every VCS build that is not exactly at a tag,
// and its numeric prefix names a patch release that was never cut.
var pseudoVersionRE = regexp.MustCompile(`-[0-9]{14}-[0-9a-f]{12}$`)

// buildInfoVersion is the only impure part: the main module's version as
// recorded in the running binary. Populated by `go install <module>@<version>`
// and by VCS stamping; "(devel)" when neither applies.
func buildInfoVersion() (string, bool) {
	info, ok := debug.ReadBuildInfo()
	if !ok || info == nil {
		return "", false
	}
	return info.Main.Version, true
}

// resolveVersion picks the version to report. It never panics and never
// returns "": it runs during package initialisation, where a panic would be
// unrecoverable and would break every command.
func resolveVersion(injected string, readBuildInfo func() (string, bool)) string {
	if injected != defaultVersion && injected != "" {
		return injected // -X is authoritative, reported verbatim
	}
	v, ok := readBuildInfo()
	if !ok || !usableBuildVersion(v) {
		return defaultVersion
	}
	return trimVersionPrefix(v)
}

// usableBuildVersion reports whether v is a real release version rather than
// "(devel)", empty, a pseudo-version, or a version carrying build metadata.
func usableBuildVersion(v string) bool {
	return releaseVersionRE.MatchString(v) && !pseudoVersionRE.MatchString(v)
}

// trimVersionPrefix strips exactly one leading "v", matching goreleaser's
// {{ .Version }}. Applied to the build-info value only — the injected value is
// whatever the release pipeline asked for.
func trimVersionPrefix(v string) string {
	return strings.TrimPrefix(v, "v")
}
```

## Risks and Edge Cases

- **Risk:** `-X` stops reaching `var version = defaultVersion`, silently
  disabling every release version. → **Mitigation:** measured working
  (measurement 9) *before* the design committed to it, and
  `TestVersion_is_injectable_at_link_time` fails loudly if it regresses.
- **Risk:** the fixture leaks a tag into the developer's repository. →
  **Mitigation:** `git init` in `t.TempDir()`, never `git worktree`, never a
  write to the source repo. `git tag -l` printed exactly `v0.1.0` before and
  after every experiment in this session; `/execute` must re-check it.
- **Risk:** the fixture is flaky under `actions/checkout`'s depth-1 default. →
  **Mitigation:** `git init` from `ls-files` does not inherit shallowness
  (measurement 6d is why a clone was rejected).
- **Risk:** a developer's global git config (signing, hooks) hangs the fixture.
  → **Mitigation:** per-invocation `-c` overrides and `--no-verify` (D8).
- **Edge case:** HEAD is exactly a tag during `/verify` or a release, so a plain
  `go build` legitimately reports the tag. → **Handling:** the exact-equality
  default test builds with `-buildvcs=false`; the wiring test derives its
  expectation from the binary's own stamp. Neither assumes an untagged checkout.
- **Edge case:** `v2+` module without a `/vN` path yields `+incompatible`. →
  **Handling:** rejected, falls back to the placeholder. Documented limitation
  (D2), safe direction.
- **Edge case:** a legitimate tag ending in `-<14 digits>-<12 hex>` would be
  misread as a pseudo-version. → **Handling:** accepted risk; the shape is
  reserved by the Go toolchain in practice.
- **Open item, not a risk:** behavior 2's literal `go install <module>@<tag>`
  proof is unreachable until a post-fix tag exists (D7). Recorded in the plan
  and the CHANGELOG rather than papered over with a skip.
