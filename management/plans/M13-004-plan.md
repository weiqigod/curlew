### How the existing `noArgs` registration pattern works (M13-002 / M13-003 mirror)

Each `$faker.*` function at `dynamic.go:430-541` is registered as
`r.funcs["faker.<name>"] = noArgs("faker.<name>", func(rng *rand.Rand) string { … })`.
The `noArgs` wrapper (line 84) rejects argument-bearing calls with a
structured `DYNFN_ARITY` error. Closures route all randomness through
`intn(rng, n)` (line 691), which is the same dispatch surface that
seeded-vs-crypto-rand routing rides on. New company functions follow
this exact shape — five `noArgs` registrations, one for each.

### Composition of `$faker.catchPhrase`

Per behavior 5 / SPECIFICATION.md:799, `$faker.catchPhrase` is a
multi-word business buzzword phrase composed of three independent
pool draws joined by a single ASCII space:

```
<adjective> <noun> <gerund>
```

Example (seed 42): `"Synergized optimal leverage"`. The shipped pools
are 30 / 30 / 30 entries each, drawn in the same `intn` style as the
location address composer. Three `intn` calls per evaluation; the
order is fixed by source-code position so seed-42 reproducibility is
deterministic.

The spec example `"Synergized optimal leverage"` reads as
`<gerund-past-participle> <adjective> <noun>` — but the task YAML
behavior 5 explicitly orders the components as
`<adjective> <noun> <gerund>`. **Decision:** follow the task YAML
behavior 5 ordering since it is what the behavior tests will assert.
Pool entries are chosen so the composed phrase remains plausibly
buzzword-shaped under either ordering (e.g. adjectives like
"Synergized", "Optimized", "Streamlined"; nouns like "leverage",
"paradigm", "synergy"; gerunds like "engaging", "scaling",
"transforming"). The example value rendered in MANUAL.md will follow
the actual implementation ordering.

### `$faker.companySuffix` is a closed canonical set

Per SPECIFICATION.md:796 + behavior 2, the suffix MUST be drawn from
a fixed five-element set:

```
{ "Inc.", "LLC", "Corp.", "Ltd.", "Co." }
```

The validator in tests asserts exact membership via the existing
`isOneOf("Inc.", "LLC", "Corp.", "Ltd.", "Co.")` helper (defined at
`dynamic_test.go:2237`). Because the set is small and closed, this is
the strongest possible black-box assertion.

### `$faker.company`, `$faker.jobTitle`, `$faker.department` are pool draws

Per behaviors 1 / 3 / 4 + SPECIFICATION.md:795-798, each of these is
a non-empty string drawn from the corresponding shipped pool. Tests
assert non-emptiness via `isNonEmpty` (line 140). Optional spot
checks ensure the seed-42 first draw is in-pool. No format
constraints beyond non-empty.

// isCatchPhrase asserts the value is exactly three space-separated
// non-empty tokens. Per behavior 5: <adjective> <noun> <gerund>.
func isCatchPhrase(t *testing.T, val string) {
    t.Helper()
    parts := strings.Split(val, " ")
    if len(parts) != 3 {
        t.Errorf("$faker.catchPhrase %q must have exactly 3 space-separated parts, got %d",
            val, len(parts))
        return
    }
    for i, p := range parts {
        if p == "" {
            t.Errorf("$faker.catchPhrase %q has empty token at position %d", val, i)
        }
    }
}

// funcName that has not been registered yet is treated as an unknown
// key by Evaluate and surfaces the standard `unknown dynamic function
// "<name>"` error. Uses faker.url (M13-005) as the example — a dotted

func TestRegistry_DottedName_InternetNotYetRegistered(t *testing.T) {

## Risks and Edge Cases

- **Risk: companySuffix pool drift.** SPECIFICATION.md:796 + behavior 2
  pin the suffix to a closed five-element canonical set. If a future
  PR adds entries (e.g. "GmbH", "S.A.", "AG") the test
  `TestFakerCompany_SuffixSet` will fail loudly. **Mitigation:**
  the test asserts both length-equality and exact set membership; any
  drift in either direction trips the test.
- **Risk: catchPhrase ordering ambiguity.** The spec example
  `"Synergized optimal leverage"` reads as `<gerund-past-participle>
  <adjective> <noun>`, but task YAML behavior 5 explicitly orders the
  composition `<adjective> <noun> <gerund>`. **Decision:** follow the
  task YAML behavior 5 ordering (it is the contract that tests
  assert). MANUAL.md example is rendered to match the implementation
  (e.g. `"Synergized leverage scaling"`), and pool entries are chosen
  so the result reads as buzzword-shaped under the chosen ordering.
- **Risk: catchPhrase RNG-draw ordering changes break --seed
  reproducibility.** Three `intn` calls per evaluation; their order
  is fixed by source-code position. **Mitigation:** comment in the
  closure explicitly documents "fixed call order"; future refactors
  must preserve the adjective→noun→gerund ordering.
- **Risk: company pool contains a real trademark.** Many of the
  shipped names are intentionally drawn from fictional company-name
  conventions (Acme, Globex, Initech, Hooli, Wonka) plus a small set
  of in-universe names common to API-test demos. **Mitigation:** the
  curated list deliberately avoids real-world trademarks and the
  comment notes the convention. If trademark concerns ever surface,
  individual entries can be replaced without affecting the test
  surface (which only asserts non-emptiness).
- **Risk: pool-size growth changes seeded output.** Two consecutive
  M13 family slices (M13-003 and M13-004) ship pools of different
  sizes; seeded output of `$faker.address` from M13-003 would shift
  if pool sizes changed. **Mitigation:** this slice doesn't modify
  M13-002 or M13-003 pools — they are independent slices. Each new
  pool addition lives in its own `var` block at file scope.
- **Risk: catchPhrase token containing a literal space.** None of
  the three pools contain entries with internal spaces (verified by
  visual review). If a future entry like "Mission Critical" (two
  words) were added to `catchPhraseAdjectives`, the
  `isCatchPhrase` validator (which splits on `" "`) would
  miscount tokens. **Mitigation:** existing test
  `TestRegistry_FakerCompany_CatchPhraseShape` checks each token is
  a member of the corresponding pool, which would surface mismatches
  loudly. The plan ships only single-token entries; a multi-word
  catchPhrase pool would require revisiting the join character.
- **Edge case: per-request memoization.** `Registry.Evaluate` already
  caches results per (name, args) within a request via the `cache`
  parameter. Two `{{$faker.company}}` placeholders in the same
  request resolve to the same value — this is documented behavior
  (MANUAL.md:1261) and is the property we want.
- **Edge case: behavior 8 (locale).** The `--locale de-DE` flag does
  not exist in M13 — `cmd/apitest/main.go` has no `locale`
  references. Behavior 8 is satisfied by the absence of the flag
  (en-US is the only path). The `t.Skip`-guarded
  `TestRegistry_FakerCompany_LocaleDeferred` documents the contract
  stub for the future locale-support milestone, mirroring the
  M13-002 / M13-003 pattern.
