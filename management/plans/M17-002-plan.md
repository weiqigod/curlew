# Implementation Plan: M17-002

## Overview

Add the first concrete signer behind M17-001's registry: an AWS Signature
Version 4 implementation in `internal/signer/awssigv4/`, registered at
init time, exercising the full canonical-request → string-to-sign →
signing-key → signature → Authorization-header pipeline against the
published AWS SigV4 test-suite vectors. Standard library only (no AWS
SDK). Mirrors the M12-005 sensitive-key auto-redaction pattern via
`SensitiveSet.AddValue` for `secret_key` and `session_token` when their
values were sourced from sensitive variables.

## Architectural Decisions

These resolve open questions surfaced during code exploration. They are
documented up-front so reviewers and downstream tasks (M17-003 OAuth1)
inherit the same conventions without re-deriving them.

### D1. How does init-time registration work given an immutable `signer.go`?

**Constraint:** the task scope forbids modifying
`internal/signer/signer.go` (M17-001 owns the registry interface). But
M17-001's `NewBuiltinRegistry()` returns a *fresh empty* `*Registry` on
every call, and there is no package-level `signer.Register(...)`
function — only the *method* `(*Registry).Register`. So a subpackage's
`init()` cannot directly populate "the" registry the runner will use.

**Resolution:** add a *new* file `internal/signer/builtins.go` (allowed —
the prohibition covers only `signer.go`) introducing:

- a package-level `builtinFactories map[string]Factory` guarded by a
  sync.Mutex;
- `Register(name string, factory Factory) error` — package-level
  function for init-time use; rejects duplicates;
- `MustRegister(name string, factory Factory)` — panic-on-duplicate
  variant for use inside `init()`;
- `NewWithBuiltins() *Registry` — constructor that calls
  `NewBuiltinRegistry()` to get an empty registry then copies every
  registered builtin into it.

The runner's existing fallback in `runner.go:494` (`signerReg =
signer.NewBuiltinRegistry()`) is changed to `NewWithBuiltins()` so that
when `vars.Signer` is nil the runner picks up every init-registered
built-in. M17-001's existing `(*Registry).Register` and
`NewBuiltinRegistry()` remain unchanged — `NewWithBuiltins()` is purely
additive.

This preserves the M17-001 interface (`signer.go` untouched) while
giving subpackages an idiomatic Go init-time registration hook.

### D2. How does the awssigv4 signer get a `*variable.Scope` for {{interpolation}} of params?

**Constraint:** `Factory` has signature `func(params map[string]any)
(Signer, error)` and `Sign` has signature `func(ctx, *Request,
*SensitiveSet) error`. Neither carries a Scope. But behaviors require
that `secret_key: "{{aws_secret}}"` resolves through the variable chain
inside `Sign` *and* that resolved-from-sensitive secrets call
`sensitives.AddValue(resolved)` from inside `Sign`.

**Resolution:** thread the per-request `*variable.Scope` via the
context that the runner already attaches to `RequestSpec`. Add a new
file `internal/signer/scope_ctx.go` (allowed — separate from
`signer.go`) exposing:

- `WithScope(ctx context.Context, s *variable.Scope) context.Context`
- `ScopeFromContext(ctx context.Context) *variable.Scope`

The runner's existing per-request signing-spec attachment sites
(`runner.go:1842`, `runner.go:2214`, `runner.go:2429`, plus
`pPreExec` at `runner.go:1318-1320`) gain a single additional line:
`execCtx = signer.WithScope(execCtx, reqScope)`. The awssigv4 `Sign`
reads the scope from ctx and uses `scope.Interpolate` for each param,
then calls `sensitives.AddValue(resolved)` for `secret_key` /
`session_token` whose pre-interpolation form referenced a sensitive
variable name.

When ctx carries no scope (e.g. unit tests that bypass the runner and
construct an awssigv4 signer directly), the signer treats params as
already-literal and skips both interpolation and AddValue. Tests that
exercise the sensitive-propagation behavior provide a scope explicitly.

### D3. Where do the AWS test-suite vectors come from?

**Resolution:** ship the canonical inputs (request line, headers, body)
and expected outputs (canonical request, string-to-sign, signature,
authorization header) as fixture files under
`internal/signer/awssigv4/testdata/`. One fixture directory per vector.
On test failure the helper diffs got-vs-want for *each* intermediate
step (canonical request → string-to-sign → signature) so a regression
points at the exact stage that broke. Use the published AWS SigV4
test-suite vectors verbatim:

- `get-vanilla` — basic GET with frozen clock; covers canonical request
  hashing, string-to-sign formatting, signing-key derivation, and final
  signature.
- `get-header-key-case` — mixed-case request headers; covers canonical
  header-name lowercasing.
- `post-x-www-form-urlencoded` — POST with form body; covers body-hash
  injection via `x-amz-content-sha256` for non-empty payloads.

### D4. `httpexec.Request.QueryParams` is `map[string]string`, not multi-valued.

**Finding:** the existing `httpexec.Request.QueryParams` field is a
`map[string]string`. But the AWS SigV4 spec requires multi-value query
params be sorted by key then by value. The behaviors call this out:
"Given a query string with multi-value parameters (e.g. ?Key=2&Key=1)".

**Resolution:** the signer parses multi-value query params from the
URL string itself (via `net/url.ParseQuery` which returns
`url.Values = map[string][]string`), then *appends* every entry from
`req.QueryParams` (single-valued, deduplicated by the map type). The
merged set is sorted by key then by value. This matches the runner's
`applyQueryParams` order in `httpexec/executor.go:86-100` (URL params
+ map params merged when the HTTP request is finally serialized).
Duplicates between URL and map are *preserved verbatim* — AWS SigV4's
canonical form requires it.

### D7. Clock seam — exposed via a Factory option, not on the registry-level Factory.

**Resolution:** the registered `Factory` ignores clock — it always uses
`time.Now`. For tests, the awssigv4 package exposes a separate
constructor `NewSigner(params map[string]any, opts ...Option) (Signer,
error)` that accepts `WithClock(now func() time.Time)`. Tests with
frozen clocks call `NewSigner` directly. Production code (the runner)
uses the registered `Factory` which always wraps `NewSigner` with
`time.Now`.

```go
// internal/signer/builtins.go
package signer

import (
	"fmt"
	"sync"
)

// builtinFactories holds first-party signer factories registered at
// init time by subpackages (e.g. internal/signer/awssigv4). It is
// distinct from the per-Run *Registry returned by NewBuiltinRegistry —
// NewWithBuiltins copies each entry into a fresh *Registry so callers
// get an isolated, mutable instance.
var (
	builtinMu        sync.Mutex
	builtinFactories = make(map[string]Factory)
)

// Register installs factory under name in the package-level builtins
// map consulted by NewWithBuiltins. Returns an error when name is
// already registered. Subpackages call this from init().
func Register(name string, factory Factory) error {
	builtinMu.Lock()
	defer builtinMu.Unlock()
	if _, dup := builtinFactories[name]; dup {
		return fmt.Errorf("signer type %q already registered", name)
	}
	builtinFactories[name] = factory
	return nil
}

// MustRegister panics on duplicate registration. Use from init().
func MustRegister(name string, factory Factory) {
	if err := Register(name, factory); err != nil {
		panic(err)
	}
}

// NewWithBuiltins returns a registry preloaded with every signer that
// registered itself via Register at package init time. Each call
// returns a fresh, independent *Registry — mutations to the returned
// registry do not affect the package-level builtins map.
func NewWithBuiltins() *Registry {
	r := NewBuiltinRegistry()
	builtinMu.Lock()
	defer builtinMu.Unlock()
	for name, factory := range builtinFactories {
		_ = r.Register(name, factory) // safe: r is fresh
	}
	return r
}
```

// internal/signer/scope_ctx.go
package signer

import (
	"context"

	"github.com/peterlindqvist/apitest/internal/variable"
)

// scopeKey is the unexported context key for the per-request
// *variable.Scope, attached by the runner before invoking the signer
// wrap. Concrete signers retrieve it via ScopeFromContext when they
// need to interpolate {{var}} references in their params.
type scopeKey struct{}

// WithScope returns a derived context carrying scope. Pass nil to
// indicate "no scope available" (downstream signers must treat params
// as already-literal in that case).
func WithScope(ctx context.Context, scope *variable.Scope) context.Context {
	return context.WithValue(ctx, scopeKey{}, scope)
}

// ScopeFromContext returns the scope previously attached via WithScope,
// or nil when none is present.
func ScopeFromContext(ctx context.Context) *variable.Scope {
	v, _ := ctx.Value(scopeKey{}).(*variable.Scope)
	return v
}
```

#### Key Algorithm — Sign

Pseudocode (the actual implementation is ~200 lines, broken into
private helpers `canonicalRequest`, `stringToSign`, `signingKey`,
`signature`):

```
Sign(ctx, req, sensitives):
    scope := signer.ScopeFromContext(ctx)
    resolved, sourceWasSensitive := resolveParams(s.rawParams, scope)
    if missing := requireFields(resolved); missing != "" {
        return structured-error code SIGNER_AWSSIGV4_MISSING_FIELD
    }

    region, service := resolved["region"], resolved["service"]
    accessKey      := resolved["access_key"]
    secretKey      := resolved["secret_key"]
    sessionToken   := resolved["session_token"] // may be ""

    // M12-005 mirror: sensitive-source propagation.
    if sensitives != nil {
        if sourceWasSensitive["secret_key"] {
            sensitives.AddValue(secretKey)
        }
        if sessionToken != "" && sourceWasSensitive["session_token"] {
            sensitives.AddValue(sessionToken)
        }
        // access_key is per AWS guidance not strictly secret — never added.
    }

    bodyBytes := serializeBody(req.Body)        // []byte
    bodyHash  := sha256Hex(bodyBytes)            // 64 lowercase hex

    now := s.now().UTC()
    amzDate := now.Format("20060102T150405Z")
    dateStamp := now.Format("20060102")

    if req.Headers == nil { req.Headers = make(map[string]string) }
    req.Headers["x-amz-date"] = amzDate
    req.Headers["x-amz-content-sha256"] = bodyHash
    if sessionToken != "" {
        req.Headers["x-amz-security-token"] = sessionToken
    }

    canonReq, signedHeaders := canonicalRequest(req, bodyHash)
    credScope := dateStamp + "/" + region + "/" + service + "/aws4_request"
    sts := "AWS4-HMAC-SHA256\n" + amzDate + "\n" + credScope + "\n" + sha256Hex([]byte(canonReq))
    key := signingKey(secretKey, dateStamp, region, service)
    sig := hmacHex(key, sts)
    auth := fmt.Sprintf(
        "AWS4-HMAC-SHA256 Credential=%s/%s, SignedHeaders=%s, Signature=%s",
        accessKey, credScope, signedHeaders, sig,
    )
    req.Headers["Authorization"] = auth
    return nil
```

#### Canonical Request Builder

```
canonicalRequest(req, bodyHash) -> (canon, signedHeaders):
    u, _ := url.Parse(req.URL)
    method := strings.ToUpper(req.Method)
    canonURI := canonicalPath(u.Path)        // RFC3986; preserve "/" if empty
    canonQuery := canonicalQuery(u, req.QueryParams)

    // Normalise headers: lowercase names, trim+collapse values, host required.
    headers := normalisedHeaders(req.Headers, u.Host)
    canonHeaders, signedHeaders := buildCanonicalHeaderBlock(headers)

    return method + "\n" + canonURI + "\n" + canonQuery + "\n" +
        canonHeaders + "\n" + signedHeaders + "\n" + bodyHash, signedHeaders
```

#### Canonical Query (D4 — multi-value merge)

```
canonicalQuery(u, mapParams) -> string:
    pairs := []pair{}
    for k, vs := range u.Query() {              // url.Values is map[string][]string
        for _, v := range vs {
            pairs = append(pairs, pair{k, v})
        }
    }
    for k, v := range mapParams {                // append, not de-duplicate
        pairs = append(pairs, pair{k, v})
    }
    sort.Slice(pairs, func(i, j int) bool {
        if pairs[i].k != pairs[j].k { return pairs[i].k < pairs[j].k }
        return pairs[i].v < pairs[j].v
    })
    parts := make([]string, len(pairs))
    for i, p := range pairs {
        parts[i] = uriEscape(p.k) + "=" + uriEscape(p.v)
    }
    return strings.Join(parts, "&")
```

#### Signing Key Derivation

```
signingKey(secret, date, region, service) -> []byte:
    kDate    := hmac([]byte("AWS4"+secret), date)
    kRegion  := hmac(kDate, region)
    kService := hmac(kRegion, service)
    kSigning := hmac(kService, "aws4_request")
    return kSigning
```

### 6.8 Request signing

The `signing:` field on a request (or as a collection-level default)
applies a built-in signer to the outgoing request between variable
templating and HTTP dispatch. Built-in signers are universally available
across all tiers — no plugin binary required.

| Type        | Required params                                          | Summary |
|-------------|----------------------------------------------------------|---------|
| `aws-sigv4` | `region`, `service`, `access_key`, `secret_key`           | AWS Signature Version 4. Optional: `session_token` for STS-issued credentials. |
| `oauth1`    | (shipping in M17-003)                                     | OAuth 1.0a HMAC-SHA1 / RSA-SHA1. |

Example:

\`\`\`yaml
requests:
  - name: list-buckets
    request:
      method: GET
      url: "https://s3.us-east-1.amazonaws.com/"
    signing:
      type: aws-sigv4
      params:
        region: us-east-1
        service: s3
        access_key: "{{aws_key}}"
        secret_key: "{{aws_secret}}"   # auto-redacted when aws_secret is sensitive
\`\`\`

**Sensitive-secret footgun:** when `secret_key` is a literal string
(no `{{var}}` reference), the resolved value is **not** added to the
sensitive set — there is no source variable to back-trace. Always
prefer variable references for credential params. This mirrors the
$hmacSha256 documentation in §3.7.
```

## Risks and Edge Cases

- **Risk:** `--dry-run` does not currently populate `request_headers`
  in JSON output. → **Mitigation:** confirmed during step-6 execute;
  if confirmed, extend dry-run with a minimal additive change (emit
  RequestHeaders after Sign even when network is skipped). If the
  change exceeds the slice's scope, fall back to a unit test with a
  mocked exec function and reduce the smoke gate to "binary built and
  exits 0 with aws-sigv4 in registry".
- **Risk:** AWS SigV4's path-canonicalization rules (RFC 3986
  unreserved chars, double-encoding for non-S3 services) are subtle —
  in particular, S3 expects single-encoded paths while every other
  service expects double-encoded paths. → **Mitigation:** the
  test-suite vectors all use service names that expect double-encoding
  by spec; we follow the spec exactly. S3 single-encoding is a
  follow-up if customer demand emerges (callable out as a known
  limitation in the package doc comment, mirroring the SigV4-A
  exclusion in scope).
- **Risk:** the `host` header may or may not be present on the inbound
  `httpexec.Request`. → **Mitigation:** if absent, the signer derives
  it from `url.Parse(req.URL).Host` and *injects* a `host` header
  before computing canonical headers. If the runner later overrides
  this via `httpReq.Host` (Go's net/http `Host` field), the on-wire
  Host matches the signed Host because Go's transport always uses
  `httpReq.Host` (or URL host if Host is empty) — same value the
  signer sees.
- **Risk:** body serialization. `httpexec.Request.Body` is `any`,
  serialized lazily by `prepareBody` in executor.go. Sign needs the
  bytes BEFORE exec to compute `x-amz-content-sha256`. → **Mitigation:**
  reuse the same serialization rules: string/[]byte → verbatim, else
  `json.Marshal`. Extract a tiny `serializeBody` helper in the
  awssigv4 package (don't depend on the unexported `prepareBody`).
  When the runner later serializes the body for transport, the bytes
  match.
- **Risk:** thread-safety of `builtinFactories`. → **Mitigation:**
  guarded by `sync.Mutex`; only mutated from `init()` (single goroutine
  by Go's runtime guarantees), but reads happen from any goroutine.
  Mutex is overkill but cheap.
- **Edge case:** empty body. → **Handling:** `bodyBytes = nil` →
  `sha256Hex(nil) == "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"`
  (the well-known empty hash). Spec'd in the task observable.
- **Edge case:** `req.URL` empty path (`https://example.com`). →
  **Handling:** canonical URI is `/` per spec.
- **Edge case:** `region` or `service` containing variable references
  (`region: "{{aws_region}}"`). → **Handling:** interpolated through
  scope before validation; literal-vs-variable distinction does not
  matter for non-secret fields.
- **Edge case:** Sign called with nil sensitives. → **Handling:**
  `SensitiveSet.AddValue` is nil-safe (variable/sensitive.go:67-70);
  no special-casing needed.
